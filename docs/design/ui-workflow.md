# UI 设计与浏览器验证流程

适用范围：新页面迁移、新增界面功能，以及现有页面的布局、样式和交互调整。2026-10-20 用户确认。

目标：开发者先依据规范和真实页面主动发现、修复问题，再交给用户验收。构建成功只表示代码能打包，不表示布局、样式和交互已经验证。

## 设计依据

1. 用户明确确认的最新需求与取舍
2. [主题落地](theme.md)、[页面布局](page-layout.md)及[配色与字体](color-and-typography.md)中的现行规则
3. 已验收的同类组件和真实页面，包括 `/dev/theme`、`MxTitle`、`MxPanel`、`MxSection`、查询表单及地图公共组件
4. 旧交互原型与旧项目中实际使用的页面，作为迁移背景，不覆盖最新规范

开始修改前指出本次参照的组件或页面，确认标题层级、字号、颜色、竖条、间距和交互状态。优先复用已有组件及令牌，不按局部截图重新发明同类样式。发现规范与实现冲突时先核对最新决策，不能把偶然的页面缺陷写成新规范。

旧原型可能在被 Git 忽略的 `apps/web/design.local/` 或 `apps/web/public/design.local/`，必要时显式检查这些目录。Git 标签不保存被忽略的文件，不能假定切回旧标签就能恢复设计稿。

## 先提供可操作的设计稿

- 新页面、较大的布局变化或新的交互形式，先提供可在浏览器中运行的原型，用户确认后再实现业务；已经确认的小幅修正直接修改真实组件并验证
- 原型默认采用 HTML / CSS / JavaScript，放在 `apps/web/public/design.local/`，不入库；需要复用现成组件时使用开发预览页，遵守现有 `pages/dev` 路由与生产隔离规则
- 使用项目字体、图标及设计令牌，提供有代表性的固定数据；涉及组件已有的交互时优先使用真实组件，避免重新手写一份后发生偏差
- 本次设计涉及的切换、展开收起、悬浮、弹窗、滚动和窄屏变化必须能操作；长名称、多项数据、空状态等可以通过明确的演示入口切换
- 模拟数据、尚未实现的操作和真实业务之间的边界需说明，不能把静态占位控件当作交互已完成
- 交付可访问地址、源文件位置、主要操作路径及实际检查过的尺寸；截图只作状态记录，不能代替可运行页面。浏览器打不开时明确原因，不宣称已完成浏览器验证

原型用于确认布局和操作方式，最终仍需检查真实实现，不能用原型通过代替业务页面通过。

## 服务与短时测试

用户已授权 UI 工作执行必要的短时浏览器测试，无需每轮重复确认。这是 UI 验证对此前“只运行 build、不启动服务”约定的专项补充，不改变现有 CI 检查。

| 场景 | 执行方式 |
|---|---|
| 用户已经启动相关服务 | 优先复用，确认地址、当前页面与本轮代码对应；保留用户的服务，不重启、不停止 |
| 现有服务能满足页面检查 | 使用已连接的 Chrome 或内置浏览器操作、测量和截图，不另外启动服务 |
| 需要真实组件布局回归 | 按改动范围运行现有 Vitest 浏览器项目中的相关用例，使用 `run` 模式，测试结束退出 |
| 没有合适服务，或测试需要隔离环境 | 允许仅供本轮验证的静态服务、构建产物预览或测试框架管理的临时服务，绑定本机地址，设置超时并在结束或失败时清理 |
| 涉及生产入口、加载、路由或页面缓存 | 按现有生产冒烟约定先构建内网产物，再运行必要用例；这组测试需要独立预览，不能用开发服务替代 |

- 不启动长期运行的 `dev`、`start`、`test:watch` 或后台常驻服务，也不把服务留给用户手动清理
- 普通页面检查优先复用服务；现有 `test:smoke` 使用独立的 4173 端口并自动启停预览，`reuseExistingServer: false` 是产物隔离要求。端口占用时不能结束用户进程或直接复用未知服务
- 实际命令及前置条件见 [commands.md](../commands.md)；只运行与本轮修改有关的必要检查，低影响样式修改不为凑覆盖率新增测试
- 优先使用固定数据和隔离浏览器上下文；在用户现有页面检查时，记录并恢复验证中改变的偏好，不提交真实业务数据
- 清理仅针对本轮创建的进程、页面及临时状态。浏览器权限或安全策略阻止操作时说明具体限制，不绕过限制

## 每轮修改的步骤

1. **修改前看现场**：读取相关规范与组件，打开真实页面，记录当前状态、浏览器视口和问题的复现步骤；有视觉变化时保留对照截图
2. **确定检查范围**：列出受影响的正常操作与边界状态，采用代表性组合，不机械穷举全部状态；较大的新布局先完成交互原型确认
3. **最小修改**：沿用状态拥有者和公共组件，不因样式调整重写业务逻辑
4. **实际操作并测量**：点击、悬浮、移出、滚动、切换与关闭，读取实际样式和元素尺寸，检查控制台错误；不能只看默认状态的截图
5. **主动修复再复查**：发现布局或交互问题先修复，复查失败场景和直接关联状态。疑似热更新残留时，在保留必要输入后刷新核对，不用旧 DOM 状态推断新代码正确与否
6. **构建与必要回归**：代码修改执行 `pnpm build`，根据风险运行相关短时浏览器用例；只有说明文档变化时检查链接与差异，无需启动服务或构建
7. **交付证据**：说明实际访问的页面、检查的尺寸与状态、结果，以及未验证项，附有代表性的真实截图或差异图；基础缺陷处理完后再交给用户验收

页面无法访问、缺少字体、测试未执行或仍有失败时，如实记录验证缺口，不能以“构建通过”代替“UI 已验证”。已有授权范围内可以解决的问题继续处理。

## 检查重点

| 范围 | 必查内容 |
|---|---|
| 视觉一致性 | 标题与副标题层级、字号字重、蓝色竖条、图标尺寸、颜色令牌、背景、间距、对齐、选中态 |
| 布局 | 页面和面板无非预期横向溢出；控件不截断、不重叠；滚动到底保留规范间距；固定标题、底栏不会随内容滚动 |
| 交互 | 默认、悬浮、鼠标移出、键盘焦点、选中、打开、关闭、禁用；浮层关闭后入口与焦点状态正确 |
| 内容边界 | 空、单项、多项、长名称、加载、失败；只覆盖当前功能确实具有的状态 |
| 屏幕尺寸 | 当前常用视口及相关窄屏、矮屏；以实际浏览器内容区尺寸为准，布局变动检查项目断点两侧 |
| 业务一致性 | UI 的勾选、排序、年份、透明度和图例状态与状态拥有者、实际地图结果一致 |

现状底图优先检查：

- 0 / 1 / 多个已勾选资源，展开与收起，拖拽后序号和图层顺序
- 1 / 3 / 4 个功能标签，以及功能面板、资源详情、底图同时打开时的布局
- 透明度 0% / 100%，打开后移出、返回、滚动、关闭再打开
- 普通与复杂图例、长名称、展开、样式编辑、恢复入口的出现和消失，以及长内容滚动
- 右侧工具栏在常规、矮屏和窄屏下的完整性，浮层定位与避让

迁移列表或表单页面时，按该页面增加筛选换行、长表格、分页固定、校验提示和提交状态，不照搬地图专用检查。

## 自动化与截图对比

优先复用现有 Playwright、Vitest 浏览器测试及固定接口数据。真实交互检查、几何断言与截图比较共同使用：尺寸检查负责溢出和遮挡，操作检查负责状态变化，截图帮助发现视觉偏差。

- 截图固定视口、缩放、设备像素比、浏览器版本和数据，等待字体、布局与必要渲染稳定；不靠任意延时或禁用所有交互来隐藏缺陷
- UI 对比优先截图相关面板，必要时仅屏蔽与本次检查无关的动态地图内容；地图本身的渲染结果另做验证
- 基线与实际截图使用相同的操作系统和字体环境，不能直接混用本机私有字体与 CI 回退字体的结果
- 保存预期、实际、差异图；操作问题按需保留轨迹与错误信息。开发者必须查看差异并判断原因，不能批量更新基线消除失败
- 已确认且仍适用的样式用于建立基线；用户主动修改的设计允许在检查实际结果后更新相应基线，不能把旧图当作不可变需求
- 成熟组件沿用相邻浏览器测试，完整产物流程沿用 `tools/smoke/`；不为截图另建一套业务实现。截图输出不得进入生产产物

当前已经具备浏览器测试与生产冒烟基础，但自动截图基线、差异报告尚未统一接入。本文件规定实施方式，不代表这些能力已经建设或运行完毕。

## 原型清理与稳定后的交互样例

- 本轮尚未稳定的界面继续在真实页面中调整，暂不另做一份需要反复同步的完整设计稿
- 页面完成并验收后，将可复用的标题、面板、工具栏、标签、列表、Popover、滑块与图例整理成交互样例；优先扩展现有开发预览并复用真实组件，不能维护一套外观相似但独立的样式
- 样例提供固定数据和状态切换，标明适用场景与规范来源；组件变动时同步验证，使其成为后续页面迁移的参照
- 临时原型在确认实现后可以清理；保留的旧原型只作为历史参考，最终规范、组件和验证结论写入仓库，不依赖某个未入库文件
- 清理具体文件由用户决定，本流程不授权批量删除旧原型；当前页面稳定后的样例整理与自动截图流程落地另记路线图，不能提前标记完成
