# 三维模型清单（`apps/yzt/public/3dt/manifest.json`）

资源图层面板的目录里列出哪些三维模型、在哪个市、是什么、数据在哪（ADR 0081、0157）。入库的是全集，随产物发布到 `dist/3dt/manifest.json`；构建时设了部署站点的，去掉那台服务器缺的模型再发布（下面"按站点发布"，ADR 0164）。部署时可以直接替换（[overview.md](overview.md)"运行时文件"）。格式由 `features/scene-models/api.ts` 的 zod 校验，严格对象：多写、写错位置的字段都让整份清单不合法，目录最后提示"三维模型清单加载失败"。

模型数据不入库，也不进构建产物（ADR 0083、0141）：本机放在 `local/3dt/`，服务器上由 nginx 在 `/3dt/` 下提供或转发（[local-files.md](local-files.md)、[deployment.md](../deployment.md)）。

新增、修改模型按最后一节"新增一个模型"做。

## 目录层级

用户 2026-11-11 定，取代 ADR 0149 第 3 节的"所有模型平铺在 `3dt/` 下"：

```
3dt/manifest.json                                 清单，随前端发布（deployment.md）
3dt/<市>/3dtiles/<模型名>/tileset.json            倾斜摄影、室内
3dt/<市>/3dtiles/<模型名>/<效果>/tileset.json     白膜，每种效果一套
3dt/<市>/lcc2/<目录>/lcc2-sog-result/<索引>.lcc2   高斯泼溅
                                     data/3dgs/*.sog
                                     data/mesh/*.ply、*.btree
                                     info/attrs.json、poses.json、media/
```

- `<市>` 是市名的拼音，小写：`suzhou`、`wuxi`、`xuzhou`；
- 3D Tiles 的目录名和清单里的 `name` 相同（2026-11-11 改成了中文名）；LCC2 保留数据方交付的目录名和里面的层级，目录名、索引的文件名都不一定是模型名（`城下城（测试）`、`20260921龟山汉墓.lcc2`）；
- 清单里写相对清单的路径，每一段按 URL 编码（`encodeURIComponent`），`catalog.test.ts` 按上面的规则检查入库的清单；
- 本机的 `local/3dt/` 和服务器上的层级相同。

## 按站点发布

几台服务器上的数据不一样多时，清单仍只有一份全集，每台服务器是一个部署站点，只记它缺哪些模型（ADR 0164）。用户 2026-11-17 定：两台内网服务器都继续用，站点名用 IP 的后两段。

站点在 `apps/yzt/tools/site/sites.json`，格式由 `tools/site/sites.ts` 的 zod 严格校验（多写、写错的字段让构建失败）。以后比如新吴区06 进了全集、153.194 上没有它的数据时写成：

```json
"153-194": {
  "label": "内网 Linux 服务器 192.168.153.194",
  "origin": "http://192.168.153.194:5173",
  "missing": [{ "id": "wx-xwq06", "reason": "只在 15.111 上，153.194 的新吴区06 缺根 tileset.json" }]
}
```

| 字段 | 说明 |
|---|---|
| 键 | 站点名，构建时 `YZT_SITE` 的取值；小写字母、数字和连字符 |
| `label` | 构建日志、`site:check` 里显示 |
| `origin` | 可选，前端的 http 地址，`site:check` 默认检查它 |
| `missing` | 这台服务器上没有数据的模型：`id` 必须在全集里、不能重复；`reason` 必填，写为什么缺，构建日志和 `site:check` 里显示；数据补齐后连这一项一起删掉 |

站点是数据文件、不是 TS 模块：插件用 fs 读它，它不是 `vite.config.ts` 的依赖。Vitest 改到配置的依赖时会把全部测试都选上，写成 TS 的话每改一次 `missing`，`test:changed` 都要跑全部单元测试和浏览器测试；写成 JSON 只选中 `tools/site/sites.test.ts`。

规则：

- 同一个 ID 在每台服务器上是同一份数据（配准、屏幕误差只做一次）。数据方重新导出、只换了一台时，在全集里另起一个 ID，各站点按有没有排除，或者所有服务器一起换；
- 每台服务器在同源的 `/3dt/` 下按上面的"目录层级"提供同一套地址，磁盘上放在哪里由它的 nginx `alias` 决定。站点不能改路径，也不能改模型的字段；测试服务器 `192.168.1.180` 还是平铺的旧目录，整理以前不建站点；
- 只给要部署的服务器建站点。数据齐全的站点 `missing` 是空的，组合出来的就是全集的原文。

用法（PowerShell）：

- 构建：`$env:YZT_SITE = '15-111'; pnpm build:intranet; Remove-Item Env:YZT_SITE`。日志里有一行`[site] 站点 15-111（…）：三维模型清单发布全集 N 个中的 M 个`；不设时是`没有设 YZT_SITE：三维模型清单发布全集 N 个模型`。站点名、缺的 ID 写错时构建在打包之前失败。`$env:` 设的变量在整个窗口里一直有效，所以构建完就清掉；
- 发布后核对：`pnpm --filter yzt site:check 15-111`（只读）：服务器上的清单是不是这个站点的组合，每个模型的入口能不能取到，每个能取到的 LCC2 的第一个数据块 Range 合不合格（[deployment.md](../deployment.md)）。新加服务器、数据有变化时加 `--suggest`：探测全集里的每个模型，打印这台缺的模型（入口 404 或回退成网页的），可以抄进 `missing`，`reason` 要改成真实的原因（[commands.md](../commands.md)）；
- 开发时看某台服务器上的模型：同时设 `YZT_3DT_PROXY` 和 `YZT_SITE`，清单来自工作区的组合、模型从服务器取（[local-files.md](local-files.md)"模型从服务器取"）；
- `pnpm --filter yzt test:unit tools/site` 检查每个站点都写对了（`sites.test.ts`）。

## 共有的字段

| 字段 | 说明 |
|---|---|
| `id` | 模型 ID，整份清单不重复；也是三维内容里瓦片集（白膜是 `模型ID/效果ID`）、高斯泼溅的 ID |
| `name` | 面板上显示的名称 |
| `cityCode` | 市的区划代码，必须在区划目录里；市名取自目录 |
| `kind` | `oblique` 倾斜摄影、`white` 白膜、`indoor` 室内、`splat` 高斯泼溅 |
| `underground` | 地下的模型：漫游时抬高、用头灯（ADR 0097、0147 第 4 节）；对 `splat` 只影响漫游别的地下模型时它是否还显示 |

## 瓦片集模型（`oblique`、`white`、`indoor`）

| 字段 | 说明 |
|---|---|
| `tileset` | `oblique`、`indoor`：`tileset.json` 的地址，相对清单，按段编码（见"目录层级"） |
| `effects` | `white`：`[{ id, label, tileset }]`，第一种是默认效果；`label` 显示在面板"图层"一段行尾 56 宽的框里，写短名（如"无纹理""效果1"），超过四个字会省略 |
| `maximumScreenSpaceError` | 可选，屏幕误差上限（正数）；不写用默认值 8，只给放不下的模型写，放不下的写 16（怎么判断见"新增一个模型"的瓦片集第 4 步；[map-three.md](../modules/map-three.md)"渲染"的瓦片） |
| `spawn` | 可选，步行的出生点 `{ lng, lat, height, heading }`：脚下地板的椭球高，朝向是正北为 0、顺时针的度数。写了就能步行，瓦片集里只给 `indoor` 写（见"新增一个模型"） |
| `routes` | 可选，预置的漫游路线 `[{ id, name, path }]`，`path` 是脚下地板的 `[经度, 纬度, 椭球高]`，至少两个点；头顶低的地方可以多一个值，是视点在地板以上的米数（大于 0、不超过 1.6，不写是 1.6，ADR 0156 第 3 节） |

## 高斯泼溅（`splat`，ADR 0149）

不写 `maximumScreenSpaceError`。可以写 `spawn`、`routes`（写法同瓦片集模型），由配准工具从扫描轨迹生成（ADR 0156 第 4 节，见下面"出生点和路线"）；写了 `routes` 就要写 `spawn`，否则整份清单不合法：路线漫游也建导航网格（小地图），只留出生点附近的区域，没有出生点时会留下全图最大的一片（可能是屋顶）。

| 字段 | 说明 |
|---|---|
| `lcc2` | `.lcc2` 索引的地址，相对清单；数据文件的路径由库按索引的地址解析。按段编码（见"目录层级"） |
| `placement` | 配准后的摆放 `{ lng, lat, height, heading }`，不用索引里的 `epsg`、`offset`（ADR 0149 第 4 节） |

**出生点和路线**（ADR 0156 第 4 节）：

- 用 `pnpm --filter yzt lcc2:register <索引> --datum 5.47 --roam --plan lcc2-plan/<模型ID>.svg`（[commands.md](../commands.md)），参数和配准时一样，出生点、路线就和 `placement` 在同一个修正下；`--plan` 把轨迹画成一张平面图，写到 `local/lcc2-plan/` 下，不入库，用浏览器打开；
- 先看平面图和打印的轨迹概要（每 20 米一行），挑路线段：扫描会来回走、绕圈闭合，一整条太长（土山墓 1.1 公里），所以按段取，每段写成 `--route ID:名称:起-止`，段由开发者提议、用户定；扫描的人在宽的坡道、走廊里左右摆得大（1.5～3 米）、路线在那里蛇形的，加大拉直的容差：整条路线用 `--route ID:名称:起-止:容差`，只有一段用 `--straight 起-止:容差`（按轨迹米数，进小室又出来的地方留默认的 1 米，否则被拉直跳过），新加的参数写进下面"现有模型的说明"那一行的命令，能重跑（[commands.md](../commands.md)）；
- 平面图上有：碰撞网格的地板（每格最低的一层表面，越深越高）、修正后的轨迹（按脚下地板的高度着色，净空不到 1.8 米的垫红色，脚下没有网格的画虚线）、每 20 米的米数、出生点和朝向、比例尺和指北针。米数和概要的行是同一批点，鼠标停在点上显示概要的那一行。按米数提议段，图也拿给用户看。轨迹脚下的地板取最高的一层，栏板、台面顶上的假地板在平面图上也会垫红，路线低不低以 `--route` 以后的红圈为准；
- 挑好段以后同样的参数加 `--route` 再跑一遍，图上多出各段生成的路线（拉直以后、写进清单的那些点）和路线上眼高低于 1.6 的点（红圈和清单里带眼高的点一一对应）：看段取得对不对、直线有没有切进墙；
- 平面图正北朝上，和 `/dev/nav-grid` 的平面图同一个方向；概要、图上提示里的"局部 (x, y)"和页面鼠标处的"局部 x, y"是同一个网格局部系，两边可以拿坐标对照；
- 提议之前先看出生点留下的是哪一片，`--plan` 的平面图看不出能不能走通：把打印的 `spawn` 先写进清单，在 `/dev/nav-grid` 构建，平面图只画出生点所在的那一片（图的范围就是这片的范围，鼠标处读得到区域）。墓室不在里面时换 `--spawn-at` 再看，把能进墓的出生点连同段一起交给用户定；段的起止也要在这一片里，否则小地图上那一段画在图外（龟山汉墓的两个甬道口在导航网格里断开，默认出生点只留下入口建筑）；
- 碰撞网格超过 200 万个三角形的（彭城广场 1565 万），出生点还决定读哪些网格：按包围盒离出生点由近到远读，下一个放不下就停，不跳过它去读后面更小的（`selectScanMeshes`），所以总数不超过 200 万、也可能明显少于 200 万（彭城广场的默认出生点只读 10 个网格、179 万个三角形）。彭城广场只读到全图约四分之一的范围、八分之一的三角形。这时多取几个 `--spawn-at` 的候选，在 `/dev/nav-grid` 逐个构建，比留下的面积和连着哪里，状态栏写着读了几个网格；
- 每个候选都切到"步行地图预览"看人落在哪：出生点那一格不在留下的区域里时，人落到附近区域里最近的地板，可能是头顶的另一层（彭城广场 `--spawn-at 640` 是夹层，地板约 -30.1 米，人落到上面约 5.7 米、局部 z 约 -24.4 的一块高起的表面，比广场主体高约 1.6 米）。读数的楼层名按出生点的地板定，出生点在地下一层时它叫 1F；
- 扫描开头常在原地绕一圈、站在网格边上，或者出生点所在的区域到不了墓室，出生点可以用 `--spawn-at` 往后挪；
- 输出的 `"spawn"`、`"routes"` 原样写进清单（数值不改；排版照清单里已有的：`spawn`、`placement` 写一行，路线对象展开写，`{`、`"id"`、`"name"`、`"path": [` 各占一行，路线的点一个一行，逗号后空一格），在 `/dev/nav-grid` 上叠在平面图上核对一遍。要先有 `spawn` 再构建：没有时导航网格留下的是全图最大的一片，可能是屋顶。设了 `YZT_3DT_PROXY` 时页面读的是服务器上的清单，工作区里改的看不到（[local-files.md](local-files.md)）。

`placement` 的口径：

- LCC2 的局部系是网格的东、北、上（Z 向上，米），原点放在 (`lng`, `lat`, `height`)；
- `height` 是椭球高，和其他模型的高度同一个口径；
- `heading` 是局部 x 轴从正东逆时针转的角度（度），包括子午线收敛角；中央经线以东是负的；
- 比例不存：3 度带内投影的比例误差每 100 米最多约 2.4 厘米。

**怎么得到**：用配准工具 `pnpm --filter yzt lcc2:register`（[commands.md](../commands.md)，ADR 0149 第 4 节），结果原样写进清单。模型只在服务器上时设 `YZT_3DT_PROXY`，工具从 `/3dt/` 读，只取索引、轨迹和碰撞网格，不下载泼溅数据。

- **水平和竖直的修正**：同一个包里的扫描轨迹（`info/poses.json`）按 `offset` 摆放是对的，工具拟合出泼溅和碰撞网格相对轨迹的平移。扫描仪拿在手里，竖直方向按"轨迹点离脚下的表面 1～1.5 米"定；
- **轨迹核对**：修正后取样的轨迹点里，离脚下的表面 1～1.5 米的至少要占 80%，不通过时命令以失败退出。不通过的要查明原因，用户同意后才作为例外写进清单，表里写明原因：把没过的点分成头顶 2 米内有顶（矮墓道里弯腰）、脚下 0.6 米内起伏超过 0.4 米（台阶、坡）、脚下没有网格，其余算找不到原因，再叠影像看位置（2026-11-11 的 `xz-tls2`、`xz-ddsh`、`xz-szs`）；
- **人工修正**（`--shift`、`--yaw`）：拟合不可信（轨迹和网格对不上）或者和影像比还要微调时才用，核对会算上它。给了 `--yaw` 时，拟合在转过 -yaw 的轨迹上求平移，再和偏航组成修正；
- **高程基准的差**（`--datum`）：两份数据都没有声明高程基准（backlog）。徐州的 LCC2 和倾斜摄影 `xz-gc` 用同一个口径：彭城广场的样例里，倾斜模型的地面比轨迹按 `offset` 的 z 定出的高 5.47 米（网格比 XZ 低 29.58 米，比自己的轨迹低 24.11 米），所以徐州的 LCC2 都写 `--datum 5.47`，和倾斜模型现在显示的高度对齐（ADR 0149 第 4 节）。这个参数必填、没有默认值：别的市没有量出差值时显式写 `--datum 0`，并在下表写明高度没有核对过。高程基准查清以后两者一起改。ADR 背景里的"约 4.8 米"是调查时 1 米方格的拟合，竖直方向那时定不到 1 米以内。

## 新增一个模型

已有的四种（`kind`）在下面写的形态以内，只改清单、不改代码：运行时代码里没有写死的模型 ID，也不要为一个模型加判断。超出的先停下和用户讨论。顺序是：先判断能不能接入，再按瓦片集或高斯泼溅的步骤做，最后过一遍检查清单。

### 先判断能不能不改代码接入

按要不要漫游、怎么漫游分开看。

- **只显示**：不写 `spawn`、`routes`。瓦片集的索引要过 `prepareTileset` 的整理（外部索引、目录外的引用、循环，ADR 0148，[map-core.md](../modules/map-core.md)"结构"）；泼溅要能配准（下面"泼溅"的第一条）。
- **只要路线**（写 `routes`，不写 `spawn`）：路线是脚下地板的经纬度和椭球高，播放不用导航网格，下面"要步行"的前提都不适用。
  - `oblique`、`white` 不建导航网格，没有小地图；`indoor` 在后台建一份只用来画小地图，建不出来只是没有小地图（`useSceneModels.ts` 的 `startRoute`）；
  - 视点（地板加眼高）到椭球高 0 米以下的模型要写 `underground: true`，漫游时抬高：MapLibre 的相机到不了 0 米以下；
  - 泼溅写了 `routes` 就必须写 `spawn`（schema 检查），按下面"泼溅"看。
- **要步行**（瓦片集）：必须写 `spawn`，而且只给 `indoor` 写。有 `spawn` 就能步行（`startWalk` 不看种类），给倾斜摄影、白膜写了会悄悄打开步行、下载整片叶节点，`catalog.test.ts` 有断言拦着。建导航网格（`buildNavigation`）的前提：
  - 根节点有 `transform`：缺了建导航网格时报错（`rootTransform`）；
  - 根节点的 `transform` 是刚体（只有旋转加平移，没有缩放），局部系 z 朝上。这两条代码不检查：`navigationFrame` 直接按刚体求逆，高度场把局部 z 当高度，不满足时不报错，楼层、出生点、平面图悄悄算错，要人工看索引；
  - 叶节点是 b3dm，里面的 glTF 没有 `extensionsRequired`：不是 b3dm、有 Draco、KTX2 这类压缩时建导航网格报错（`parseB3dmTriangles`）；
  - 头顶 20 米内有遮盖的地板才能站（`NAV_DEFAULTS.requireCover`）：露天的地面、屋顶不能走；
  - 全部叶节点都要下载（`navigationLeaves`），没有规模上限。苏州站是 23 个；
  - 真实数据只验证过地下的苏州站。地上、有顶的室内只用合成数据测过（`packages/map-three/src/roam.browser.test.ts`）：楼层名按 `frame.ground`（原点处椭球高 0 米）分地上地下，地面不在 0 米附近时会偏（徐州的地面约高 40 米，地下一层也会叫 1F）；`chooseSpawn` 里从画布中心、模型中心往下找的两条只找比 0 米低 2 米以上的地板，地上的模型只能靠清单的 `spawn`。
- **泼溅**（步行和路线）：
  - 配准工具要数据带扫描轨迹 `info/poses.json` 和索引 `root.meshFiles` 列的碰撞网格，`meshFiles` 是空的时 `lcc2:register` 直接报错；投影只认 CGCS2000 3 度带、不带带号的 EPSG:4534～4554；
  - 碰撞网格是二进制小端的 PLY，格式要求见 `packages/map-core/src/scene/nav/ply.ts`；
  - 模型整体要在椭球高 0 米以上：漫游泼溅只隔离、不抬高（`deriveSceneContent`）。没有检查，要人工判断：看 `placement.height` 加碰撞网格的最低处；
  - 碰撞网格超过 200 万个三角形（`SCAN_MAX_TRIANGLES`）时导航网格只读出生点附近，走到边上走不出去（[backlog](../backlog.md)"泼溅的漫游"），出生点决定能走哪一片（"出生点和路线"）。
- **要停下讨论的**：
  - 不是车站的室内瓦片集要漫游：界面一律叫"站内"（"站内空间""站内地图""正在进入站内…"，`catalog.ts` 的 `roamPlaceOf`、`STATION_PLACE`），要改代码；
  - 上面的前提有一条不满足，或者要按模型调导航参数（格子、身高、遮盖）；
  - 给倾斜摄影、白膜开步行；这四种以外的数据（点云、BIM 等）。

|---|---|---|---|---|---|---|---|---|---|---|

- "不接管"是不抬高、不隐藏二维图层和别的模型；相机和手势照样由漫游接管。抬高、隔离时画面怎样见 [map-three.md](../modules/map-three.md)"漫游"的"抬高"，头灯和太阳光见"光照"，裁掉见"高斯泼溅"的"和倾斜模型的重叠"；
- 两套导航参数的取值和原因、`chooseSpawn` 的先后、楼层名的规则见 [map-core.md](../modules/map-core.md)"导航网格""第一人称步行"；
- 种类在界面上的名称是 `catalog.ts` 的 `MODEL_KIND_LABELS`；目录里列不列泼溅看能力声明 `splats`（`useSceneModels`）。

### 瓦片集的步骤

"谁"一列：开发者是做接入的人或 AI；开发机是软件渲染时，画面和性能要在显卡机器上复查，由用户跑、把结果带回来。

| 步骤 | 命令或做法 | 产物 | 验收 | 谁 |
|---|---|---|---|---|
| 1 放数据 | 按"目录层级"放到 `local/3dt/<市>/3dtiles/<模型名>/`；只在服务器上的设 `YZT_3DT_PROXY`，同时设 `YZT_SITE` 选数据所在的服务器（只设代理时页面上是服务器部署的旧清单，看不到新加的模型，见上面"按站点发布"、[local-files.md](local-files.md)） | 模型目录 | 根 `tileset.json` 在，目录名等于清单的 `name` | 开发者；服务器上的目录由用户上传 |
| 2 写清单 | 加一项：`kind`、`cityCode`、`underground`、`tileset`（白膜写 `effects`），路径按段编码 | 清单的一项 | `pnpm --filter yzt test:unit src/features/scene-models` 通过（断言先按"检查清单"改） | 开发者 |
| 3 在页面上看 | `pnpm --filter yzt dev`，现状底图切到三维，从面板的"资源"里加入、定位 | 无 | 能加载，定位落在模型上，高度和底图对得上，11～17 级俯视和倾斜都没有空洞 | 开发者看对不对；观感由用户在显卡机器上看 |
| 4 屏幕误差 | 在 `tools/measure-3d/scenes.ts` 加场景，`pnpm --filter yzt measure:3d --only <场景>`（[commands.md](../commands.md)） | `local/measure-3d/<时间>/report.md` | 默认 8 下放得下、静止时不再加载和卸载；放不下的写 `maximumScreenSpaceError: 16` | 用户在显卡机器上跑；没跑之前记在 backlog |
| 5 取出生点和路线 | 没有工具，见表下 | 清单的 `spawn`、`routes` | 高度是椭球高；出生点 30 米内有能站的地板 | 位置和路线段由用户定，开发者取点 |
| 6 核对（只对 `indoor`） | 开发服务器的 `/dev/nav-grid`：选模型、构建，"平面图"里打开"预置路线"，再切到"步行地图预览" | 无 | 路线落在能站的区域里、不穿墙；高度写错层的一段在那一层上不画；预览里人落在出生点：读数的朝向等于清单的 `heading`，楼层是 `spawn` 那一层 | 开发者 |
| 7 走一遍 | 现状底图的"漫游" | 无 | 步行落在出生点、朝向对，路线不穿墙、不擦顶 | 开发者；显卡机器上由用户 |

只显示的模型做到第 4 步。倾斜摄影、白膜的路线不做第 6 步：在 `/dev/nav-grid` 上构建要下载全部叶节点，而且要求遮盖，露天的地方都站不住，路线不可能落在能站的区域里。它们的核对办法先和用户商量，或者只走第 7 步。

**出生点和路线现在没有取点工具**（[backlog](../backlog.md)"瓦片集的取点导出"）：

- 苏州站的路线来自 ADR 0083 时的离线规划：用旧项目的 `navGrid` 建导航网格、在上面寻路，脚本没有迁过来。"进站乘车"的前半段后来按 ADR 0103 在浏览器里用产品的 `NavGrid` 重新规划过。验收时 39 个点和站内地板最多差 1.08 厘米（[map-three.md](../modules/map-three.md)"测试"）；
- `/dev/nav-grid` 现在能给的是平面图、区域和鼠标处的经纬度、局部坐标。鼠标处显示的"地板"是导航网格局部系的 z，不是椭球高，不能直接抄进清单：要用这份导航网格的 `frame.toLngLat` 换，页面没有显示换出来的高度；
- 平面图上只画路线、不标出生点。"步行地图预览"按清单的 `spawn` 放人，规则和真实的步行一样，读数里有楼层、局部坐标、地板和朝向，可以粗核出生点的位置和朝向，也能用 W、A、S、D 试走。`spawn` 30 米内找不到能站的地板时它退到模型中心、不提示，这时读数的朝向（取整到度）不是清单的 `heading`，所以要对一下朝向和楼层；
- 所以新的瓦片集要漫游时，取点的办法先和用户商量，不要估一个高度写进去。

### 高斯泼溅的步骤

| 步骤 | 命令或做法 | 产物 | 验收 | 谁 |
|---|---|---|---|---|
| 1 确认数据 | 目录按"目录层级"：`.lcc2` 索引、`data/3dgs`、`data/mesh`、`info/poses.json`；只在服务器上的设 `YZT_3DT_PROXY`，工具只取索引、轨迹和碰撞网格；在页面上看时同时设 `YZT_SITE`（同瓦片集第 1 步） | 无 | 四样都在；缺轨迹或碰撞网格的配准不了，停下讨论 | 开发者；数据由用户上传 |
| 2 配准 | `pnpm --filter yzt lcc2:register "<市>/lcc2/<目录>/lcc2-sog-result/<索引>.lcc2" --datum <米>` | 打印的 `"placement"` | 轨迹核对 80% 以上（命令成功退出）。不通过的按上面"轨迹核对"查原因，用户同意后才作为例外 | 开发者跑；例外由用户同意 |
| 3 写清单 | 加一项：`kind: "splat"`、`lcc2`（按段编码）、`placement` 原样 | 清单的一项 | 同瓦片集第 2 步 | 开发者 |
| 4 和影像比 | 把轨迹、网格叠在影像上看水平位置；三维里俯视泼溅再比一遍 | "现有模型的说明"里的"影像"一句 | 入口、露天的部分和影像对得上（现有的差 1～4 米） | 开发者粗看；俯视泼溅在显卡机器上，记进 backlog |
| 5 取出生点和路线 | 同样的参数加 `--roam --plan lcc2-plan/<模型ID>.svg`，看平面图和概要挑段；先把 `spawn` 写进清单、在 `/dev/nav-grid` 看它留下的区域（做法同第 6 步），到不了墓室的换 `--spawn-at`；挑好后加 `--route`、`--spawn-at` 再跑一遍，在图上看生成的路线（上面"出生点和路线"） | 平面图 `local/lcc2-plan/<模型ID>.svg`；打印的 `"spawn"`、`"routes"`，原样写进清单 | 这次打印的 `placement` 和清单里的一致，不一致就停下问用户；出生点和路线段由用户定，交给用户时说明出生点留下的区域连不连着墓室；眼高低于 1.6 的点逐处记进说明表，写面板上"已走"的米数：按清单里这条路线的点累计三维长度（`RoutePath`，和 `catalog.test.ts` 的长度同一个口径），平面图红圈的提示里只有眼高 | 开发者提议，用户定 |
| 6 核对 | `/dev/nav-grid`：出生点所在的区域就是留下的那一片，路线叠在平面图上；再切到"步行地图预览" | 无 | 除了矮处、门口这类短段，路线在留下的区域里；预览里人落在出生点（读数的朝向等于清单的 `heading`），试走能进到里面。出生点所在的区域连不进墓室的、提示"只读了出生点附近"的，先告诉用户 | 开发者 |
| 7 显卡复查 | 进去走一遍每条路线 | 用户的结论，写进说明表 | 低视点的地方不别扭、不擦顶 | 用户；没看之前记在 backlog |

- `--datum` 必填：徐州写 5.47（上面"高程基准的差"）。别的市没有量出差值时写 `--datum 0`，并在说明表里写明高度没有核对过；
