# 三维模型清单（`apps/yzt/public/3dt/manifest.json`）

三维模型面板列出哪些模型、在哪个市、是什么、数据在哪（ADR 0081）。随产物发布到 `dist/3dt/manifest.json`，部署时可以直接替换（[overview.md](overview.md)"运行时文件"）。格式由 `features/scene-models/api.ts` 的 zod 校验，严格对象：多写、写错位置的字段都让整份清单不合法，面板显示加载失败。

模型数据不入库，也不进构建产物（ADR 0083、0141）：本机放在 `local/3dt/`，服务器上由 nginx 在 `/3dt/` 下提供或转发（[local-files.md](local-files.md)、[deployment.md](../deployment.md)）。

## 目录层级

用户 2026-11-11 定，取代 ADR 0149 第 3 节的"所有模型平铺在 `3dt/` 下"：

```
3dt/manifest.json                                 清单，随前端发布（deployment.md）
3dt/<市>/3dtiles/<模型名>/tileset.json            倾斜摄影、室内
3dt/<市>/3dtiles/<模型名>/<效果>/tileset.json     白膜，每种效果一套
3dt/<市>/lcc2/<目录>/lcc2-sog-result/<索引>.lcc2   高斯泼溅
                                     data/3dgs/*.sog
                                     data/mesh/*.ply、*.btree
                                     info/attrs.json、poses.json、media/
```

- `<市>` 是市名的拼音，小写：`suzhou`、`wuxi`、`xuzhou`；
- 3D Tiles 的目录名和清单里的 `name` 相同（2026-11-11 改成了中文名）；LCC2 保留数据方交付的目录名和里面的层级，目录名、索引的文件名都不一定是模型名（`城下城（测试）`、`20260922龟山汉墓.lcc2`）；
- 清单里写相对清单的路径，每一段按 URL 编码（`encodeURIComponent`），`catalog.test.ts` 按上面的规则检查入库的清单；
- 本机的 `local/3dt/` 和服务器上的层级相同。

## 共有的字段

| 字段 | 说明 |
|---|---|
| `id` | 模型 ID，整份清单不重复；也是三维内容里瓦片集（白膜是 `模型ID/效果ID`）、高斯泼溅的 ID |
| `name` | 面板上显示的名称 |
| `cityCode` | 市的区划代码，必须在区划目录里；市名取自目录 |
| `kind` | `oblique` 倾斜摄影、`white` 白膜、`indoor` 室内、`splat` 高斯泼溅 |
| `underground` | 地下的模型：漫游时抬高、用头灯（ADR 0097、0147 第 4 节）；对 `splat` 只影响漫游别的地下模型时它是否还显示 |

## 瓦片集模型（`oblique`、`white`、`indoor`）

| 字段 | 说明 |
|---|---|
| `tileset` | `oblique`、`indoor`：`tileset.json` 的地址，相对清单，按段编码（见"目录层级"） |
| `effects` | `white`：`[{ id, label, tileset }]`，第一种是默认效果 |
| `maximumScreenSpaceError` | 可选，屏幕误差上限（正数）；不写用默认值 8，只给放不下的模型写（[map-three.md](../modules/map-three.md)"渲染"的瓦片） |
| `spawn` | 可选，步行的出生点 `{ lng, lat, height, heading }`：脚下地板的椭球高，朝向是正北为 0、顺时针的度数 |
| `routes` | 可选，预置的漫游路线 `[{ id, name, path }]`，`path` 是脚下地板的 `[经度, 纬度, 椭球高]`，至少两个点；头顶低的地方可以多一个值，是视点在地板以上的米数（0～1.6，不写是 1.6，ADR 0156 第 3 节） |

## 高斯泼溅（`splat`，ADR 0149）

不写 `maximumScreenSpaceError`。可以写 `spawn`、`routes`（写法同瓦片集模型），由配准工具从扫描轨迹生成（ADR 0156 第 4 节，见下面"出生点和路线"）；写了 `routes` 就要写 `spawn`，否则整份清单不合法：路线漫游也建导航网格（小地图），只留出生点附近的区域，没有出生点时会留下全图最大的一片（可能是屋顶）。

| 字段 | 说明 |
|---|---|
| `lcc2` | `.lcc2` 索引的地址，相对清单；数据文件的路径由库按索引的地址解析。按段编码（见"目录层级"） |
| `placement` | 配准后的摆放 `{ lng, lat, height, heading }`，不用索引里的 `epsg`、`offset`（ADR 0149 第 4 节） |

**出生点和路线**（ADR 0156 第 4 节）：

- 用 `pnpm --filter yzt lcc2:register <索引> --datum 5.47 --roam`（[commands.md](../commands.md)），参数和配准时一样，出生点、路线就和 `placement` 在同一个修正下；
- 先看 `--roam` 打印的轨迹概要（每 20 米一行）和平面图，挑路线段：扫描会来回走、绕圈闭合，一整条太长（土山墓 1.1 公里），所以按段取，每段写成 `--route ID:名称:起-止`，段由开发者提议、用户定；
- 扫描开头常在原地绕一圈、站在网格边上，出生点可以用 `--spawn-at` 往后挪；
- 输出的 `"spawn"`、`"routes"` 原样写进清单，在 `/dev/nav-grid` 上叠在平面图上核对一遍。

`placement` 的口径：

- LCC2 的局部系是网格的东、北、上（Z 向上，米），原点放在 (`lng`, `lat`, `height`)；
- `height` 是椭球高，和其他模型的高度同一个口径；
- `heading` 是局部 x 轴从正东逆时针转的角度（度），包括子午线收敛角；中央经线以东是负的；
- 比例不存：3 度带内投影的比例误差每 100 米最多约 2.4 厘米。

**怎么得到**：用配准工具 `pnpm --filter yzt lcc2:register`（[commands.md](../commands.md)，ADR 0149 第 4 节），结果原样写进清单。模型只在服务器上时设 `YZT_3DT_PROXY`，工具从 `/3dt/` 读，只取索引、轨迹和碰撞网格，不下载泼溅数据。

- **水平和竖直的修正**：同一个包里的扫描轨迹（`info/poses.json`）按 `offset` 摆放是对的，工具拟合出泼溅和碰撞网格相对轨迹的平移。扫描仪拿在手里，竖直方向按"轨迹点离脚下的表面 1～1.5 米"定；
- **轨迹核对**：修正后取样的轨迹点里，离脚下的表面 1～1.5 米的至少要占 80%，不通过时命令以失败退出。不通过的要查明原因，用户同意后才作为例外写进清单，表里写明原因：把没过的点分成头顶 2 米内有顶（矮墓道里弯腰）、脚下 0.6 米内起伏超过 0.4 米（台阶、坡）、脚下没有网格，其余算找不到原因，再叠影像看位置（2026-11-11 的 `xz-tls2`、`xz-ddsh`、`xz-szs`）；
- **人工修正**（`--shift`、`--yaw`）：拟合不可信（轨迹和网格对不上）或者和影像比还要微调时才用，核对会算上它。给了 `--yaw` 时，拟合在转过 -yaw 的轨迹上求平移，再和偏航组成修正；
- **高程基准的差**（`--datum`）：两份数据都没有声明高程基准（backlog）。徐州的 LCC2 和倾斜摄影 `xz-gc` 用同一个口径：彭城广场的样例里，倾斜模型的地面比轨迹按 `offset` 的 z 定出的高 5.47 米（网格比 XZ 低 29.58 米，比自己的轨迹低 24.11 米），所以徐州的 LCC2 都写 `--datum 5.47`，和倾斜模型现在显示的高度对齐（ADR 0149 第 4 节）。高程基准查清以后两者一起改。ADR 背景里的"约 4.8 米"是调查时 1 米方格的拟合，竖直方向那时定不到 1 米以内。

## 修改时的检查清单

- `pnpm --filter yzt test:unit src/features/scene-models`：入库的清单要通过校验，测试里列着全部模型的 ID 和市，并按"目录层级"检查路径
- 新的模型：按"目录层级"放数据、写路径；新的市要在 `catalog.test.ts` 的 `CITY_DIRECTORIES` 里加上它的拼音
- 新的 LCC2 模型：`placement` 用配准工具的结果（轨迹核对要通过；不通过的查明原因、用户同意后作为例外），在上表里记下命令和核对的数字；再在三维里俯视，和影像比一遍
- 新加字段时同步改 `api.ts` 的 schema、`catalog.ts`，和这篇文档
