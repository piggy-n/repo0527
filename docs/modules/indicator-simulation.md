# 指标智能推演

纯前端的"城市国土空间监测指标 AI 模拟计算"：编排计算条件，看 AI 分步推演，可以人工干预，在地图和图表上看结果、对比版本。全部是确定性的模拟数据，不接后端。设计与取舍见 [ADR 0102](../adr/0102-indicator-simulation.md)。

- 页面：`apps/web/public/design.local/indicator-simulation/`；第一版留在同级的 `indicator-simulation-v1/` 作对照

## 推演模型

`features/indicator-simulation/model/`，都是纯函数，不依赖 Vue、地图引擎和时间；所有数字（叙述、地图、图表）都从这里来。

```
model/
├─ indicators.ts   推演支持的 22 项指标：目录里的名称与单位，加上模型（覆盖率的服务半径、设施类型）和简称；四类分组；演示目标值
├─ params.ts       推演条件与参数的类型、默认参数、取值范围、参数项的改动与说明
├─ districts.ts    区县：从区划目录和县界算面积（椭球面）、撒点中心、范围
├─ calculator.ts   人口、区县基准值、两类模型、多年度、缺失人口 → 区县、市、全省的结果
├─ analysis.ts     变化归因、敏感性、建议情景、分级断点、达标三态
├─ facilities.ts   设施点：数量与撒点（地图示意）
├─ cache.ts        按键缓存纯函数的结果
└─ test-atlas.ts   只供测试：经正式的边界加载器、用县界文件建全省 95 个区县
```

**数据从哪里来**：页面用 `shared/map/region` 的边界加载器取 95 个区县的县界，交给 `createDistrictAtlas`；`createCalculator(atlas)` 和 `createFacilityLayout(calculator)` 持有各自的缓存，同样的参数只算一次。市级基准值是 `shared/city-indicators` 的 `mockIndicatorValue`，与驾驶舱一致。

**两类模型**：

- 区县基准值：覆盖率在 logit 空间加区县差异（市辖区高一点）后整体平移，人均值按比例加差异后缩放；两者的人口加权均值都等于市的模拟值
- 覆盖率 = 1 − (1 − 基准)^((v ÷ 60)² × 口径系数 × (1 + 新增))；固定距离类（消防、派出所、火车站、长途站、医院）不随步行速度变化。口径系数：全部设施 1.18、规模以上 1、仅中大型 0.72
- 人均 = 基准 × 面积口径系数 × (1 + 新增) × 常住人口 ÷ 汇总用的人口。面积口径系数 1.07、1、0.86
- 汇总：区县 → 市 → 全省都按所选口径的人口加权；剔除的区县不参与

**人口**：13 市的常住人口和户籍/常住之比是演示量级；市的人口按年份小幅变化（2023 为锚点）；区县份额 = 面积^0.35 × 市辖区 2.2 倍 × 散列扰动，户籍口径城区少一点、郊县多一点。

**缺失人口**只出现在最新年度：按年份和范围固定选 2 个区县（优先不同的市）。插补 = 人口 × 1.008（一位小数）；剔除时不参与汇总；手动填写的人口直接用于汇总和人均值。

**分析**：

- 变化归因按 `PARAM_KEYS` 的先后把参数项一项一项从对比版本换成当前版本，每一步全省值的变化就是这一项的贡献，加起来等于总变化；别的指标改了目标值不算
- 敏感性：步行类覆盖率看步行速度（40～100，步长 5），其余看规划新增（0～50%，这项指标算进作用范围）
- 建议情景：在 0～50% 的新增里找最小的、能让全省达标或多约四分之一的市达标的比例，作用于同一种设施的已选指标（新增公园绿地同时影响覆盖率和人均值）；做不到时给出新增 50% 的"上限情景"，全部达标时没有建议
- 分级断点：所选年度在默认参数下的区县值取五档分位数，年度和版本之间颜色可比

**设施点**只用于地图示意：数量按覆盖率反推（覆盖率 = 1 − e^(−密度 × π r²)），没有覆盖率指标的设施按人口估算；每个区县最多 150 个现状点、80 个规划新增点；围绕撒点中心正态分布，落在区县外时重取。纳入口径按点的 rank 筛掉最小的 15% 或 45%。点不避开水体。

**实测**（2026-10-28，全省 13 市）：建 95 个区县约 50 ms；4 项指标 × 2 个年度一次计算约 10 ms；公园绿地 1.1 万个点约 40 ms。B-65 默认参数下全省 64.62%、5/13 市达标，建议新增 20% 后 70.35%、7 市，与确认的原型一致。

**取舍**：项目里没有装 `lodash-es`，缓存和参数比较各写了十几行（`cache.ts`、`params.ts` 的 `changedParams`），不为这一步新增依赖。

**测试**（6 个文件、37 项，node 环境）：指标清单与目标值、区县面积与中心、参数改动与说明、计算（市值等于驾驶舱的模拟值、缺失只在最新年度、剔除与手动填写、步行速度与口径、作用范围、户籍口径、确定性）、分析（归因加和、敏感性、建议的最小性与上限、断点）、设施（点都在区县内、同种设施共用、口径、规划新增）。逐个改坏 8 处（覆盖率不看步行速度、每个年度都有缺失、剔除不生效、别的指标的目标值也算、建议门槛变成 1 个市、口径不筛点、规划新增不看作用范围、作用范围按顺序比较），每处都有断言失败。

## 推演引擎

`features/indicator-simulation/engine/`，纯 TS，不依赖 Vue 和动画库（ADR 0102 第 5 条）。引擎只管"现在走到哪一步、在等什么、参数是什么、出了哪些版本"，按时钟推进；界面和动效（S6）订阅它的状态快照来演出，不反过来驱动它。

```
engine/
├─ steps.ts        9 个步骤的层、依赖、演示时长、确认点的位置；左侧列表的分组；参数项属于哪一步；downstream、restartStep
├─ clock.ts        Clock 接口（now、sleep），systemClock，PausableClock（可叠加的暂停）
├─ engine.ts       SimulationEngine：状态快照、确认点、人工干预、版本、暂停、停止、释放
└─ test-clock.ts   只供测试：手动推进的 ManualClock
```

**步骤**：条件解析 → 人口 / 设施 / 用地（并行）→ 数据核查 → 空间分析 → 指标计算 → 评价分级 → 结论生成。同一层并行，上一层全部完成才开始下一层。开始时先"规划步骤" 1.3 秒；时长沿用确认的原型，全程约 22 秒（不含等人确认）。

**状态**是不可变的快照（`engine.state`），每次变化整体替换、`revision` 加一，并发出 `change` 事件：

- 整体 `status`：idle、planning、running、checkpoint、done、failed；`paused` 与它互不影响
- 每一步 `status`：waiting（没开始）、running、checkpoint、done、reused（沿用上一轮）、stale（开始过、受干预影响待重算）；`human` 表示用过人工确认或干预的参数
- 进度不放进快照：`engine.progress(step)` 按时钟实时计算，等人确认、暂停时不走

**确认点**：

- 数据核查在 1.2 秒处停下，问最新年度缺失人口怎么处理（`checkpoint` 带缺失的区县和插补值）；所选范围没有缺失时不问
- 空间分析一开始确认参数；没有覆盖率类指标时不问
- 用 `resolveCheckpoint` 决定，或者用干预改这一步的参数；决定过的（`decided`）重算时不再问，没决定过的重算时还会问

**人工干预** `apply(next, { baseIndex? })` 的结果：

| 结果 | 条件 | 做法 |
|---|---|---|
| unchanged | 参数没变 | 什么也不做 |
| saved | 推演中，改动最靠前的步骤还没开始或待重算 | 只保存参数，执行到时生效 |
| resolved | 推演中，改动最靠前的步骤正停在确认点 | 作为这个确认点的决定，接着执行 |
| rerun | 其余情况，以及结果阶段 | 作废这一轮；这一步、它的下游和还没完成的步骤标为待更新（没开始的仍是等待），其余沿用；0.8 秒后从这一步重算 |

改动的参数项所属的步骤标为人工；属于确认点的，确认点算作已决定。结果阶段可以基于任一版调整（默认最新一版）：版本记相对**所基于版本**的改动（`changes`），从哪一步重算则和**上一轮实际用的参数**比，基于旧版本时可能比改动的项更靠前。

**版本**：每轮完成时追加一版（v1、v2…），带参数、计算结果（`calculator.compute`）、所基于的版本与参数、改动的参数项。重新开始时清空。

**时间**：引擎只通过 `Clock` 读时间和等待，内部包一层 `PausableClock`。`pause()` 返回解除函数，页面停用和打开人工干预各拿一个，全部解除才继续，调用方不用记"是不是我暂停的"。测试注入 `ManualClock`，`advance(ms)` 按到期先后逐个唤醒，每唤醒一个用 `setTimeout(0)` 让出事件循环，被唤醒的代码登记的新等待也在同一次推进里到期。

**取消**：开始、重算、停止都经 `@yzt/utils` 的 `LatestController` 作废上一轮；每次等待返回后再确认信号没有中止（到期和中止可能在同一轮里）。停在确认点时作废，确认点随之失效。计算出错时进入 failed 并记下错误，不留在"进行中"。

**取舍**：

- 暂停交给时钟，不做成 `status`：等人确认时也可能暂停，两者正交
- 引擎只依赖窄接口 `EngineCalculator`（缺失人口、插补、整体计算），测试可以替换其中一项
- 只发一个 `change` 事件，不发"步骤开始 / 结束"：动效按前后两份快照的差异演出，页面缓存恢复、减少动画时直接画终态，不会漏掉事件

**测试**（3 个文件、34 项，node 环境）：步骤表的层与依赖、分组、下游与重算起点；时钟的暂停顺延、叠加、重复解除、暂停中的零等待、中止；引擎的推进时间点、两个确认点、四种干预结果、结果阶段基于新旧版本、版本内容、暂停、停止、重新开始、释放、计算出错、快照不可变。逐个改坏 19 处（同层不并行、等确认时仍计时、确认后不算决定、干预不算决定、重算不复用、没完成的不重算、复用按所基于的版本判断、版本不记改动、待更新的不能保存、干预不作为确认、没有覆盖率也确认、停止 / 释放不作废、出错不进 failed、不显示待更新、暂停时 now 仍走、解除一处全部解除、解除函数重复生效、暂停中的零等待不等），每处都有断言失败。

## 条件编排

页面的第一阶段：左侧条件库，右侧"年份 → 监测范围 → 监测指标 → 计算参数 → AI 推演"五列编排图。组件样例 `/dev/indicator-simulation` 是真实页面，不登录就能看。

```
compose/
├─ composition.ts   编排的纯函数：条件的增删与排序、作用范围的整理、还缺什么、参数影响哪些指标、参数节点的取值
└─ board.ts         编排图的纯函数：节点标识、按节点位置连线、悬停时的关联与点亮
composables/
├─ useComposition.ts      编排的拥有者：点选、拖入（已有的返回 false）、移除、排序、换参数、清空
├─ useConditionDrag.ts    条件库到编排图的拖放通道：记下拖的是什么
└─ useSimulationModel.ts  下载县界、建区县和计算器；整个应用共用一份，失败可以重试
components/
├─ ComposeStage.tsx    分栏布局：条件库在侧栏（320，窄屏进抽屉），编排图在主区
├─ ConditionLibrary.tsx 年份、城市（全省复选框）、指标（四类分组、可搜索、可折叠）
├─ ComposeBoard.tsx    五列、连线、拖入、手柄排序、参数浮层、AI 推演入口
├─ ParamPopover.tsx    参数节点的编辑浮层：即时预估 + 编辑项，确定后交给拥有者
├─ ParamFields.tsx     参数的编辑项（人工干预会复用）
├─ ParamEstimate.tsx   最新年度全省值与达标的市，改前 → 改后
└─ StageStepper.tsx    阶段条
format.ts              指标值、变化量的格式（百分比一位小数，其余两位）
```

**排布**：五列是 CSS grid，列内是普通的纵向排列（竖直居中），节点高度由内容决定，监测范围的城市标签自然换行。连线不靠估算位置，而是量出各节点相对连线层的位置后由 `boardLinks` 算出：条件变化后的约 0.4 秒内每帧重量一次，连线跟着节点的出现、平移动画走；尺寸变化（字体加载、窗口缩放）由 ResizeObserver 触发。列宽按比例分，最窄到 1200 断点时取各列的最小宽度，主区刚好放下、不出横向滚动。

**交互**：

- 条件库的芯片可以点选切换，也可以拖到编排图：拖动时能放下的那一列高亮，已有的节点闪一下；只认从条件库开始的拖动，指标排序的拖动不当作放入
- 节点上的叉移除（年份的叉浮在右侧，不占年份的位置）；监测范围的每个城市标签单独移除
- 指标按手柄拖动排序（`useSortableList`），手柄也可以用上下方向键，移动后焦点回到手柄（浏览器实测：不回焦点时上移会丢到 body）
- 悬停（或键盘聚焦）参数时，高亮它影响的指标和连线：步行速度只关联步行类覆盖率，规划新增按作用范围；悬停指标时高亮上游的年份、范围和影响它的参数
- 点参数节点打开浮层：只编辑这一项，上方即时预估最新年度全省值与达标的市；确定后才交给拥有者，取消、点外面、Esc 丢弃草稿。规划新增的"作用于"用标签切换，规划新增大于 0 时编排图上画紫色虚线、指标节点标出"新增 n%"
- AI 推演节点：条件不全时写"还缺……"，齐全后光环转动、连线流动；区县数据没加载好时不能开始，失败时可以重试
- 节点出现时弹出、换位置时平移，移除的立刻消失；减少动画时都不动

**取舍**：

- 原型能把节点拖回条件库来移除，正式实现只用叉和再点一次：指标节点的拖动已经交给排序手柄（ADR 0054），同一个节点上两种拖动容易误操作
- 参数节点外面包一层 `span` 作为 Element 浮层的触发元素：Element 在触发元素重新渲染时会去掉它上面的 `aria-*`（实测），按钮自己的 `aria-haspopup`、`aria-expanded` 放在里层才能保留
- 开始推演在 S5 只提示"下一步接入"，S6 接上引擎和推演界面
- 新增令牌 `--color-ai-violet`、`-ai-cyan`、`-ai-glow`、`--color-scenario`、`-scenario-light`（[color-and-typography.md](../design/color-and-typography.md) 第 6.3 节）；连线、画布用已有令牌

**测试**（6 个文件、31 项）：编排的增删、排序、作用范围整理、参数与指标的关系、搜索；连线的条数与种类、缺位置时不连、情景线、悬停的关联与点亮；拥有者的拖入返回值与不替换状态；模型加载的失败、重试与作废；组件的点选与移除、拖入与闪烁、非条件库来源的拖动、手柄键盘排序、全省半选、开始的条件、参数浮层的打开、确定、作用范围标签、Esc。逐个改坏 16 处都有断言失败；移动后焦点回手柄在 jsdom 里测不出（jsdom 移动元素不丢焦点），在浏览器里删掉这一行确认会丢焦点。
