## 第一轮上传原型（2026-10-21，待用户确认）

设计理由：以现有文件列表为上下文，复用 FileCategoryTree、FileFilterBar、MxSplitLayout、MxPanel、MxSection 与 Element 组件。元数据和文件分区，整批共用元数据与进度，不引入逐文件独立上传任务。相较重写一份静态样式，这样能直接检查已验收组件的实际排版与键盘交互。

- 源码：`apps/web/src/pages/dev/file-management/`，开发路由 `/dev/file-management`；只在 `devRoutes` 注册，生产构建不包含原型
- 离线设计稿：当前 worktree 的 `apps/web/public/design.local/file-upload-preview.html`，直接在浏览器打开即可，字体和脚本已内嵌；该目录按规范不入库，不进入生产产物
- 本地生成与检查脚本：`apps/web/design.local/export-preview.mjs`、`verify-preview.mjs`；从 `apps/web` 运行 `node design.local/export-preview.mjs`、`node design.local/verify-preview.mjs`。这些临时脚本与截图同样不入库；持久的可维护来源是上述开发组件
- 原型只使用固定数据、真实 File 选择对象与模拟进度，不读取文件内容、不发上传/下载请求、不保存偏好。分类切换展示实际分类控件，但固定样例不按后台分类过滤；列表没有复制业务删除操作。下载、查看下一轮补充，不能将本轮当作完整文件管理验收

### 操作与状态

1. 点“上传文档”：默认当前叶子分类，可改选；年份默认今年、禁止未来年份；业务标签必填，备注可选。按用户确认不展示、不提交上传人，现有列表上传人列保留
2. 多选、拖入和逐项移除；未凭空增加文件类型、数量或大小上限；长名称完整换行
3. 点“开始上传”检查空文件和必填项。发送中锁定表单、选择和重复提交；总量未知时不显示假百分比；100% 后进入“文件已发送，正在处理”
4. 关闭按钮或 Esc 收起窗口，保留草稿或同一批次进度，点击页面入口恢复；点击遮罩不关闭。收起不代表撤销服务端写入；正式实现不得因组件卸载或路由离开自动取消写操作
5. 成功后演示列表更新，支持继续上传；失败保留选择与信息，提示先核对列表再重试，不自动重试
6. 页面顶部可切换列表正常/加载/失败/空状态，以及上传成功/失败/停在处理中/总量未知；“停在处理中”可收起窗口后点“模拟处理完成”继续

### 已完成的浏览器检查

先在本 worktree 的短时隔离服务查看 `/file-management`、`/dev/theme`、`/dev/map-ui`，再验证新增原型。尺寸覆盖 1600 × 900、1440 × 900、1200 × 800、1199 × 800、760 × 800、390 × 844、1440 × 600。检查了多选、拖入、移除、空校验、长名称、Esc 收起恢复、处理等待、成功刷新、失败保留与重试入口、总量未知、列表状态和离线 HTML 打开。

弹窗不越界，底部操作保持可见，窄屏/矮屏内容在弹窗内滚动；分类浮层限制在视口内并可横向滚动。复查时修复了原型表格在状态切换后丢失标签单元格的问题：列插槽与现有 FileTable 一样返回数组，不包额外 Fragment。原型未发业务请求。截图与尺寸数据在 `apps/web/design.local/evidence/`；已查看桌面、窄屏、矮屏、失败与离线截图，截图不替代交互设计稿。

已知基线问题：连续跨断点缩放时，Vite 记录 `ResizeObserver loop completed with undelivered notifications`，在未修改的真实文件列表页按相同尺寸序列也复现两次。布局随后稳定；本轮没有更改共享 QueryForm、主题或压制错误事件，后续由共享布局维护统一处理，不能声称控制台完全无提示。

验证还包括 6 项路由测试、类型检查、lint、内网构建与 4 项生产冒烟。公共层另有 119 项单元/回归测试、4 项原生浏览器测试及公网构建。开发页与离线设计稿没有进入生产产物。所有测试服务结束时自动关闭，用户原有服务保持运行。

## 后续接入顺序

1. 用户确认上传原型后，按真实返回结构接入 feature 的 API、mutation 和状态拥有者；先核对整批/部分成功语义，不用宽松 unknown 冒充契约
2. 上传是写操作，防重复且不自动重试；页面/会话变更后不更新旧界面，缓存失效限定发起会话。正式页面的路由离开、会话过期、卸载及晚到结果需补逻辑测试
