## 第一轮上传原型（2026-10-21，已按用户调整确认）

设计理由：以现有文件列表为上下文，复用 FileCategoryTree、FileFilterBar、MxSplitLayout、MxPanel、MxSection 与 Element 组件。元数据和文件分区，整批共用元数据与进度，不引入逐文件独立上传任务。相较重写一份静态样式，这样能直接检查已验收组件的实际排版与键盘交互。

- 源码：`apps/web/src/pages/dev/file-management/`，开发路由 `/dev/file-management`；只在 `devRoutes` 注册，生产构建不包含原型。确认后将弹窗与草稿规则迁到 feature 的 `FileUploadDialog`、`useFileUploadForm`，原型复用正式组件，仅模拟请求结果
- 离线设计稿：当前 worktree 的 `apps/web/public/design.local/file-upload-preview.html`，直接在浏览器打开即可，字体和脚本已内嵌；该目录按规范不入库，不进入生产产物

- 原型只使用固定数据、真实 File 选择对象与模拟进度，不读取文件内容、不发上传/下载请求、不保存偏好。分类切换展示实际分类控件，但固定样例不按后台分类过滤；列表没有复制业务删除操作。下载、查看下一轮补充，不能将本轮当作完整文件管理验收

### 操作与状态

1. 点“上传文档”：默认当前叶子分类，可改选；年份默认今年、禁止未来年份；业务标签必填，备注可选。按用户确认不展示、不提交上传人，现有列表上传人列保留
2. 多选、拖入和逐项移除；未凭空增加文件类型、数量或大小上限；长名称完整换行
3. 点“开始上传”检查空文件和必填项。发送中锁定表单、选择和重复提交；总量未知时不显示假百分比；100% 后进入“文件已发送，正在处理”
4. 用户调整：标题用 `MxTitle level="panel"` 显示蓝色竖条；关闭按钮、右上角 X 或 Esc 清空本次文件和填写，不展示保留草稿的提示。点击遮罩不关闭；已发送的批次用独立快照完成，再打开只查看进度，不能恢复已丢弃的草稿。关闭、组件卸载或路由离开不自动取消服务端写操作
5. 成功后演示列表更新，支持继续上传；失败时窗口仍打开则保留选择与信息，提示先核对列表再重试，不自动重试；关闭后不保留
6. 页面顶部可切换列表正常/加载/失败/空状态，以及上传成功/失败/停在处理中/总量未知；“停在处理中”可收起窗口后点“模拟处理完成”继续

## 正式上传（2026-10-21）

用户说明后端当前不可达，并明确同意暂按旧逻辑“仅判断 code”实现。`uploadFiles` 复用公共 HTTP 对信封的 `code === 200` 判断，主动丢弃未知 `data` 并返回 void；不统计成功文件数，不解释部分成功。这是临时业务决策，不是接口实测结论，也不改变资源管理的响应契约。

- `api.ts` 创建多文件 FormData，非空备注去掉首尾空白后发送；不传上传人、不另建客户端
- `useUploadFilesMutation` 显式关闭重试；发请求前检查发起会话，成功后只使同一有效会话的文件分页缓存失效，保留当前分类、筛选与页码。列表仍由已有查询控制
- `useFileUpload` 立即防重复；字节进度到 100% 仅进入等待处理，拿到成功响应后才成功。总量未知不显示百分比，加载反馈沿用 `useDelayedFlag`
- 关闭清草稿但不取消写操作；窗口关闭后同会话的完成/失败由入口提示。路由离开后请求继续，同会话缓存仍可失效，旧界面与提示不再更新；重新进入页面不恢复上一页面的任务视图，不实现跨页面任务队列
- 换会话、会话过期、组件卸载后忽略晚到的界面结果与进度；新会话不会被旧上传的成功结果刷新
- `FileUploadDialog` 传送到 body，避免嵌在查询表单内；X / Esc 在用户动作时清草稿，动画完成事件不承担清理

响应待核对项：后端恢复后检查整批或部分成功、成功/失败 data、服务端文件限制及权限。若能部分成功，再按真实契约增加反馈；当前不凭猜测删除失败项或自动重试。没有向真实后端提交测试文件。

本次新增 API、草稿/任务与正式组件测试，覆盖多文件字段、仅 code 的结果、无效/失败响应、防重复、失败保留、关闭清空、未知总量、100% 后等待、卸载、会话切换及同会话缓存失效。原生 multipart 文件名/字节的证据沿用公共基础浏览器测试；jsdom 的 File 与 Node 序列化不兼容，因此本轮单元测试检查交给公共 HTTP 的 FormData，不能把模拟 XHR 的文件名/内容当作浏览器证据。

验证结果：相关 17 个测试文件、150 项测试通过，类型检查、lint、公网构建通过；构建仍只有既存的 crypto 外置及大块提示。分别故意破坏“发送中关闭清文件”“旧会话不刷新缓存”“X 关闭清草稿”，三次均得到预期断言失败，随后恢复并重新通过。本轮未修改共享 HTTP、主题、依赖清单或锁文件。

本次浏览器在本 worktree 的限时 HTTP 服务复查标题、关闭按钮/X/Esc 清空、失败保留和重试入口；正式页面检查空列表、标签选择、关闭清空、空提交校验，尺寸为桌面 1440 × 900、窄屏 390 × 844、矮屏 1440 × 600，底栏可见、内容内部滚动。当前 Chrome 扩展未允许从磁盘选择文件，本轮未更改权限，也未完成正式页面从文件选择器到上传成功的完整浏览器验证；该连接由真实组件 + MSW 测试覆盖。正式后端仍不可达，待恢复后验收。

用户接受列表上方独立下载进度与统一预览弹窗，并允许按需引入 docx-preview。以下保留原型阶段的设计和验证记录，正式实现见下一节。

### 可操作入口与提案

- 离线设计稿：本 worktree 的 `apps/web/public/design.local/file-transfer-preview.html`，脚本、主题、字体内嵌，可直接用浏览器打开；仍由 `apps/web/design.local/export-preview.mjs` 从真实开发组件导出，设计稿和临时脚本不入库
- 列表的“下载”按文件防重复；不同文件各自显示接收进度、取消与重试。进度区位于筛选与表格之间，即使筛选隐藏了原行，任务仍可见；已结束项可清除。总量未知只显示已接收数量，完成文字明确是演示，不声称文件已保存到磁盘
- 顶部“演示选项”默认收起，可设置下载成功、失败、总量未知、持续接收；预览成功、读取失败一次、显示失败一次、持续加载。预览失败后的“重新加载”演示恢复成功，便于在同一弹窗内验收
- 预览范围仍是 DOCX、PDF、TXT、PNG/JPG/JPEG/GIF/WebP/BMP，固定列表提供 DOCX/PDF/PNG/TXT 样例，XLSX、ZIP 显示“仅下载”。没有开放 DOC、XLS、XLSX、PPT、PPTX、HTML 或 SVG 文件预览
- 容器提案：从旧项目的“DOCX 弹窗、其他支持格式另开标签页”调整为统一弹窗。理由是返回列表、加载失败与取消的交互一致；后续已获用户接受
- 弹窗复用 `MxTitle` 蓝色竖条，文件名完整换行；文档上下滚动、放大/缩小/适合宽度，TXT 自动换行。X、Esc、关闭按钮立即停止本次读取并清空预览，遮罩不关闭；从预览发起的下载独立继续，关闭后在列表查看
- 读取使用 `LatestController` 演示替换与关闭清理，下载按文件持有独立取消信号；不把这些开发演示模型作为 shared 通用框架。页面离开释放全部模拟计时器

内容限制：DOCX/PDF 的两页内容、图片示意图和 TXT 都是固定内容，不读取选择的文件、不解析真实文档、不取流、不保存文件。它们只验证入口、容器、状态和操作。PDF 正式实现拟使用浏览器内置阅读器，内部工具栏与缩放呈现随浏览器变化；当前排版示意不等于真实 PDF 或 DOCX 渲染验收。

### 原型阶段的依赖提案

DOCX 正式预览建议继续用旧项目的 `docx-preview`，打开 DOCX 时再动态加载。浏览器没有原生 DOCX 阅读能力；该库将 DOCX 转为 HTML，包含 JSZip 依赖，排版受 HTML 能力限制，不能承诺与 Word 完全一致，参考 [官方项目说明](https://github.com/VolodymyrBaydalka/docxjs)。用户确认后再核对并记录具体版本、许可与打包增量。

替代方案：后端转换 PDF，需要新增后端能力及转换服务；或只提供下载，会缺失旧项目已有的 DOCX 预览。因此本轮未选择替代或安装依赖。PDF、图片与 TXT 拟使用浏览器已有能力，不为它们增加 Office 全格式或 PDF 渲染库。

## 正式下载与预览（2026-10-21）

### 请求与状态归属

- `fetchFileContent` 复用 `shared/file-transfer.fetchFile`，准确传递 objectKey；列表名称作为后备文件名，白名单格式提供后备 MIME。缺失 objectKey 本地失败，不调用旧项目未使用的 `/file/preview`
- `useFileContentRequest` 在 queries.ts 内创建一次操作一个 key 的手动查询，合并调用方与 QueryClient 的取消信号；不重试，离线立即失败，结束后移除查询，避免长期缓存 Blob。请求前和每次异步返回后检查会话，结束会话仍可由全局 QueryClient 清理
- `useFileDownloads` 按文件 ID 防重复。不同文件各自接收、取消、重试；筛选和翻页不影响任务区。100% 后仍检查响应内容，成功才交给 `saveFile`，界面只写“已交给浏览器保存”；取消后的晚到结果不得保存，也不得移除新的重试任务
- `useFilePreview` 使用 LatestController 管理替换；关闭/X/Esc、换文件、卸载、会话变更会停止读取并清空内容。图片/PDF URL 在替换、关闭、显示失败时释放；取消不显示错误。预览中的下载是独立操作，关闭预览后仍在列表进度区继续
- 正式组件为 `FileDownloadPanel`、`FilePreviewDialog` 和 `DocxPreviewContent`。保留分类、筛选、分页、上传与删除；紧凑布局下操作列随表格横向滚动，避免三个固定按钮盖住文件名，桌面仍固定右侧

### 真实内容与依赖

精确安装 `docx-preview@0.4.1`，许可 Apache-2.0，间接包含 JSZip；依赖清单及锁文件由本文件管理分支维护。公共 HTTP、主题与资源管理代码未改。打开 DOCX 时才动态加载，公网构建的独立解析块为 171.37 kB（gzip 49.06 kB），不进入登录首屏的静态依赖。

DOCX 使用无脚本 iframe 隔离样式和文档资源，CSP 不允许外部图片或字体，嵌入资源转为 data URL；禁用 HTML 片段，文档链接仅显示文字。库解析过程无法中途停止，因此每轮在独立容器完成，再核对信号后提交；关闭后晚到解析不能覆盖后续内容。支持基本中文、表格、图片、显式分页与页眉页脚，字体、复杂布局和自动分页受 HTML 能力限制，不承诺 Word 等价。

PDF 使用浏览器自带阅读器，其内部工具栏和解码错误由浏览器呈现；外层 load 只能说明容器加载，不能证明每个 PDF 有效。图片用原生 img 并处理解码失败；TXT 作为纯文本显示，空文本有独立提示，不解释 HTML。白名单仍为 DOCX、PDF、TXT、PNG/JPG/JPEG/GIF/WebP/BMP，其他格式仅下载。
