# 布局（app/layout）

对应目录：`apps/web/src/app/layout/`
设计稿：2026-09-30 确认，沿用旧项目的顶部栏（`src/layout/components/TheHeader.vue`）

业务页面共用的布局：顶部栏（Logo 与系统名称、导航、消息、用户菜单）加内容区。登录页、404 不使用布局。

```
app/layout/
├─ AppLayout.tsx          顶部栏 + 内容区（RouterView）；内容区占满剩余高度，页面在其中滚动
├─ menus.ts               导航配置、按角色过滤、选中判断（纯函数）
├─ message-routes.ts      消息指向的页面（纯函数）
├─ _breakpoints.scss      顶部栏专用的两档断点（窄屏断点在 @yzt/ui）
├─ images/                顶部栏背景与 Logo（UI 提供的 2x webp）
└─ components/
   ├─ AppHeader.tsx       顶部栏
   ├─ HeaderNav.tsx       导航（按角色过滤、桌面导航）
   ├─ CompactNav.tsx      窄屏时的"菜单"下拉
   ├─ NavDropdown.tsx     下拉："查询统计"的两级下拉、"智能体"的一层下拉
   ├─ HeaderMessages.tsx  消息按钮与弹框（ADR 0093）
   └─ UserMenu.tsx        用户菜单与退出登录
```

## 导航配置

`menus.ts` 的 `navItems` 是一份有序清单，每项是三种之一，由 `kind` 区分：

- `link`：直接跳转，渲染为 `RouterLink`（`<a>`），可以在新标签页打开
- `dropdown`：展开两级面板，`groups` 是分组，每组是若干页面
- `menu`：展开一层面板，`links` 是页面，没有分组（页面少的"智能体"，ADR 0105）

```ts
{ kind: 'link', label: '文件管理', icon: FolderOpened, route: RouteName.fileManagement }
```

**权限不写在菜单里。** 导航项对应的页面允许哪些角色访问，由 `HeaderNav` 通过 `router.resolve({ name }).meta.roles` 读取路由表，再用 `canAccess` 过滤。页面权限只维护一份（路由 meta，见 [auth.md](auth.md)）。清单的顺序是两种角色合并后的顺序，按角色过滤后正好是旧项目各自的顺序：

| 角色 | 导航 |
|---|---|
| 管理员 | 资源管理、现状底图、查询统计、文件管理、系统管理、智能体 |
| 普通用户 | 现状底图、查询统计、数据下载、文件管理、智能体 |

"智能体"下是"AI对话"和"城市国土空间监测指标AI计算"（2026-10-28 由一级的"AI对话"改成；后者原名"指标智能推演"，2026-10-29 改名，ADR 0109）。下拉中没有权限的页面会被去掉，整组或整项都没有页面时一并去掉。

一个页面有几个路由时（如系统管理的资源审核、统计报表），导航项写 `alsoActiveOn` 列出其他路由，在这些路由上也显示为选中，宽屏导航和窄屏菜单都按 `isNavItemActive` 判断。

新增业务页时：先在路由表中加路由（需要限定角色就写 `meta.roles`），再在 `navItems` 中加导航项。`menus.test.ts` 会检查导航中的每个页面都在路由表中。

`icon` 是 `SvgIcon` 的图标名（`nav-*`，UI 提供，见下文"素材"），写错名字时类型检查会报错。

## 选中状态

`isNavItemActive(item, route.name)`：链接项在对应页面时选中；下拉项在它的任一页面时选中。选中样式是左右渐隐的白色高亮条，沿用旧项目。

下拉（`NavDropdown`）用 `ElPopover`，点击展开，跳转后自动关闭（监听 `route.name`）：

- 两级下拉：左列是分组，悬停或聚焦分组时右列显示该组的页面；打开时默认显示当前页面所在的分组
- 一层下拉：只有一列页面，当前页面高亮

## 用户菜单

显示名（真实姓名，没有时用登录名，过长时省略）、下拉菜单中的"登录名 · 角色"和"退出登录"。按钮没有悬停效果（2026-09-30 确认），键盘聚焦时的轮廓线保留。修改密码、修改头像在迁移对应功能时再加（2026-09-30 确认）；消息按钮放在用户菜单左边（见下文"消息按钮"）。

退出登录：`ElMessageBox.confirm('确定要退出登录吗？')` → `session.clear()` → `router.replace` 到登录页 → 提示"已退出登录"。取消时什么也不做。用 `replace`，退出后按后退键不会回到业务页（回去也会被路由守卫拦下）。

## 消息按钮（ADR 0093）

`HeaderMessages` 放在用户菜单左边，和它间隔 8。消息的数据、筛选、已读和弹框里的内容在 `features/message-center`（见 [system-management.md](system-management.md) 的"消息"），这里只装配：

- **按钮**：32 的圆，平时和头像一样是 `--color-inverse-active` 底，悬停、打开时 `--color-inverse-strong` 底；`header-bell` 图标 22，角标用小号变体 `badge-mini`（16 高、10 号字）（2026-10-28 用户要求加大图标、缩小角标、未选中时也有底色，ADR 0102）。`ElBadge` 显示未读数（超过 99 是 99+，0 时不显示），按钮的名称是"消息，N 条未读"。角标的中心压在铃铛图标的右上角：Element 默认把角标整个放在锚点右边，"99+" 宽 34px，会盖住右边的用户名；代价是"99+" 时铃铛被盖住大半（2026-10-28 验收通过）
- **弹框**：`ElPopover`，`role="dialog"`（Element 据此给按钮加上 `aria-haspopup`、`aria-expanded`、`aria-controls`），点击触发、`bottom-end`。打开时（`before-enter`）现量顶栏和按钮的下沿，顶边离顶栏下沿 8；宽 `min(400px, 100vw - 32px)`，最高 `min(640px, 视口高 - 顶栏下沿 - 24px)`，用 CSS 变量 `--message-panel-max-height` 交给面板；窄屏时 Popper 的 `preventOverflow` 让左右至少离窗口 16。`AppHeader` 把自己的元素传给它作为 `header`
- **开关**：`ElPopover` 的 `visible` 不能受控（不把 `update:visible` 传给内部的 tooltip），关闭用它暴露的 `hide()`，开关状态跟着 `before-enter`、`before-leave` 记下；这个状态也是 `useMessageCenter` 的参数，打开时才取全部消息。点击触发的弹框不响应 Esc，自己监听，关闭后焦点回到按钮
- **跳转**：`message-routes.ts` 的 `messageLocation` 把目标换成路由（申请是系统管理的 `?apply=`，报表是统计报表栏目）；能不能去由路由的 `meta.roles` 决定，和顶部导航一致，去不了时按钮禁用、写"数据下载页面迁移后可用"。点业务按钮先 `hide()`，再用 `navigate` 跳转
- **轮询**：未读数的查询在按钮挂载时开始（进入应用时取一次），之后由 Vue Query 在标签页可见时每 60 秒刷新；退出登录、会话过期时布局卸载、查询缓存清空

## 宽度适配

顶部栏的内容在 1920 宽时放得下，窄屏会放不下：Logo 在 75px 高度下 320px 宽，系统名称 28px 约 309px，管理员的导航约 810px，消息按钮和用户菜单约 168px。按宽度逐级收缩：

| 视口宽度 | 顶部栏 | 实测需要的宽度（管理员） |
|---|---|---|
| ≥ 1680 | 完整，导航项内边距 17 | 1678px |
| 1440～1679 | 导航去掉图标、内边距收窄到 11 | 1438px |
| 1200～1439 | 再隐藏系统名称，只保留 Logo | 1113px |
| < 1200 | 导航收进"☰ 菜单"下拉（结构见下文） | — |

- 1680、1440 两档只和顶部栏的内容有关，在 `_breakpoints.scss`，由 `HeaderNav` 和 `AppHeader` 的样式共用
- 1200 是全应用共用的窄屏断点，分栏布局的侧栏也在这里收进抽屉，定义在 `@yzt/ui`，样式中用 `@use 'ui'` 引用（见 [ui.md](ui.md)）
- 媒体查询用区间写法 `(width < 1680px)`，原因见 [ui.md](ui.md) 的"窄屏断点"
- 更窄（设计范围以外）时，Logo 区域允许收缩并裁掉右侧，保证菜单和用户区可见。窄屏时导航区是 `flex: 1 0 auto`：只写 `flex: 1` 时基准是 0，375 宽时"菜单"溢出到 Logo 上、白字落在 Logo 的白底上看不见（5D.8 验收时发现，换 Logo 素材以后才出现）
- 断点最初按旧 Logo（344px 宽）量出，换成 UI 的新素材后重新测量，三档仍然成立，断点不变；以后更换 Logo、增减导航项或顶栏右侧的按钮时要重新测量
- 加消息按钮（2026-10-28）：按钮 32、和用户菜单间隔 8，多出 40px，管理员在中间一档要 1450px，1440 宽时导航比留给它的位置宽 10px，向两边溢出、贴住系统名称。中间一档的导航内边距从 14 改成 12（6 项省 24px），断点不变；另一个办法是把隐藏系统名称的断点提高到 1460，但 1440 宽的屏幕就看不到系统名称了
- "AI对话"改成带下拉箭头的"智能体"（2026-10-28，ADR 0105）：多出约 10px，管理员在 1680、1440 宽时导航向两边各溢出 5px。两档的导航项内边距各收 1px（18 → 17、12 → 11，6 项省 12px），断点不变；两档都只剩约 2px 的余量，以后再增减导航项要先重新测量
- 实测的用户名是"管理员"（3 个字）。用户名最宽 100px，比实测多出最多 52px，名字很长时中间一档仍可能放不下，导航向两边溢出，不会出现横向滚动

已验证（2026-10-28，加消息按钮后重新测量）：用临时的浏览器测试挂载真实的 `AppHeader`、全局样式和普惠体字体（字体放在不入库的 `public/fonts/`），1920、1680、1679、1440、1439、1366、1280、1200、1199、1024、375 宽度下，管理员与普通用户的顶部栏都按上表切换，Logo 区域只在 375 宽时被裁（设计范围以外，和以前一样），用户区都在屏幕内，都没有横向滚动。普通用户三档分别要 1515、1315、990px。

再次验证（2026-10-28，"智能体"下拉之后）：同样用临时的浏览器测试挂载真实的 `AppHeader`，1920、1680、1679、1440、1439、1366、1280、1200、1199 宽度下，管理员和普通用户的导航都不压住系统名称和用户区，没有横向滚动；普通用户三档分别要 1545、1345、1020px（含消息按钮和用户菜单）。

### 窄屏菜单

`CompactNav` 把全部页面放进一个下拉菜单：

```
[图标] 资源管理
[图标] 现状底图
────────────
[图标] 查询统计          标题，不可点击
       数据查询          分组名，灰色小字
       国土变更调查      子页面，缩进到与一级项文字对齐，不带图标
       ……
────────────
[图标] 文件管理
……
```

- 一级项带导航图标（16px，颜色跟随文字，悬停和当前页时为主色）
- 下拉项（"查询统计""智能体"）自成一块，前后加分隔线；排在第一项或最后一项时外侧不加
- 一层下拉（"智能体"）没有分组名，标题下直接是缩进的页面
- 最初只用一行灰色的"查询统计 / 数据查询"表示分组，子页面和后面的一级项看起来连在一起，容易把"文件管理"等误认为子菜单（2026-09-30 反馈后改成现在的结构）

## 内容区背景

`AppLayout` 的内容区是从顶部栏延续下来的浅蓝渐变：`linear-gradient(180deg, var(--color-bg-page-top) 0%, var(--color-bg-page) 25%)`，在内容区高度的 25% 处过渡到页面底色。

设计稿给的是 `#aacefd → #f6fafd`。换算成 HSL 比较：

| 颜色 | 色相 |
|---|---|
| 设计稿起始色 `#aacefd` | 214° |
| 顶部栏背景（平均） | 212° |
| 主题色系（primary、primary-border、primary-bg、bg-page） | 220～227° |

起始色取自顶部栏的蓝色，不属于主题色系。试过把色相调到 225°（`#aabffd`），放在顶部栏下面对比，泛紫，和顶部栏之间能看出色相跳变；原色衔接自然，主按钮、选中项放在上面也不冲突。所以起始色保留原稿，作为令牌 `--color-bg-page-top`；结束色换成 `--color-bg-page`（与 `#f6fafd` 肉眼几乎无差别），渐变之后与其他页面的底色一致。

## 颜色

顶部栏是深色背景，使用 2026-09-30 补充的令牌：`--color-text-inverse`（白色文字）、`--color-inverse-hover`（悬停）、`--color-inverse-active`（选中高亮）。"查询统计"和用户名旁边的下拉箭头是 UI 提供的渐变三角（`nav-arrow-color`，16×10，保留原色）。下拉面板和菜单是白底，悬停和当前项用 `--color-primary-bg` 底色加 `--color-primary` 文字。

## 页面缓存（ADR 0063）

`AppLayout` 的 `RouterView` 里常驻一个 `KeepAlive`：路由 meta 写了 `keepAlive: true` 的页面放进去，切到别的页面时缓存，回来时是同一个实例；其余页面照常渲染在它外面，每次重新创建。

- 现在只有现状底图缓存：回到地图约 10 ms 画面就稳定，相机、勾选、点选结果、测量、打开的面板、区划选择都保留；重建要约 550 ms，这些状态也都丢了（5E.4 实测）
- 不另设缓存的上限：`KeepAlive` 里只会出现标了 `keepAlive` 的页面。按组件类型缓存，两个标了 `keepAlive` 的路由不能共用同一个页面组件
- 布局卸载时缓存跟着清空：登录页、404 不在布局里，退出、会话过期、别的标签页退出都会回到登录页，缓存的页面随之卸载；之后再登录（包括换了用户）是新的页面
- 缓存的页面里，停用期间要结束的临时交互用 `shared/composables` 的 `usePageActive`，量尺寸用 `useShownElementSize`（见 [composables.md](composables.md)）；地图怎样暂停见 [map-vue.md](map-vue.md) 的 `MapCanvas`
- 开发时：改了被缓存页面用到的文件，热更新会在缓存的页面上报 Vue 的 `emitsOptions` 之类的错误（KeepAlive 和热更新的已知问题），刷新页面即可；生产构建没有这个问题（5E.5 在干净的会话里来回切换两次，没有错误）
- 三维（3D.5b，2026-10-27 真实页面验证）：第一次切到三维、Cesium 还在加载时切走，回来以后三维照常显示；钻地中切走，回来相机、钻地条和地表不透明度不变；路线漫游播放中切走，停用期间不前进，回来接着走；步行中切走，回来还在步行、朝向不变，在别的页面上按 W、空格、Esc 都不作用到地图；完整地图开着切走，别的页面上看不见，回来还开着，Esc 只关地图；进站飞行中切走，回来照样进到站内；步行中退出登录，三维视图和步行的监听都释放，再登录是全新的地图。地图上的浮层（操作条、小地图、完整地图、钻地条）都在页面里，停用时随页面一起离开文档，不会留在别的页面上
- 测试：`AppLayout.test.tsx` 检查缓存的页面切走再回来是同一个实例、其他页面重新创建、离开布局后缓存清空；`routes.test.ts` 列出缓存的页面；`CurrentMapPage.test.tsx` 检查停用期间按空格、Esc 不作用到漫游
