# 布局（app/layout）

对应目录：`apps/web/src/app/layout/`
设计稿：2026-09-30 确认，沿用旧项目的顶部栏（`src/layout/components/TheHeader.vue`）

业务页面共用的布局：顶部栏（Logo 与系统名称、导航、用户菜单）加内容区。登录页、404 不使用布局。

```
app/layout/
├─ AppLayout.tsx          顶部栏 + 内容区（RouterView）；内容区占满剩余高度，页面在其中滚动
├─ menus.ts               导航配置、按角色过滤、选中判断（纯函数）
├─ _breakpoints.scss      宽度适配的断点
├─ images/                顶部栏背景与 Logo（UI 提供的 2x webp）
└─ components/
   ├─ AppHeader.tsx       顶部栏
   ├─ HeaderNav.tsx       导航（按角色过滤、桌面导航）
   ├─ CompactNav.tsx      窄屏时的"菜单"下拉
   ├─ NavDropdown.tsx     "查询统计"的两级下拉
   └─ UserMenu.tsx        用户菜单与退出登录
```

## 导航配置

`menus.ts` 的 `navItems` 是一份有序清单，每项是两种之一，由 `kind` 区分：

- `link`：直接跳转，渲染为 `RouterLink`（`<a>`），可以在新标签页打开
- `dropdown`：展开两级面板，`groups` 是分组，每组是若干页面

```ts
{ kind: 'link', label: '文件管理', icon: FolderOpened, route: RouteName.fileManagement }
```

**权限不写在菜单里。** 导航项对应的页面允许哪些角色访问，由 `HeaderNav` 通过 `router.resolve({ name }).meta.roles` 读取路由表，再用 `canAccess` 过滤。页面权限只维护一份（路由 meta，见 [auth.md](auth.md)）。清单的顺序是两种角色合并后的顺序，按角色过滤后正好是旧项目各自的顺序：

| 角色 | 导航 |
|---|---|
| 管理员 | 资源管理、现状底图、查询统计、文件管理、系统管理、AI对话 |
| 普通用户 | 现状底图、查询统计、数据下载、文件管理、AI对话 |

下拉面板中没有权限的页面会被去掉，整组或整项都没有页面时一并去掉。

新增业务页时：先在路由表中加路由（需要限定角色就写 `meta.roles`），再在 `navItems` 中加导航项。`menus.test.ts` 会检查导航中的每个页面都在路由表中。

`icon` 是 `SvgIcon` 的图标名（`nav-*`，UI 提供，见下文"素材"），写错名字时类型检查会报错。

## 选中状态

`isNavItemActive(item, route.name)`：链接项在对应页面时选中；下拉项在它的任一页面时选中。选中样式是左右渐隐的白色高亮条，沿用旧项目。

两级下拉（`NavDropdown`）用 `ElPopover`，点击展开：

- 左列是分组，悬停或聚焦分组时右列显示该组的页面
- 打开时默认显示当前页面所在的分组
- 跳转后自动关闭（监听 `route.name`）

## 用户菜单

显示名（真实姓名，没有时用登录名，过长时省略）、下拉菜单中的"登录名 · 角色"和"退出登录"。按钮没有悬停效果（2026-09-30 确认），键盘聚焦时的轮廓线保留。修改密码、修改头像、消息铃铛在迁移对应功能时再加（2026-09-30 确认）。

退出登录：`ElMessageBox.confirm('确定要退出登录吗？')` → `session.clear()` → `router.replace` 到登录页 → 提示"已退出登录"。取消时什么也不做。用 `replace`，退出后按后退键不会回到业务页（回去也会被路由守卫拦下）。

## 宽度适配

顶部栏的内容在 1920 宽时放得下，窄屏会放不下：Logo 在 75px 高度下 320px 宽，系统名称 28px 约 309px，管理员的导航约 810px。按宽度逐级收缩：

| 视口宽度 | 顶部栏 | 实测需要的宽度（管理员） |
|---|---|---|
| ≥ 1680 | 完整 | 1626px |
| 1440～1679 | 导航去掉图标、内边距收窄 | 约 1410px |
| 1200～1439 | 再隐藏系统名称，只保留 Logo | 约 1084px |
| < 1200 | 导航收进"☰ 菜单"下拉（结构见下文） | — |

- 断点在 `_breakpoints.scss`，由 `HeaderNav` 和 `AppHeader` 的样式共用
- 更窄（设计范围以外）时，Logo 区域允许收缩并裁掉右侧，保证菜单和用户区可见
- 断点最初按旧 Logo（344px 宽）量出，换成 UI 的新素材后重新测量，三档仍然成立，断点不变；以后更换 Logo 或增减导航项时要重新测量

已验证：1920、1680、1679、1440、1439、1366、1280、1200、1199、1024、375 宽度下，管理员与普通用户的顶部栏都按上表切换，用户区都在屏幕内，都没有横向滚动。

### 窄屏菜单

`CompactNav` 把全部页面放进一个下拉菜单：

```
[图标] 资源管理
[图标] 现状底图
────────────
[图标] 查询统计          标题，不可点击
       数据查询          分组名，灰色小字
       国土变更调查      子页面，缩进到与一级项文字对齐，不带图标
       ……
────────────
[图标] 文件管理
……
```

- 一级项带导航图标（16px，颜色跟随文字，悬停和当前页时为主色）
- 下拉项（"查询统计"）自成一块，前后加分隔线；排在第一项或最后一项时外侧不加
- 最初只用一行灰色的"查询统计 / 数据查询"表示分组，子页面和后面的一级项看起来连在一起，容易把"文件管理"等误认为子菜单（2026-09-30 反馈后改成现在的结构）

## 内容区背景

`AppLayout` 的内容区是从顶部栏延续下来的浅蓝渐变：`linear-gradient(180deg, var(--color-bg-page-top) 0%, var(--color-bg-page) 25%)`，在内容区高度的 25% 处过渡到页面底色。

设计稿给的是 `#aacefd → #f6fafd`。换算成 HSL 比较：

| 颜色 | 色相 |
|---|---|
| 设计稿起始色 `#aacefd` | 214° |
| 顶部栏背景（平均） | 212° |
| 主题色系（primary、primary-border、primary-bg、bg-page） | 220～227° |

起始色取自顶部栏的蓝色，不属于主题色系。试过把色相调到 225°（`#aabffd`），放在顶部栏下面对比，泛紫，和顶部栏之间能看出色相跳变；原色衔接自然，主按钮、选中项放在上面也不冲突。所以起始色保留原稿，作为令牌 `--color-bg-page-top`；结束色换成 `--color-bg-page`（与 `#f6fafd` 肉眼几乎无差别），渐变之后与其他页面的底色一致。

## 颜色

顶部栏是深色背景，使用 2026-09-30 补充的令牌：`--color-text-inverse`（白色文字）、`--color-inverse-hover`（悬停）、`--color-inverse-active`（选中高亮）。"查询统计"和用户名旁边的下拉箭头是 UI 提供的渐变三角（`nav-arrow-color`，16×10，保留原色）。下拉面板和菜单是白底，悬停和当前项用 `--color-primary-bg` 底色加 `--color-primary` 文字。

## 素材

UI 在 2026-09-30 提供（此前用旧项目的 PNG 转 webp 占位）：

| 素材 | 位置 | 说明 |
|---|---|---|
| 背景 | `images/header-background.webp` | 3840×192（2x），28 KB |
| Logo | `images/header-logo.webp` | 810×190（2x，带透明），14 KB；显示为 320×75 |
| 导航图标 | `src/assets/icons/nav-*.svg` | 20×20，由 `@yzt/icons` 规范化为单色（跟随文字颜色） |
| 下拉箭头 | `src/assets/icons/nav-arrow-color.svg` | 16×10，带渐变，文件名以 `-color` 结尾，保留原色 |

两个图标做了手工处理（在 UI 原稿上修改后交给图标工具规范化）：

- **文件管理（`nav-files`）**：原稿中间的横条单独着色为 `#7E9EFA`。按单色处理时它会变成与文件夹相同的颜色而看不见，所以改为文件夹主体上的镂空（在主体路径中加上横条的子路径，`fill-rule="evenodd"`），透出头部背景，效果与原稿一致
- **资源管理（`nav-resource`）**：内容的外框中心在 (9.02, 9.94)，比其他图标偏左约 1 个单位；`viewBox` 从 `0 0 20 20` 改为 `-0.98 -0.06 20 20`，使内容居中。其他图标的中心都在 (10, 10) 附近（AI对话偏 0.24，可以忽略）

测量内容外框用浏览器的 `getBBox()`，方法见 [icons.md](icons.md) 的"常见问题"。

## 测试

- `menus.test.ts`：两种角色的导航与旧项目一致（用真实路由表的 `meta.roles`）；导航中的页面都在路由表中；空分组、空下拉项被去掉；选中判断
- `HeaderNav.test.tsx`：两种角色渲染出的导航与当前页的选中状态；链接渲染为 `<a href>`
- `UserMenu.test.tsx`：显示名与角色；确认退出后清空会话、回到登录页并提示；取消时保持登录
- `CompactNav.test.tsx`：窄屏菜单的结构（一级项图标、分隔线、分组名、缩进、当前页）；下拉项在首尾时外侧不加分隔线。逐个改坏 4 处（去掉前分隔线、总是加后分隔线、一级项不带图标、子页面不缩进），每处都有用例失败

已验证：逐个改坏 6 处（链接项不按角色过滤、保留空分组、下拉项从不选中、退出不清会话、取消也退出、导航不过滤），每处都有用例失败。浏览器中实测：两级下拉切换分组、点击后跳转并关闭、下拉项显示为选中；退出时取消保持登录、确认后回到登录页并提示；窄屏菜单列出当前角色的页面并标出当前页。
