# AI 对话与系统管理迁移

2026-10-23 开始。分支 `codex/migrate-ai-system-management`，新项目起点 `5b4feaf`；使用当前 checkout，不修改其他迁移 worktree。旧项目 `master-demo` 基线 `6b4799b922efb2ed276cc28122fbe78527234b75`，只参考实际在用的入口，不处理旧仓库未提交修改。

## 范围与实施顺序

| 步骤 | 内容 | 当前状态 |
|---|---|---|
| 1 | 核对旧入口、接口、依赖，提供真实组件交互预览 | 系统管理已确认；AI 按用户最新要求改回旧版布局并适配项目规范 |
| 2 | 系统管理：管理员资源审核、申请详情、统计报表、下载 | 前端已按旧调用接入；真实记录、审核写入与下载待联调 |
| 3 | AI：鉴权、历史会话、流式回答、停止、失败状态 | 用户确认鉴权接口暂未提供，本轮仅完成交互预览，真实接入待后续契约明确 |
| 4 | AI：地图结果、表格、图表、导出及地图操作 | 未接入业务 |
| 5 | 边界测试、浏览器复测、构建与验收 | 系统管理本轮前端验证完成；真实后端与 AI 业务仍待后续验收 |

两模块在同一分支分别组织功能目录，避免互相导入。系统管理不依赖 AI，可先接入；路由与公共样式集中调整，避免两套实现。

2026-10-23 用户先确认 AI 凭据接口暂未提供，本轮只做交互预览；随后确认两份预览布局。系统管理已独立进入业务接入。接口只读核对未取得真实记录后，用户进一步确认：“暂时没有，按旧调用契约实现，记录待联调”。

AI 鉴权待办：取得访问凭据的接口、请求与响应结构，以及凭据有效期、刷新和退出时的处理约定。契约明确后再核对真实响应、补充测试并接入会话与流式回答，不使用旧前端共享账号密码，也不假定主系统 token 可直接用于 AI 服务。

本轮不扩展用户侧资源申请、修改密码、头像、用户角色 CRUD、消息中心或现状底图 Cesium。前两项不是删除旧功能，而是按最新请求保留在后续迁移计划。

## 旧实现核对与重写边界

系统管理实际只有资源审核与统计报表，和用户侧资源申请共用旧 `ApplicationListSection.vue`。迁移后保持列表、条件、分页、申请详情、审核与下载；准备状态仍需按真实接口区分等待、处理中、完成、超时、失败。原型的“尚未完成”只用于确认布局，不替代正式状态模型。

已核对调用：`POST /api/apply/list`、`GET /api/apply/{id}`、`POST /api/apply/status/{id}`（status、reason 参数）、`POST /statistics/page`；申请下载为 `POST /api/apply/download/{id}`，报表为 `GET /statistics/download?id=…`。真实响应的确认程度见下文；详情失败展示失败及重试，不沿用旧版静默退回列表行数据的逻辑。

AI 旧页面包括推荐问题、会话列表与删除、流式回答与工具步骤、地图 / 表格 / 图表 / Excel 结果。流使用 `/api/chat/stream`，另有 `/api/chat` 同步入口及 `/api/sessions` 会话接口。旧前端独立登录 AI 服务的共享凭据不迁移；需要主系统会话与 AI 访问凭据的正式契约，不能猜测主系统 token 可以直接使用。

流式接口失败不自动重新提交同步请求，避免同一问题被服务端处理两次。流式协议、事件 payload、结束与中断、结果字段均先核对，再用类型和 schema 描述；不复刻旧组件中的多种猜测字段与兜底链。

正式代码参考 `stage-5e` 之前的写法及 `post-5e-code-review.md`：

- `api.ts` 负责边界解析，`queries.ts` 管理接口缓存，组合式函数持有交互与操作状态，TSX 组件只组合与渲染；不把旧的大组件换成同样大的 TSX 文件。
- 审核、删除按 `useSessionGuard` 保护提交前后会话；可替换查询用 `LatestController`，组件卸载取消读操作，已发出的写操作不随卸载取消。
- 下载、保存与进度复用 `shared/file-transfer`；不从文件管理 feature 借业务组件，不重复鉴权、Blob 保存、错误解析。
- 地图用 `map-vue` 和 `shared/map` 组合，AI 结果的图层状态由本 feature 拥有；不迁移 Mapbox，也不从现状底图 feature 导入私有逻辑。
- 样式使用令牌和 CSS Modules，Element 外观变体集中于主题文件；按用途拆分、完整写块与 JSX，保留简洁中文注释，不新增大量只为转调的函数。

## 系统管理业务接入（2026-10-23）

- `/system-management` 与 `/system-management/statistical-report` 保留旧地址，共用管理员权限及路由名，通过 props 区分栏目；栏目切换重建筛选与详情，下载任务继续由页面持有，顶栏保持系统管理选中。
- `features/system-management` 分开接口 schema、查询缓存、筛选 / 审核组合式函数与界面组件。查询默认每页 20 条；输入法选字不触发查询；翻页失败保留当前条件的总数，换条件不会误用旧总数。
- 详情必须与请求 ID 一致，读取失败提供重试，不使用列表摘要兜底。审核结果默认不选，拒绝需要非空原因，最长 500 字；提交立即防重复，失败保留草稿。提交前后核对会话，已发送的写操作不因关闭页面取消；旧会话结果不刷新新会话缓存、不弹成功提示。
- 下载沿用旧实际调用：申请 `POST /api/apply/download/{id}`，报表 `GET /statistics/download?id=…`。公共 HTTP 增加 `postBlob`；文件管理的下载任务与进度区移到 `shared/file-transfer/useDownloads`、`DownloadPanel`，两模块提供各自的取流函数。系统管理任务 ID 加栏目前缀，避免两个接口同名 ID 相互覆盖。
- 仍使用已确认的灰底标题、菜单、查询表单、表格及分页。审核弹窗与文件上传一致采用顶部 6vh、最大高度 88dvh，长内容内部滚动，标题和底部按钮保持可见。
- `/dev/system-management` 默认展示同一套正式组件，固定数据不会调用业务接口；审核只改本地记录，下载生成明确标记的演示 TXT。原已确认设计作为对照保留，未复制第二份正式业务逻辑。AI 预览不变。

### 接口确认程度与待联调

| 项目 | 当前证据 | 后续核对 |
|---|---|---|
| 申请列表 | 旧调用为 POST，参数 applyName / status / taskStatus / pageNum / pageSize；未登录只读请求与当前浏览器管理员页均未取得列表 | 真实记录的字段类型、空值、ID 及 storage_status 枚举；恢复接口后再验收 |
| 统计报表列表 | 实际 POST 返回 code=200，PageHelper 分页 list 为空、total=0；正式页面显示空状态 | 非空记录的 id / year / 时间 / status 类型 |
| 申请详情 | 按旧 GET 路径与 apply_id 等字段实现，失败不兜底 | 实际响应样本及权限 |
| 审核 | 按旧 POST 路径，status / reason 放 query；用户允许先按旧契约接入，只判断公共成功码并丢弃未知 data | 成功和失败响应、重复审核冲突、权限、审核后状态变化 |
| 两类下载 | 方法和参数按实际调用链核对，本地 MSW 验证 POST / GET、文件名和失败体 | 真实响应头、二进制内容、鉴权和取消后的后端行为 |

当前 schema 中 ID 按字符串、报表年份按字符串、data_formats 按旧提交使用的逗号串接收；未取得真实记录，不能将这些类型标记为后端已验证。申请 status 仅接受 pending / approved / rejected / table；准备状态保留原值，界面只识别旧筛选使用的 waiting / processing / success / timeout / failed，未知值不猜测为成功、不开放下载。不迁移旧版的多字段猜测与状态同义词兜底链。
