## 范围与结论

复核两个 feature、页面装配、公共传输调用、既有规范及测试；验收资源目录维护、筛选分页、详情编辑、启停、Excel 导入，文件分类、筛选分页、上传、下载和文档预览。修复后前端与本地固定接口验收通过；真实后端写入及未知业务契约仍属于联调范围。

不迁移资源申请、地图服务 / 数据接口的旧版内存实现，不把图片改为其他预览方式。未向真实后端执行试验性上传、导入、启停、编辑或删除。

## 审查发现与处理

| 项目 | 证据与影响 | 处理 |
|---|---|---|
| 资源写操作的会话竞态 | 目录维护、详情保存、启停、Excel 导入只在调用前检查会话；mutation 调度期间切换账号后仍会进入 API，可能借用新凭据发送旧操作。4 个回归用例在原代码上均断言失败 | 在各 mutationFn 发请求前复核提交的 token，沿用现有文件上传的检查方式；会话变更返回 canceled |
| 文件删除的旧结果 | 删除发出后卸载或切换账号，仍返回成功、触发成功提示；mutation 成功也会刷新新会话列表。新增用例复现 | 删除持有原 Session，在发请求、刷新缓存、返回成功三个位置复核；已发出的写操作继续完成，不以卸载取消冒充撤销 |
| 未保存确认框样式 | 默认 Element 标题未使用统一浅灰标题栏 | 复用 dialog-panel-header + MxTitle，48 高、16 / 600、4 × 16 主色竖条；正文清除默认段落外边距，沿用统一留白 |
| 预览头部过空 | 文件名和缩放工具分行，留白叠加 | 文件名、类型、缩放同行；允许窄屏换行，阅读区上方间距 8，正文不缩放适宽 |
| 依赖安全公告 | 官方 npm 审计命中 source-map-js 1.2.1 与 follow-redirects 1.16.0 的 3 条高危公告 | 仅将两个间接依赖更新为 1.2.2 / 1.16.1；清单和直接依赖范围不变，冻结安装与生产依赖审计通过 |

依赖公告：[source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)、[follow-redirects 数组请求头](https://github.com/advisories/GHSA-q3jh-wrc6-jgq8)、[follow-redirects 自定义敏感头](https://github.com/advisories/GHSA-8r9p-f939-6h3c)。后两项属于 Node 重定向路径；本次未发现页面直接触发这些路径，不把依赖公告等同于已发生的页面攻击。默认镜像没有 audit 接口，仅本次命令改用官方 registry，没有修改项目 registry 配置。

## 规范与安全复核

- 保持 pages → features → shared → libs；两模块不互相导入，HTTP、FormData 进度、文件名处理和保存继续复用 shared
- 业务数据由 Query 缓存持有；详情草稿与目录快照独立，异步结果有身份检查；不同后端分页契约分别处理，没有合并为错误的通用分页逻辑
- 不增加 Excel 大小、表头、影响图层等未经确认的约束，不猜测成功响应 data；失败不自动重试写入，100% 只表示上传完成、仍等待服务端处理
- 检查管理员路由、字段白名单、详情 ID 校验、确认框卸载清理、按行防重复和权限切换；保留服务端鉴权作为最终边界
- DOCX 保持无脚本 iframe、CSP 限制、禁用 HTML 片段及文档链接跳转；TXT 按文本渲染；PDF 只交给浏览器原生阅读器；Blob URL 继续按生命周期释放
- 未发现需要扩展兼容层或重构公共组件的理由；样式复用标题、区块、表单、表格和分页组件及主题令牌
