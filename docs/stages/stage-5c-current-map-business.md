# 阶段五 5C：现状底图业务

- 完成日期：2026-10-15
- 相关决策：ADR 0039（异步操作的作废规则）、0040（真实浏览器测试）、0041（资源图层）、0042（偏好的持久化）、0043（只读图例）、0044（符号覆盖）、0045（面的描边与纹理）、0046（分类取值的纹理默认色与按线型拆层）、0047（点选与详情）、0048（点选识别的修正）、0049（框选）、0050（框选估数的修正）、0051（区划裁剪）、0052（资源的年份）

5C 的目标是"除三维外与旧页面功能对齐"：把旧现状底图里的资源图层、图层面板、图例、符号编辑、点选与框选、区划裁剪、年份迁到 `features/resource-map`，现状底图页把它们和 5B 的公共能力组装起来。开始前先插入 5C.0，把 5A、5B 里各写一套的"结果还算不算数"统一成一套规则。每一步都先读旧代码、用真实后端实测，再写 ADR 和用户讨论，接受后实现，最后在真实数据上验收。

本文分两部分：第一部分记录做了什么、每项改动的目的；第二部分按主题整理可以学到的知识、设计理由和替代方案。实测数据在 [migration.md](../migration.md) 的"现状底图"各节，公共能力的用法在 [modules/shared-map.md](../modules/shared-map.md)，存储在 [modules/storage.md](../modules/storage.md)，地图部分的 ADR 关系在 [modules/map-overview.md](../modules/map-overview.md)。

## 改动与目的

### 0. 地图内核加固（5C.0，ADR 0039）

5B 收尾时的时序问题一个接一个（区划定位、坐标定位、默认视角各自判断请求是否过期），写法有三种。5C 开始前讨论后统一：

- 异步分三类：能写成状态收敛的不写成操作；可替换操作（同一件事的先后请求）在同一通道里只认最新，统一用 `@yzt/utils` 的 `LatestController`，不再手写递增计数；服务端写操作按业务处理，不随组件卸载取消
- 命名：状态快照的序号叫 revision（只增不减），一次意图用信号表示（operation，只能作废），version 只用于外部格式。先单独提交改名（5C.0b），再提交行为调整（5C.0d），出了回归容易定位
- map-vue 的相机操作对象：`beginCameraOperation()` 开始一次操作，`run` 负责等就绪、跨视图失败等待和等待后的再确认；`view` 只在视图就绪时有值
- `MapLibreView` 的状态改成转换表，用穷举短序列测试所有转换；之后又修了两处：`LatestController` 在取消回调里重入时留下了旧信号；样式失败后整体重建要先回到 initializing
- 写了地图架构总览，按主题列出现在有效的 ADR 和修正关系

### 1. 资源图层（5C.1，ADR 0040、0041）

- 先做了 Vitest 浏览器模式（ADR 0040）：少量依赖真实 MapLibre 或真实布局的行为在 Chromium 无界面版里测，CI 安装浏览器
- `/dev/resources` 实测页用真实资源树和瓦片定下 ADR 0041 的事项：瓦片由后端现场生成，没有固定金字塔，重的资源要有最小显示级别（低层级瓦片最大 42 MB）；12 个资源没有瓦片；未勾选的图层不放进样式；Chrome 下 MapLibre 默认只有 1 个 Worker，改为按核数设置
- 结构：接口树 → 目录（纯函数，按 `code` 合并年份）→ 样式登记表（按 `code` 的静态数据）→ 拥有者 `useResourceLayers`（按 `code` 的显示状态）→ `resources` 分组。状态连同它所基于的目录放在同一个 `shallowRef` 里，推导读不到"目录换了、状态还没合并"的中间态；只在目录变化时逐个资源校验，不合法的不进会话
- 数据源错误成为视图的状态：带 `sourceId` 的错误不算样式失败，数据源移除、整体重建时清除，拥有者从上下文推导"部分瓦片加载失败"。读 MapLibre 源码时发现瓦片返回 404 根本不报错
- 地类配色（编码表 69 项、历史名称表 6 项）用旧仓库生成的 fixture 逐条对照；城镇村等用地的按属性配色改为按值确定（旧项目每次刷新随机）

### 2. 图层面板（5C.2）

- 浏览勾选和调整叠放分开：目录树只负责勾选，按目录顺序；"已勾选"区按叠放顺序上移、下移、调透明度。旧项目在树里同级排序，和"所有资源一份顺序"的模型对不上
- 拥有者加批量勾选，勾选分类时只替换一次状态；面板的数据都由纯函数推导；页面浮层分两列，左边是面板

### 3. 偏好的持久化（5C.3，ADR 0042）

- IndexedDB + idb-keyval，经 `shared/storage` 的异步键值接口读写；按登录名区分，退出不清除
- 共用流程 `usePreference`：读取最多等 1 秒、恢复只应用一次、恢复前用户已操作时放弃恢复并保存、防抖 300 ms、生命期结束和页面隐藏时提交；存下的值用 zod 校验，包括自洽（顺序不重复、和设置一一对应）
- 资源图层等目录和存储都就绪再合并，不先按默认值显示再换成上次的选择

### 4. 只读图例（5C.4，ADR 0043）

- 读旧代码发现"当前出现的地类"统计只为发现表外编码，图例本身一直列全表；实测全省 18.9 万个要素统计要 327～563 ms，三个视野都没有表外编码，所以不做统计
- 图例从样式登记表推导，测试保证预览的颜色和图层相同；面板进入页面时收起，条目只在集合变化后只剩一条时自动展开

### 5. 符号编辑（5C.5，ADR 0044～0046）

- 符号模型：点、线、面各自的字段，四档与自定义大小，覆盖只记和默认不同的字段；拥有者持有覆盖和拖动取色时的预览，分组和图例都从默认符号、覆盖和预览推导
- 分类样式：各取值的符号用 `match` 组合在一个图层里，大小保留外层的缩放插值；按属性配色的资源可以换成统一样式
- 面的纹理和描边：SDF 花纹作为样式图片随分组提交（图片进入快照），面按需拆成主图层、纹理图层、描边图层；纹理图层关掉抗锯齿，否则默认的边线盖住 1 像素描边
- 验收时发现 MapLibre 6.12 在 `line-dasharray` 于常量和按要素取值之间切换时报错（浏览器测试复现），改为按线型拆层，每层的线型是常量；分类取值的纹理默认色改为取值颜色在 Lab 空间加深，同色花纹在不透明填充上看不见
- 取色器的行为写成规则：`ElColorPicker` 没有关闭事件，Esc、点外面时重置并再发一次 `active-change`，由拥有者规定"预览等于确认的值就是没有预览"

### 6. 点选与框选（5C.6，ADR 0047～0050）

- 地图内核加选择状态（只存数据源和 `guid`）和视图的渲染要素查询；查询接口成功时没有信封，`shared/http` 加 `envelope: false`
- 识别：二维 14 级以上只用渲染要素；14 级以下和三维由登记的数据集查后端第一页和总数（ADR 0048：后端识别按数据集登记，不按前缀）；选中的要素用完整几何高亮、定位并闪烁
- 框选：离起点不小于 3 像素进入框选，进入后屏蔽这次手势派生的单击；松手时先估数，超过 5000 提示缩小范围；批量高亮在瓦片上按 `guid` 过滤；列表虚拟滚动
- 冒烟时发现地类图斑的瓦片 14 级以下不带 `guid`，按 `guid` 去重的估数是 0，6.4 级的大框让后端统计了 103.9 万个、用了 16.2 s。ADR 0050 改为按渲染要素加权计数（只数画出要素本身的图层，聚合要素按 `point_count`）
- 实测高亮更新：1048 个约 0.3～0.4 s 画完，5000 项的过滤条件 124 ms，暂不需要 feature-state；验收中发现虚拟列表的行是响应式代理，拥有者按对象身份找不到，改为按序号取原对象

### 7. 区划裁剪（5C.7，ADR 0051）

- 实测 183 个瓦片集的区划字段，发现业务数据的区县代码和区划目录对不上（崇川区合并前的旧代码、7 个功能区代码），旧项目按属性过滤的做法在区县级不可靠，改为按区划边界几何：区划外用不透明遮罩盖住，点选、框选按几何限定范围
- 遮罩按环的嵌套深度构造（奇偶规则），洞里属于区划的小岛不被盖住；测试检查本地边界数据满足"环之间不交叉"的前提
- 发给后端的几何：GET 地址约 8 KB 封顶，求交结果按 0～2 像素依次简化，舍入、去掉退化的环，不超过 120 个坐标且通过自己写的有效性检查才发出，都不通过时提示范围太复杂
- 求交前先按外包矩形裁掉区划远处的边，南京市界的求交从约 140 ms 降到 1～20 ms；用真实市界写的测试发现多部分的市界裁剪后有空的部分、求交报错
- 真实数据验收：崇川区按代码过滤会一条不剩，按几何正常显示；跨区县框选只列出区划里的（县界简化过，边界附近有几块出入）

### 8. 年份（5C.8，ADR 0052）

- 每个资源各自选年份，另有"批量设置年份"：有这一年的资源不论是否勾选都切过去，没有的保持不变；不存"当前年份"，批量设置是一次操作
- 年份作为独立字段推导到已勾选条目和图例条目，条目的身份、名称、符号仍按 `code`，换年份不重置图例的展开和编辑
- 真实数据验收：批量设成 2023，34 个资源切过去、6 个保持 2025；点选的详情查询用新年份的图层编码；刷新后还原

## 一、先实测，再定方案

5C 的大多数决定是被真实数据改过的：

| 原来的假设 | 实测 | 结果 |
|---|---|---|
| 所有资源的瓦片要素都带 `guid` | 地类图斑 14 级以下不带 | 估数改为加权计数（ADR 0050）；低级别框选只有列表 |
| 后端识别能力按前缀判断 | `csxhjctb_*` 只有部分数据集的分页结果带 `guid` | 按数据集登记（ADR 0048） |
| 区县可以按要素属性里的代码过滤 | 业务数据的代码和区划目录对不上 | 按边界几何裁剪（ADR 0051） |
| 简化到顶点数以内就能发给后端 | 简化后外环自相交 | 加有效性检查和固定的尝试次数（评审复现） |
| 要做"当前出现的地类"统计 | 没有表外编码，统计要几百毫秒 | 不做（ADR 0043） |

实测的方式也在演进：开发页（`/dev/resources`）、浏览器测试、在页面里通过组件树拿到拥有者直接调用、Node 脚本读仓库里的边界数据。共同点是先拿到数字，再写 ADR。

用户在 5C.7 之后提出一条原则：后端有些级别、有些资源暂时没有数据时，不为适配这种现状调整既定方案。实测的作用是发现方案本身的错误（比如代码对不上），而不是让方案去迁就暂时的数据缺口。

## 二、异步的统一规则

ADR 0039 把"结果还算不算数"从各个拥有者的自由发挥变成三条规则：

- 能写成状态收敛的不写成操作：比如资源图层的推导，状态变了就重新推导，不存在"过期的推导"
- 可替换操作在同一通道里只认最新：`LatestController.next()` 给出新信号、中止旧信号，每个等待点返回后检查 `signal.aborted`
- "等待会因中止而结束"不等于"返回时一定没中止"：每个 `await` 之后都要重新确认

到了 5C.8 验收"请求进行中切年份"时，这些规则已经保证了晚到的识别、加载更多和详情都不会出现，测试只是把它们写出来。

## 三、样式按分组推导的扩展

5C 在样式模型上加了不少东西，没有改"拥有者用纯函数推导分组、整体替换"的基本做法：

- 样式图片（SDF 花纹）随分组提交，图片进入快照：`setStyle(…, { diff: false })` 换上的新样式不保留旧图片，整体重建后要按快照补上
- 一个资源按需拆成多个图层（主图层、纹理、描边，线型不同的再拆），图层 ID 以资源的数据源 ID 加后缀，推导和校验照常
- 选中要素的高亮、框选的批量高亮、区划遮罩都是各自的分组，叠放靠分组顺序：遮罩在 `selection` 之上、注记之下，区划外的高亮自然被盖住，不用裁剪几何

## 四、MapLibre 的几个行为

| 行为 | 影响 | 做法 |
|---|---|---|
| 瓦片返回 HTTP 404 不报错 | 发现不了缺瓦片 | 后端用 200 加 JSON 时会以解析失败报出，带 `sourceId` |
| `line-dasharray` 在常量和按要素取值之间切换报错（6.12） | 分类线型切换时报错 | 按线型拆层，每层是常量 |
| 纹理图层默认的抗锯齿边线 | 盖住 1 像素描边 | 纹理图层 `fill-antialias: false` |
| `match` 的分支标签必须唯一 | 重复的 `guid` 让整个视图失败 | 拥有者按 `guid` 去重 |
| 只在移动不到 3 像素时发 `click` | 框选和单击要互斥 | 3 像素进入框选，屏蔽派生的单击 |
| `queryRenderedFeatures` 也返回透明图层的要素 | 估数按样式图层重复计数 | 只数画出要素本身的图层 |
| `within` 只判断点和线 | 不能按多边形裁剪面图层 | 遮罩 |
| 瓦片在 Worker 里请求 | 主线程和浏览器的网络记录都看不到 | 验收时看样式的瓦片地址和要素属性（瓦片图层名带年份） |
| Chrome 下默认只有 1 个 Worker | 加载慢 | 按核数设置，最多 4 个 |
| 只随级别变化的 `fill-pattern` 也有 300 ms 过渡，过渡期间按旧图片取图集位置 | 换花纹后约 300 ms 画出别的花纹（重新加载的瓦片里没有旧图片） | 纹理图层设 `fill-pattern-transition` 为 0；按要素取值的不过渡 |

## 五、Vue、Element 和 TanStack Query 的几个行为

- `useQuery` 的 key 变化后，`data` 要到下一轮调度才换成新 key 的结果：详情查询用 `select` 给结果标上要素，否则会按上一个要素定位
- TanStack Query 5 在还没有数据的查询重试时把状态重置为 `pending`，列表的"失败"直接用 `isError`
- `useVirtualList` 把数据放进深层 `ref`，给出的行是响应式代理，按对象身份比较时要按序号取原对象；列表在同一轮调度里被替换时滚动容器不重新挂载、滚动位置保留，新一轮结果要按列表的身份显式回到顶部
- `ElColorPicker` 没有关闭事件，Esc、点外面时重置并再发一次 `active-change`，随组件卸载时什么也不报，预览要由编辑器自己丢弃；`ElInputNumber` 会把越界的值改成边界值，需要提示范围时改用普通输入框
- 批量设置年份是一次操作，选择框的 `modelValue` 一直是空、不保留选中值，所以连续两次选同一年都会执行；测试里点的是真实的下拉项，走 Element 自己的事件

## 六、几何的正确性

区划裁剪是 5C 里几何最多的一步：

- 奇偶规则：一个点在遮罩里，当且仅当包含它的区划环有偶数个。按嵌套深度构造遮罩，不依赖数据标的外环、洞和环的方向
- 有效性检查：turf 的 `kinks` 不查共线重叠，`boolean-valid` 不查外环自相交，所以自己写。坐标换成整数微度后叉积在 2^53 以内，判断是精确的，不需要 `robust-predicates`
- 判断要能结束：容差的档位固定，每次的工作量有上限，做不到时返回明确的状态，而不是"一直加大容差直到满足"
- 优化先证明不改变结果：先按外包矩形裁剪再求交，在全部市、区县上随机 400 个框比较结果相同；原本想把矩形放大一点避开退化边，随机比较后发现不需要，删掉

## 七、拥有者：状态与操作

延续 5B 的写法，5C 的几个拥有者有两点新的体会：

- 状态连同它的依据放在一起（资源图层的状态带着目录），推导什么时候执行都读不到中间态
- 能写成操作的不存成状态：批量设置年份是一次操作，不存"当前年份"；存了就会和各资源的年份对不上
- 界面条目的身份和显示的值分开：图例按 `code` 管理展开和编辑，年份只是显示的字段

## 八、测试

### 1. 改坏验证的收获

| 类型 | 例子 | 处理 |
|---|---|---|
| 测试数据区分不了 | 图层面板的目录全是单年份资源；自洽检查的重复顺序项在数量检查那一步就被拒 | 换数据：加多年份资源；数量相等但有重复 |
| 判断方式看不出结构问题 | 遮罩里洞挂错了地方，点在不在遮罩里的判断（也是奇偶规则）结果一样，MapLibre 却画不对 | 同时比较遮罩的结构 |
| 只测了一半 | 行内的年份选择误调成批量设置，原用例只检查了这个资源 | 补"别的资源不变" |
| 对称的冗余 | 线段相交判断里四个对称子句只去掉一个，其余三个仍能拦下 | 整段去掉时能测出，记下原因 |
| 合成数据测不出 | 多部分的市界裁剪后有空的部分，求交报错 | 用仓库里的真实市界写测试 |
| 改坏的工具本身有问题 | 对还没进 git 的文件用 `git checkout` 还原，改动留了下来 | 改用文件内容的副本还原 |

类型检查也抓到过一处：`holes.flatMap(hole => roundRing(hole) ?? [])` 会把保留的洞展开成散的坐标，先补了复现的测试再修。

### 2. 浏览器测试

只写依赖真实引擎或布局的用例：MapLibre 的线型切换报错、样式图片的首次加载与恢复、渲染要素查询、IndexedDB。要等的事件在操作前登记，可能挂起的等待和"出现未捕获的错误"赛跑。

### 3. 真实数据验收

每一步的最后在真实后端上验收，并记下数字。在页面里通过 Vue 的组件树拿到拥有者、在画布上派发合成的鼠标事件，不改代码；验收要临时改勾选、年份时，开始前记下用户的偏好，结束后恢复并刷新确认。

## 九、工作方法

- **ADR 先评审再实现**：每份 ADR 都由用户评审，补上了大量边界条件，比如单击和框选的互斥、渲染结果是快照、估数只是拒绝阈值、简化后的有效性和必然结束、批量设置的界面文案。评审时提出的复现（南通市界简化后自相交）直接成了测试
- **一步一提交，改名和改行为分开**：5C.0b 只改名，5C.0d 才改行为
- **先实测再优化**：高亮更新、估数、求交，都是测出问题再动手；高亮更新实测够快，就不引入 feature-state
- **范围变了就拆**：符号编辑拆成三步并另写两份 ADR，点选和框选分开写 ADR
- **不为后端的暂时缺口改方案**：记成待办，方案按业务语义设计

## 十、替代方案汇总

| 领域 | 本项目选择 | 常见替代 | 没选的主要原因 |
|---|---|---|---|
| 异步作废 | 三类规则 + `LatestController` | 各处手写递增计数；用相机变化判断 | 写法不统一；相机没变的操作、动画的每一帧会判断错 |
| 真实引擎的测试 | Vitest 浏览器模式 | 全部用假对象；Playwright 端到端 | 假对象测不出引擎的行为；端到端太重 |
| 资源图层的状态 | 按 `code`，年份单独存 | `code_年份`（旧项目） | 换年份时勾选、透明度、顺序要搬家 |
| 偏好的存储 | IndexedDB + idb-keyval | localStorage | 同步阻塞、容量小 |
| 地类统计 | 不做 | 每次视图变化统计渲染要素 | 没有表外编码，统计要几百毫秒 |
| 面的纹理 | SDF 图片，颜色由样式给 | 每种颜色一张图片 | 图片数量随颜色增长 |
| 线型不同的要素 | 按线型拆层 | 按要素取 `line-dasharray` | MapLibre 6.12 切换时报错；实线走虚线着色器会变浅 |
| 要素身份 | `guid` | 按全部属性匹配（旧项目） | 慢，且不唯一 |
| 批量高亮 | 瓦片上按 `guid` 过滤的图层 | feature-state；取回完整几何 | 实测过滤够快；完整几何要几秒到几分钟 |
| 框选估数 | 渲染要素加权计数 | 只按 `guid` 去重；问后端 | 低级别没有 `guid`；后端统计本身就慢 |
| 区划裁剪 | 几何遮罩 + 按几何限定查询 | 属性过滤加遮罩兜底（旧项目） | 业务数据的代码和区划目录对不上 |
| 几何有效性 | 自己写的整数判断 | `@turf/kinks`；`@turf/boolean-valid` | 各漏一类问题 |
| 年份 | 各自选 + 批量设置 | 全局年份（时间切片）；只按资源各自选 | 不能单独改；批量切换要改几十次 |
