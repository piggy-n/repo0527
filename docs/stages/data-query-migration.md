## 二、知识点与设计理由

### 四个路由一个组件，按专题加 key

旧页面靠 `resetQueryModuleState` 手动清状态。新写法让外层的 `DataQueryPage` 只做一件事：按专题给内层加 `key`，专题一变就整页重建，地图会话、表单、结果都不会带到另一个专题。比起在每个拥有者里侦听专题变化再重置，这样不会漏掉某一份状态。

ADR 0104 和最初的注释说"四个路由是同一个组件实例"，补冒烟用例时发现不对：四个路由共用的懒加载函数经 `withMapRuntime` 包装，Vue Router 按路由记录分别调用它，每次都返回一个新的 `MapRuntimeProvider` 组件，所以四个路由是四个不同的组件，切路由时页面本来就整页重建。`key` 在正式页面上是多一层保险，真正用到它的是实测页：那里同一个 `DataQueryPage` 只换 `topic`。注释已改正，ADR 按约定不改，以这里为准。

### 页签是四个拥有者加一个编排者

属性、空间、高级、自然语言各有自己的表单拥有者，只管自己的状态和"能不能查询"（`check()` 返回查询或原因）；`useDataQuery` 只负责页签之间的规则：哪些切换清结果、离开空间查询时结束绘制、离开自然语言时作废解析、高级查询没写区划时借属性查询的。提交返回结果对象（不能查询、画完没选图层、没有识别、被作废），提示由面板决定，组合式函数不弹提示。

### 绘制放在 shared/map，复用点/框选的手势

框选、多边形不属于某个业务域，放在 `shared/map/draw`。框选直接用点/框选已有的手势纯函数（3 像素才算开始、屏蔽派生的单击）和浮层；多边形的点击规则同测面。画完的范围带上"一个像素对应多少经纬度"，发给后端前用 `queryGeometry` 整理（ADR 0051），整理不出来（自相交）时让用户重画，而不是像旧页面那样原样发出去。

### 定位在结果面板挂上之后

旧页面自己算定位留白；新页面把查询面板、结果面板都用 `useMapOverlay` 登记，定位时自动避开。前提是定位那一刻结果面板已经在 DOM 里，所以 `fitAfterRender` 先等 `nextTick` 再取范围、开始相机操作；shp 查询要等命中的要素到了才知道范围，记下一次待定位，结果到达时再执行。

### 查询缓存的 key 里有 File

shp 查询的参数里有上传的 `File`。TanStack Query 的 `hashKey` 把它序列化成 `{}`，两个不同的文件会被当成同一个查询；所以每次选文件给一个递增的 `fileId` 放进 key。Vue Query 克隆 key 时只深拷贝普通对象和数组，`File` 原样传到 `queryFn`，请求能拿到真正的文件。

### 验收时补上的检查

分支提交时没有跑类型检查和 lint：Vitest 不做类型检查，测试文件里的错误（假的区划边界少了 `geometry` 字段）运行时不报错，只有 `tsc` 抓得到；lint 报了 mock 缺类型参数、`expect` 的第二个参数、条件里的 `expect`。配置自检原来逐项 `expect(..., label)`，改成"找出不符合的条目、断言为空列表"：失败时直接列出是哪几项，也不需要条件断言。改写后逐条改坏配置（重复字段、初始值不在选项里、自然语言规则指向不存在的表、示例匹配不到规则），都是断言失败。提交前 `pnpm typecheck`、`pnpm lint` 必须通过，这次是漏跑。

## 五、合入之后：生产冒烟

合入 main 后补了 `tools/smoke/data-query.spec.ts`，三项用例都登录后经过正式页面，接口用本地固定样本：

- 属性查询：选图层后先请求全省、不带条件的预览瓦片；查询后结果表两行、"2 条"，分页参数每页 100 条，结果瓦片带上条件；导出默认勾选 Excel，请求体同旧页面，下载的文件名是"学校点层.xlsx"（后端没给文件名时的后备名）
- 空间查询：在真实引擎上拖一个框，鼠标旁的提示出现说明视图就绪、工具在用；松手后直接查询，提示"已绘制 2 个结果"，工具退回移动，发给后端的几何是首尾相同的五个点
- 从顶栏切专题：先查出结果，再从"查询统计"切到国土变更调查，原来的画布已经从页面上移除、新页面没有条件和结果；再切到森林草原湿地荒漠，只有"建设中"的说明、没有页签。这一项补上了验收时没法在登录后验证的"菜单之间切换专题"

几个要点：查询接口成功时没有信封，样本照真实返回直接给分页或数组；查询瓦片的地址由页面换成绝对地址后在 Worker 里请求，仍是同源，夹具拦得到；Playwright 的文件过滤按完整路径匹配，工作树目录也叫 `data-query`，只跑这一个文件要写 `data-query\.spec`。

改坏验证（每次重新内网构建）：导出请求体的 `relation` 写错、画完不查询、预览瓦片的区划写错，都是断言失败。只去掉 `key` 时切专题的用例仍然通过，由此查出上面"四个路由是四个不同的组件"；改成让四个路由共用同一个包装组件、同时去掉 `key` 后，这项用例因面板标题还是上一个专题而失败；只共用包装组件、保留 `key` 时通过。
