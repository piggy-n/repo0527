## 二、知识点与设计理由

### 轮询交给查询库，规则留在拥有者

旧页面用 `setTimeout`、递增版本号、"上一次应用的数据签名"、骨架屏延迟定时器和条件防抖定时器管理轮询，一千多行。新写法里状态在查询缓存中，拥有者只回答一个问题：下一次多久以后查（`refetchInterval` 返回毫秒数或 `false`）。版本号由查询键代替（换条件就是换键，旧请求自动作废），签名比较由查询库的结构共享代替（结果没变时还是同一个对象，界面不重绘），标签页隐藏时暂停是查询库的默认行为。

结构共享带来一个陷阱：跟踪最初侦听的是"当前结果"这个对象，结果没变时对象也没变，侦听不触发，截止时间永远不检查——新统计等不到任务时会一直等。改坏验证时写的超时用例抓到了它，改成侦听每次成功的查询（`dataUpdatedAt`）。

### 跟踪是一个纯函数的状态机

提交后每个组合一条跟踪：提交中、等待、处理中、失败、超时，查到本次的结果就去掉。状态转换（创建成功、被拒绝、没有明确结果、查到状态）都是纯函数，测试不需要组件和定时器；拥有者只在合适的时机调用它们。每次提交带一个序号，创建请求返回时只更新这一次的跟踪，不碰之后对同一组合的提交。

### 被拒绝和"不知道"要分开

创建请求失败不一定说明没有创建：网络错误、超时、5xx 时后台可能已经接受了任务。只有业务码和 4xx（408 除外）算被拒绝；其余按"提交响应未确认"继续跟踪，并提醒不要重复提交。这条规则沿用旧页面，写成 `isRejection` 一个函数，用例分别覆盖两种。

### 布局能力放进组件库，而不是页面

宽屏收起侧栏如果由页面自己做，要重复窄屏的窄条、自己处理滚动位置和抽屉的关系。放进 `MxSplitLayout` 后，页面只开启 `collapsible` 并持有 `collapsed`；侧栏面板通过布局上下文自己加收起按钮（和抽屉里的关闭按钮同一个机制），窄屏时自然退回抽屉。

### 窄屏下的几处排版

- 面板的操作区不能换行：筛选标签放在操作区里时，窄屏会把标题挤掉，改放在标题下面单独一行
- `ElTableV2` 默认按比例分配列宽，窄时把七列挤进 300 像素；改为放不下时固定列宽、横向滚动
- 左列两个面板默认平分高度（`MxPanel` 的 `flex: 1`），排成一列后要按内容的高度，否则下面的面板被裁掉

### 构建工具链的小坑

在 Git Bash 里给 Node 脚本传以 `//` 开头的参数，MSYS 会把它当成路径改成 `/`；插入的注释因此少了一个斜杠，之后改用 `MSYS_NO_PATHCONV=1`。批量替换 ADR 编号时误改了 main 上另一份 ADR 0099 的引用，按文件从 git 恢复。
