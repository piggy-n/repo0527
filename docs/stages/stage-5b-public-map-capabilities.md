# 阶段五 5B：公共地图能力

- 完成日期：2026-10-10
- 相关决策：ADR 0031（底图）、0032（内网构建模式）、0033（行政区边界与默认视角）、0034（交互工具）、0035（测量）、0036（区划定位）、0037（坐标定位与位置点）

5B 的目标是"任何地图页都能装上底图、边界和工具栏"：把旧项目在多个地图页里各写一份的底图、行政区边界、工具切换、测量、定位做成 `shared/map` 里独立的能力，现状底图页挑选组合。开始前先修了 5A 之后发现的三处问题；中途把坐标定位从 5B.5 拆成 5B.6，因为旧项目的坐标定位只是占位按钮，用户决定新做成"坐标定位与位置点"。

本文分两部分：第一部分记录做了什么、每项改动的目的；第二部分按主题整理可以学到的知识、设计理由和替代方案。各能力的用法在 [modules/shared-map.md](../modules/shared-map.md)，内核和衔接层的变化在 [modules/map-core.md](../modules/map-core.md)、[modules/map-vue.md](../modules/map-vue.md)。

## 改动与目的

### 0. 5A 之后的三处修复（`260e6cf`）

5A 结束后的评审发现三处会在真实使用中出错的地方，都先写出复现的测试再修：

| 问题 | 修复 |
|---|---|
| `whenReady()` 只看"当前有没有就绪的视图"：画布重建时，旧视图就绪会被当作新视图就绪 | 等待绑定具体的视图实例；视图被卸下或替换时以 `AbortError` 结束，返回前确认仍是当前视图 |
| 现状底图在页面 setup 里发起初始定位：首次创建地图失败、重试成功后不再定位；画布重建后又会覆盖用户调整过的视角 | 本次进入页面后视图第一次就绪时定位一次，之后的再次就绪不覆盖 |
| 外部传入的 `onError` 自己抛错时，会打断视图进入 `failed`、`whenReady()` 的结束和卸载 | 在 `MapLibreView` 和 `provideMap` 的入口用 `@yzt/utils` 的 `safeReporter` 包装：报告器抛错时打印到控制台，内部照常进行 |

### 1. 底图（5B.1，ADR 0031、0032）

- 矢量、影像底图和注记都用天地图（用户决定不迁移旧项目只有 1～9 级的内网影像）。底图分两个分组：`basemap`（背景加底图）和 `basemap-labels`（注记），以后资源图层插在两者之间
- 天地图的配置是 `appConfig.tianditu: { key } | null`：两个环境变量在读取时合成一个值，"开启了却没有 key"在类型上就不存在；为 `null` 时样式里不放天地图数据源，面板只剩"无底图"
- 内网部署用 Vite 的 `intranet` 模式：差异都写在 `.env.intranet`，`pnpm build:intranet` 构建、`dev:intranet` 开发；代码只读 `appConfig`，不判断模式名（ADR 0032）。旧项目靠改源码里的常量切换，切换后界面上仍有"矢量底图"选项，选了也看不到
- 第一个"拥有者"`useBasemap`：组合式函数持有选择和每种底图各自的透明度，操作校验参数并整体替换状态，推导分组的是纯函数，面板通过 props 拿到它。之后的边界、测量、区划定位、位置点都沿用这个写法
- 浏览器验证：改透明度只产生 `setPaintProperty`、不重新请求瓦片；放大到 19.6 级时请求 18 级瓦片放大显示；内网配置下整个页面没有外部请求

### 2. 行政区边界与默认视角（5B.2，ADR 0033）

- 省、市、县界由转换脚本从旧项目的 GeoJSON 生成：坐标保留 6 位小数、只留名称和代码，市界从 2.4 MB 减到 1.4 MB。数据源写成 `?url` 导入的地址，带哈希的独立文件，由 MapLibre 在 Worker 里下载和解析；关闭的级别不在样式里，打开时才下载
- 叠放更正为底图、注记、边界（旧项目的边界实际一直被移到最顶，ADR 0031 写错了）
- 江苏的范围按省界数据更正，原来的范围切掉了启东；缩放范围 5～18
- `useDefaultView`：第一次就绪时不带动画地适配一次，`goToDefaultView` 回到这里；默认视角要平视，MapLibre 6 的 `fitBounds` 不把俯角归零，视图接口加了 `pitch`
- 县界简化过，用数据算出与市界的偏差中位数约 150 米，没有更精细的数据，原样迁移

### 3. 交互基础（5B.3，ADR 0034）

- 会话里的工具模型：同一时间只有一个当前工具；"移动"是内置的常驻模式，测量、拾取是临时任务，退出后回到上一个常驻模式；Esc 没有被工具处理时临时任务退出
- 输入由二维视图直接交给会话的当前工具，不经过 Vue；只有就绪的视图转交。工具只拿到 `ToolView`（`kind`、`pick`、`project`），光标和手势由工具声明、只由适配器应用（只恢复自己关掉的手势）
- map-vue 增加 `registerTools`（只能在页面的 setup 里登记）、当前工具和切换；视口增加 `pick`、`project`
- 样式模型、相机模型、工具模型共用的"事件加释放"抽成 `ModelEvents`（组合，不用继承）
- 开发页的坐标拾取工具验证了拾取与投影互为逆运算（回投偏差 0 像素）、光标和手势的切换

### 4. 测量（5B.4，ADR 0035）

- 距离和面积用 geographiclib-geodesic 按椭球面计算；`MeasureStore` 持有测量结果和正在画的一条，测距、测面两个工具共用；双击里的第二次单击靠输入事件新增的 `clickCount` 忽略
- 标签、删除按钮和提示用 DOM 浮层，文字由纯函数推导；单位格式沿用旧项目
- 预览线每次鼠标移动都提交一次样式。在开发页加上 200 个图层实测，从事件到提交完成中位 0.5 ms，不按动画帧合并
- 浏览器验证发现测距的折线下面被填充成了三角形：MapLibre 的 fill 图层会把线也当成环填充，填充图层的 `filter` 加上 `['geometry-type']`。原来的测试按状态求值 `filter`，没带几何类型，所以没发现
- 工具栏加了三个按钮后在 375 宽时伸出屏幕，改为换行、控件列左右留边距

### 5. 区划定位（5B.5，ADR 0036）

- 读旧代码发现：面板用的区划列表 `region.js` 有 8 个区县的代码是旧的或错位的，旧项目先按代码匹配边界，所以选梁溪区高亮的是锡山区；天地图行政区接口实际不会被请求（本地数据完整）
- 区划目录改由旧项目的标签坐标表转换（代码现行），测试保证目录和市界、县界数据逐条对应；边界只用本地数据，内网也能用
- 边界的加载：同一个 `?url` 地址（命中 HTTP 缓存），解析结果按文件缓存，同时发起的加载共用一次，失败不缓存；连云港的两个要素合并成 `MultiPolygon`
- `useRegionLocate`：每次选择一个 `AbortController`，晚到的成功和失败都不写入；边界到位后等视图就绪再定位
- 工具栏的动作增加按下状态（`pressed`）：面板开关是页面的界面状态，工具栏不保存
- 实测第一次按市定位：在浏览器主线程 `JSON.parse` 1.4 MB 的市界约 8 ms，校验和建索引约 3 ms，之后用缓存
- 名称标签和天地图行政区接口不迁移（用户决定）

### 6. 坐标定位与位置点（5B.6，ADR 0037）

- 旧项目没有实现，交互先做成可以试的原型，和用户确认：长按 0.5 秒拖动、图钉下方"坐标定位点"、拾取后打开位置信息、定位至少 14 级、复制用规范的 `′″`、"清除"连同位置点、所在区划用县界判断、两个定位面板互斥
- 经纬度的识别：度分秒和小数按同一套规则识别（单位、分隔、连写、方向），格式只决定显示；输入时显示识别结果，离开输入框时规范写法，不在输入过程中插入符号
- `flyTo` 增加留白：MapLibre 的 `padding` 会留在地图上，适配器换成只对这一次有效的 `offset`；视口不传时避开悬浮元素
- 位置点的拥有者、拾取工具（单击一次就放点并退出）、所在区县（先用外包范围排除，再用 `@turf/boolean-point-in-polygon` 判断）
- 图钉的长按拖动写成与 DOM 无关的手势状态机，用假定时器测试；位置信息的位置是纯函数（上方放不下翻到下方，左右不出画布）；复制用 VueUse 的 `useClipboard({ legacy: true })`，兼顾内网的 http
- 写页面测试时发现：回车定位时先规范再识别，会把输入的小数度取整到百分之一秒，改成先识别、后规范
- 验收时用户发现：拾取开启后按 Esc 没反应。键盘事件只在地图获得焦点时收到，而拾取、测距、测面都由按钮激活，焦点停在按钮上。改为切换到临时任务时由适配器把焦点移到画布上（`f5c7701`）

# 第二部分：可以学到什么

## 一、配置的形状决定调用方的写法

`appConfig.tianditu` 不是两个布尔值和字符串，而是 `{ key } | null`。"开启了却没有 key"在读取配置时就报错，进入代码的只有两种合法状态；调用方拿到 `null` 时类型系统逼着它处理，不会像旧项目那样在每条调用路径上各写一次判断。这是"解析而不是校验"（parse, don't validate）：在边界上把松散的输入变成精确的类型，之后的代码不再重复检查。

内网和公网的差异放在构建模式的环境文件里，而不是代码里的 `if (MODE === 'intranet')`：模式名只出现在命令和 `.env.intranet` 里，代码只认 `appConfig`。新增一个部署环境时只加一个环境文件。

## 二、拥有者：状态、操作、纯函数推导

5B 的每项能力都是同一个形状：

- 组合式函数持有状态，用 `shallowRef` 整体替换；值没变时不替换，免得触发重新推导和渲染
- 操作校验参数，不合法时抛错（编程错误）；外部数据的失败表示成数据（`failed` 状态）
- 推导分组的是纯函数，测试不需要 Vue 和地图
- 界面通过 props 拿到拥有者，只显示和调用；5D 换界面时拥有者不动

和 Pinia store 的区别：拥有者的生命周期跟着页面，同一页面可以有多份，也不会在页面之间残留状态。

## 三、静态数据的加载

- `?url` 导入得到的是带哈希的文件地址：内容不变地址不变，浏览器可以长期缓存；边界图层（MapLibre 在 Worker 里下载）和区划定位（主线程 `fetch`）用同一个地址，第二次命中 HTTP 缓存
- 主线程解析大 JSON 先实测：1.4 MB 的市界解析约 8 ms，只做一次，不值得移到 Worker
- 校验的粒度：边界文件用 zod 检查结构，坐标只确认是数组。逐个检查坐标在 Node 里要 40 ms，而坐标由自己的转换脚本生成并检查过
- 在测试里用 `?raw` 导入大 JSON：直接 `import x from 'a.json'` 会让 TypeScript 为 1.4 MB 的内容推断类型
- 用测试代替手工核对：区划目录和边界数据逐条对比，旧项目的 8 个错误代码就是这样暴露出来的

## 四、工具模型（状态模式）

同一时间只有一个工具接管鼠标，切换时旧工具 `deactivate`、新工具 `activate`，取代旧项目里各个交互互相询问"你在忙吗"。几个细节：

- 常驻模式和临时任务：临时任务退出时回到上一个常驻模式，而不是总回到"移动"
- Esc 先交给工具：测量正在画时 Esc 只取消这一条，没在画时才由工具模型退出
- 光标和手势由工具声明、只由适配器应用；适配器只恢复自己关掉的手势，不覆盖别处的设置
- 输入不经过 Vue：视图直接调用会话的工具，三维视图将来同样转交，不需要 map-vue 参与
- 工具在处理输入时可以同步退出自己（拾取工具单击后 `releaseTool`）：工具模型切换后只对 Esc 做额外判断
- 键盘焦点：地图只在获得焦点时收到按键，这样不影响页面上的输入框；但工具由按钮激活时焦点在按钮上，Esc 到不了地图。切换到临时任务时把焦点移到画布上（`preventScroll`，不滚动页面）；常驻模式和视图就绪时不移，进入页面不会抢走焦点。没有改成在整个页面监听 Esc：关闭下拉框、对话框时按的 Esc 也会把工具退掉

## 五、椭球面计算与精度

- geographiclib 是 Karney 算法的作者维护的库，距离和面积都按椭球面计算；turf 是球面公式。浏览器验证时用另一种实现（Vincenty）按同样的坐标独立算出 383.92 km，结果一致
- 参数顺序是先纬度后经度，封装函数负责转换；面积的经纬度写反在赤道附近的正方形上测不出来，测试改用江苏纬度上长宽不等的矩形
- 显示精度要和用途对得上：小数 6 位约 0.1 米，度分秒的秒两位小数约 0.3 米。按显示的文字再识别会丢精度，所以定位用输入的原值，规范写法只用于显示

## 六、MapLibre 6 的几个行为

| 行为 | 影响 | 做法 |
|---|---|---|
| fill 图层会把 LineString 当成环填充 | 测距的折线下面出现填充 | 填充图层的 `filter` 加上 `['geometry-type']` |
| `flyTo`、`easeTo` 的 `padding` 会留在地图上 | 之后的相机中心不再是画布中心 | 换成只对这一次有效的 `offset` |
| `fitBounds` 把旋转归零，俯角不变，算缩放时不考虑俯角 | 倾斜时区划显示不全 | 视图接口的 `fitBounds` 加 `pitch` |
| `padding` 等选项里值为 `undefined` 的键会覆盖默认值 | `maxZoom` 变成 `undefined`，中心算出 NaN | 适配器去掉值为 `undefined` 的键 |
| 拖动平移在 `document` 上监听移动 | 自动化工具在画布上的拖动不平移地图 | 验证时直接在画布上派发事件 |

## 七、DOM 浮层与样式图层

测量标签、图钉、位置信息都用 DOM 浮层，而不是 MapLibre 的符号图层：

- 符号图层的文字需要字形文件（中文很大，内网取不到），也做不了可点击的按钮、长按和拖动
- 浮层用视图的 `project` 定位，三维视图同样能提供
- 浮层和画布是兄弟元素：点在浮层上的事件不经过地图，不会触发平移或测量；浮层本身 `pointer-events: none`，只有按钮、图钉等需要交互的元素接收鼠标
- 当前工具不是"移动"时，图钉也不接收鼠标，单击落到地图上
- 按下时 `setPointerCapture`，拖出元素也能收到移动和松开；它要求是"活动的指针"，在浏览器里用脚本模拟时需要临时替换

## 八、取消与晚到的结果

- 每次选择一个 `AbortController`：换选、回到全省、作用域销毁时中止，结果回来后先检查 `signal.aborted`；等视图就绪用 `whenReady(signal)`，选择过期时它也随之结束
- 同一个文件的下载由多次加载共用，不随某一次选择取消；取消的是"等待"和"写入"，不是下载
- 所在区县的判断在拖动时每次移动都发起，用递增的计数只采用最后一次的结果；晚到的成功和失败都要测，前者测了而后者漏了，改坏验证才发现

## 九、交互的状态机与时间

长按拖动有五种输入（按下、移动、到时、松开、取消）和三个阶段（空闲、按住中、拖动中）。把它写成与 DOM 无关的状态机：

- 组件只把指针事件翻译成状态机的输入，把状态机的回调翻译成拥有者的操作
- 状态机用假定时器测试（`vi.useFakeTimers()`、`advanceTimersByTime(500)`），不依赖真实时间
- 拖动开始时记下原位，Esc 或指针被浏览器取消时回到原位（连同来源）
- 拖动结束后浏览器还会派发一次 `click`；状态机只在"按住中"松开时算单击，不需要额外屏蔽

## 十、测试

### 1. 改坏验证的收获

5B 的每一步都做了改坏验证（合计数百处，各模块的数字记在 shared-map.md 等模块文档里）。没被发现的情况可以归成几类：

| 类型 | 例子 | 处理 |
|---|---|---|
| 测试数据区分不了 | 面积的经纬度写反（赤道上的正方形）；只用外包范围判断区县（测试的点刚好落在第一个外包范围对的区县） | 换数据：长宽不等的矩形；外包范围重叠的浦口区 |
| 只测了一半 | 晚到的成功测了、晚到的失败没测；页面只用工具栏关面板、没用面板上的关闭按钮 | 补另一半 |
| 求值方式不完整 | 按状态求值 `filter`，没带几何类型 | 按每个要素的真实几何类型求值 |
| 等价改动 | 叉积整体变号（形心的比值不变）；拾取提示不看当前工具（鼠标位置只在拾取时才有） | 记下原因，不硬写测试 |
| 界面上看不出来 | 拖动时记下的来源 | 由拥有者的测试覆盖，记下原因 |
| 改坏的写法本身有误 | 行尾符不匹配、语法错误、实际没改变行为 | 重写这处改坏；用文件的原始行尾符生成替换文本 |

### 2. jsdom 的限制

- 没有布局：`getBoundingClientRect` 都是 0，悬浮元素的登记测不出来，拖动时的坐标换算要用 `vi.spyOn` 给出矩形
- 没有 `PointerEvent`：用同名的 `MouseEvent` 代替；`ResizeObserver` 不存在，VueUse 的 `useElementSize` 保持 0
- CSS Modules 的类名带哈希、样式不生效：检查"不响应鼠标"只能看类名

### 3. 用假地图走完整条输入链路

页面测试注入一个实现 `MapLike` 的假地图：鼠标事件经过真实的 MapLibre 适配器、工具模型、拥有者、浮层，断言的是用户看得到的结果（标签的位置和文字、输入框的值、图层的叠放）。假地图的投影随相机变化，才能测出"图钉随相机移动"。

### 4. 浏览器验证发现的问题

单元测试没发现、在浏览器里发现的：测距折线下面的填充、工具栏在窄屏伸出屏幕、区划面板的内边距加在宽度外面、`flyTo` 的留白是否留在地图上。验收时用户又发现了按钮激活工具后 Esc 没反应：自动化验证用脚本在画布上派发按键，绕过了焦点，真实的键盘操作才暴露出来。每项能力完成时都在真实地图上走一遍，并截图或用 DOM 测量记下结果。

## 十一、工作方法

- **读旧代码时找出旧 bug**：区划列表的错误代码、"坐标定位"只是占位按钮，都是读代码和对比数据发现的，不是用户报告的
- **交互先做原型**：坐标定位的交互用一个可以操作的原型和用户确认（长按时长可以调着试），再写 ADR
- **性能先实测再优化**：预览线 0.5 ms、市界解析 8 ms，都不需要优化；ADR 里写"先照直实现、实测后再定"，避免预先加复杂度
- **修 bug 先复现**：每个修复都先写出在原实现上失败的测试
- **范围变了就拆**：坐标定位从"加一个输入框"变成完整的位置点能力后，拆成 5B.6 单独设计

## 十二、替代方案汇总

| 领域 | 本项目选择 | 常见替代 | 没选的主要原因 |
|---|---|---|---|
| 天地图配置 | `{ key } \| null` | 开关和 key 两个值 | 每个调用方都要组合判断 |
| 内网部署 | Vite 构建模式 + `.env.intranet` | 代码里判断模式名；运行时配置 | 模式名散落在代码里；没有运行时切换的需求 |
| 能力的组织 | 拥有者（组合式函数 + 纯函数推导） | Pinia store；带开关的全能地图组件 | 生命周期不跟页面；开关越来越多 |
| 边界数据 | `?url` 资源，Worker 解析 | 直接导入 JSON | 打进 JS 包，主线程解析 |
| 交互切换 | 会话的工具模型 | 各交互互相询问 | 互相耦合，新交互要改所有旧交互 |
| 测量计算 | geographiclib（椭球面） | turf（球面）；geodesy（Vincenty） | 精度；Vincenty 个别情况不收敛、没有面积 |
| 标签与图钉 | DOM 浮层 | 符号图层 | 要字形文件；不能交互 |
| 预览线的提交 | 每次移动直接提交 | 按动画帧合并 | 实测 0.5 ms，没有必要 |
| 区划目录 | 标签坐标表 + 一致性测试 | 旧 `region.js`；天地图行政区接口 | 代码有错；内网不可用、需要第二个 key |
| `flyTo` 避开面板 | `offset` | MapLibre 的 `padding` | 会留在地图上 |
| 所在区县 | `@turf/boolean-point-in-polygon` | 自己写射线法 | 洞和多面要自己处理 |
| 位置信息的位置 | 纯函数 | tippy、floating-ui | 锚点随相机每帧移动，需要的只是翻转和不出画布 |
| 长按拖动 | 与 DOM 无关的状态机 | 写在组件的事件处理里 | 难测，要真实时间 |
| 复制 | `useClipboard({ legacy: true })` | `navigator.clipboard` | 内网 http 不是安全上下文 |
