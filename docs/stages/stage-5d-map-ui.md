# 阶段五 5D：地图页界面的专门设计

- 完成日期：2026-10-16
- 相关决策：ADR 0053（地图页的布局与工具栏）、0054（拖动排序用 SortableJS）、0055（地图上的浮层）

5A～5C 的界面只做到能联调：临时骨架、Element 图标，状态和规则都在拥有者、store 和纯函数里。5D 按用户的设计想法，逐块替换这些骨架：先定整体布局和视觉语言（5D.0），再依次做工具栏、资源图层面板、状态栏、各个面板、图例、点选详情、地图上的浮层，最后补上手机宽度并整体验收。

每一块的做法都一样：

1. 出静态 HTML 设计稿（不入库），底图是真实的天地图瓦片，数据是从真实接口取到的记录
2. 把需要用户决定的细节并排画出来，每处给出推荐；用户选定后再实现
3. 需要补的逻辑写在拥有者或纯函数里，和界面一起提交；改了已经接受的 ADR，就新写一份
4. 改坏验证，再在真实页面上按设计稿验收，最后同步文档

本文分两部分：第一部分记录做了什么，第二部分按主题整理可以学到的东西。各块的细节在 [roadmap.md](../roadmap.md) 的"5D 地图页界面的专门设计"，用法在 [modules/shared-map.md](../modules/shared-map.md)，区域和视觉规范在 [design/page-layout.md](../design/page-layout.md) 的"画布型"。

## 改动与目的

### 0. 布局（5D.0，ADR 0053）

- 浮层分三列：左边是资源图层面板；中间上面是两组 Tab 面板（功能面板：区划定位、坐标定位、资源详情；显示面板：图例、底图），下面一行是状态栏和卡片行；最右边一列只放工具栏
- 每组面板同一时间只显示一个内容；打开期间一直挂载，切走时隐藏、`active` 为 false，内容据此结束拾取、取色预览这类临时交互，关闭时才卸载
- 窄屏（小于 1200）时左右只显示最后操作的一边：只推导显示，不改资源面板的收起偏好和右边已打开的功能
- 先拆分面板的外壳和内容，再搭骨架：外壳负责标题、关闭和悬浮元素的登记，内容不再各自登记

### 1～2. 工具栏与资源面板（5D.1、5D.2，ADR 0054）

- 业务组带文字，基础组只有图标；矮屏时业务组只显示图标，提示放在左边
- 放大、缩小每次 ±1，连续点击累计目标级别，被别的相机操作作废后重新开始
- 目录有独立的展示顺序（偏好），地图的叠放顺序只在"已勾选"里调整；拖动用 SortableJS，放下后先还原 DOM，再交给拥有者改顺序，Vue 照常按数据渲染

### 3. 状态栏（5D.3）

- 工具模型在把输入交给当前工具之前发出只读的输入事件，map-vue 按动画帧合并成上下文的 `pointer`；状态栏不再依赖当前工具
- 比例尺取画布中心两侧各 50 像素的两点，按椭球面算距离；放不下时先去掉角度，再去掉经纬度，用隐藏的量尺量出三种排法的宽度
- 核实了天地图的署名要求，按用户的决定不写署名（以后换内网底图），关掉 MapLibre 的版权控件

### 4～5. 面板与图例（5D.4、5D.5）

- 区划定位：格子加当前位置，搜索结果标出关键字；坐标定位：写法切换、拾取的按下状态
- 底图卡铺满缩略图（和底图用同一个地址模板）；行政区的线宽改成"级别 → 线宽"的几档数据，地图上的插值表达式和面板的示意都由它生成
- 图例的预览按参考级别的像素画出线宽、线型和点的大小，有上限；按属性配色的条目显示前三个取值的颜色；改过符号的条目加小圆点

### 6. 点选详情（5D.6）

- 名称和分类按资源取字段（地类、城市现状数据、其他），`-9999`、`-999` 和空字符串算没有值，收在最后
- 被面板挡住时平移：map-vue 的相机控制加了 `reveal(lngLat)`，只在位置真的落进登记元素的方框时平移到可视区域的边上；单击、相机本来不动时使用，等面板按结果渲染以后再量

### 7. 地图上的浮层（5D.7，ADR 0055）

- 测量的单位：不到 1 km 用米，面积取整加千分位；靠近画布右边的标签放到左边，测面的结果放在形心正中
- 鼠标旁的提示 `PointerHint` 测量和拾取共用，画的过程中写出含鼠标所在点的长度或面积，靠边时翻到另一侧
- 位置信息只放在可视区域里（上下文的 `overlayPadding()`），带指向图钉的小三角
- 当前区划条：选中区划后在地图上方写出区划和"回到全省"，登记为贴上边的悬浮元素

### 8. 手机宽度与验收（5D.8）

- 浮层网格的左列可以收缩（`minmax(0, auto)`）：手机宽度时资源面板不超过画布去掉工具栏一列和间距（375 宽时 255），工具栏一列始终在屏幕里
- 地图区域窄于 768 时（`mapPageLayout`）图例卡、底图卡叠到工具栏一列，业务组在放不下两张卡片时提前只显示图标；当前区划条放进中间一列、过长时省略，资源面板展开时不显示
- 区划定位的格子按宽度排列（每格至少 64，桌面上仍是 4 列）；资源面板的页签放不下时在自己的区域里横向滚动，收起按钮始终可见
- 顶部栏：窄屏时导航区 `flex: 1` 的基准是 0，375 宽时"菜单"溢出到 Logo 上，白字落在 Logo 的白底上看不见；改成 `flex: 1 0 auto`，由 Logo 区域收缩

验收的结果（真实页面）：

| 尺寸 | 结果 |
|---|---|
| 1920 × 1080 | 五块区域的位置和间距正确，两组面板同时打开 |
| 1366 × 680 | 业务组只显示图标，和基础组不重叠 |
| 1200、1199 | 1199 起顶部收成"菜单"，导航区占满剩下的宽度、菜单靠右 |
| 1024 × 768 | 打开右侧面板时资源面板收成竖条 |
| 768、767 | 768 是常规排法；767 起卡片叠到工具栏一列；地图区域 925 高时业务组仍显示文字 |
| 375 × 812 | 资源面板 255 宽，工具栏、卡片、基础组都在屏幕里，没有横向滚动；区划定位 215 宽、格子 2 列；区划条省略成"苏州市 › 张…"；"菜单"看得见 |

各块的功能（点选、框选、测量、坐标定位、区划定位、面板挡住时平移、位置信息让开面板）在 5D.6、5D.7 的验收里走过，新开的标签页没有控制台错误。

这三步里学到的：

- MapLibre 的鼠标手势只在按下时判断一次是哪种手势。要改变按住某个修饰键时的行为，只能在它之前（捕获阶段）截下这次按下，开关它自带的手势做不到：拖动平移本身就不认 Ctrl
- MapLibre 的级别按 512 像素的瓦片算，同一级别下画面覆盖的范围是 256 像素瓦片的一半；圆头虚线的圆头画在线段外面，和 SVG 的 `stroke-linecap: round` 一样
- 线型的设计稿直接用真实的引擎和数据画，在设计阶段就发现了问题：市界和省界共用的边顶点一致，实线能盖住、点划线不能；县界和市界不重合；紫色的省界和天地图的高速公路撞色

# 第二部分：可以学到什么

## 一、设计稿先行

- **静态 HTML，不入库**：放在 `public/design.local/`（`*.local` 被忽略），用模板加构建脚本生成（填入图标和天地图的 key）。比画图工具快，样式和真实页面同一套令牌，用户直接在浏览器里看
- **真实瓦片、真实数据**：点选详情的稿子用接口取到的消防站、坑塘、村级调查区，才发现 `-9999` 占满了城市现状数据的字段、村级调查区的名称在 `zldwmc`；测量的稿子按椭球面算出数值，才看出"981323.07 m²"难读
- **并排画出选项，给出推荐**：每块 3～4 处细节，用户可以一次说"都按推荐"，也可以逐条回复。推荐要写理由，没选的方案写清楚问题
- **设计稿也要验收**：生成以后在浏览器里看一遍，几次发现稿子本身的问题（示意面板太淡、卡片放不下度分秒、超出小框）

## 二、界面与逻辑解耦的回报

- 5A～5C 把当前工具、面板开关、失败原因都做成了数据，5D 替换界面时拥有者基本不动，测试也大多不用改
- 需要补的逻辑是"界面才暴露出来的能力"：鼠标位置（`pointer`）、被挡住时平移（`reveal`）、可视区域里的摆放。它们放在 map-vue 或纯函数里，界面只调用
- 界面上的判断尽量写成纯函数：标签放哪一边（`labelSide`）、提示翻不翻（`pointerHintSides`）、状态栏的取舍（`fitStatusLayout`）、页面的排法（`mapPageLayout`）。组件只把量到的尺寸交给它们，测试不依赖布局

## 三、布局与 CSS 的几个坑

- **flex 的基准**：`flex: 1` 的基准是 0%，加 `flex-shrink: 0` 也不会按内容撑开；要按内容宽度又能长大，写 `flex: 1 0 auto`（顶部栏的"菜单"）
- **grid 的 auto 列不会收缩到内容以下**：`auto` 的最小值是内容的最小宽度，固定宽度的面板会把工具栏挤出去；`minmax(0, auto)` 才能收缩，宽屏时仍按内容宽度
- **`writing-mode` 加在 flex 容器上会改变主轴**：竖排的容器里 `column` 是水平方向，只让文字竖排（资源面板的竖条）
- **简写会覆盖别处的单边设置**：`margin: 4px 0` 盖掉了地类图例给的 `margin-left: -20px`，改成 `margin-block`
- **`box-sizing` 影响宽度的计算**：滑块带内边距时没有 `border-box` 会压到旁边的百分比
- **滚动容器会连带裁掉另一个方向**：页签区横向滚动后，当前页签下面的横线被裁掉，要留出内边距
- **层级跟随手势的元素**：鼠标旁的提示放到面板上面一层是安全的，因为鼠标移到面板上时画布收不到移动，提示自己会消失

## 四、浮层的摆放

| 浮层 | 规则 | 依据 |
|---|---|---|
| 测量标签 | 只看节点的位置：离右边不到 160 时放左边 | 不量标签，规则稳定、好测 |
| 鼠标旁的提示 | 按量出的提示尺寸，放不下时翻到另一侧 | 提示的内容随鼠标变化，长度不固定 |
| 位置信息 | 限制在可视区域（画布去掉登记的悬浮元素）里，小三角跟着图钉 | 和定位用同一套 padding，面板变化不用另外处理 |
| 被面板挡住的点 | 落进元素的方框（含间隔）才平移，平移最少的距离 | 平时点地图不动；只看方框，点在矮面板下面不算挡住 |

## 五、测试

- **改坏验证**：每块 7～26 处，都要求失败原因是断言。几次因此补了断言（"最后一级也能点"起初只让测试报错）、换了观察方式（预览组件单独测、测量标签加 `data-side`）
- **CSS Modules 的类名不适合做断言**：测试里用 `data-*`（`data-empty`、`data-side`、`data-edited`、`data-map-page`）
- **jsdom 没有布局**：尺寸相关的逻辑用 `ResizeObserver` 替身手动给出尺寸（状态栏、手机宽度的页面）；真正的位置和重叠在浏览器里验收
- **页面级的测试检查接线**：纯函数测规则，页面测试只确认结果交给了组件（卡片在哪一列、工具栏是否只显示图标、区划条是否显示）

## 六、工作方法

- **一块一提交**：设计稿确认后实现、验收、写文档，用户说提交再提交
- **验收时发现的问题当场分清归属**：顶部栏的"菜单"是第 3 阶段的问题，作为待选细节让用户决定是否在 5D.8 一起修
- **偏离设计稿要说明**：停在面板左边 16（稿子写 24）、单击时"范围太复杂"的说法、区划条在手机宽度的位置，都在提交前说明理由

## 七、替代方案汇总

| 领域 | 本项目选择 | 常见替代 | 没选的主要原因 |
|---|---|---|---|
| 设计稿 | 静态 HTML，真实瓦片和数据 | 画图工具；直接改代码看效果 | 画图工具和真实样式有差距；直接改代码返工多 |
| 右侧面板 | 两组 Tab 面板 | 每个功能各自一块面板 | 同时打开几块时互相挤压、位置不固定 |
| 拖动排序 | SortableJS，放下后还原 DOM | `@vueuse/integrations` 的 `useSortable`；自己写指针事件 | 前者直接改数组；后者要自己处理滚动和边界 |
| 鼠标位置 | 工具模型的只读输入事件 | 状态栏自己监听画布 | 和当前工具耦合；视图切换时要另外处理 |
| 署名 | 不写（换内网底图） | MapLibre 的版权控件 | 控件和基础组位置冲突；数据源没写署名 |
| 被挡住时平移 | 落进方框才平移 | Leaflet 的 `panInside`（进了留白就平移） | 点在画布边上也会动 |
| 测量的单位 | 不到 1 km 用米，面积取整 | 沿用旧项目的 km 两位小数；面积用公顷 | 几百米显示成"0.35 km"；公顷对多数用户不直观 |
| 选中区划的显示 | 上方的区划条 | 区划中心的名称标签（旧项目） | 和天地图注记重复，也没有回到全省的入口 |
| 手机宽度 | 悬浮面板变窄 | 底部抽屉 | 要另做一套外壳和手势，抽屉会挡住地图和基础组 |
