# 3D.3b：MVT 数据、Worker 绘制与缓存

状态：实现与本步验收完成（2026-10-19）。本步沿用 [ADR 0021](../adr/0021-worker-strategy.md)、[ADR 0025](../adr/0025-worker-contract-and-tile-data-service.md) 的分层与通信契约；用户已确认受限 Worker 子入口，见 [ADR 0066](../adr/0066-mvt-worker-runtime-boundary.md)。业务页三维入口仍未开放。

## 设计与实现边界

会话仍是二三维共用的唯一样式来源。MVT 的 fill、line、circle 与 GeoJSON、栅格进入同一影像集合；不改资源勾选、年份或符号拥有者，也不另外实现样式表达式求值器。下载、解码和缓存属于 map-core，OffscreenCanvas 绘制属于 map-cesium，通信复用 utils 的 WorkerHost / serveWorker。

| 模块 | 本步职责 |
|---|---|
| `map-core/tile/tile-identity.ts` | 模板、scheme、数据版本、权限范围与原生 XYZ 身份；显示瓦片到父瓦片的换算 |
| `map-core/tile/mvt-decode.ts` | 使用 vector-tile / pbf 解码，裁剪属性，保留 extent、ID、buffer 与多部件几何 |
| `map-core/tile/tile-data-service.ts`、`byte-cache.ts` | 消费者共享、独立取消、字段并集重解、字节预算 LRU 与统计 |
| `map-core/worker.ts` | 唯一受限 Worker 子入口，不导入 DOM 或 MapLibre |
| `map-cesium/style-fields.ts`、`canvas-renderer.ts` | 规范表达式树字段提取；GeoJSON 与 MVT 共用基础绘制语义 |
| `map-cesium/mvt-provider.ts`、`mvt-worker-pool.ts` | 影像任务、稳定分片、容量约束、暂停恢复与释放 |
| `map-cesium/mvt-worker-handler.ts`、`mvt-render.ts`、`mvt.worker.ts` | Worker 内取得数据、按目标子块重画、转移位图与返回统计 |

直接声明已经随 MapLibre 安装的 `@mapbox/vector-tile` 3.0.0 和 `pbf` 5.1.2，不自行编写 MVT 解码器。Worker 的独立 tsconfig 只使用 WebWorker 环境；允许 `@yzt/map-core/worker` 是对单入口规则的明确例外，不能把同名别名按环境偷偷指向不同代码，也不能混入 DOM 类型绕过检查。

## 支持范围

支持显式 `tiles` 模板的 vector 来源，XYZ/TMS、minzoom/maxzoom、bounds、attribution，以及非空 `source-layer`。`promoteId` 支持单字段名或按来源层指定字段名；缺失属性时不回退原始 ID，布尔身份按 MapLibre 语义转换为数字。TileJSON、尚未实现的来源选项或样式属性继续逐层诊断。

数据的 minzoom 与 SDK 的影像起始级别分开：影像从 0 级开始，低于来源 minzoom 时返回本地透明祖先、不下载或启动 Worker。业务来源可只设置较高 minzoom 而不提供 bounds，不能因此要求先铺满全球的高等级瓦片或修改业务配置。

有限 bounds 由提供者内部过滤和裁剪，向 SDK 声明完整 Web Mercator 范围。这样避免 Cesium 26.3 对局部影像边缘求交时的浮点缺陷：地形与影像本应贴边，却形成极小交集，SDK 修正列号后把空交集继续投影并抛错；保留原来的高 minimumLevel 也不能彻底解决。范围外只返回透明画布，不下载 MVT；边缘瓦片按 bounds 裁剪，跨 180° 范围拆成两段处理。代价是可视区域内的数据范围外仍有透明影像，内存与快速平移成本留到 3D.4 一并测量。

MVT 保留各来源层自己的 extent，不默认所有瓦片均为 4096。几何用 Int32 路径保存，接受合法的瓦片外 buffer 坐标，避免 Int16 截断；多个外环与孔洞由成熟解码库分类，填充时分别处理每个面及其洞。样式仍由 style-spec 按相机的真实级别、要素类型、属性和身份求值。

显示级别超过来源 maxzoom 时，同一原生父瓦片供所有子块复用。Worker 根据 extent、父子比例和子块偏移重新绘制 512 像素纹理；线宽与点半径按相机级别补偿，不把父级位图直接放大。MVT 与 GeoJSON 共用 Canvas 绘制器，完整路径交给画布裁切，保持原有孔洞、透明度与端点规则。

## 缓存、并发与资源所有权

初始参数为每个三维视图最多 2 个惰性 Worker、总计 64 MiB 驻留数据预算、16 个未完成绘制请求、每个 Worker 最多同时处理 4 个任务。预算平分，父瓦片完整身份经确定性散列分配线程；不维护无限增长的归属表。参数均可配置，目前只作为有界的初始值，尚未由省域压力场景确定最优值。

同源样式、过滤与 promoteId 的字段需求取并集。普通表达式按静态字段名裁剪；动态字段名或整属性对象读取才使用 `fields: null`。并集扩大时复用缓存中的原始 PBF 重解，颜色修改而字段不变时直接复用解码结果。来源仍有缓存或任务时字段只增不减；最后一份驻留数据和任务消失后清理字段登记，防止切年份累积元数据。

相同数据身份共享下载和解码，每个消费者的取消只影响自己，最后一人离开才中止底层任务。失败不缓存；200 的合法空瓦片可以缓存。LRU 统计原始 PBF 字节、TypedArray 字节及几何/属性对象估算，命中刷新最近使用顺序；超过整个预算的单瓦片可以完成当前任务，但不驻留，不永久突破预算。预算不包含正在解码和绘制的工作集、Canvas、位图或 Cesium 纹理，不能等同于进程总内存上限。

解码缓存始终留在 Worker，不转移给主线程。绘制器按 256 顶点和 64 要素的批次让出事件循环，等待后重新检查信号；第三方单次 `loadGeometry()` 的同步工作无法从外部打断。一次性 ImageBitmap 转移后 Worker 不再保留，取消或过期的产物关闭。主线程收到有效位图后复制到 Canvas，并在 finally 中立即关闭位图，再把 Canvas 交给 Cesium；不依赖 SDK 未提供的纹理上传完成释放回调。

暂停、图层隐藏、provider 替换和销毁会取消对应任务。暂停保留已完成缓存，恢复重新请求被取消的影像；首次 inactive 候选仍完成首帧准备后再暂停。释放视图终止 Worker 和缓存，不建立跨用户全局池，也不增加持久化缓存。Worker 异常按现有通信层契约结束等待并有限重建。

当前公开 Cesium API 不能逐个通知活动平移中被丢弃的瓦片；不能调用私有 RequestScheduler 方法或读取私有取消状态。此类任务可能继续到完成才回收，未完成任务数量由池限制；容量不足时 provider 返回 undefined，SDK 稍后再请求。持续平移、缩放、多来源与复杂样式下的取消延迟、吞吐和内存工作集留给 3D.4 验收。

## 自动化验证与改坏记录

自动化使用本地合成 PBF，不访问后端或天地图。开发页加入同一份合成 MVT，并保留二三维切换、变色、显隐、重排、暂停、失败恢复及销毁入口。

本步测试覆盖：

- 数据身份、原生父瓦片换算、extent、字段裁剪、ID、安全整数、buffer、多部件及孔洞；下载去重、字段扩大重解、独立取消、晚到下载、合法空响应、失败不缓存、LRU 与来源元数据清理
- 主线程池的惰性创建、稳定分片、预算平分、并发上限、暂停与释放；Worker 处理函数的预算一致性及异步返回后的取消检查
- 真实 OffscreenCanvas 的孔洞、多外环透明合成、跨子瓦片接缝及超采样的点线尺寸；真正 Worker 的下载、绘制、ImageBitmap 转移和关闭
- 真实 Cesium 中 MVT、栅格与 GeoJSON 混排，以及重排、变色、显隐和暂停恢复后的层序

绘制部分的定向结果：14 项单元测试通过（包含原有 GeoJSON 的 3 项），新增 3 项 OffscreenCanvas 浏览器测试通过，原 GeoJSON 的 9 项浏览器回归通过。最终全量回归见下方“最终集成验证”。

已完成的绘制改坏验证：把长路径 checkpoint 间隔改到不触发后，取消用例出现“Promise resolve 而非 reject”的断言失败；把父子坐标比例固定为 1 后，绘制起点从预期 `(0, 256)` 变成 `(-256, 128)`；移除等待绘制返回后的取消检查后，关闭晚到位图用例出现“Promise resolve 而非 reject”的断言失败。三处均恢复后重新通过。

数据与集成层也执行了断言改坏验证：停止来源字段登记回收后出现“来源应为 1、实际 2”；不平分线程预算后出现“应为 2048、实际 4096”；忽略样式字段或拒绝全部 vector 来源后相应用例失败；将 provider 传入的相机级别加 1 后，真实 Worker 的预期红点变成蓝点。所有临时修改均恢复。真实 Worker 测试还发现原生 fetch 被错误绑定到服务实例的问题，先加回归断言再修复；高 minzoom、无 bounds 的合法业务来源被拒绝也先由回归断言复现，再改为透明祖先。

范围修复补充 2 项单元测试，以及高 minzoom、局部 bounds、跨 180° 和真实 Cesium 首屏的浏览器用例。故意移除 Canvas 裁剪后，局部范围和跨经线两项均因范围外像素由透明变绿而断言失败，恢复后 provider、Cesium 混排和开发页共 11 项真实浏览器用例全部通过。独立只读复核确认裁剪使用显示瓦片坐标，父瓦片坐标只负责下载与缓存复用。

## 独立真实瓦片只读实测

2026-10-19，从已有代理配置确定地址，匿名只读 GET `bgdc_dltb_2022/14/13598/6650.pbf`，设置 15 秒超时；返回 HTTP 200。未使用登录凭据，未保存原始 PBF 或属性值，也未把请求地址中的环境信息写入记录。

| 输入 | 结果 |
|---|---|
| 原始数据 | 70,995 字节 |
| 面要素 / 顶点 | 301 / 8,715 |
| SHA-256 | `840078740027173d6f6c92458081d779891298642415567d1c1c6ef68c4d19c0`，与 3D.0 一致 |
| 匿名下载耗时 | 约 774 ms，单次观测 |
| 绘制属性 | 常量填充，`fields: []`，不保存业务属性 |

用无配置的 Vite 库构建把实际 `mvt.worker.ts` 编译为单文件 IIFE，在 Chromium 空白页通过 Blob Worker 运行。真实 PBF 仅在内存中转成 data URL 交给新管线，主线程使用实际 MvtWorkerPool；没有启动 dev/start 或 HTTP 服务。临时脚本与构建产物放在忽略目录 `apps/web/node_modules/.tmp/mvt-measure/`。

按 1、2、2、1 个 Worker 的配置顺序，各执行一次冷绘制、三次热绘制，以及同一父瓦片的四个显示子块并发绘制：

| 观测 | 结果 |
|---|---|
| 首次绘制 | 32.1～46.1 ms |
| 热绘制 | 6.6～8.6 ms |
| 四个子块并发绘制 | 17.5～18.6 ms |
| 非透明像素 | 父瓦片及每个子块均为 262,144，热绘制与首次一致 |
| 每轮 Worker 统计 | 下载 1 次、解码 1 次、命中 7 次、未完成任务 0 |
| 驻留缓存 | 211,439 字节，包含原始与裁剪后的解码数据 |
| 预算仅 1 字节的附加实验 | 连续两次绘制均成功；下载/解码各 2 次，驻留字节、瓦片和来源数均为 0 |

由于四个子块属于同一个父瓦片，稳定分片让配置 1 个或 2 个 Worker 时都实际只创建了一个线程；上述时间差不能证明增加线程的收益，也不能用于认定初始数量最优。首次与热绘制时间从内存数据请求开始，包含 Worker 管线与位图返回，不包含前面的真实网络下载或 Cesium 纹理上传。实验没有执行业务分类样式、全省浏览或连续交互；它只证明这一张真实瓦片能够被新管线绘制、复用和按预算回收。

## 最终集成验证

最终 `pnpm test` 通过：图标包 35 项、web 1836 项，合计 1871 项（199 个文件），包含真实 Chromium 的 Worker、Cesium、MapLibre 与开发页回归。`pnpm typecheck`、`pnpm lint`、`pnpm build` 和 `pnpm build:intranet` 全部通过。

另外使用 Vite 库构建独立编译开发页、二三维运行时与画布，确认生产路由排除的三维实现也能构建，MVT Worker 输出为独立的约 150.28 kB 文件。未启动本地 dev/start 服务。既有的 sm-crypto-v2 浏览器兼容提示与大分块提示仍保留；产物检查通过。

业务三维入口、完整业务样式与省域性能尚未验收；本步通过不代表这些后续工作完成。

## 本步知识点与下一步

- Worker 的环境边界不只影响运行，也影响类型检查；受限入口防止 DOM 实现经公共索引流入 Worker
- 数据下载/解码缓存与每次绘制产物拥有不同的生命周期，转移所有权不能破坏仍被其他消费者复用的缓存
- 原生数据级别、显示瓦片级别和相机级别各有职责，父矢量重画能保留清晰度，但仍需要测量持续缩放下的工作量
- 共享请求的取消按消费者计数；取消某个调用方不等于取消所有使用方，也不等于同步计算已经立即停止

下一步 3D.3c 完成剩余业务样式，包括花纹、虚线、高亮与区域遮罩；复杂图层、持续交互、真实业务样式和省域性能随 3D.4 综合验收。当前不开放业务页三维切换。
