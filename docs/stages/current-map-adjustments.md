# 现状底图的调整

- 完成日期：2026-10-28
- 相关决策：ADR 0094～0097

用户 2026-10-28 提出一轮现状底图的优化，分整体、二维、三维三部分，要求可以直接调整的按要求实施，涉及重新设计的布局或交互先出方案确认。开工前就几处歧义问了用户：批量年份固定加上 2020、2021；资源树和"已选择图层"仍是两份顺序；状态栏固定在左下角；"外部路线新增功能"指预置路线的选择。

按这些回答分成 7 步：前三步是直接调整和小的布局改动，第 4 步给漫游改版做可操作的原型，用户确认后第 5、6 步实现，第 7 步收尾。每一步都在真实页面上验证、逐处改坏被测代码，用户验收后提交。各步骤的状态在 [roadmap.md](../roadmap.md) 的"现状底图的调整（2026-10-28）"，确认过的界面细节在 [current-map-reference.md](../design/current-map-reference.md)。

## 改动与目的

### 1. 直接调整（ADR 0094）

- 复合图例默认展开：原来记"展开了哪些"，改成记"收起了哪些"（`collapsed`），新出现的复合图例自然是展开的
- 没有勾选任何图层时，再次进入资源树默认展开全部分类（`expandedByDefault`）；有勾选时仍只展开勾选所在的分类
- 批量年份固定加上 2020、2021：目录里没有这一年数据的资源保持原样；一个资源都没有时提示"没有资源有 2021 年的数据，图层保持不变"，`withYearForAll` 不再因为没有数据而抛错
- 三维：苏州站的名称改成"星海广场站"（清单），已加载列表去掉最近定位的蓝条，"回到起始点"，步行默认 4 m/s

### 2. 状态栏移到左下角（ADR 0095）

状态栏从地图底部居中移到左下角，左列用 `padding-bottom` 固定留出状态栏的高度和一档间距，面板不会盖住它。没有选按实际高度留：状态栏的高度是固定的，量出来再排版要多一轮渲染，量到之前会跳一下。地下空间时状态栏和视图控件一起隐藏，左列不留这段（`.noStatus`）。

### 3. 上移、下移（ADR 0096）

- 资源树和"已选择图层"是两份顺序（用户选定）：树里的上移、下移只改目录里的顺序，"已选择图层"里的才改地图上的层级。按钮的说明写清是哪一种（"目录里上移：名称"、"上移一层：名称"）
- 按钮宽 18、树的拖动手柄 16：在真实目录的 66 个资源里比较过，24 宽时有 8 个名称被省略，改成 18 以后剩 3 个
- 移动后列表按新顺序重新渲染，焦点交回同一个资源的同一个按钮（`focusMoveButton`），键盘可以连续移动；到顶、到底时按钮不可用

### 4. 漫游改版（原型，ADR 0097）

改动较大，先在 `/dev/map-3d` 做了能操作的原型：已加载的模型右侧一个"漫游"按钮（代替"步行漫游""路线漫游"两个入口），开始漫游后左侧的模型面板换成漫游面板（步行和路线在里面切换，路线从预置的几条里选），路线漫游也显示小地图，没有单独的钻地。用户按默认确认：路线速度统一用米/秒，路线漫游能打开完整地图但不能瞬移，地下的模型保留定位。

### 5. 漫游面板（第 5 步）

- 路线的意图从倍速（`rate`，乘一个固定的基准速度）改成米/秒（`speed`），和步行共用一组档位（`ROAM_SPEEDS`，默认 4 m/s）；档位从 map-core 移到 feature：选哪几档是业务的事，内核只按给的速度走
- 拥有者加 `startRoam`、`setRoamMode`、`setSpeed`：入口只有一个，方式和速度在面板里改，换方式时速度沿用
- 漫游期间只留漫游面板和小地图：模型面板换成漫游面板（`KeepAlive` 不缓存 `RoamPanel`，退出后模型面板原样回来），不能勾选别的模型、不能切二维
- 顺带发现的问题：浮层里几个区域按条件出现，开始漫游时有的出现、有的消失，没有 key 的 `div` 被 Vue 按位置配对，左侧面板的 `KeepAlive` 被配到别的 `div` 上重建，搜索文字、展开状态都丢了。进入地下空间、窄屏时换边也会触发，是原来就有的问题。给浮层的每个区域加 key，页面测试检查开始、退出漫游后搜索文字还在

### 6. 去掉单独的钻地（第 6 步）

- 拥有者不再有钻地的状态和地表透明度的操作：场景内容由漫游推导，漫游地下的模型时就是地下空间（地表固定 25% 不透明、不显示地面上的模型），退出漫游就回到地面。原来"退出漫游后还在钻地，要再点一次退出钻地"的中间状态不存在了
- 导航网格按模型建（`NavigationBuild` 带模型 ID），步行和路线共用：同一个模型上换方式时接着建，换模型才停下重建；路线只给室内的模型建（为了小地图）
- 路线漫游的小地图和完整地图：`route-track.ts` 把路线和人换到导航网格的局部系，人的位置按走过的米数从路线上取；只画落在当前楼层上的部分。整条路线是细虚线、走过的一段是粗实线，都垫一层白色描边：在按区域着色的平面图上，单独一条主色细线几乎看不出来
- 路线漫游时打开完整地图：路线暂停，关上时打开前在播放就接着播放（`routeMap` 记下 `resume`），打开期间空格不让路线走；双击只提示"路线漫游时不能瞬移"
- 实测更正 ADR 0097 的一处说法：没有钻地时 Cesium 不按地表遮挡（`depthTestAgainstTerrain` 只在地下空间打开），定位地下的模型从上方就看得到它。ADR 接受后不改，更正记在 roadmap 和 current-map-reference

### 7. 收尾

三维的生产冒烟在第 5、6 步已跟着改成新的入口（点"漫游"步行进站、Esc 退出漫游回到地面、再回到二维）；收尾时跑全部的检查和生产冒烟，改掉测试名和文档里过时的"倍速""退出钻地"，写本文。

# 第二部分：可以学到什么

## 一、默认值的表示：记例外，不记全部

"默认展开"如果记"展开了哪些"，每出现一个新的复合图例都要有人把它加进集合，忘了就是收起的。改成记"收起了哪些"，集合里只有用户主动做过的选择，默认值由"不在集合里"表达，新来的自然是默认。同样的思路：资源树在没有勾选时全部展开，判断的是"有没有勾选"这一事实，而不是另存一个"首次进入"的标志。

## 二、固定的留白和量出来的留白

状态栏的高度是令牌和固定的行高决定的，左列直接按它留白。按实际高度留要先渲染、再量、再排版，第一帧会跳一下，被缓存的页面恢复时还要防着量到 0（AGENTS.md 的 `useShownElementSize`）。尺寸能从规范推出来时就不要量；真正随内容变化的（如功能面板的高度）才量。

## 三、两份顺序，各管各的

资源树的顺序是"目录里怎么排"，"已选择图层"的顺序是"地图上谁压着谁"。合成一份看起来省事，但目录有分类、地图只有勾选的那些，一个里的"上移一格"在另一个里没有明确的含义。保持两份，按钮的说明写清改的是哪一份。上移、下移是拖动的补充：拖动要按住手柄，键盘和精确移动一格靠按钮；移动后焦点留在同一个资源的按钮上，键盘用户才能连续操作。

## 四、在意图里用用户看到的单位

路线原来记倍速，乘一个固定的基准速度才是米/秒；步行记的是米/秒。合并成一个面板后两种方式要共用速度，倍速就成了翻译层：面板要换算，换方式时要换算，基准速度改了以前存的倍速就变了含义。改成意图里直接写米/秒，内核只管"按这个速度走"，档位属于业务，从 map-core 移到 feature。跨三层改一个字段时一次改完、一起验收，不留兼容的旧字段。

## 五、Vue 怎样配对没有 key 的兄弟节点

模板里的 `v-if` 由编译器加上标记和 key，TSX 没有这一步，Vue 对子节点做完整的比较：先从两头逐个对齐，中间剩下的部分里，没有 key 的旧节点和第一个还没配上的同类新节点配对。一个区域按条件出现时，两头对齐就够了；几个区域同时变化时（开始漫游时有的出现、有的消失），中间的 `div` 就可能和不是同一个的 `div` 配上，里面的组件因为类型不同被卸载重建，`KeepAlive` 在被重建的子树里时缓存一起丢掉。每个区域给 key 以后，配对按身份而不是顺序。这个问题在漫游以前就有（进入地下空间、窄屏时换边），只是没人注意到搜索文字没了；页面测试从"状态还在"这个结果断言，比检查 DOM 结构可靠。

## 六、能推导的就不要另存

钻地原来是拥有者的一份状态，漫游地下的模型时打开，退出漫游不关，于是有了"不在漫游、仍在钻地"这个用户没要的中间状态，还得给它一个退出按钮。改成从漫游推导之后，状态的组合少了一半，"退出漫游同时退出钻地"不用写成一条规则，它就是推导的结果。判断标准：一份状态如果总能由另一份决定，就不要单独存。

## 七、按身份缓存进行中的工作

导航网格要建好几秒。步行和路线都要它，用户可能在同一个模型上来回切换方式：如果每次开始漫游都重建，切一次就白等一次。给进行中的构建带上模型 ID，开始漫游时同一个模型的构建接着用，换了模型才停下重建。和查询缓存按 key 复用是同一个道理，只是这里缓存的是一个进行中的 Promise。

## 八、暂停时记下"原来在不在播放"

打开完整地图要暂停路线，关上时要恢复，但"恢复"不等于"播放"：用户原来就暂停着，关上地图不该自己走起来；路线已经走完也不该重新开始。所以暂停时记下打开前的状态（`resume`），关上时按它和当时的阶段决定。同样的问题在任何"临时接管、之后交还"的场合都会出现。

## 九、原型上的说法也要实测

ADR 0097 写的是"没有钻地时地下的模型被地表挡住，所以保留定位"，实测发现 Cesium 只在地下空间打开按地表遮挡，从上方看得到它。结论（保留定位）没变，理由错了。ADR 接受后不改，更正写在 roadmap 和设计参考里，以后读 ADR 的人顺着链接能找到。

## 十、替代方案汇总

| 领域 | 本轮选择 | 常见替代 | 没选的主要原因 |
|---|---|---|---|
| 默认展开 | 记收起了哪些 | 记展开了哪些，新来的手动加入 | 新出现的条目容易忘了加 |
| 状态栏的留白 | 按令牌固定留出 | 量状态栏的实际高度 | 多一轮渲染、第一帧会跳；高度本来就是固定的 |
| 上移、下移的顺序 | 两份顺序，按钮写明改哪份 | 树和"已选择图层"共用一份 | 目录有分类、地图只有勾选的，"上移一格"含义不同（用户选定） |
| 路线的速度 | 意图里直接写米/秒 | 保留倍速，面板换算 | 换方式、改基准速度时都要换算，存下的值含义会变 |
| 钻地 | 从漫游推导 | 保留钻地的状态，退出漫游时顺手关掉 | 两份状态要靠规则保持一致，漏一处就有中间状态 |
| 导航网格 | 按模型复用进行中的构建 | 每次开始漫游重建 | 在同一个模型上换方式要白等几秒 |
| 路线在平面图上 | 细虚线 + 粗实线，垫白色描边 | 只画一条主色细线 | 按区域着色的平面图上看不出来 |
| 浮层区域（TSX） | 每个区域给 key | 不给 key，或把条件渲染改成 `v-show` | 按位置配对会重建 `KeepAlive`；`v-show` 让隐藏的区域仍挂载着，里面的组件（小地图、工具栏）照常运行 |
