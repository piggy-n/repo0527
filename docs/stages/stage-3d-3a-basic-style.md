# 3D.3a：基础图层样式

状态：已完成（2026-10-19）。已确认统一影像层方案，见 [ADR 0065](../adr/0065-basic-geojson-imagery-layers.md)。本步只接入基础样式，不开放业务页三维切换；MVT、花纹、虚线、高亮与区域遮罩仍按 [3D.0 计划](stage-3d-0-plan.md) 分步推进。

## 设计边界

会话仍拥有完整样式。三维按 `StyleModel.current.layers` 的顺序镜像，不读取二维引擎，也不复制资源勾选、年份或符号状态。求值与绘制分开：`style-expression` 使用已有 style-spec 库，`style-plan` 校验支持范围，`style-mirror` 管同步与释放，实际绘制由窄接口承接。

相机级别用于属性求值、过滤与 `[minzoom, maxzoom)` 显隐；不能用影像瓦片的层级或取整后的级别替代。暂停期间不写引擎，恢复时只应用最新会话；排序保留未改变的图层实例，样式或数据源替换只重建受影响图层。

## 基础支持清单

支持范围以实际绘制能力收敛，完成状态见验证记录。

| 类型 | 本步属性或输入 |
|---|---|
| 通用 | 常量 `visibility`、`minzoom`、`maxzoom`；规范库的属性表达式与过滤器 |
| background | `background-color`、`background-opacity` |
| raster | `raster-opacity`；`tiles`、XYZ/TMS、尺寸、级别、范围、署名 |
| fill | `fill-color`、`fill-opacity`、`fill-outline-color`；`fill-antialias` 仅允许 true |
| line | `line-color`、`line-opacity`、`line-width`；`line-cap`、`line-join`、`line-miter-limit` |
| circle | 半径、颜色、不透明度，以及描边宽度、颜色、不透明度 |
| GeoJSON | 会话内联的点、线、面及其 Multi 类型、GeometryCollection、孔洞；属性与要素身份供规范库求值 |

未支持的图层、属性、数据源选项或表达式上下文明确报出对应图层并跳过该层，其他层继续；不将花纹改成纯色、虚线改成实线。暂不提供 URL GeoJSON、TileJSON、聚合、自动生成身份、feature-state、图片或瓦片几何表达式上下文。显式样式过渡只允许零时长、零延迟。

栅格请求使用 Cesium 的公开提供者和请求调度，保留节流返回值与取消对象，不绕过 SDK 用 DOM 图片重试，也不吞掉下载失败。最小级别覆盖范围超过 SDK 推荐的 4 块瓦片时明确拒绝，不擅自降低数据源级别。

## 已确认的绘制选择

Cesium 原生点线面图元不能与影像层任意穿插，旧项目的 GeoJSON 实体始终在全部影像之上；这会影响当前“底图 → 面图层 → 注记”的顺序。用户已确认将基础 GeoJSON 绘制成透明影像，与栅格使用同一层序；代价是需要验证像素尺寸、清晰度和接缝。

渲染器使用透明的全球底层影像，阻止 Cesium 把局部影像边缘延展到全世界。每个样式层各有影像，改变顺序只移动影像；GeoJSON 缩放时按新的相机级别重绘并释放旧影像，透明度或显隐不另存业务状态。完整路径交给画布裁切，不在瓦片边界增加线端点或多边形闭合边。

几何限于 Web Mercator 有效纬度，跨 180° 经线和世界遮罩明确拒绝。Canvas 的抗锯齿与球面透视允许存在像素差异，关闭抗锯齿和显式 `line-round-limit` 暂不支持；三维圆点与线随地表透视变化，不能视为屏幕浮层。当前同步 Canvas 绘制面向基础小样，大数据绘制与缓存预算仍在 3D.3b。

## 集成验证结果

2026-10-19：完整回归通过，icons 35、web 1764，共 1799 个用例，本步新增 110 个。类型检查、lint、公网构建、内网构建和三维开发页独立构建全部通过。构建仍有既有的 `sm-crypto-v2` 浏览器模块提示和大分块提示；没有新增依赖。

真实 Chromium 使用本地数据验证了以下行为：

- 透明画布的孔洞、分类颜色、过滤、Multi 与几何集合、透明度、线宽和圆点半径；相机级别与瓦片级别不同时仍按预期像素尺寸绘制，跨瓦片边界没有新增端点或闭合边
- 真实 Cesium 场景的栅格 → 面 → 栅格叠放、重新排序、背景覆盖、变色、显隐、来源替换与局部覆盖不向全球延展
- 视图暂停后只在恢复时应用最新样式；尺寸变化引起级别重算时，稳定事件等待新样式画面，不能读取上一帧
- 默认三维加载器收到不支持图层的诊断后仍保持 ready；开发页来回切换、隐藏期间变色与排序后仍使用同一个会话，定位、失败重试和释放重建继续通过

故意改坏求值级别、笔宽换算、图层顺序、调色板、会话样式传递和诊断处理后，测试均出现预期断言失败，恢复后通过。回归测试还先复现并修复了跨经线栅格范围被截断、透明底层图片无效、Canvas 忽略零斜接限制、画布异常误报整体渲染失败、样式修正残留来源错误，以及旧帧过早发出稳定事件的问题。

全量运行曾两次仅在首次渲染等待上限内未就绪，单独运行通过。浏览器测试改为按文件顺序执行，避免软件 WebGL 场景争用资源；关键三维首帧等待统一为 15 秒，仍按事件和像素断言结束，不使用固定延时。普通测试继续并行。

## 本步知识点与后续

- 会话、样式求值与引擎绘制分层后，可以独立测试同步规则，也能用真实像素检查假对象无法证明的层序与投影
- 相机级别决定业务样式，瓦片级别决定纹理分辨率，两者需要显式换算；影像随地表透视，不能承诺与二维逐像素相同
- ready、下载完成与画面稳定是不同条件，稳定事件必须对应这一帧实际使用的样式
- 图层诊断、来源加载错误与引擎失败分开处理，局部不支持不能让整个地图进入失败

下一步 3D.3b 接入 MVT 数据服务、Worker 绘制及缓存预算，并测量真实数据的清晰度、接缝和性能；本步的小样通过不代替大数据验收。
