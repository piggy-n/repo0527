# 第二部分：可以学到什么

## 一、Vue 3

### 1. Teleport 只移动 DOM，不重建组件

窄屏时侧栏内容要从侧栏移到抽屉里。如果用 `v-if` 在两处各渲染一份，切换时组件会重建，树的展开状态、输入框里的内容都会丢失。`<Teleport :disabled>` 在 `disabled` 时原地渲染，切换时只把同一份 DOM 移到目标位置，组件实例不变。

代价是浏览器移动 DOM 会把元素的滚动位置清零（`display: none` 不会）。`MxSplitLayout` 在内容被隐藏或移动之前记下滚动位置，在新位置显示出来后写回。写回的时机试了三次：组件更新后写回失败（抽屉显示得更晚），抽屉的 `open` 事件里写回也失败（比 Teleport 移动还早），最后用 `ResizeObserver`：内容从隐藏变为显示、或换到尺寸不同的容器时一定会触发，而且在绘制之前。

### 2. 布局状态用 provide / inject 传递

窄屏时，侧栏里的目录树选中一项后要关闭抽屉；面板放进抽屉后要去掉圆角、加关闭按钮。这些组件和布局之间隔着页面的好几层，用 props 一层层传很笨重。`MxSplitLayout` 用 `provide` 提供 `compact`、`openAside`、`closeAside`，里面的组件用 `useSplitLayout()` 取。`MxPanel` 还用一个布尔值的 `provide` 标记"我是侧栏的最外层面板"，并对自己的后代重置为 false，嵌套的面板就不会误加关闭按钮。

### 3. TSX 中的指令要局部注册

`v-loading` 在 TSX 中只 `import { vLoading }` 不会生效：TSX 编译后按名字查找已注册的指令。在组件里写 `directives: { loading: vLoading }` 局部注册即可，不需要全局注册。

### 4. `watch` 的 `flush` 时机

`flush: 'pre'`（默认）在组件更新前执行，适合在 DOM 变化之前读取旧状态（例如移动前记下滚动位置）；`flush: 'post'` 在 DOM 更新后执行，适合读取新的布局。查询表单最初用 `flush: 'post'` 在标签切换宽度后补量一次，后来改为直接观察每个条件的尺寸，因为字体加载完成同样会改变条件的宽度，后者能一并处理。

## 二、TanStack Query

### 1. 接口数据交给查询缓存，store 只放客户端状态

文件列表没有用 Pinia。分类、筛选、分页这些界面状态放在组合式函数 `useFileList` 里，接口数据由查询缓存持有，组件里也不另存一份。查询键由工厂生成（`fileKeys.page(params)`），`queryFn` 从键里取参数、把 `signal` 交给接口函数。删除后在 `onSuccess` 里返回 `invalidateQueries` 的 Promise，删除按钮的加载状态就会持续到列表刷新完。

### 2. 几个状态字段的含义

| 字段 | 含义 | 文件管理怎么用 |
|---|---|---|
| `isFetching` | 正在请求，包括后台重新请求 | 第一版的遮罩直接用它，导致缓存数据已经正确显示时也盖上遮罩 |
| `isLoading` | 没有数据且正在请求 | 显示骨架屏 |
| `isPlaceholderData` | 显示的是占位数据（上一次条件的结果） | 显示遮罩 |
| `isPending` | 没有数据；没有数据时重新请求，状态会从 `error` 重置为 `pending` | 失败后重试也算"首次加载" |

### 3. 几个实测出来的行为

- 查询键不变时，`search()` 不会触发请求，所以条件没变时点"查询"要主动 `refetch()`
- 连续 `refetch()` 时，前一次请求被取消，但它返回的 Promise 要等最新的请求完成才结束（最初以为会提前结束，写了计数器；改坏测试时发现计数器多余）
- `queryClient.clear()` 会中止进行中的查询；页面还没卸载时清空，页面上的查询不会重新请求，显示的数据也不变。所以会话结束时可以先清缓存再跳转

## 三、TypeScript

### 1. 按实测的接口结构写类型

开始迁移文件管理时，先用浏览器中的会话把每个接口实际请求一次，记录字段、空值和边界行为（页码越界、缺参数、文件不存在），再写 zod schema。只有实测中会是 `null` 的 `remark` 声明为可空，其余字段不判空。`AGENTS.md` 增加了一条：不照搬旧代码为假设情况写的兜底判断。

### 2. 库的类型与实际要求不一致时

- ElTree 的 `data` 要求可变数组，因为它会在节点数据上写入标记，所以分类配置不能声明为 `readonly`
- VueUse 的 `useResizeObserver` 不接受 Element 的 `FormInstance` 类型，改为传一个返回 `$el` 的 getter，并在注释里说明 `$el` 没有具体类型
- `fetchQuery` 在当前版本已不推荐，lint 的 `no-deprecated` 规则会报出来，改用 `queryClient.query()`

## 四、架构设计

### 1. 代码放在哪一层

| 代码 | 位置 | 理由 |
|---|---|---|
| 布局、面板、标题 | `libs/ui` | 与业务无关，只依赖 CSS 变量，将来可以拆成包 |
| `QueryForm`、`TableSkeleton` | `shared` | 依赖 `element-theme.scss` 里的样式规则（骨架行高要和表格行高一起改），离不开这个应用 |
| 文件接口、分类、列表状态 | `features/file-management` | 只属于这个业务 |
| `endSession()`、401 的处理、多标签页同步 | `app` | 要协调会话、缓存、路由和提示，只有 `app` 可以依赖所有目录 |

### 2. 依赖倒置又一次派上用场

`shared/http` 不认识会话，但要在发请求前知道 token 是否过期。和阶段二的 `getHeaders`、`onUnauthorized` 一样，它只声明一个钩子 `isCredentialExpired`，由 `app/http.ts` 注入实现。http 只知道"凭据过期就不发、按 401 处理"，不知道凭据从哪里来。

### 3. 只清理，不跳转

`endSession()` 只做清理（缓存、会话），不跳转、不提示：退出是成功提示，过期和其他标签页退出是警告，路由守卫里还不能主动跳转（要返回重定向）。各入口的跳转和提示不同，交给调用方，统一的只是"会话结束时必须清掉什么"。

### 4. 反馈做成规则

验收时的每个问题，都先问"其他列表页会不会遇到同样的问题"。会的，就写进 `element-theme.scss` 的全局样式、`shared` 的组件和文档里的规范，而不是只改文件管理这一页。

## 五、CSS 与界面细节

### 1. `<label>` 会转发点击

`<label>` 包住控件时，点击 label 里的任何位置，浏览器都会再给其中第一个可交互的控件派发一次点击。点选择框里的清除图标，这次补发的点击落到了输入框上，下拉框随之展开。jsdom 不做这次转发，模拟点击的测试在有 bug 的代码上也能通过，所以测试改为检查结构（标签不能包住控件），行为在真实浏览器里验证。

### 2. 用 CSS 解决的几处

| 需求 | 写法 |
|---|---|
| 表格空值显示 `-` | `.el-table__body .cell:empty::before { content: '-' }`：Element 对空值只渲染注释节点，单元格匹配 `:empty` |
| 识别树的分组 | `.el-tree-node__content:has(> .el-tree-node__expand-icon:not(.is-leaf))` |
| 层级引导线 | 画在子级容器的 `::before` 上，位置按层级用 Sass 循环生成 |
| 标签文字两端对齐 | 固定宽度 + `text-align-last: justify`；Element 的标签是 `inline-flex`，要先改成块级 |
| 骨架屏撑满空状态区域 | `.el-table__empty-text:has(> .table-skeleton)` |

依赖 Element 内部类名的地方，都登记进了 theme.md 的"升级检查清单"。

### 3. CSS 做不到、要靠测量的

查询表单要判断"条件放不放得下一行"，还要让"上传文档"和最右边的输入框右对齐。最右边的输入框在哪，取决于每行能放几个条件，CSS 拿不到这个值；Grid 让按钮行横跨所有列时，空着的列也算在内。最终用 `ResizeObserver` 测量，并踩了两个坑：

- 标签切换宽度后条件的位置变了，但表单的宽高没变，只观察表单不会再次触发
- 字体加载完成后标签变宽，同样只有条件的尺寸变了

所以同时观察表单和每个条件。另外，标签统一宽度后条件会变宽，如果此时重新量"排成一行要多宽"，就会一直被判断为放不下，所以只在标签按文字宽度时量，之后沿用。（阶段四开始前改为每次临时去掉统一宽度再量：沿用的值在条件减少后会过时，见 [modules/query-form.md](../modules/query-form.md)）

### 4. 加载状态的取舍

- 遮罩的意思是"这些数据已经过时"，只在显示的确实是旧数据时出现
- 骨架屏和遮罩都延迟 300ms 显示：内网请求通常更快，快的时候什么都不出现
- 骨架行与数据行同高（48），数据到达后原位替换，界面不跳动

## 六、工作方法

### 1. 设计稿先行，在预览页里讨论

布局规范、树的样式、窄屏入口、查询表单都先在主题预览页里用真实组件拼出几种方案，截图讨论，确认后再写代码；临时设计稿不提交。查询表单讨论了多轮，每一轮都比上一轮更接近真实需求，这个过程本身就是在澄清需求。

### 2. 先复现，再修复

"切回看过的分类时遮罩盖住缓存数据""换行后上传按钮没对齐"都是先写出在旧代码上失败的测试，再修代码。无法在 jsdom 中复现的（`<label>` 转发点击），就测原因本身，并在浏览器里验证。

### 3. 改坏测试时发现自己的假设错了

改坏代码后测试仍然通过，不一定是测试写得不好，也可能是对代码的理解有误：

- 计数器改成布尔值后测试仍通过：Vue Query 的 `refetch` 不会提前结束，计数器本来就多余
- `isLoading` 换成 `isPending` 后测试仍通过：两者在这里等价
- "统一宽度后重新量"没被抓到：用例选的宽度恰好能被补量纠正，换成 776～860 之间的宽度才暴露问题

另外，"失败"还要看原因：两个用例在改坏后是超时或抛错，而不是断言失败，都改写成了断言。

### 4. 在浏览器里量，而不是看

对齐、行高、遮罩出现的时机都用脚本量出数值：给 `/file/page` 加 2 秒延迟记录"旧数据 → 遮罩 → 新数据"的时间线；量出纯文字行 48、带标签的行 49.2；比较"上传文档"和最右边输入框的右边缘。截图只用来给人看。

### 5. 排除环境的干扰

- 开发服务器漏掉了一次文件修改，浏览器拿到的还是旧样式：更新文件时间戳后恢复
- 控制台里攒着热更新替换模块时留下的报错：开一个干净的标签页复查，确认不是代码问题
- 截图有时是没刷新的旧画面：DOM 里的状态和截图对不上时，以 DOM 为准，重新截图

## 七、替代方案汇总

| 领域 | 本项目选择 | 常见替代 | 没选的主要原因 |
|---|---|---|---|
| 通用 UI 组件的位置 | `libs/ui` | 放在 `shared`；直接做成包 | 将来可能拆出去，先在 libs 里按包的规则约束（ADR 0016） |
| 窄屏时的侧栏 | 收进抽屉，左侧留窄条 | 直接隐藏；标题行放按钮 | 侧栏多是导航或筛选，隐藏等于拿掉功能；按钮抢了标题的位置 |
| 侧栏内容在两处切换 | Teleport 移动 DOM | `v-if` 各渲染一份 | 组件重建，状态丢失 |
| 接口数据 | TanStack Vue Query | Pinia 手写缓存；每个组件各自请求 | 缓存、去重、取消、加载状态都要手写（ADR 0017） |
| 加载提示 | 按显示内容分三种 | 遮罩跟着 `isFetching` | 后台刷新时盖住正确的数据 |
| 首次加载 | 表格空状态里的骨架行 | 整个表格换成骨架；用假数据渲染真实的列 | 表头消失、界面跳动；插槽要处理假数据 |
| 空值 | CSS `:empty` | 每列写 `formatter` | 容易漏 |
| 筛选栏排布 | 一行放得下时紧凑排列，换行时统一标签宽度 | Grid 等宽列；`inline` 表单；容器查询 | 宽屏被拉开；换行后对不齐；临界宽度要手动写死 |
| 标签两端对齐 | `text-align-last: justify` | `letter-spacing`；拆字后 flex | 要按字数计算，或拆成单独的元素 |
| 会话结束 | `endSession()` 统一清理，跳转和提示在入口 | 每处各自清理；统一入口连跳转和提示一起做 | 容易漏掉缓存；各入口的跳转和提示不同，路由守卫里也不能主动跳转 |
| token 过期 | 发请求前也检查 | 只靠路由守卫和后端 401 | 有接口不校验 token |
