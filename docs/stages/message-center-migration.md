## 数据与业务接入

只读核对返回 1227 条完整记录，`data` 是数组，没有分页外层；`isRead` 仅见字符串 `"false"` / `"true"`；`msgId`、标题、正文和时间为字符串，`taskId`、`taskStatus` 可为 null。样本分类为 `table` / `resource`，旧调用明确包含 `approval`，暂无该类真实记录。忽略界面未使用的发送人等字段，不猜测多种返回结构。

接口与操作位于 `features/message-center`：

- 查询缓存按账号区分；结果标注账号，切换账号同步隐藏上一账号数据，迟到读取重新核对会话
- 写请求捕获会话，发出前核对；已发送的不随卸载取消，响应后再次核对再更新缓存
- 单条按 ID 防重复；全部已读与单条操作互斥，成功只更新提交时见到的记录，后到的新消息保留自身状态
- 写成功先取消旧列表请求，避免旧结果恢复红点；刷新失败保留已有消息并显示重试，首次失败显示错误状态
- 管理员报表通知进入统计报表列表；资源通知按旧实际调用将 `taskId` 交给申请详情接口，消息无 ID 时明确进入资源审核列表
- 系统管理通过路由 props 接收 `applicationId`，打开后消费一次性查询参数，同一消息可再次打开详情；已在目标栏目时关闭消息弹框，不重复导航
- 用户侧申请及报表仍未迁移，关联按钮禁用并提示；消息列表、全文与已读操作可正常使用

沿用以下调用地址，列表读取已核对；已读写操作仅在固定接口测试，尚未修改真实业务消息进行联调：

| 操作 | 旧请求 |
|---|---|
| 消息列表 | `POST /api/message/list`，传 `{}`，返回完整数组 |
| 单条已读 | `POST /api/message/read/{id}` |
| 全部已读 | `POST /api/message/read/all` |

进入应用读取一次，之后弹框打开时刷新；不增加后台持续轮询。未读角标表示最近一次成功读取的数量。
