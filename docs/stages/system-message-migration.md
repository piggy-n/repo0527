## 二、知识点与设计理由

### 先量真实接口，再定方案

旧代码为消息写了分页、未读数接口、5 秒轮询和右上角通知，实测接口一次返回全部（505 条、约 225 KB），没有计数接口，497 条是报表通知。按真实情况定下：未读数取未读列表的长度、页面可见时 60 秒刷新、打开弹框才取全量、前端筛选和分批显示。消息里的时间是北京时间的字符串，申请里是带时区的 ISO；开发机在太平洋时区才发现同一条申请两处差 9 小时，于是统一按北京时间显示（`formatBeijingDateTime`）。

### 拥有者与组件：同一个组件，真实数据和样例数据都能驱动

`MessagePanel` 只认 `MessageCenter`（`useMessageCenter` 的返回值），`ApplicationDialog` 只认 `ApplicationReviewOwner`。开发页给它们一个形状相同、数据固定的演示拥有者，就能在不请求接口的情况下展示正式组件。两边共用的逻辑（消息的筛选和分批）提成 `useMessageFilters`，演示拥有者只替换数据来源和写操作，不复制规则。

### Element 的弹框不是受控组件

`ElPopover` 不把 `update:visible` 传给内部的 tooltip，`visible` 不能双向绑定：关闭用它暴露的 `hide()`，开关状态跟着 `before-enter`、`before-leave` 记下。`role="dialog"` 让 Element 自己给按钮加 `aria-haspopup`、`aria-expanded`、`aria-controls`；自己写这几个属性会被它覆盖掉。测试里，`@vue/test-utils` 默认把 `Transition` 换成替身，过渡钩子不触发，开关状态永远是关的，所以这类测试要写 `stubs: { transition: false }`（浏览器测试也一样）。

### 淡出期间的内容

弹窗的开关跟着数据（打开的申请没了就关上），但 Element 要淡出约 300 毫秒，这段时间内容已经按"没有申请"渲染，闪成"申请不存在或已被删除"；提交成功时详情先刷新成"审核通过"，关上前又闪一下"审核结果"。这类问题单元测试默认测不出来（过渡被替身跳过），是在组件样例里提交审核时看到的。改法是弹窗显示一份内容快照，从提交到关上、以及淡出期间不更新。浏览器里用 `MutationObserver` 记录弹窗出现过的内容来确认，比截图抓 300 毫秒的瞬间可靠。

### 写操作的会话核对与本地先改

已读、全部已读、审核都按 `useSessionGuard` 核对：提交时记下 token，发请求前、收到结果后各核对一次。已读成功后先改两个缓存（红点和角标马上变），再让查询失效、按服务端刷新；不等刷新完成，因为全量列表较大。全部已读的接口没有参数、后端改全部，前端只能先改看到的那些，和 ADR 的出入写进文档，没有为它改方案。

### 测得出来才算写对

几次改坏验证测不出来的情况，各有原因：

- 测试数据恰好让两种写法结果相同（全部已读提交的 ID 恰好是全部未读、未读不到一批时"换条件回到开头"看不出来）：换数据
- 应当立即返回的调用被挂起的请求拖到超时：和只经过一轮宏任务的等待赛跑（`setTimeout(0)`），失败时是断言而不是超时
- 写法本身多余：业务按钮阻止冒泡（同一条按 ID 只提交一次）、滚动容器的 `min-height: 0`（滚动容器的最小高度默认就是 0）、`ElBadge` 的 `max={99}`（默认值）：删掉

### 顶栏加按钮要重新量

加 40px 的按钮后，管理员的顶栏在 1440 宽时需要 1450px，导航向两边溢出贴住系统名称。实测用临时的浏览器测试挂载真实的 `AppHeader`、全局样式和字体，在 11 个宽度下记录各部分的自然宽度，再决定改中间一档的内边距而不是提高断点（1440 宽的屏幕仍能看到系统名称）。"99+" 角标宽 34px，Element 默认放在锚点右边会盖住用户名，改为压在铃铛右上角。
