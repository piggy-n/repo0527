# 城市国土空间监测指标的迁移

日期：2026-10-28。分支 `migrate-space-monitoring-indicators`，从 main `0cfef2c` 切出；旧项目基线 `master-demo` 的 `b4f3987`。决策见 [ADR 0098](../adr/0098-space-monitoring-indicators.md)，用法见 [modules/monitoring-indicators.md](../modules/monitoring-indicators.md)，接口实测和与旧页面的差异见 [migration.md](../migration.md)。

本次按"最小必要迁移"做：保留旧页面的功能、业务规则和交互，界面换成新项目的规范，不扩展功能。

## 二、知识点与设计理由

### 先量真实接口：旧代码的假设有一半对不上

旧代码按"可能是这样也可能是那样"写了很多兜底：状态可能是文字也可能是 0～3、几何类型读 `geomType ?? type`、区划范围认 `urban`、结果都要去掉冒号前的文字。实测之后：

- 状态只有文字；几何类型只有 `type`；区划范围的图层名是 `cqjcfwa`、`xzq`，没有 `urban`；成果的结果本来就没有前缀，只有进度接口的结果带"分析结果:"
- `sfjy` 在城市体检评估里是布尔，在综合分析指标里是字符串 `"false"`。旧页面 `Boolean(node.sfjy)` 把字符串当真，综合分析指标在旧页面上全部是禁用的——这是实测才发现的旧缺陷，新页面按真假值解析
- 综合分析指标里有一个没有下级的分类，旧页面把它当成指标显示（又因为上一条被禁用，看不出问题）；分类和指标的区别是有没有统计范围 `bz`
- 展示树在没有成果时是 `null`、同一个分类在顶层重复出现十几次；进度在没有任务时也是 `null`

这些都写进了 zod schema 和用例（`api.test.ts` 的样本就是实测的形状），使用处不再判空。兜底写法删掉之后，类型反而更窄：`IndicatorResult.value` 从 `string | null` 变成 `string`，展示树之外的指标 `dataId` 是 `null`。

### 轮询按 ADR 0039 归类

旧页面的计算进度用递增序号、`setTimeout` 和一份"任务快照"判断过期。新写法把它拆成两件事：

- **开始计算是服务端写操作**：提交前后按 `useSessionGuard` 核对会话，已经发出的不随页面卸载取消
- **查进度是这次任务的可替换操作**：每个任务从 `LatestController` 拿一个信号，重置、新任务、页面销毁都中止它；每次 `await` 之后先看信号再写状态

任务的阶段（创建、开始、查询、停下、完成、失败）是一个联合类型的字段，面板和按钮都从它推导，不另存"正在计算""失败次数"这类标志。测试用假定时器按真实间隔推进（3 秒、每 5 秒），连续失败、`null` 进度、重新获取都能确定地重现。

### 同步读取时也不能是上一个指标的成果

`useQuery` 的 key 换了以后，`data` 要到下一轮调度才变。成果的拥有者如果只看 `data` 是否存在，换指标的那一刻会把上一个指标的成果当成新指标的显示一帧。成果查询的结果标上记录 ID，拥有者只在 ID 和当前指标一致时才算就绪。改坏验证时，原来的用例在 `await flushPromises()` 之后才检查，测不出来；加上"换指标后立即同步读取"的断言才能抓到。

### 同一个页面组件，真实接口和样例数据都能驱动

页面通过 `IndicatorApi` 拿接口，默认是真实实现；`/dev/monitoring-indicators` 传入固定数据的实现、一个独立的查询缓存（和真实页面的同名 key 互不影响）和一个总是有效的会话核对。用户确认的就是将来上线的组件，不是另做的原型；实测接口后只改了 `api.ts` 和样例数据，组件没有动。

### 标签不能包住 Element 控件

条件区最初用 `<label>` 包着年份和监测范围。[page-layout.md](../design/page-layout.md) 记过这个坑：点级联框里的清除图标，浏览器把点击转给输入框，下拉框随之展开。改成普通的 `div`。

### 后端没有数据时不改方案

成果瓦片在三个城市的 96 个成果上都返回"目录不存在"。没有为此改图层的写法，瓦片失败按数据源错误处理（ADR 0041），记进 migration.md 待后端补数据后验收；生产冒烟用空瓦片确认地址和请求路径。
