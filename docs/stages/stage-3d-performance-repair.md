# 三维性能修复：影像更新时机与重复绘制

日期：2026-10-19。依据：[ADR 0069](../adr/0069-three-dimensional-imagery-update-scheduling.md)。本步沿用已经确认的统一影像方案，不改变样式层序，不接入 3D Tiles 或地下空间。

## 问题与原因

用户反馈首次加载慢、拖动和缩放卡顿，以及工具栏“＋／－”偶发 `This object was destroyed`。

原来的镜像在共享相机浮点 zoom 每次变化时替换矢量影像，包括隐藏层。平移会改变地表距离或中心纬度，也可能造成共享尺度变化；一次动画因此反复取消请求、创建瓦片和上传纹理。相机通知来自 SDK 渲染回调，替换还可能在 SDK 尚在使用旧影像时销毁它。

新增真实引擎测试在四次缩放中观测到 32 次 SDK 渲染调用栈内的影像销毁，断言失败；修复后为 0。没有稳定复现用户截图中的原始异常，因此这项证据证明的是危险销毁时序已消除，不能代替同一故障的现场复验。

GeoJSON 的另一项重复开销是每层、每次缩放重新投影，并在每张瓦片扫描所有图形。省界包含 20,829 个坐标，三个描边层原本每次重建合计投影 62,487 次。

## 本步改动

- 相机仍逐帧精确同步；已显示的影像在运动期间复用，停止后按最终精确 zoom 更新一次。显隐阈值、新显示层、业务变色和数据替换仍响应
- 后续镜像更新合并到 SDK 渲染返回后的微任务；首轮构造同步准备。就绪和稳定帧检查待处理更新，暂停或释放使旧回调失效
- 隐藏层不随缩放重建，恢复时追赶一次；暂停中断动画后清理移动状态，恢复首个稳定帧对应最终样式
- 视图独占弱缓存复用同源投影及包围盒；替换数据对象自然失效，释放时清空。省界三个描边层首次合计投影 20,829 次，后续缩放复用
- 瓦片绘制前排除完全不相交的图形，保留圆描边、宽线、尖角、模糊和抗锯齿余量。不会切断面环或简化坐标
- 空瓦片复用透明像素；空间恒定的纯色背景和整层空内容只保留根级单像素影像，避免无效细分。非空图层仍保持正常瓦片精度
- 已取消的 URL GeoJSON 用独立空占位结束，避免迟到结果访问已释放的投影缓存

运动期间符号可能随旧影像暂时缩放，停止后恢复精确尺寸。大环包围盒覆盖当前瓦片时仍需扫描该环；本步没有引入 GeoJSON Worker 或空间索引。

## 回归与故障注入

单元测试覆盖移动期间合并、业务样式变化、显隐阈值、隐藏层恢复、暂停和释放后的排队回调、迟到 URL 请求、投影复用及空瓦片绘制次数。真实 Chromium 覆盖 Canvas 像素、真实 Cesium 生命周期，以及公共工具栏放大、缩小、连续点击和真实拖动。

- 修复前的运动、业务变色和隐藏层回归均以调用次数断言失败；移除移动门控和回调身份保护后重新出现断言失败
- 关闭投影缓存时，同源两层的投影调用数从预期 2 变成 4；关闭瓦片粗筛时，完全离屏图形仍发生 2 次描边
- 取消共享恒定画布后，三次瓦片请求创建 3 张画布而非预期 1 张
- 面抗锯齿描边默认尖角最多伸出约 5 个相机像素；最初粗筛余量不足，邻瓦片尖角像素 alpha 为 0，新增断言失败后修正
- 释放后晚到 URL 回归先出现“GeoJSON 投影缓存已释放”，取消占位改为独立缓存后通过
- 候选视图和动画中暂停的测试使用按 zoom 变色背景，等动画实际推进后暂停，恢复首个稳定帧必须为终点颜色
- 全量回归补出斜视定位一直没有稳定事件：SDK 发出 moveStart 后因微小数值抖动始终没有 moveEnd，项目姿态比较却连续相等。运动结束判定改用既有姿态精度，不能只等待 SDK 通知
- 斜视稳定后再移动的真实回归：临时省略重新进入运动时的镜像保护，影像销毁 429 次，超过 12 层上限，产生断言失败而非超时；恢复后进入最终回归
- 缓存恢复的中间版本把静止确认窗口同时用来推迟镜像，保留的 `sample-line` 仍以 4 级尺度参与 11 级视角渲染，单帧约 4～6 秒。恢复时先追赶镜像，再观察后续真实运动；新增“恢复首轮 Scene.render 前已替换影像”的断言先得到 0 而非 1，修复后通过，带探针恢复阶段约 657 毫秒、最长帧约 590 毫秒
- 优化后自然取消数量可能为零，旧资源压力测试的“必须发生取消”断言失败。改为扣留一次真实 Worker 位图，在明确暂停后交回迟到结果，验证本轮确实取消、位图关闭及恢复后的真实像素，不再靠时序碰巧撞上取消窗口
- 临时关闭 Worker 池的迟到结果释放，新增位图宽度断言得到 512 而非 0；恢复后通过。监听释放统计同时覆盖本次新增的 postUpdate
- 用户补充“刚进入三维”和“加载完成后”均会报错：独立真实按钮回归在首次 ready 通知中同步点击 DOM 放大按钮，明确断言当时尚无稳定帧，最终确实到达 12 级、发生影像替换且 SDK 渲染栈内销毁为 0；原完整按钮用例继续覆盖稳定后的点击、连续操作与拖动

全部故障注入已恢复。测试只使用本地数据，不请求后端或天地图，没有启动本地开发服务。

## 交替性能实测

基线固定为 `8f9a566`，使用独立干净工作区；依赖与测试配置相同。三轮按“修改后 → 基线 → 修改后”串行执行，期间无其他浏览器测试或构建，四个生产源码文件在测量前后 SHA256 一致。

场景为 `DevCesiumPage.browser.test.tsx` 的 27 层本地样例、约 1100×727 画布、Chromium / SwiftShader 软件 WebGL。首次模拟失败未创建三维实例，故重试阶段对应首次三维实例加载；依赖已由测试工具准备，不包含完整应用冷启动和生产网络。

| 阶段 | 修改后① | 基线 | 修改后② |
|---|---:|---:|---:|
| 首次三维就绪 | 16,251.1 ms | 31,565.5 ms | 14,156.9 ms |
| 缓存三维恢复并追赶样式 | 494.3 ms | 244.7 ms | 120.9 ms |
| 普通缓存往返，第 1 次三维 | 450.2 ms | 566.1 ms | 692.9 ms |
| 普通缓存往返，第 2 次三维 | 283.0 ms | 1,142.6 ms | 445.2 ms |
| 完整用例 | 20.212 s | 35.754 s | 17.828 s |
| 整轮测试运行 | 29.07 s | 48.90 s | 29.94 s |

上表为恢复首帧修复后的最终源码；本轮夹具首次三维耗时下降约 48.5%～55.2%，只有三轮，不作为统计承诺。此前其他版本对照中的同一基线测得约 22.6～23.0 秒，说明本机软件渲染计时波动明显；不选取中间版本延后必要换层而得到的约 9 秒作为最终成绩。缓存恢复的两次结果一慢一快，没有一致改善，不宣称缓存切换提速。

真实工具栏测试曾因软件渲染中一次点击响应超过 3 秒而超时；15 秒操作预算下功能通过，保留最终相机、视图可用和图层替换次数断言。该预算只用于功能回归，不能证明交互帧率达标。

最终全项目回归中通过的工具栏用例记录：单次放大、缩小、拖动各销毁 23 个旧影像，连续两次放大再缩小合计 46 个，均符合每次操作至多一轮更新的约束。该轮 389 次公开 `Scene.render` 调用累计约 72.9 秒，最大一次约 4.47 秒；该计时包含 SDK 在渲染调用中的工作，不单独区分 CPU、Canvas 与 GPU 等待。全项目测试还有其他普通测试负载，不能把它加入上表的独立 A/B 或用它计算硬件 FPS，但它明确表明软件渲染下仍存在阻塞峰值。

用户补充两种点击时机后，包含早点击的完整按钮文件再次通过（2 项，108.51 秒）。稳定后操作的替换次数仍为 23/23/46/23，但这轮最长 `Scene.render` 约 5.16 秒；测试通过表示行为和更新次数正确，不表示卡顿已经消失。

## 最终验证

- 全量测试：图标包 5 个文件、35 项；应用 210 个文件、1,943 项全部通过，应用运行约 285 秒
- 随后只补充首次 ready 早点击测试，受影响按钮文件 2 项通过；共验证 1,979 项不同测试（全量 1,978 项，加补充 1 项）。生产源码在最终性能对照、全量与补充测试之间未变
- 类型检查、lint、公网与内网构建及内置产物检查通过；三维开发页、二三维运行时及 Worker 独立构建通过
- 公网与内网构建保留既有 `sm-crypto-v2` 的 `crypto` 浏览器外置提示及大分块提示，没有通过关闭检查规避
- `git diff --check`、UTF-8、LF 和 `AGENTS.md` 原有无末尾换行检查通过；临时探针和故障注入已恢复，基线工作区已清理归档

## 后续测量

部署环境需要复验截图的原始故障，并分开记录网络、SDK 初始化、GeoJSON 主线程绘制、MVT Worker 和纹理上传成本。下一步优先测全省边界与实际勾选资源的移动长任务；根据证据再选择环片段索引、GeoJSON Worker 或影像合并。新绘制架构仍需保留符号尺寸、孔洞、接缝、层序和释放规则。

旧项目 `master-demo` 基线为 `6b4799b`，其整数/瓦片级别求值与 Entity 绘制只作为行为参考，本轮没有在两个项目之间做同场景性能对照，不能据此宣称已经追平旧项目。硬件帧率、生产首次加载和总内存尚未验收。
