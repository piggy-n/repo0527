## 二、知识点与设计理由

### 引擎只管状态和时间，动效从进度来

引擎是纯 TS：步骤状态、确认点、干预后的失效与复用、版本，等待由注入的时钟完成，测试用手动推进的假时钟（`ManualClock`），34 项测试不用真实等待。界面上的一切动效——一句话出现、逐字打出、数字滚动、进度条、地图扫描、落点、服务圈扩散——都是"步骤进度 → 画面"的纯计算，不另开计时器。由此几件事自然成立：

- 暂停（人工干预、页面停用）只停时钟，所有动效一起停，回来后对得上
- 回看已完成的一步，进度是 1，直接是终态
- 减少动画就是"每一段开始就是终态"（`mapFrame(..., still)`、`StepRecordView` 的 `still`），不是把动画放慢

替代方案是用 GSAP 时间线兼作时钟（第一版原型的做法）：演出和推演绑在一起，暂停、回看、测试都要另想办法。

### 同一份规则：先预告，再执行

人工干预的按钮要写出"保存 / 确定 / 应用并重算"，说明还要写出从哪一步重算、复用几个环节。引擎拆出不改状态的 `planApply`，`apply` 按它执行，界面的预告和真正的执行用同一份规则，不会说一套做一套。

### 文字和数字由纯函数从计算结果生成

叙述（`stepRecord`）、结果摘要（`resultSummary`）、地图着色（`mapColoring`）都是纯函数，同样的状态得到同样的文字，所以测试可以直接比对整句话；叙述、关键数字、图表和地图里的 64.6%、5/13 来自同一份计算，不会对不上。

### 结果阶段只存一份选择

拥有者只存 `ResultSelection`（看哪一版、和谁比、指标、年度、着色），对比的一方、关键数字、结论、图表配置、地图颜色都是由它推导的计算属性。新的一版生成时整体换一份选择；不合法的值直接抛错。建议情景按正在看的指标和年度算（2025 年要新增 25%，2026 年 20%）——这是测试里先写错、再核对模型才确认的行为。

### 地图：数据每轮一份，动画只改阈值

区县和设施点每轮推演只生成一次，交给会话的是同一个对象；扫描、落点、扩散只改图层里的阈值和不透明度（`fill-opacity` 是"经度排序 ≤ 扫描进度"），会话只发 paint 的修改，不重新切片。演出值没变时保留原对象，样式不重新推导。扫描带和标注用 DOM 叠在地图上，按投影定位。

### 页面缓存与可叠加的暂停

路由 `keepAlive` 后，页面停用时 `usePauseWhileInactive` 拿一个暂停、激活时解除；人工干预也拿一个，两者叠加，全部解除才继续。侦听用 `flush: 'sync'`，停用的同一刻停住时钟。最初写了"已经暂停就不再暂停"的判断，改坏后测不出来——侦听在值不变时根本不触发，这个判断是多余的，删掉了。

缓存期间页面的 DOM 被移出文档，量到的尺寸都是 0：图表用 `useShownElementSize`、只在宽高大于 0 时重排；编排图的连线停用期间不重新测量。否则回来的第一帧会按 0 排版。

### 窄屏沿用已有的规则

小于 1200 时没有新设计一套，沿用现状底图的"左右只显示最后操作的一边"（ADR 0053 第 8 节、`visibleSides`）：只推导显示，不改两边各自的收起状态；推演阶段本来就有的窄条和胶囊就是隐藏一边时的样子。

### 踩过的坑

- **页面根元素高度为 0**：S7 把推演阶段改成全部绝对定位后，页面根元素在不是弹性容器的内容区里 `flex: 1` 不生效，整页空白；S7 的实测没发现，S8 实测时才看到。改成和现状底图一样的 `height: 100%`，规则补进 [page-layout.md](../design/page-layout.md) 的"画布型"
- **`scrollIntoView` 会滚动 `overflow: hidden` 的祖先**：浏览器测试工具点元素前会先滚动到可见，把整个推演阶段滚出了画面；页签露出选中项也因此只滚页签条自己
- **阶段条换行**：1200 宽结果阶段"重新编排"比"停止"宽 28 像素，阶段条换成两行；下面的面板改为按量出的高度排，不假设一行
- **jsdom 没有画布**：ECharts 在组件测试里替换成占位组件，只检查分区和配置，图表本身在页面验收（与 `AiResultPanel.test.tsx` 相同）
- **Element 的弹出层会去掉触发元素的 `aria-*`**：S5 的参数浮层在外面包一层 span 承载无障碍属性
- **原生拖放和模拟输入**：内置浏览器模拟的鼠标拖动触发不了 HTML5 原生拖放，条件库拖入改用无界面 Chromium 的原生拖放验证；滑块这类按指针事件实现的拖动在内置浏览器里可以直接拖
- **热更新后的组件**：改了组件后热更新，模板里的 `ref` 没有绑上，整页刷新后正常；验收前先整页刷新

## 三、S10：按 Excel 重做参数与 AI 推演指令

用户给出指标计算方法的 Excel 之后，S1～S9 按页面需要设计的参数（步行速度、人口口径、缺失数据处理、规划新增、设施纳入口径）几乎都要换掉（ADR 0106）。

### 参数从计算规则里来

- **先找依据，再定参数**：22 项指标逐项对照 Excel，归成住宅用地覆盖率、城区面积覆盖率、人均三类，参数只在对应的类型上生效（`paramApplies`）。之前的全局参数看起来灵活，但说不清"步行速度对消防站覆盖率意味着什么"
- **标准口径与模拟情景分开**：标准值就是 Excel 的规则，偏离就标"模拟情景"，只改这次推演。这让"在指标上改服务时长"这类需求有了判断标准：它会改指标的定义，和计算规程重叠，于是暂不做
- **改模型时测试的数字会整体移动**：公园绿地覆盖率从 64.6% 变成 66.6%，是因为汇总权重从人口换成了住宅用地，不是 bug。先核对模型再改期望值，别直接抄新的输出

### 一句话变成逐个出现的节点

- **步骤是纯函数，节奏在组合式函数里**：`buildSteps` 给出每一步出现哪个节点、编排长到哪里，测试不用计时器；`usePromptComposer` 只负责等待和作废（`LatestController`），用假计时器测节奏
- **区分自己写的和用户改的**：组合式函数改编排时置一个 `writing` 标记，侦听用 `flush: 'sync'`，在同一刻就知道是不是手动修改，手动修改才停下编排
- **中间状态用真实的编排**：每一步交出去的都是合法的编排，连线、模拟情景标记、预估栏都照常推导，不为"编排中"另写一套显示

### 踩过的坑

- **系统开着"减少动画"**：用户的系统设置了减少动画，按 ADR 0105 第 5 条，逐个出现被跳过，用户看到的是"瞬间生成"。先把"节奏"和"动效"分开（节奏不受影响），用户最后决定这一页照样播放；开关收在 `motion.ts` 一处，样式用根元素的类，不再散在各处的媒体查询里
- **原生 `button` 不继承字体**：条件库的按钮用了浏览器默认字体，看起来又细又淡；写 `font-family: inherit`
- **浅灰底标题栏叠在一起**：两个侧栏面板上下排时，浅灰底标题栏和页面背景连成一片，改用白色标题栏
- **`[data-node^=""]` 什么也选不到**：CSS 的前缀选择器给空字符串时不匹配任何元素，测试里要取全部节点得写 `[data-node]`
- **jsdom 没有 `scrollBy`**：编排时把最新的节点滚到看得见，组件测试里要补一个空实现
- **ADR 编号撞车**：分支开发期间本地 main 用掉了 0102～0104，合入前把分支的 ADR 改号为 0105，新决定写成 0106
