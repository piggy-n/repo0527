# 0022. 样式模型与会话提交：分组推导、快照对比

- 状态：已接受
- 日期：2026-10-09
- 修正 ADR 0020 第 1 条：选择状态不包含候选列表和详情（见下文第 6 条）

## 背景

ADR 0020 确定地图会话状态是二三维唯一的真相源，样式模型用 MapLibre 样式规范描述，但实现方式留到设计接口时再定：可变存储加细粒度事件，还是不可变快照加 style-spec 的 `diff`。评审时又提出：只规定"发出事件"不够，还要规定怎样提交变化（批次、异步顺序、恢复）以及视图在各个阶段的行为。

旧项目（yzt `master-demo` 836f03b）对样式的写操作都是 MapLibre 的标准操作：增删数据源和图层、调整顺序、改 paint 和 layout、改过滤条件、`setData`、feature-state、图片。高频的只有 `setData`（测量、绘制、高亮）。命令式写法带来了几处复杂逻辑：

- `MapRegionLayerFilter` 先记下各图层原来的过滤条件，取消区划裁剪时再还原
- `LayerManager` 按需添加、删除纹理和描边的伴随图层
- 每次变化后都要重新调整边界和标注的层级
- 测量结束、鼠标不动时，两个测量数据源仍每秒 `setData` 60 次

2026-10-09 用 `@maplibre/maplibre-gl-style-spec` 26.4.4（maplibre-gl 6.12.0 依赖的版本）实测 `diff`。样式规模接近旧项目：30 个矢量数据源、150 个图层，带 60 个地类编码的 `match` 表达式和区划过滤条件：

| 情况 | 每次 diff 耗时 |
|---|---|
| 大块数据不在样式里 | 约 0.15 ms |
| 一个 2 万顶点的区划边界 GeoJSON 在样式里 | 约 0.57 ms |
| 一个 10 万顶点的区划边界 GeoJSON 在样式里 | 约 2.3 ms |

原因是 style-spec 的 `deepEqual` 不会先比较引用，只要数据在样式里，即使没有变化也要逐个比坐标。`diff` 的输出是带类型的命令列表（`command` 与 `args` 构成可辨识联合）；生成失败时，退回为一条 `setStyle` 命令。

## 候选方案

| | A. 可变存储加细粒度事件 | B. 各方直接编辑同一份不可变快照 | C. 分组推导加快照对比 |
|---|---|---|---|
| 写法 | Manager 调用 `addLayer`、`setPaint` 等方法，存储发出对应事件 | 各方生成新快照替换旧快照 | 每个拥有者用纯函数从自己的状态推导出一个分组，整体替换 |
| 上面那几处复杂逻辑 | 仍然存在 | 仍然存在 | 变成推导 |
| 晚加入的订阅者 | 要另写一条"取完整状态"的路径 | 和空样式做 diff | 和空样式做 diff |
| 归属 | 谁都能改任何图层 | 各方互相覆盖 | 每个分组只有一个拥有者 |

## 决定

选方案 C。

### 1. 分组与推导

- 每个拥有者（底图、业务图层、边界、遮罩、高亮、测量、绘制、AI 结果等）负责一个分组 `{ sources, layers }`。分组是不可变的值，由拥有者用纯函数从自己的状态推导出来，变化时整体替换
- 业务语义留在 features：图层树的勾选、地类配色这类状态放在 features 里，由它们推导出分组交给会话。map-core 只认识分组，不认识业务
- 分组的叠放顺序由装配方用常量元组声明，`setGroup` 的分组 ID 有类型检查。样式的根属性（`glyphs`、`sprite` 等）也由装配方提供
- 数据源和图层的 ID 在所有分组之间必须唯一，提交时发现重复就抛错（属于程序错误）

旧逻辑在推导写法下的对应：

| 旧代码的命令式逻辑 | 推导写法 |
|---|---|
| 记下原过滤条件，取消裁剪时还原 | 推导时把区划条件与原条件组合，取消裁剪就是不组合 |
| 按需增删伴随图层 | 推导时按符号设置决定生成哪些图层 |
| 每次变化后重排层级 | 分组顺序固定，拼出来就是有序的 |
| 数据没变也反复 `setData` | 数据引用没变，就不产生命令 |

### 2. 快照对比

- 各分组按顺序拼成完整样式，与上一份做对比：`diffStyle(prev, next)`
- 对比前把 GeoJSON 数据源的 `data` 换成同一个占位值，其余部分交给 style-spec 的 `diff`；`data` 本身按引用比较，不同就生成 `setGeoJSONSourceData`。高频更新（测量的橡皮筋）因此只付出约 0.15 ms
- 输出沿用 style-spec 的 `DiffCommand` 类型。消费方要能处理 `setStyle`（diff 失败时的退路），按整体重建处理
- 推导时没有变化的部分沿用原对象。`diff` 每次都会遍历数据以外的全部样式；图层数增加一个数量级时，重新测量

### 3. 提交与通知

- `setGroups({ business, mask })` 是一次提交，`setGroup(id, group)` 是只改一个分组的简写。每次提交，版本号加 1；`current`（完整快照）和 `version` 同步更新
- 跨分组的业务操作用一次 `setGroups` 提交，保证原子性。批次不能跨越 `await`：需要等异步数据时，先把数据都拿到再提交
- 通知在微任务中合并：同一轮事件循环里的多次提交只对比一次，监听器收到起止版本、命令列表和当前快照。测试中等待微任务完成即可拿到通知
- 版本号用来标识快照。基于某个快照的异步计算（三维镜像重画、统计）记下版本号，结果回来时核对。业务数据的异步请求（例如切换年份时获取配置）仍然用 `AbortSignal` 和查询键判断是否过期（AGENTS.md 的现有规则），不用会话版本号：任何一个无关的提交都会改变版本号

### 4. 消费方：首次挂载、暂停与恢复、失败重建

- 每个消费方（二维适配器、Cesium 镜像）记下自己最后应用的快照
- 首次挂载：与空样式对比，得到"全部添加"的命令，和增量更新走同一条路
- 暂停：不处理通知。恢复：用最后应用的快照与当前快照对比。不需要命令日志
- 按需追上：三维期间二维暂停，点选需要二维时（ADR 0020 第 6 条），用同样的恢复路径临时追上
- 一次通知的命令在同一个任务里应用完；MapLibre 在两次渲染之间不会画出中间状态
- 某条命令抛错时，用当前快照整体重建（MapLibre 用 `setStyle`），记录错误，再把当前快照记为已应用

### 5. 视图的生命周期

会话状态本身只有"存活"和"已释放"两种状态。每个视图（二维、三维）有自己的生命周期：

| 状态 | 含义 | 是否应用会话的变化 |
|---|---|---|
| `idle` | 还没有创建 | 否 |
| `initializing` | 创建中（加载 SDK、建地图、加载样式） | 否；完成后按"首次挂载"追上 |
| `ready` | 可用，当前显示 | 是 |
| `paused` | 可用，但切走了 | 否；恢复时追上 |
| `failed` | 创建或运行失败（例如不支持 WebGL2 时的 `GPUInitializationError`） | 否；不影响会话状态和另一个视图 |
| `disposed` | 已释放 | 否；释放后的行为见 ADR 0023 |

几件事分开控制：

| 控制项 | 由谁决定 |
|---|---|
| 保留状态 | 会话，切换视图时始终保留 |
| 应用变化、渲染、下载瓦片 | 视图的 `ready` / `paused` |
| 统计、查询 | 各自的订阅，有独立的生命周期 |

### 6. 会话的组成

会话分为 `style`、`camera`、`tool`、`selection` 四部分，各自发出事件。拖动地图时相机每秒变化几十次，不能因此触发样式对比。

**修正 ADR 0020 第 1 条**：选择状态只保存地图需要的信息，即要素身份（数据源和稳定的业务 ID）和高亮所需的数据。候选列表、详情等接口数据留在 feature 的查询缓存里，会话不另存一份（AGENTS.md"接口数据由查询缓存持有"）。高亮分组直接引用查询结果中的对象，不复制。

### 7. 样式之外的两个通道

- **feature-state**：它不在瓦片或 GeoJSON 的属性里。如果使用，作为会话中的一个独立通道（按数据源、源图层、要素 ID 存储），两个视图都读它。高亮是用 feature-state，还是用按要素 ID 过滤的图层，做高亮时实测再定：改过滤条件会让 MapLibre 重新处理瓦片，改 feature-state 不会
- **图片**：填充图案由图案 ID 确定性地生成，不作为状态保存。二维通过 `setMissingStyleImageResolver` 调用生成器；三维的 Worker 用 `OffscreenCanvas` 调用同一个生成器。需要从地址加载的图标出现时，再加图片登记

## 后果

- 好处：区划裁剪的过滤还原、伴随图层、层级重排这些命令式逻辑变成纯函数，可以单独测试
- 好处：首次挂载、增量更新、暂停后恢复、失败后重建都基于"快照对比"，只有一条路径
- 好处：分组整体替换，跨分组用一次提交，消费方看不到半完成的状态
- 代价：每个拥有者都要写推导函数；每轮事件循环都要对比一次完整样式（约 0.15 ms）
- 代价：需要安装 `@maplibre/maplibre-gl-style-spec`，版本与 maplibre-gl 依赖的一致（ADR 0019）
- 约束：ID 在分组之间必须唯一；GeoJSON 数据一旦交给会话就不能原地修改，要换成新对象，否则按引用比较时发现不了变化
