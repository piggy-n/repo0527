# 0064. 页面导航失败的提示与恢复

- 状态：已接受
- 日期：2026-10-19

## 背景

地图页和运行时通过动态导入加载。加载失败发生在页面挂载之前，地图内部的失败状态与重试按钮不能覆盖它。`router.onError` 会收到导航异常，但导航返回的 Promise 仍会拒绝，程序式跳转需要接住它。

## 候选方案

- 在每个跳转入口提示：首次导航、浏览器前进后退仍会遗漏，也容易重复提示
- 自动重试或刷新：网络未恢复时可能反复请求，刷新还会丢失临时状态
- 应用根部统一显示失败，由用户选择重试或刷新：覆盖首次导航，保留当前页面

## 决定

1. 在鉴权守卫之前登记导航恢复，失败保存为 app 内的响应式状态；应用根部用现有的 Element Plus 对话框显示一份提示，不使用全局 MessageBox
2. 只接受当前导航的错误，旧导航晚到的错误不能重新打开提示；成功导航清除失败，原始异常保留在控制台
3. 重试重新经过路由守卫，保留目标路径、查询和锚点，使用 replace；重复点击不并发。刷新重新打开失败目标，不自动重试或刷新
4. 程序式跳转使用 `shared/router/navigate`，只在返回 true 时执行成功后的动作。异常提示由 app 负责，调用方不重复提示；RouterLink 沿用其导航处理
5. 登录页的空闲预加载失败仍静默；真正导航失败时才提示。已经挂载的地图引擎失败继续由地图状态与重试机制处理

## 后果

无需新依赖，也不扩展为通用错误监控。导航故障测试覆盖首次加载、重复失败、恢复、查询与锚点、权限变化和旧导航晚到；生产分块的失败与刷新由下一步浏览器冒烟覆盖。
