# 0104. 数据查询：四个页面共用一个组件、高级查询并入页签、通用的绘制工具

- 状态：已接受
- 日期：2026-10-29

## 背景

"查询统计 → 数据查询"下有四个页面。旧项目里国土变更调查、城市国土空间监测共用 `views/space-monitoring-query/index.vue`（4780 行），按路由 meta 的 `queryModule` 换图层配置（`config.js` 1550 行）；森林草原湿地荒漠、水资源两个页面是 `views/data-query-map`，只有地图和"建设中"角标。

旧页面左上是"当前模块"的面板（属性查询、空间查询、自然语言查询三个模式），旁边的"高级查询"按钮切出第二个面板；底部是结果栏（属性表格、统计图、统计表三段，可以收起、最大化）和导出。2026-10-28 读完代码、实测接口（[migration.md](../migration.md)"数据查询：接口实测"），发现：统计图、统计表是写死的假数据；输入框的 LIKE 不加通配符（等于精确匹配），NOT 拼出的 SQL 不合法（后端 500）；配置里有字段名写错（医疗机构的两个"是否"字段都写成 `IFTC`、城镇村的"备注"写成 `FEATID`、地类名称有两处选项错位），结果表有两列字段名和返回对不上；空间查询直接用 mapbox 画框和多边形，`getSpatialQueryFitPadding` 自己算定位留白。

用户要求最小必要迁移：保留核心功能和交互，样式按新规范，高级查询并入空间查询之后作为独立页签。设计稿（`public/design.local/data-query/`，不入库）当天确认，四项取舍按建议执行。

## 候选方案

1. **四个页面**：四个路由各一个组件；一个组件按路由 `props` 换专题
2. **高级查询**：保留单独的按钮和第二个面板；并入页签
3. **空间绘制**：在 feature 里写；做成 `shared/map` 的绘制工具；做成 map-core 的通用绘制
4. **统计图、统计表**：照搬；去掉
5. **LIKE、NOT**：照旧；改成包含、不包含

## 决定

1. **一个页面组件，专题由路由 `props` 给出**（`pages/data-query/DataQueryPage`）。四个路由是同一个组件实例，换专题时按专题加 `key` 整页重建，条件、结果、地图都不带过去（同旧页面的 `resetQueryModuleState`）。专题、图层、条件字段、结果列和自然语言规则是 `features/data-query` 的数据（`topics.ts`、`layer-fields.ts`）；地类编码表只写一份，地类名称的选项由它推出；森林草原、水资源是没有图层的专题，面板只显示"建设中"
2. **四个页签**：属性查询、空间查询、高级查询、自然语言查询，标题下面单独一行（标题和四个页签放不进 320 宽的一行）。属性查询和自然语言查询共用结果，其余切换清掉结果；离开空间查询时结束绘制、清掉画的范围（同旧页面）。各页签的表单是各自的拥有者，`useDataQuery` 负责切换、提交和重置的规则；组合式函数不提示，提交返回结果对象（不能查询的原因、画完还没选图层、自然语言没有识别），由面板提示
3. **绘制工具放在 `shared/map/draw`**：框选、多边形不属于某个业务域；框选复用点/框选的手势（`box-gesture`）和浮层（`BoxSelectOverlay`），关掉拖动平移、按住修饰键临时拖动（ADR 0056）；多边形同测面，单击加节点、双击完成。只保留一个画完的范围；都是临时任务，画完或 Esc 退回移动。发给后端的几何经 `queryGeometry` 整理（ADR 0051），整理不出来（如自相交）时提示重新绘制；为此把 `query-geometry` 和屏幕框转多边形、像素距离从 `features/resource-map` 移到 `shared/map`。没有放进 map-core：手势的纯函数已经在 shared/map，测面的绘制和这里规则不同（多条、带数值），暂不合并（ADR 0035 留的问题到此为止）
4. **结果面板只留属性表格**，去掉统计图、统计表（后端没有统计接口），记为待办。面板在地图中间一列底部，可以收起、最大化；分页每页 100 条，用 `usePagedList`（后端是 PageHelper）；查询面板和结果面板都用 `useMapOverlay` 登记，定位在结果面板挂上之后进行，替代旧的留白计算
5. **LIKE、NOT 按包含、不包含拼**（`LIKE '%值%'`、`NOT LIKE '%值%'`），下拉显示"包含 / 不包含"。旧配置写错的字段名按接口实际认的修正；结果表沿用旧页面的列，接口不返回的列保留、显示为空
6. **地图上的结果按拥有者推导分组**：属性类（属性、自然语言、高级查询）用带条件的 MVT，空间类画命中的要素；选了图层先显示全省的灰色预览，压在注记下面。瓦片走同源 `/backend`，条件做 URL 编码；结果用现状底图点选的高亮色
7. **其余照旧**：自然语言查询仍是模拟解析（等 2 秒、按预设规则回填属性查询，作废表示成结果对象，不抛错）；高级查询的导出仍"暂不支持"；shp 查询把文件放在正文里，导出时再传一次。导出经 `shared/file-transfer`，为此 `fetchFile` 的 POST 可以带正文

## 后果

- 好处：四个页面一份代码，专题之间不串状态；高级查询不再占一个按钮和一套面板；绘制、几何整理、几何的 schema 都在 shared，以后别的页面能直接用
- 代价：动了资源图层的三个文件（导入路径），和 main 上并行的修改可能冲突；绘制和测面各写一套点击规则
- 待办：统计图、统计表等后端有统计接口；高级查询导出；导出接口未登录时报错，要在登录后的业务页验收；学校的 `QUOTA`、`IFCON` 等表里没有的字段（[migration.md](../migration.md)）
