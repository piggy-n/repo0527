# 0041. 资源图层：目录、样式登记表、显示状态与数据源错误

- 状态：已接受
- 日期：2026-10-11
- 补充 ADR 0026 第 5 条（后端驱动的图层由拥有者校验）、ADR 0027（资源图层是 feature 的拥有者）；修正 ADR 0026 第 1、2 条（带数据源的错误不算样式加载失败，见第 6 节）

## 背景

现状底图的资源图层来自后端的资源树（`/resource-map/base/tree`），瓦片来自 `/api/tiles/{code}_{year}/{z}/{x}/{y}.pbf`。旧项目的做法见 migration.md 的现状底图一节：接口树按 `code` 去重后补上前端的样式登记表，所有资源的图层都放进样式、未勾选的设为隐藏，每个资源每个缩放分段建面、线、点三个图层。

5C.1b 用真实数据实测（结论见 migration.md"现状底图：资源图层实测"），和旧项目的假设有几处不同：

1. 瓦片是后端现场生成的，任何级别都有数据，旧注释里的"金字塔有洞"已经不成立；低层级的瓦片极重（南京位置的一张 z7：水域面层 42 MB、20 s，全部资源合计 124.5 MB），全省视图下勾选水域面层要 14.3 s 才画出来
2. 78 个资源里有 12 个没有瓦片，任何级别都返回 HTTP 200 加"系统异常"的 JSON；MapLibre 当作瓦片解析失败，`error` 事件带 `sourceId`。适配器现在只把 `event.error` 交给 `onError`，失败对应不到资源；而且样式整体加载期间收到的任何错误都按样式失败处理（ADR 0026 第 1 条），数据源的错误也可能把整个视图错判为 `failed`
3. 未勾选的图层放进样式（隐藏）并没有让重新勾选变快，隐藏时 MapLibre 反而重新请求了这些数据源的瓦片
4. Chrome 下 MapLibre 默认只有 1 个 Worker（只有 Safari 会多开），4 个时全选快约 40%
5. 瓦片里的几何类型与接口的 `geoType` 一致（城镇村等用地夹着 8 条退化的线）；地类图斑、地类图斑（城镇村）的样本瓦片里，地类编码和名称都在表 A.2 之内
6. 瓦片出错不会触发重绘，没有重绘就没有 `idle`

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 放在哪里 | `shared/map`；一个 feature | feature `features/resource-map`（与后端的 `/resource-map` 对应）：资源图层属于业务域（ADR 0027）；面板、图例、符号编辑、点选详情都读同一份目录，feature 之间不能互相导入，所以都放在这个 feature 里 |
| 显示状态的身份 | `code_年份`（旧项目）；`code`，年份单独存 | `code`（5A 已定）：换年份是推导结果变了，勾选、透明度、顺序不丢 |
| 目录重新加载后 | 重新初始化；原样保留；按资源合并 | 按资源合并（第 3 节）：保留已有资源的设置，丢掉不存在的资源和年份 |
| 未勾选的图层 | 放进样式、隐藏（旧项目）；不放进样式 | 不放进样式：实测没有收益，隐藏时还多出瓦片请求 |
| 每个资源几个图层 | 面、线、点三个（旧项目）；按 `geoType` 一个 | 按 `geoType` 一个：瓦片里的几何类型与它一致 |
| 缩放分段（旧项目的 `mvtZoomFallbacks`） | 照搬；去掉，改为每个资源的级别范围 | 去掉：瓦片是现场生成的，没有洞；每个资源一个数据源，显示和请求的级别范围由登记表决定 |
| 低层级太重 | 不限制；所有资源统一一个最小级别；按实测给重的资源单独设 | 按实测单独设：z7 单张超过约 2 MB 或生成超过约 2 s 的资源设最小显示级别（约 9～10），其余不限制；地类图斑默认勾选、全省视图 0.7～1.0 s，不限制 |
| 按属性配色（城镇村等用地） | 每次刷新随机（旧项目）；按值的顺序从配色板取 | 按值的顺序取：每次一样，图例能列出实际颜色（2026-10-11 讨论确定） |
| 地类图斑编码没命中 | 直接用兜底色；再按名称查历史分类 | 再按名称查历史分类：旧项目靠运行时发现地类间接做到，新项目不做运行时发现，写进表达式 |
| 瓦片错误 | 只打印；弹提示；对应到资源、标在面板上 | 对应到资源：不弹提示（一勾选会连续弹好几个） |
| 瓦片错误怎样传给拥有者 | 视图发出事件，拥有者记录并在适当时候清除；视图记录数据源的错误作为状态，拥有者推导 | 状态：清除的时机（数据源移除、整体重建、视图替换）由视图和 map-vue 决定，拥有者只推导（ADR 0039 规则 1：能写成状态收敛的不写成操作） |
| 带 `sourceId` 的错误 | 和其他错误一样处理；单独处理 | 单独处理，永远不算样式失败：数据源出错不影响整个视图 |
| 没有瓦片的 12 个资源 | 前端过滤掉；照常显示，勾选后标为失败 | 照常显示：资源树由后端给出，前端不另外过滤；问题告诉后端 |
| 后端配置的校验（ADR 0026 第 5 条） | 每次提交都校验；目录变化时逐个资源校验 | 目录变化时：用 style-spec 的 `validateStyleMin` 校验每个资源的图层，不合法的资源不进入推导、标为配置错误 |
| Worker 数量 | 用 MapLibre 的默认值；设 4 | `min(4, max(1, ⌊核数 / 2⌋))`：实测 4 个最好，再多主线程更卡；核数少的机器按一半，与 MapLibre 给 Safari 的算法一致 |

## 决定

### 1. 目录（纯函数）

- 接口的 schema（zod）按实测写：分类节点 `{ code: string | null, name, children }`，图层节点 `{ code, name, geoType: 'Polygon' | 'Line' | 'Point', resource, yearList: number[] }`（至少一个）；用"有没有 `children` 键"区分，不猜
- 目录由纯函数从接口树得出：按 `code` 去重并合并年份（升序、去重）；分类的 ID 用名称路径（有的分类 `code` 是 `null`）；资源按树里的顺序排列，记下所属分类、几何类型（`fill` / `line` / `circle`）和年份
- 同一个 `code` 出现在两个分类、或者几何类型不同：实测没有出现，出现时按第一次出现的为准，记进目录的问题列表，不抛错（目录在 `computed` 里得出，`computed` 不抛异常，ADR 0028）
- 资源树由 TanStack Query 缓存（ADR 0017），不放进 Pinia；加载失败时页面显示失败和重试，不回退本地快照

### 2. 样式登记表（按 `code` 的静态数据）

- 只登记和默认值不同的部分：最小显示级别、瓦片里的图层名例外（`bgdc_czcdyd_2022` 是 `czcdyd`，`bgdc_dltb_czc_2021` 是 `dltb_czc_2021`）、按属性配色、`promoteId`、默认勾选（只有地类图斑）
- 默认样式按几何类型：颜色按资源在树里的顺序从 10 色配色板循环取（与旧项目相同），面是半透明填充加同色描边，线是实色，点是实色加白描边
- 按属性配色写成数据（属性、取值、颜色或"按值的顺序取色"），由纯函数转成 `match` 表达式；图例（5C.4）读同一份数据
- 标注不在本次范围：需要时只带 Noto Sans 的 0-255 字形区段，汉字由 `localIdeographFontFamily` 用本地字体画（5C.1b 实测可行），时机另定

地类配色有两张表，用途不同，分别迁移、分别验证：

| 表 | 内容 | 用途 |
|---|---|---|
| 编码表 | 表 A.2 二级类，69 项：编码、名称、颜色（旧项目的 `LANDUSE_CLASS_TREE`） | 地类图斑按编码（`dlbm`）配色；地类图斑（城镇村）按名称（`dlmc`）配色 |
| 历史名称表 | 表 A.2 之外的 6 个历史地类名称和颜色（后备耕地、城市用地、建制镇用地、村庄用地、采矿及盐田用地、风景名胜及特殊用地；旧项目的 `LEGACY_NAME_COLORS`） | 编码表没命中时按名称兜底 |

- 地类图斑：先按编码匹配编码表；没命中再按名称匹配历史名称表；都没命中用兜底色（旧项目的 `rgba(128, 128, 128, 0.5)`）。旧项目靠运行时发现地类，把表外的编码按名称补进历史颜色；新项目不做运行时发现，所以直接写进表达式
- 地类图斑（城镇村）：按名称匹配编码表的名称和历史名称表（共 75 个名称）；名称为空时先把编码换成名称（编码表的 69 项，加城镇村编码 201～205（含 203A）对应的历史名称，同旧项目的 `LANDUSE_NAME_FROM_CODE`）
- 测试分别验证：编码表的 69 项与旧项目逐条一致；历史名称表的 6 项与旧项目逐条一致；编码到名称的对照与旧项目一致；用 style-spec 对样本要素求值，覆盖编码命中、编码没命中但名称是历史分类、都没命中三种情况
- 5C.1b 的样本瓦片（6 个位置、3 个级别）里没有表外的编码和名称；历史名称表为旧数据保留，成本很小

### 3. 显示状态与拥有者

- 拥有者 `useResourceLayers`（feature 的组合式函数，ADR 0031 的写法）持有按 `code` 的显示状态：勾选、透明度、顺序、年份（默认最新的一年）；`shallowRef` 整体替换，值没变时不替换；操作的参数不合法时抛错
- 勾选、透明度、顺序的界面在 5C.2，持久化在 5C.3，年份的界面在 5C.8；本次只做状态和操作

目录重新加载后，显示状态按资源合并（持久化恢复的状态同样按这些规则合并，不直接使用存下的值）：

- 目录里仍有的资源：保留用户的勾选、透明度和顺序
- 新出现的资源：用默认值（登记表的默认勾选、默认透明度）；顺序上插到目录里排在它后面的第一个已有资源之前，没有就排在最后
- 目录里没有了的资源：删掉它的全部状态
- 年份：当前年份仍在资源的年份列表里就保留，否则改用最新的一年

分组推导是纯函数：

- 只有勾选的资源进入 `resources` 分组；每个资源一个数据源（`resources-<code>`，矢量瓦片）和一个图层（按几何类型，`filter` 限定几何类型，见 AGENTS.md 的地图规则）；面板上排在前面的资源画在上面
- 数据源的瓦片地址：用 `appConfig.apiBaseUrl` 和 `location.origin` 先得到绝对的基础地址（MapLibre 在 Worker 里请求瓦片，要绝对地址），再拼上 `{code}_{year}/{z}/{x}/{y}.pbf`（不经过 `URL`，否则 `{`、`}` 会被转义）；不带 token（瓦片不校验 token，5A 实测）
- 级别：数据源的最大级别约 15，更高的级别由 MapLibre 放大；有最小显示级别的资源，数据源和图层用同一个最小级别，不请求低层级的瓦片
- 最小显示级别要能被界面解释：拥有者给出每个资源的最小显示级别，面板（5C.2）结合当前的缩放级别，对勾选了但还不显示的资源提示"放大至第 N 级显示"，避免被当成加载失败

### 4. 校验

- 目录变化时，对每个资源用 `validateStyleMin` 校验只含它的数据源和图层的样式；不合法的资源不进入推导，状态标为"配置错误"，原因交给 `onError`
- 只在目录变化时校验（ADR 0026 第 5 条）：显示状态的操作自己校验参数（如透明度在 0～1），不在每次提交时校验
- 配置错误随目录变化，不随视图清除（见第 5 节）

### 5. 数据源错误（视图的状态）

- 视图记录当前样式里每个数据源的第一条错误（MapLibre 的 `error` 事件带 `sourceId` 时），作为视图状态的一部分，变化时发出事件；没有 `sourceId` 的错误照旧
- 记录的清除由视图决定：数据源从样式里移除时清掉它的记录（取消勾选；换年份时数据源的地址变了，同样是先移除再添加）；整体重建开始时全部清掉（新的一轮，错误会重新出现）；视图释放时随之消失
- map-vue 把当前视图的记录桥接成上下文里的只读状态；卸下、替换视图时置空，新视图从空开始（引擎失败后重试，旧视图上的失败不会留到新视图）
- 资源拥有者从中推导每个资源的"瓦片加载失败"（按数据源 ID 的前缀对应到资源）；它和目录校验产生的"配置错误"分开记，前者随视图和数据源清除，后者随目录
- 含义：当前视图里这个资源至少有一张瓦片加载失败，不表示整个资源不可用（可能只是部分区域失败）；面板（5C.2）的措辞按这个含义写，不弹提示
- 三维视图接入时，自己的瓦片加载失败按同样的形式记录

### 6. 带数据源的错误不算样式失败（修正 ADR 0026 第 1、2 条）

- ADR 0026 第 1 条"加载中收到 `error` 就判定加载失败"、第 2 条"应用增量命令期间同步收到 `error` 就整体重建"，只适用于没有 `sourceId` 的错误
- 带 `sourceId` 的错误只进第 5 节的记录，照样交给 `onError`，不影响视图的状态和整体重建

### 7. 运行时

- app 的 `setupMapRuntime()` 设置 Worker 数量 `min(4, max(1, ⌊navigator.hardwareConcurrency / 2⌋))`
- 瓦片出错时 MapLibre 不发 `idle`：以后依赖"加载完成"的功能（5C.4 的图例统计）不能只等 `idle`，到时另定

## 后果

- 好处：未勾选的资源不占样式，全选时也只有 78 个图层（旧项目约 234 个）；换年份、改透明度不重建地图；目录重新加载、持久化恢复都不丢用户的设置
- 好处：没有瓦片的资源在面板上能看出来，不再只是控制台里的一串错误；数据源出错不会再被错判为整个视图失败；重试后旧视图的失败不会残留
- 好处：重的资源在全省视图下不请求几十 MB 的瓦片，面板上说明要放大到几级
- 代价：最小显示级别、例外表是按实测写死的，后端数据变了要重新测（开发页 `/dev/resources` 和 5C.1b 的探测方法留着）
- 代价：视图接口多了数据源错误的状态，三维视图要补上同样的记录
- 待定：标注的时机；图例统计怎样判断加载完成（5C.4）
