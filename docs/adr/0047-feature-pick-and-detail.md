# 0047. 点选与详情：渲染要素识别、guid 主键与完整几何高亮

- 状态：已接受
- 日期：2026-10-14
- 补充 ADR 0022 第 6 条（会话的选择状态）、ADR 0024（视图的只读查询）、ADR 0034（点选工具）、ADR 0011（没有信封的接口）

## 背景

5C.6 迁移旧页面的点选、框选与详情面板，本文定点选（5C.6a）和两者共用的部分；框选（5C.6b）另写 ADR，第 9 节只记下讨论得出的方向。

### 旧项目（yzt `master-demo` 836f03b，`components/CommonMap/selection/` 约 1200 行、`FeatureDetailPanel.vue`）

- 工具栏的"点选"是常驻模式：单击识别，点选模式下拖动画矩形框选；Esc 关闭
- 识别：按图层的渲染顺序逐个资源识别，命中就锁定这个资源。14 级以上且渲染出的要素都有主键时直接用瓦片要素；否则把屏幕上的容差框（点 10、线 8、其他 6 像素）换成地理范围，调后端的分页范围查询（每页 30 条，可加载更多）
- 只有一个候选时直接选中，多个时列出候选（按"包含点击位置、渲染顺序、屏幕距离"排序）；从候选进入详情后可以返回列表，返回时恢复列表的滚动位置和进入前的视角
- 详情：按主键查属性，再用"全世界范围 + 主键条件"取完整几何（范围查询返回的几何会被裁到查询范围内）；不用瓦片的片段当完整几何
- 高亮：单独的 GeoJSON 数据源放完整几何（面填充 0.12 加描边、线、点），红色 `#f5222d`，描边宽度跟随原图层；选中后定位（`fitBounds`，最大 17 级），从候选选中或低级别识别时闪烁两次
- 主键按资源配置的字段、`promoteId` 或 `bsm`、`wybm`、`objectid`、`fid`、`id` 依次找；都没有时用"全部属性相等"拼条件，唯一命中才算
- 字段名先读资源管理的字段配置，没有时地类用本地的中文名，其他显示字段编码
- 区划裁剪（5C.7）的范围参与命中判断和高亮裁剪

### 实测（2026-10-14，真实后端）

- 查询接口没有信封：`/api/query/scope/geojson/page`、`/api/query/attr/page` 成功时直接返回 `{ total, list, … }`，`/api/query/scope/geojson` 直接返回数组；失败时返回 `{ success: false, code: 500, data: null, msg }`。`shared/http` 要求 `{ code, msg, data }` 信封，解析不了成功的返回
- 分页范围查询只有属性、没有几何；不分页的范围查询返回 `[{ guid, geom }]`，`geom` 是 GeoJSON 字符串，几何被裁到查询范围内；用"全世界范围 + 条件"得到完整几何
- 所有资源的瓦片要素都带 `guid`；属性查询、几何查询都能以 `"guid" = '…'` 为条件（地类图斑按 `bsm` 取几何 18 ms、按 `guid` 552 ms；城市现状图斑按 `guid` 查属性 22 ms、几何 326 ms）
- 资源分三类：`bgdc_*` 的分页范围查询结果带 `guid`、`bsm`；`csxhjctb_*` 的分页范围查询结果不带 `guid`，也没有其他主键字段，但按 `guid` 查属性、几何都可以；`szy_*`、`lcsh_*`、`gtkjgh_*` 的查询接口都返回"系统异常"
- 资源管理的字段配置能按"数据集_图层_年份"找到记录，但字段名目前都是空或"字段1"这样的占位
- 部分 12、13 级的地类图斑瓦片为空（见 roadmap 待办），这些地方停在这两级时渲染要素里点不到

### 框选的实测（2026-10-14，地类图斑，涟水一带）

旧项目的框选最多 200 条：框得大时要等后端统计完才提示"超过上限"，反馈太晚。实测各环节：

- 分页范围查询的第一页（带总数）：框内 34～1.2 万个要素时 0.1～0.7 s，4.8 万 1.2 s，17 万 2.1 s，62 万 8.1 s；每页 1 条和 200 条耗时相近，时间主要花在统计上
- 补完整几何（旧做法：30 个主键一组 `OR` 条件、4 个并发）：200 个 7 组约 1 s、169 KB；按比例 2000 个约 10 s，1.2 万个超过 1 分钟
- 不分页的范围查询一次返回全部（几何裁到框内）：254 个 171 KB，934 个 644 KB，3678 个 2.5 MB（约 0.7 KB/个）；属性约 0.5 KB/个
- 旧流程反馈晚的原因：大框的统计本身要几秒；资源按顺序逐个查询，上面没有命中的资源每个也要等 0.2～0.7 s；没有超限时还要逐个补完整几何才显示

### 已有的约定

- ADR 0022：会话分样式、相机、工具、选择四部分；选择状态只存要素身份和高亮所需的数据，候选列表和详情留在 feature 的查询缓存里，高亮分组直接引用查询结果
- ADR 0024：适配器按需要提供只读的查询方法，要素属性按 `unknown` 返回
- ADR 0034：移动、点选是常驻模式，测距、测面是临时任务；工具只拿到 `ToolView`
- ADR 0039：同一件事的先后请求后发覆盖先发（`LatestController`）
- ADR 0041、0045：一个资源一个数据源（可以有多个图层），点选按数据源判断资源

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 范围 | 点选、框选一起；先点选再框选；只做点选 | 先点选（5C.6a），再框选（5C.6b）：两者共用识别后的流程、详情和高亮，框选只多一种识别方式和矩形绘制 |
| 主键 | 按资源配置的字段或常见字段名，没有时按全部属性匹配（同旧项目）；统一用 `guid` | `guid`：所有资源的瓦片都有，查询接口都能按它作条件，`csxhjctb_*` 不用再按全部属性匹配 |
| 识别 | 渲染要素优先、后端兜底（同旧项目）；一律后端；只用渲染要素 | 渲染要素优先、后端兜底：快、和所见一致；低级别、空瓦片时有后端兜底；地图内核加只读的渲染要素查询 |
| 高亮 | 完整几何的 GeoJSON 分组；feature-state；按 `guid` 过滤的图层 | GeoJSON 分组：跨瓦片完整，定位也用同一份几何，三维直接镜像；feature-state、过滤图层都只覆盖已加载的瓦片，过滤图层还会让资源重新解析瓦片 |
| 字段名 | 迁移字段配置接口；先只用本地字段名 | 本地字段名：配置里的名称现在都是空的；资源管理模块迁移、管理端能配名称时再接，展示层留好字段名的来源 |
| 面的容差 | 同线、点，6 像素；只取包含点击位置的面 | 只取包含点击位置的面：面的边界处 6 像素的容差会让相邻图斑都成为候选，点一下常常要再选一次 |
| 选中后定位 | 每次都定位（同旧项目）；只在从候选选中、后端识别时定位 | 后者：直接点中的要素就在眼前，定位只会放大打断浏览；从列表选中、低级别识别的要素可能很小或不在当前位置，需要定位并闪烁 |
| 移动地图时 | 取消识别（同旧项目）；不取消 | 不取消：识别用的是点击时换算出的地理范围，移动后结果仍然对应原来的位置；新的点击、Esc、关闭、换工具时作废 |
| 没有信封的接口 | 每个接口函数自己用 axios；`shared/http` 加不带信封的模式 | `shared/http` 加 `envelope: false`：超时、取消、鉴权、错误提示仍走同一条路径 |

## 决定

### 1. 主键与资源的查询能力

- 要素身份是"数据源 + `guid`"，数据源 ID 反查资源（`resourceCodeOfSource`），图层编码是 `资源编码_年份`（同瓦片集名）
- `guid` 在拼条件前校验格式（32 位十六进制），不符合时不发请求
- 查询能力按数据集前缀登记在 feature 里（实测得出，后端变化时改这张表）：

| 数据集 | 后端范围识别 | 详情（属性、完整几何） |
|---|---|---|
| `bgdc_*` | 可以 | 可以 |
| `csxhjctb_*` | 不可以（结果不带 `guid`） | 可以 |
| `szy_*`、`lcsh_*`、`gtkjgh_*` | 不可以 | 不可以 |

### 2. 识别

- 点选工具的单击（不是拖动后的松手）触发识别；资源按叠放顺序从上到下，只看勾选、在当前级别显示、没有被校验拦下的资源
- 渲染要素：地图内核的只读查询（第 4 节）取点击位置的要素，面取包含点击位置的，线、点取 8、10 像素的容差框；按数据源归到资源，按 `guid` 去重
- 逐个资源：14 级以上且有渲染要素时用渲染要素；否则能做后端范围识别的，把容差框四角经 `pick` 换成地理范围调分页查询（每页 30 条）；都不行时有渲染要素就用渲染要素。第一个有结果的资源胜出，后面的不再查询
- 只有一个候选、没有更多页时直接选中；否则列出候选：资源名、年份与名称（地类取地类名称，其他取 `name`）、几何类型；渲染要素按"包含点击位置、屏幕距离"排序，后端结果按返回顺序；有更多页时可以加载更多
- 识别是可替换操作（ADR 0039）：新的点击作废上一次；Esc、关闭面板、离开点选工具时作废并清除

### 3. 详情

- 能查详情的资源：按 `guid` 并行查属性（`/api/query/attr/page`，行政区 `320000`）和完整几何（`/api/query/scope/geojson`，全世界范围）；属性不是恰好一条、几何不是恰好一条时报错，可以重试
- 不能查详情的资源：属性用渲染要素的属性，没有完整几何，不高亮、不能定位，面板注明"这个资源暂不支持查询完整信息"
- 详情由 TanStack Query 持有（按图层编码和 `guid` 缓存），切换选择时取消上一个；会话、组件都不另存一份
- 字段按接口返回的顺序列出，不显示 `guid` 和几何；字段名：地类图斑（含城镇村）用本地的中文名（迁自旧项目，大小写不敏感），其他显示字段编码；空值显示 `-`

### 4. 地图内核：选择状态与渲染要素查询

- 会话加上 `selection`：当前选中的要素 `{ sourceId, featureId }[]`，可以设置、清除，变化时发事件；只存身份，不存属性和几何（ADR 0022）
- 视图加只读查询 `queryRendered(area, { sources })`：`area` 是屏幕上的点或矩形，返回从上到下的 `{ sourceId, layerId, properties, geometry }`，`properties` 是 `Record<string, unknown>`，`geometry` 是渲染用的几何（可能被瓦片切开，只用于排序和距离）；只在 `ready` 时可用。加进 `ToolView` 和上下文的 `view`；三维视图返回空数组，识别退回后端
- map-vue 上下文加选择状态的读写（ADR 0028 留下的）

### 5. 高亮与定位

- 选择的拥有者推导 `selection` 分组：从会话的选择和详情查询里的完整几何得出，直接引用查询结果的几何，不复制；放在 `resources` 之上、`basemap-labels` 之下
- 面是 0.12 透明度的填充加 3 像素描边，线 3 像素，点是半径 8 的圆加白色描边；红色 `#f5222d`（同旧项目），描边宽度不跟随原图层（5D 再看）
- 加载详情时不高亮；从候选选中、低级别后端识别选中时定位（相机操作 `fitBounds`，最大 17 级，避开悬浮元素）并闪烁两次（`#ff7875`，每 200 ms 切换），直接点中的不移动相机；面板上可以随时"定位到要素"
- 从候选进入详情时记下视角，返回列表时回到这个视角

### 6. 交互与状态的变化

- `shared/map` 的工具栏加"点选"按钮（工具 ID 由 `shared/map` 导出），实现由 feature 用 `registerTools` 登记：常驻模式、默认箭头光标，5C.6a 不关拖动平移（5C.6b 加框选时再关）
- 离开点选工具（换成移动、测距、测面）时清除选择和面板（同旧项目）
- 选中的资源取消勾选、换了年份、目录重新加载后不在了时清除；叠放顺序变化时保留详情，但不能再返回旧的候选列表
- 移动地图不取消识别和详情

### 7. 界面（5D 之前只做到能联调）

- 详情面板在右列：识别中、候选列表、加载中、详情、失败五种状态；标题是资源名，副标题是年份与名称；按钮有返回、关闭、加载更多、重试、定位到要素
- 面板登记为贴右边的悬浮元素；状态和操作都在拥有者里，面板只显示和调用

### 8. 接口

- `shared/http` 加 `envelope: false`：成功的返回直接按 schema 校验；返回体是 `{ success: false }` 或带非 200 的 `code` 时按业务错误处理；超时、取消、鉴权、提示和有信封时一样
- 查询接口写在 `features/resource-map/api.ts`，返回值由 zod 推断；几何字符串解析后按 GeoJSON 几何校验；不能用时给出资源名和原因，不弹全局提示（`silent`），由面板显示

### 9. 框选（5C.6b，另写 ADR）

不沿用旧项目的 200 条上限，也不取消上限后全部取回：取消上限时，统计随数量线性变慢、补完整几何的请求数是 N/30、不分页的接口在几十万条时返回几百 MB，前端几万个要素的对象占几百 MB，几千行的列表也没有人能逐条看。5C.6b 按下面的方向设计：

- 交互：点选模式下拖动画矩形（屏幕空间），关掉拖动平移；滚轮、Esc、失焦、地图移动时取消
- 即时估数：松手时先用矩形内的渲染要素按 `guid` 去重计数（毫秒级），明显过多时立刻提示缩小范围，不请求后端；估计值在低级别（瓦片简化）、空瓦片处偏少，只用于尽早拦下，准确的总数以后端为准
- 后端只取第一页和总数，按页加载（"共 N 个，已显示前 M 个"），不设硬上限，每次只取一页
- 批量高亮在瓦片上做（按 `guid` 的 `match` 过滤图层或 feature-state），不逐个取完整几何；选中其中一个后同点选，用完整几何高亮和定位
- 列表虚拟滚动或分页；总数很大时引导缩小范围，或到阶段六的数据查询里统计、导出
- 14 级以上的瓦片带全部属性，列表可以先用渲染要素的属性，后端给出准确总数和低级别兜底
- 需要后端配合的优化：统计加上限（数到上限加一就停），或不统计、只返回有没有下一页的分页

### 10. 验收

- 地类图斑 14 级以上点中直接出详情、高亮跨瓦片完整；低级别、12～13 级空瓦片处由后端识别，列出候选、选中后定位并闪烁；加载更多
- 城市现状的线、点按容差点中，详情能查到属性和完整几何；`szy_*` 只显示瓦片属性
- 多个资源重叠时选中最上层的；取消勾选、换年份、离开点选工具时清除；Esc 关闭；新的点击作废旧的识别（慢网络下先点后点，结果是后一次）
- 返回候选列表时回到进入前的视角；面板不挡住定位（悬浮元素避让）

### 11. 分步

- 5C.6a-1：地图内核的选择状态与渲染要素查询（含浏览器测试）、map-vue 上下文的选择读写
- 5C.6a-2：`shared/http` 的 `envelope: false`；查询接口、查询能力表、识别与详情的纯函数
- 5C.6a-3：选择的拥有者、点选工具、`selection` 分组、详情面板、页面组装，真实数据验收
- 5C.6b：框选（另写 ADR）

## 后果

- 好处：主键统一成 `guid`，不再需要按全部属性匹配；高亮和定位用同一份完整几何，三维镜像会话即可
- 好处：识别优先用渲染要素，高级别下点击只发详情的两个请求
- 代价：查询能力表靠实测维护，后端支持的资源变化时要改；`csxhjctb_*` 在低级别只能点到渲染出的要素
- 代价：地图内核多了选择状态和渲染要素查询，三维接入时查询退回后端
- 代价：`shared/http` 多一种解析模式
