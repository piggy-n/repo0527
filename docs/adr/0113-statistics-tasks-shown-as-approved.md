# 0113. 资源审核里的统计任务按审核通过显示，名称后标"统计任务"；准备状态 error 换成处理失败

- 状态：已接受
- 日期：2026-10-29
- 修改：ADR 0092 第 3、6 节（统计任务标成"统计任务"）

## 背景

后端把基本统计的任务（`status: 'table'`）混在申请表里。ADR 0092 在审核状态列显示"统计任务"标签，并请后端排除它们。用户 2026-10-29 要求审核状态参考旧项目，统计任务显示"审核通过"等对应状态，有更合理的命名可以讨论。

核对旧项目（`views/resource-application/components/ApplicationListSection.vue`）：`resolveAuditStatus` 把 `table` 当作 `approved`，显示"审核通过"（管理员侧写成"申核通过"）；数据准备状态照常显示；操作是置灰的"查看"和准备完成后的"下载"。准备状态 `error` 换成 `failed`（"处理失败"）。

只照旧显示的问题：按"审核通过"筛选时后端只返回 `approved`，统计任务显示成审核通过却筛不出来；它们也不是真的申请（没有图层、区划，常常没有名称）。

## 决定

用户选推荐方案：

- 审核状态列：统计任务显示"审核通过"（绿色），同旧页面
- 数据名称列：统计任务的名称后面跟小号标签"统计任务"（`tag-mini`，灰色）；没有名称时只有标签。名称放不下时先省略，标签始终完整
- 操作照旧：统计任务没有"查看"，准备完成时可以下载
- 准备状态：后端 2026-10-30 起返回 `error`，原来的 schema 不认识，整页报"加载失败"。按旧页面换成 `failed`（"处理失败"）；其他没见过的值仍按返回格式错误处理

## 后果

- 筛选"审核通过"时仍然不包含统计任务；请后端排除统计任务的待办不变
- 筛选"处理失败"传给后端的是 `failed`，存成 `error` 的记录可能筛不出来，联调时核对
- 统计报表的状态是另一处显示（`isPrepareStatus` 不认识的照原文显示），这次没有改
