# 0167. 图层记住三维模型和顺序，后加入的放在最上面，行内提示可以按类关掉

- 状态：已接受（2026-11-17 用户提出三条：图层要记录三维模型；加入的顺序"后进的无论是模型还是资源，都压在最上面"；行内提示加总开关和每项的开关，关掉的一类在数据加载的明细里也不显示。用户随后说明这些开关只在配置文件里配，选了 `.env`，不做界面、不按账号记。白膜效果也记、按类开关、关掉加载失败时重试一起隐藏、行内的瓦片失败和明细改成同一份，都按推荐）
- 日期：2026-11-17
- 取代：ADR 0161 第 3 节（新加入的放在哪），以及 0161 第 1 节和后果里"两者怎样穿插不持久化"；ADR 0157 里"三维模型的列表不持久化"
- 修改：ADR 0041 第 5 节、0059（资源行的"有瓦片加载失败"改按请求状态这一轮的失败，不再按视图的数据源错误）
- 补充：ADR 0158（条目和明细按类显示）、0042 和 0140（两项新偏好）

## 背景

- 2026-11-17 摸底的现状：
  - 刷新、重新登录、离开页面再回来时，二维资源的加入、显隐、年份、透明度、标注和资源之间的先后都恢复（偏好 `resource-layers`）。三维模型的加入、显隐、白膜效果、模型之间的先后都只在内存里，资源和模型怎样穿插（`useCurrentLayers` 的 `settled`）也不记，都清空。
  - 加入的规则是 ADR 0161 第 3 节：新模型放最上面，新资源插在"最上面那个模型"的紧下面。顶上连着几个模型时，新资源夹在第 1、2 个模型之间，每次都是第 2 位；画面上和放在所有模型下面一样，只是列表不对。另外再加一个模型时，它会排到原来盖住模型的资源上面，那个资源就不再盖住模型。
  - 名称后面的提示（加载中、瓦片加载失败、配置错误、未到显示级别、盖住模型、模型加载失败和重试）没有任何开关。
  - 行内的"有瓦片加载失败"来自视图的数据源错误：每个数据源只记第一条，换年份、样式重建时才清掉。明细里的失败是这一轮的统计，下一轮开始就清零。两处可能对不上：明细里已经没有失败，行内的三角还在。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 加入的位置 | A 现状；B 新资源放在"模型下面那些资源"的最上面，新模型放在盖住模型的资源下面；C 后加入的都放最上面 | C（用户）：一句话说得清、最好预测，常见的 GIS 软件也这样。代价是三维里新加的面会盖住模型，有"盖住模型"的图标提示，自己调透明度或往下挪 |
| 记在哪 | 页面一项偏好记全部；模型和顺序各由拥有者记 | 各记各的：模型的状态在 `useSceneModels`，穿插在 `useCurrentLayers`，拥有者自己持久化（`.claude/rules/state.md`） |
| 顺序什么时候写 | 列表一变就写；只在用户操作时写 | 用户操作时写（加入、移出、移动）：恢复、目录晚到引起的变化不是用户的操作。偏好读取还没回来时列表就变，会被当成"已经操作过"而放弃恢复。唯一的例外是都到齐以后丢掉没有了的行，也写回去 |
| 开关的粒度 | 每个图层单独开关；按类 | 按类（用户按推荐） |
| 开关放在哪 | 面板上给用户开关、按账号记（偏好）；`.env`，按部署；代码里的产品开关（`shared/config/*-options.ts`） | `.env`（用户）：只由部署方决定，用户界面上没有开关；按部署取值的属于构建时的环境变量（`docs/config/overview.md` 的四类配置） |
| 关掉的在哪里生效 | 只管行内；行内和数据加载一起 | 一起（用户）：显示时过滤，数据照常统计 |
| 行内的瓦片失败 | 保持数据源错误；改成请求状态这一轮的失败 | 这一轮（用户按推荐）：和明细一致，下一轮没有失败就消失；数据源错误照样记录、打印到控制台 |

## 决定

### 1. 加入的位置

- 用户加入的（目录的添加、行尾按钮、右键菜单、Insert 键）整批放在列表最上面，批内保持给出的先后（目录里的先后），模型和资源一样。资源的拥有者把它们插在第 0 位，模型的拥有者放在最前，和列表的先后一致。已经在的不动；移出后再加入当作新加入。
- 新加的模型在最上面，原来盖住模型的资源落到它下面、不再盖住模型：后进的压在最上面。
- 不是用户加入、自己出现的（恢复以后出现的、目录或清单晚到的、目录里新出现的默认资源）接在最后，先模型后资源，不挤动已有的行。

### 2. 记住三维模型（偏好 `scene-models`，版本 1）

- `useSceneModels` 接收页面的偏好范围，记加入的模型（先后）、隐藏的、白膜换过的效果。不记加载状态、重试次数和漫游（速度、人称仍按 ADR 0086、0090 不记）。
- 清单到了才合并：清单里没有了的（换了服务器、站点缺这个模型，ADR 0164）丢掉，效果只留白膜、清单里还有的那一种。合并时不飞过去。合并之前列表里没有模型，拥有者的 `restored` 为 false。
- 移出时换过的效果一起忘掉（以前的说明这么写，代码没做），再加入是默认的效果。
- 页面仍然从二维进入：记下的模型在二维里列着、变淡，切到三维才加载。

### 3. 记住列表的顺序（偏好 `current-layers`，版本 1）

- `useCurrentLayers` 记整个列表的键（`resource:`、`model:`），只用它的穿插，内容按各自拥有者的先后（同 0161）；在加入、移出、移动时写，都到齐以后丢掉没有了的行也写回去。
- 目录、清单还没到时就操作：记下的顺序里还没到的项留着位置，跟在它前面最近的那个还在的行后面（`withPending`）。资源目录和模型清单都到了、记下的模型也恢复了以后，丢掉顺序里没有了的行。
- 加入时按拥有者里真有的行判断已经在不在：记下的顺序里还没到的（或模型的记录里已经没有的）照样能加入，放到最上面。
- 刷新以后，原来排在模型上面的资源照样盖住模型。

### 4. 行内提示的开关（`.env`，按部署）

- 六类：加载中、加载失败、加载完成（这三类同时管数据加载的条目和明细），配置错误、未到显示级别、盖住模型。
- 总开关 `VITE_LAYER_HINTS_ENABLED` 加每类一个 `VITE_LAYER_HINT_*`（`LOADING`、`FAILED`、`DONE`、`CONFIG_ERROR`、`MINZOOM`、`COVERING`），都为 true 才显示，提交的都是 true。只在 `shared/config/app-config.ts` 读，`appConfig.layerHints` 是开着的几类，种类列在 `shared/config/layer-hints.ts`。改了要重新构建，所有用户一样；界面上没有开关，也不按账号记。
- 关掉一类：行内的图标、状态栏条目和明细里对应的状态一起不显示，数据照常统计。关掉"加载失败"时模型的"重试"一起隐藏（明细里的重试本来就在"有失败"一组里）；都关掉时状态栏的条目不出现。关掉"加载中"时，还在加载、已有失败的项不算"有失败"，还有在加载的项时也不说"已加载完成"，条目和明细一致。
- 实现：页面把 `appConfig.layerHints` 交给面板（`hints`）和 `useRequestStatus`（显示哪几类）；`useRequestStatus` 的 `loadingKeys`、`failedKeys` 按它过滤，`requestSummary`、`requestGroups` 多一个参数；资源行的状态图标按 `statusKinds` 过滤，模型行的失败按 `failureShown`，盖住模型由面板判断。开发页不传，全都显示。

### 5. 行内的瓦片失败和明细用同一份

- 资源行的"有瓦片加载失败"改成请求状态里这一轮结束、有失败的（`failedKeys`），下一轮请求开始时清掉。这一轮还在加载时行内是转圈，结束后才是失败。
- `useResourceLayers` 不再推导 `tileErrors`；视图照旧记录数据源错误、打印到控制台（ADR 0041 第 6 节不变）。

### 6. 偏好的开关

- 两项偏好各有分项开关 `VITE_PREFERENCE_SCENE_MODELS`、`VITE_PREFERENCE_CURRENT_LAYERS`，提交的都是 true（ADR 0140）。开发页不传偏好范围，不读不写。

## 后果

- 刷新、重新登录、离开页面再回来，图层里的模型、显隐、白膜效果和整个列表的顺序都回来；换了服务器、站点缺的模型自动丢掉。
- 三维里新加的面资源会盖住模型（行内有"盖住模型"的图标）；以前默认在模型下面。
- 资源图层、三维模型、顺序三项偏好各自防抖写入，不是一次写完：只写了其中一项就关掉页面时，模型和顺序可能对不上，恢复时按"内容按拥有者"合并，不会出错，穿插回到大致的位置。
- 行内的瓦片失败不再一直留着：下一轮请求开始就清掉，和明细一样。一直失败的数据源要看控制台。
- 行内提示是部署的决定：想对某台服务器关掉一类，改那次构建的 `.env`（内网写在 `.env.intranet`）；用户自己关不掉。
- 多个标签页之间不同步，后写的为准（同 ADR 0042）。
