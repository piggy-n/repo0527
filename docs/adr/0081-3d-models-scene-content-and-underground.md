# 0081. 三维模型：3DT 清单、会话的三维内容与钻地

- 状态：已接受
- 日期：2026-10-26
- 落实 ADR 0078 第 3～5 节（3DT 清单、三维模型面板、钻地）；补充 ADR 0020、0028：三维独有的内容也由会话持有、拥有者推导

## 背景

3D.3 要把 3DT 模型加载到三维里：全省的模型由一份静态清单描述，三维时左侧换成"三维模型"面板，勾选即加载，可以定位、卸载、换白膜效果，定位到地下的模型时进入钻地观察。

现有的数据（旧仓库 `public/` 下，不入库，2026-10-26 查看）：

- `SZ_3DT`：苏州站地下空间，90 MB、60 个文件。根索引的 `geometricError` 是 53670，子节点引用外部索引（`./Tile_*/Tile_*.json`），其中一个是指向数据目录外的空占位 `../../../../../../../../../.json`（包围球全是 0、没有子节点）
- `SZ_WhiteModel`：苏州白膜，`plain`、`window`、`tech` 三种效果各是一套瓦片集（`shp-to-3dtiles` 导出的 b3dm），共 15 MB，索引正常

旧代码的做法：

- `prepareLocalTileset` 加载前整理索引：合并外部索引、跳过已核实的空占位、拒绝数据目录外的引用和循环引用、没有内容的节点取子节点误差的最大值、叶节点误差为 0、子节点误差不超过父节点；整理后的索引交给 Cesium（Blob 地址），瓦片地址改成绝对地址
- 瓦片集的参数：`maximumScreenSpaceError: 16`、加大缓存（站内实测显存约 200 MB）、移动时不请求、不预加载、`skipLevelOfDetail: false`、关闭动态误差和阴影、不做碰撞、双面渲染；第一个瓦片可见时才算"已显示"，瓦片失败算失败
- 地下空间用"头灯"光照：以相机为光源，和时间无关，转折面保留明暗
- 白膜：切到新效果时，新效果的首批瓦片到位前留着旧效果；切走的效果只隐藏不销毁；钻地时隐藏白膜（地面上的楼会挡住地下空间）
- 钻地：只把模型占地范围（外扩 40 米）里、离相机不远的地表变透明，透明范围随相机离地高度放大；土层颜色、相机进到地下时换深色背景；关掉碰撞检测、近裁剪面 0.1；退出时相机在地下的先飞回地表上方

用户 2026-10-26 选定：清单入库、模型数据不入库；索引在运行时整理；三维独有的状态放在会话里，拥有者绑定推导函数。

## 决定

### 1. 清单

- 位置：`apps/web/public/3dt/manifest.json`，入库；模型数据放在同一个目录下、不入库（和字体一样，`.gitignore` 只放行清单），部署时和数据一起放到 `${BASE_URL}3dt/`。开发时从旧仓库复制数据
- 格式（zod 校验，任何一处不合法整份清单按加载失败处理）：

  ```json
  {
    "models": [
      {
        "id": "sz-station",
        "name": "苏州站地下空间",
        "cityCode": "320500",
        "kind": "indoor",
        "underground": true,
        "tileset": "SZ_3DT/tileset.json",
        "spawn": { "lng": 120.6660669, "lat": 31.317559, "height": -5.1, "heading": 76 },
        "routes": [{ "id": "...", "name": "...", "path": [[120.66, 31.31, 2]] }]
      },
      {
        "id": "sz-white",
        "name": "苏州白膜",
        "cityCode": "320500",
        "kind": "white",
        "underground": false,
        "effects": [{ "id": "plain", "label": "无纹理", "tileset": "SZ_WhiteModel/plain/tileset.json" }]
      }
    ]
  }
  ```

- `kind` 是 `oblique`（倾斜摄影）、`white`（白膜）、`indoor`（室内）；白膜用 `effects`（至少一种，第一种是默认），其他用 `tileset`，两者有且只有一个；地址相对清单
- `cityCode` 必须在区划目录里，市名取自目录（`shared/map/region`），清单不写名称
- `spawn`（步行的出生点）和 `routes`（预置路线，`[经度, 纬度, 椭球高]`）在 3D.4 使用，3D.3 只校验
- 清单是业务数据，放在 `features/scene-models`：`api.ts` 用 `http.get` 读静态文件（不经过 `/backend`、没有信封），`queries.ts` 缓存

### 2. 会话的三维内容（map-core、map-vue）

- 会话加一份和引擎无关的三维内容（`SceneContentModel`）：

  ```ts
  interface SceneContent {
    readonly tilesets: readonly TilesetLayer[];
    readonly underground: { readonly tilesetId: string; readonly surfaceOpacity: number } | null;
  }
  interface TilesetLayer {
    readonly id: string;
    /** 索引的绝对地址：瓦片地址按它解析，会话校验 */
    readonly url: string;
    readonly show: boolean;
    /** 同组的只显示一个（白膜的各种效果）：换显示的那个时，旧的留到新的首批瓦片到位 */
    readonly group?: string;
    /** 地下、室内用头灯光照 */
    readonly lighting: 'sun' | 'headlight';
    /** 失败后重试时加 1，视图看到新的值就重新加载 */
    readonly attempt: number;
  }
  ```

- 整体替换、每次替换修订号加 1、同一轮事件循环合并通知，和样式模型一样（ADR 0022）；二维视图不读它
- 页面用 `map.bindScene(() => SceneContent)` 绑定拥有者的推导函数，一个上下文只能绑定一个（ADR 0028 的做法，只在 `provideMap` 所在组件的 setup 里绑定）
- `CesiumView` 按 ID 增删瓦片集，暂停期间的变化留到恢复时应用；每个瓦片集的状态通过视图的 `scenestatuschange` 报告：`loading`、`ready`、`failed`（索引或瓦片失败，带错误）
- `ready` 是索引整理好、瓦片集建好并加进场景，带上建议的相机（让整个包围球进入画布，俯角 55°）；不等第一个瓦片可见：不在画面里的模型不会有瓦片可见，等它就永远不能定位。钻地用的占地矩形由场景按包围球自己算，不报告
- 上下文的 `sceneStatus` 只反映当前视图的报告，二维时是空的（和 `sourceErrors` 一样，ADR 0041）

### 3. 加载（map-cesium）

- `prepareTileset(url, load)` 是纯函数（下载函数注入）：按旧代码的规则整理索引，地址都改成绝对地址；旧代码只整理苏州站，白膜直接加载。白膜的根节点没有内容、下面都是叶节点，按"没有内容的取子节点误差的最大值"会变成 0，Cesium 不再细分、什么也不画（页面验证时发现），所以这种节点保留自己的误差，苏州站整理的结果不变；`CesiumScene` 把整理后的索引作为 Blob 地址交给 `Cesium3DTileset.fromUrl`，参数沿用旧代码
- 头灯光照沿用旧代码的 `CustomShader`
- 索引和 GeoJSON 一样由视图注入的 `loadJson` 下载（ADR 0080），场景只拿到整理好的索引
- 释放视图时取消正在下载的索引，晚到的瓦片集直接销毁

### 4. 定位

- 定位是一次相机操作（ADR 0038）：拥有者用 `sceneStatus` 里建议的相机 `flyTo`；还没就绪的模型不能定位
- 定位到地下的模型时同时进入钻地；定位到地面上的模型时结束钻地

### 5. 白膜效果

- 白膜的每种效果是一个瓦片集，同一个 `group`；拥有者把加载过的效果都留在三维内容里，只有当前效果 `show: true`，换效果不重新下载
- 视图负责"旧的留到新的首批瓦片到位"（`initialTilesLoaded`），拥有者不管

### 6. 钻地

- 进入：定位地下的模型；结束：钻地条上的"退出钻地"、切到二维、卸载这个模型、定位地面上的模型
- 地表不透明度 0～60%，默认 25%，由钻地条的滑块改
- 视图的做法沿用旧代码：占地矩形外扩 40 米里、离相机不远的地表按设定的不透明度透明（范围随相机离地高度放大，最多 3 千米）；土层颜色和相机在地下时的背景色；关掉碰撞检测、近裁剪面 0.1；退出时相机在地下的先飞回离地 120 米，到了再恢复设置
- 钻地期间白膜不显示，由拥有者的推导决定（`show: false`）

### 7. 三维模型面板

- 按 ADR 0078 第 4 节和确认的原型（`/dev/map-3d` 的 `ModelListPanel`）：三维时左侧换成这个面板，二维时换回资源图层面板，两边的收起状态各自保留；两个面板放在 `KeepAlive` 里，切走的缓存起来，回来时搜索词、展开这些界面状态还在（停用期间量尺寸、登记悬浮元素按 ADR 0063 的做法）
- "已加载"按勾选的先后排列；状态来自 `sceneStatus`；"步行漫游""路线漫游"在 3D.4 接入，3D.3 不显示
- 钻地条在地图下方居中、状态栏上方，只在钻地期间显示
- 清单在第一次切到三维时才读（查询的 `enabled`），只用二维的不请求
- 勾选状态本阶段不持久化

### 8. 验收

- 纯函数（node）：会话三维内容的校验与通知、清单校验（两种写法、市代码、地址）、索引整理（外部索引、空占位、目录外的引用、循环、误差）、拥有者的推导（效果、钻地时隐藏白膜、重试）
- 绑定（map-vue）：推导出错、内容不合法时跳过这一轮；上下文的 `sceneStatus` 只反映当前视图
- `CesiumView`（假场景）：按 ID 增删、暂停期间不应用、状态报告、重试、同组的替换、钻地参数、释放时中止加载
- `CesiumScene`（浏览器，真实 Cesium，测试里生成的一个方块瓦片集）：加载并画出、建议的相机、首批瓦片的报告、失败与中止、相机在地下时退出钻地
- 面板（jsdom）：清单的加载与失败、按市分组与搜索、勾选与已加载、定位与钻地条、换效果与卸载
- 页面：用旧仓库的 `SZ_3DT`、`SZ_WhiteModel` 在真实页面验证加载、定位、换效果、钻地和退出

## 后果

- 好处：模型和样式一样由会话持有，视图重建、暂停、二三维切换后自动恢复；地图内核和视图都不认识业务的清单
- 好处：清单可审、数据不入库；索引问题在运行时处理，部署时不用改数据
- 代价：会话多了一份二维用不到的状态；每个模型加载前多读几个索引文件
- 代价：本地开发、浏览器测试之外的验证依赖旧仓库的数据
- 待定：勾选状态是否持久化；以后有接口时清单的来源；步行和路线漫游（3D.4）
