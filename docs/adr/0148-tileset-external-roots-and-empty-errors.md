# 0148. 整理 3D Tiles 索引：外部索引的根节点换到引用它的位置，没有内容的节点不改小误差

- 状态：已接受（2026-11-05 用户确认）
- 日期：2026-11-05
- 修改：ADR 0081 第 3 节"没有内容的取子节点误差的最大值"和白膜的例外；`prepareTileset` 合并外部索引的做法

## 背景

服务器上新加的无锡经开区倾斜摄影（JKQ，CesiumLab `osgb2tiles5` 从 OSGB 转换）只在 15 级左右完整显示，其他级别缩放、转动时有成块的空洞：13 级只剩两块，16 级镜头前方空了一大片。

它的索引一层套一层：`tileset.json` → `top/0.json` → `top/0-xxxx.json` → `Tile_+xxx_-yyy/Tile_+xxx_-yyy.json`。`prepareTileset` 原来把每个外部索引换成"没有内容的节点 + 外部根节点作为它的子节点"，这个节点的误差取子节点的最大值。

Cesium 1.146 的基础遍历（`skipLevelOfDetail: false`）对这两种节点的处理不同：

- 引用外部索引的瓦片总是往下走到外部根节点（`Cesium3DTilesetTraversal.canTraverse`），而且父节点要等外部根节点准备好才细分。
- 没有内容的节点只在屏幕误差大于 16 时才往下走；停在这里时它被"选中"，但没有内容可画（`selectDesiredTile` 要求 `contentAvailable`）。它的父节点已经细分，也不画；`executeEmptyTraversal` 遇到没有内容的节点直接放行，父节点不会等它。

于是在"父节点要细分、包装节点不细分"的距离区间里，包装节点覆盖的范围什么也不画。CesiumLab 每一级都有这样一段，所以几乎每个级别都有某一级出空洞。用 `0.json`、`0-1310.json` 和真实的 `prepareTileset` 模拟 Cesium 的选择，13 级只画出 `0-1212.glb` 和 `0-1311.glb`，和截图一致；换成下面的做法后各级覆盖率都是 100%。

另一个问题：没有内容的节点误差改成子节点的最大值，JKQ 的根从 4424.79 变成 163.89，大约 12.5 级以下 Cesium 在根上停下，整个模型都不画。

"取子节点的最大值"来自旧项目的 `prepareLocalTileset`，当时是为苏州站：它的包装节点继承了引用瓦片上万米级的误差。没有内容的节点误差大并没有坏处，只是总会往下细分；误差小才会在要显示子节点时停下。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 外部索引怎么合并 | 外部根节点换到引用它的位置；保留包装节点、把误差调大；不合并，让 Cesium 自己加载外部索引 | **换位置。** 模拟里各级都没有空洞。调大误差时包装节点的包围体比父节点小、离相机更远，模拟里仍有 5%～14% 的空洞，而且父节点不等外部根节点加载，流式加载时会闪。不合并会丢掉目录检查、空占位、误差修正，导航网格也拿不到完整的树 |
| 外部根节点自己没有内容 | 照样换上来；换上它的子节点 | **换上它的子节点。** Cesium 在外部根节点不细分期间继续画上一级；换上来的是没有内容的节点，父节点不会等它，又会空出来。换上子节点以后，父节点细分时直接显示子节点，最多比 Cesium 早一级变精细。索引的根引用这种外部索引时仍换上根节点：根没有上一级，Cesium 在根上停下时同样什么也不画 |
| 没有内容的节点的误差 | 取子节点的最大值；用自己的；取自己和子节点的较大值 | **较大值。** 取子节点的最大值会把它改小（JKQ 的根）。只用自己的时，自己比子节点小就由 `constrain` 把子节点压下来，子节点也没有内容的话，就轮到它停下、空出来。较大值两头都不会改小，误差偏大只会让它早一点细分。现有数据的结果和"用自己的"相同，白膜的例外也不再需要 |
| 引用外部索引的瓦片又有子节点 | 报错；保留包装节点 | **报错。** 3D Tiles 不允许；Cesium 遇到时显示和可见判断对不上 |

## 决定

- 外部索引的根节点整理好以后，换到引用它的瓦片的位置：
  - 内容、子节点、包围体、误差都用外部根节点的；
  - 两边都有 `transform` 时，引用瓦片的在外、外部根节点的在内相乘，只有一边时照原样；
  - 外部根节点没写 `refine` 时沿用引用瓦片的；
  - 引用瓦片自己的其他字段（如 `viewerRequestVolume`）丢掉，现有数据都没有。
- 外部根节点没有内容时，换上来的是它的子节点，`transform` 和 `refine` 按同样的规则再算一层；索引的根除外。
- 没有内容的节点取自己和子节点误差的较大值；有内容的用自己的；叶节点仍为 0，子节点仍不超过父节点，索引的误差仍等于根节点的。
- 引用外部索引的瓦片有子节点时报错。

## 后果

- **好处：**
  - CesiumLab 这类多层外部索引的倾斜摄影不再出现空洞，远处也不会整个消失。
  - 整理后的树里没有包装节点，节点更少。本机的苏州站、白膜三种效果、徐州逐个比对过：内容地址、导航网格用的叶节点和它们的坐标变换完全相同，苏州站的导航网格在开发页上照常构建。
- **代价：**
  - 苏州站的索引误差从 33.85 变成 53670，徐州从 1000 变成 2000。勾选苏州站以后，不论多远，只要在视野里就会加载最粗的 6 个 b3dm（约 5.6 MB），以前只在约 3 千米内加载。这和 Cesium 直接加载原始数据时一样。
  - JKQ 近处会选中更多瓦片（模拟 16 级：82 块，原来 16 块），缓存预算是否够用要在真实页面上看。
  - 索引的根直接引用外部索引时，根换成外部根节点，导航网格的局部系是两层 `transform` 的乘积，建议相机用外部根节点的包围体。现有数据没有这种结构。
- **没有验证：**
  - JKQ 在页面上的效果。本机没有完整的 JKQ 数据，要放进 `local/3dt/` 或部署后看（记在 [backlog](../backlog.md)）。
  - JKQ 的 `Tile_` 索引和另外五个 `top/0-xxxx.json` 没有拿到，模拟时按引用它们的瓦片补的；"引用外部索引的瓦片又有子节点"只核对了本机的三份数据和 JKQ 的两个索引文件，JKQ 其他文件里有的话整个模型会加载失败。
