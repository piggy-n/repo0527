# 0058. 基础组的指北针

- 状态：已接受
- 日期：2026-10-16
- 补充 ADR 0053 第 3 节（基础组的按钮）；修正 ADR 0053 第 8 节（矮屏的高度阈值）

## 背景

用户的优化意见（2026-10-16）：在基础组的放大、缩小下面加一个指南针按钮。具体要求有两点：

- 点击后只把旋转和俯仰恢复成正北、垂直俯视，当前的缩放级别和中心点都不变
- 图标跟着地图一起转，指示当前的朝向

现状：

- 二维地图允许右键拖动旋转和俯仰。在"移动"工具里，按住 Ctrl 拖动也会旋转（ADR 0056 的后果）
- 现在恢复视角只有两个途径：基础组的"默认视角"会连中心和级别一起回到全省；另一个是自己拖回去
- 旋转和俯仰的角度在状态栏里有（ADR 0053 第 5 节）
- 旧项目没有指北针

设计稿（静态 HTML，不入库）比较了三种图标：

- A：竖直的菱形指针，北半红、南半灰
- B：单色指针，北半实心、南半空心
- C：Tabler 的 `compass`，指针本来就斜 45°

用户选择 A，其余细节按推荐。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 图标 | A 北红南灰的菱形指针；B 单色指针；C Tabler 的 `compass` | A（用户选择）：地图应用的习惯，一眼能认出北方；C 的指针本来就斜着，转起来看不出朝向 |
| 位置 | 放大、缩小下面；默认视角旁边；单独一段 | 放大、缩小下面，和它们算一段：都只改视角里的一项，不动中心 |
| 正北、没有俯仰时 | 置灰；隐藏；照常可点 | 照常可点（点了没有变化）：置灰像是功能不可用，隐藏会让基础组的高度变来变去 |
| 俯仰的指示 | 图标压扁表示俯仰（MapLibre 的做法）；只表示旋转 | 只表示旋转：俯仰的角度状态栏里有，压扁后的图标不好认 |

## 决定

### 1. 按钮

- 放在基础组的"缩小"下面，和放大、缩小在同一段，只有图标
- 图标是多色图标 `map-compass-color`（北半 `#E64B4B`、南半 `#9AA5B8`，取自 `--color-danger`、`--color-text-placeholder` 的色值）
- 用 `SvgIcon` 的 `rotate` 跟着地图转：转的角度是 `-bearing`，指针总是指向地图上的正北
- 悬停时在左边提示"指北针：恢复正北、垂直俯视"。转过时再写出当前的角度，例如"旋转 35°"；角度的写法和状态栏一样（`visibleAngles`，小角度不写成 358°）
- 无障碍名称和提示相同；正北、没有俯仰时照常可点

### 2. 行为

- 点击是一次新的相机操作（`runCameraOperation`）：作废之前没完成的定位，只改 `bearing`、`pitch`，都回到 0
- 用相机控制的 `flyTo({ bearing: 0, pitch: 0 })`，动画 300 毫秒，和放大缩小一样
- 不传中心，所以中心和级别都不变：相机控制只在有中心时才换算避让的留白（ADR 0037）
- 逻辑写成组合式函数 `useCompassButton`（`shared/map/view-controls`）：给出旋转的角度、提示和恢复正北的操作，组件只显示和调用（ADR 0053～0055 的界面与逻辑分离）

### 3. 布局

- 基础组的高度由 209 变为 241
- "带文字的业务组和基础组都放得下"的地图区域高度由 640 改为 672，即 16 + 380 + 16 + 241 + 16 + 余量；低于它时业务组只显示图标（修正 ADR 0053 第 8 节）
- 手机宽度时卡片叠在基础组上面，判断"业务组放不下"用同一个高度加上卡片的 132（`mapPageLayout`），由 772 变为 804

### 4. 验收

- 单元测试：
  - 提示的写法（正北、转过、角度取整和换算）
  - 点击时只交出 `bearing: 0`、`pitch: 0` 和动画时长，中心和级别不变
  - 图标的旋转跟着相机
  - 页面排法的新阈值
- 真实页面：右键拖动旋转、俯仰后点指北针，地图回到正北、垂直俯视，中心和级别不变；图标跟着地图转

## 后果

**好处**

- 不用回到全省视角，也能把旋转和俯仰恢复；图标还能随时指示当前的朝向

**代价**

- 基础组高了 32，矮屏时业务组更早只显示图标：从低于 640 改为低于 672
- 图标是多色的，颜色写死在 SVG 里，不随令牌变化；令牌的色值改了要同步改图标
