# 0024. 二三维共用的视图接口

- 状态：已接受
- 日期：2026-10-09
- 修正 ADR 0020"候选方案"中对方案 B 的比较，以及 ADR 0021 第 5 条"与二维完全一致"的表述（见下文第 10、11 条）

## 背景

ADR 0020 规定交互工具只接收统一的指针事件（经纬度和屏幕坐标），由当前激活的框架提供。评审指出，这个输入不足以表达三维操作：拾取到的是哪个表面、有没有命中、坐标是否带高度、测量算的是哪种距离、切换视图时未完成的绘制怎么办，都需要事先约定。旧项目（yzt `master-demo` 836f03b）里这些问题都存在：

- 三维拾取先找已加载的地表（`globe.pick`），打不到就退回椭球（`pickEllipsoid`），**只返回经纬度**：命中的表面和高度都丢了；3D Tiles 和白膜不参与拾取，点在建筑上时，得到的是视线穿过建筑后打在地面上的点
- 测距用 `turf.distance`，按球面计算，不含高度；三维里的测量借用了叠在上面的二维画布，结果也是球面距离
- 二三维相机同步靠 260 ms 的时间窗口抑制回声
- 引擎之外有 12 处 `getNativeMap()` 直接拿原生地图

MapLibre 6 的相机移动事件（`MapMovementEvent`）带有 `originalEvent`：用户操作引起的移动有这个字段，程序调用没有。`jumpTo`、`easeTo` 等方法可以传入 `eventData`，内容会合并进它们触发的事件。

## 决定

### 1. 共用的是视图接口，不是引擎接口

map-core 定义几个小接口：生命周期、相机、输入、拾取、投影。二维由 MapLibre 适配器实现，三维由 map-cesium 实现。类型现在就定好，三维以后实现时不用再改接口。

写样式仍然不共用：只有二维适配器写二维地图，Cesium 镜像会话状态，不实现二维的引擎接口（ADR 0020 不变）。生命周期的状态见 ADR 0022 第 5 条。

### 2. 拾取

```ts
type PickSurface = 'map' | 'ellipsoid' | 'terrain' | 'model';

type PickResult =
  | { kind: 'miss' }
  | { kind: 'hit'; surface: PickSurface; lngLat: LngLat; height?: number };
```

- 二维的表面总是 `map`（地图平面），没有高度
- 三维按什么顺序拾取（模型、地形、椭球）由 map-cesium 决定，结果如实报告命中的表面；什么都没打到时返回 `miss`，不悄悄退回到别的表面

### 3. 高度

单位米，以椭球面为基准。CGCS2000 与 WGS84 的椭球在这里视为相同。接口不提供 1985 国家高程基准的高度：换算需要大地水准面模型，业务确实需要时在显示环节说明换算方法。

### 4. 测量

- 测量结果记录各点（可以带高度）、测量方式和计算出的数值。数值只计算一次，另一个视图原样显示，并标注测量方式
- 测量方式：

  | 方式 | 含义 | 支持的视图 |
  |---|---|---|
  | `geodesic` | 椭球面上的距离和面积 | 二维、三维 |
  | `spatial` | 带高度的直线距离 | 三维 |
  | `surface` | 贴着地形量的距离 | 三维，并且要有地形数据 |

- `geodesic` 取代旧项目的球面距离，用哪个库实现在做测量时决定（候选：geographiclib-geodesic）。展示图斑面积时仍直接用后端字段（如 `TBMJ`），不在前端重新计算

### 5. 切换视图时的工具状态

- 已经确定的顶点（例如绘制到一半的多边形）属于会话里的工具状态
- 目标视图支持当前工具：继续使用
- 目标视图不支持：工具暂停，保留已画的顶点，切回来后继续
- 鼠标悬停、跟随鼠标的橡皮筋这类瞬时状态直接丢弃

### 6. 相机

- 二三维共用 `CameraState`（中心、缩放级、方位角、俯角）。三维相机的精确状态（高度、俯角超出二维范围、钻地、漫游）属于框架独有状态，由 map-cesium 保管
- 相机变化的事件带两个字段：
  - `view`：`2d` 或 `3d`，表示变化发生在哪个视图
  - `cause`：`user`（用户操作）、`program`（程序定位，例如区划定位、复位视角）、`sync`（从另一个视图同步过来）
- 二维的判断方法：有 `originalEvent` 就是 `user`；程序调用和同步在调用 `jumpTo` 等方法时通过 `eventData` 写明 `cause`
- 当前显示的视图把相机写进会话；切走的视图只在切换回来时、或者按需追上时同步，不实时跟随（旧注释：二维实时跟随三维，一次跳转主线程最高占 9.2 秒）
- 还原三维精确视角的条件（ADR 0020 第 5 条）：切走期间，二维相机只发生过 `cause` 为 `sync` 的变化。用户移动过或程序定位过，就按会话里的相机重新换算
- 这样就不再需要旧项目的时间窗口

### 7. 投影

`project(lngLat, height?)` 返回屏幕坐标；三维中点在相机背后或在地球之外时返回 `null`。

### 8. 输入

统一的指针事件只带屏幕坐标、按键和修饰键。需要经纬度时再调用拾取接口，避免三维每次鼠标移动都做一次拾取。

### 9. 不提供通用的原生地图出口

- 不提供 `getNativeMap()` 这样的通用出口。限制 SDK 的导入位置，挡不住调用方通过拿到的原生实例去改地图
- 适配器按实际需要提供只读方法（查询、投影）。查询结果里的要素属性按 `unknown` 返回，由调用方收窄（ADR 0019）
- 必须拿到原生实例的第三方集成（例如以后如果采用 terra-draw，它的适配器需要地图实例）放在适配器模块内部。它自己的图层使用保留的 ID 前缀，快照对比不会触碰这些图层
- 用 lint 限制 maplibre-gl 只能在适配器和 app 的装配中导入，仍然保留，作为第二道防线

### 10. 三维样式支持的范围

修正 ADR 0021 第 5 条：用同一个库求值，保证的是**表达式和过滤条件的求值语义一致**，不保证渲染效果一致。标注碰撞、像素线宽在栅格化后的表现、遮挡关系都会不同。

- 实现镜像之前，先写出三维的支持清单：支持哪些图层类型、哪些样式属性、不支持时怎样降级
- 不支持的图层或属性按清单降级（跳过图层或者取默认值），开发环境下每个图层提示一次，不悄悄地画出不一样的结果
- 三维求值时的上下文：缩放级来自相机（旧注释记录过"显隐按相机缩放、绘制按瓦片层级"的错位问题，实现时保留说明）；feature-state 来自会话的独立通道；图片来自共用的生成器（ADR 0022 第 7 条）

### 11. 对 ADR 0020 方案比较的修正

ADR 0020 的比较表说方案 B 要把点选、测量、绘制等功能"在 Cesium 里各写一遍"，这并不必然成立：B 和 C 都能共享业务算法，也都需要各自框架的渲染和拾取实现。方案 C 更准确的优势是：

- 复用现有的样式规范，不用自己设计一套图层模型
- 共享状态和业务逻辑
- 旧项目已经验证过镜像这种做法

## 后果

- 好处：三维的拾取、高度、测量口径从一开始就有类型约束，以后实现三维时不用回头改二维的接口
- 好处：相机回声靠事件里的 `cause` 判断，不再依赖时间窗口；精确视角能否还原有了明确的规则
- 代价：二维暂时用不到的字段（高度、`surface` 的多种取值）也要先定义并处理
- 待定：三维的支持清单（实现镜像前）、测地线计算库（做测量时）
