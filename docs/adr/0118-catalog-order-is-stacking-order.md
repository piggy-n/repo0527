# 0118. 资源图层的目录树顺序就是地图的叠放顺序

- 状态：已接受
- 日期：2026-10-30
- 取代：ADR 0053 第 6 节"目录顺序和叠放顺序分开"、ADR 0096 中"树里的上移、下移只调目录顺序"
- 补充：ADR 0041 第 3 节（显示状态的 `order`）、ADR 0054（拖动排序只能按住手柄）

## 背景

ADR 0053 第 6 节把两份顺序分开：目录树的顺序只管展示（`useCatalogOrder`，偏好 `resource-catalog-order`），"已选择图层"的顺序才是地图的叠放顺序。2026-10-28 用户仍选定保持两份顺序（ADR 0096）。

用户 2026-10-30 要求：资源图层树支持拖拽调整实际地图图层层级，并与下方"已选择图层"的顺序双向同步，界面排序和地图渲染顺序一致。旧项目（`current-map-new`）就是这样：树里同级排序，地图按树的叶子从上到下叠放（`orderedLeafIds`）。

难点在于树有层级、"已选择图层"是平铺的：只要"已选择图层"能把一个资源挪到别的分类的资源中间，树就排不出同样的顺序。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 唯一的顺序放在哪 | 以目录顺序为准，叠放顺序从树推导；以叠放顺序（资源图层的 `order`）为准，树从它推导 | 以 `order` 为准：图例、点选优先级、分组推导、偏好都已经读它；树上同级按最靠前的资源排就能推导出来，不用新增跨拥有者的依赖。去掉 `useCatalogOrder` |
| 怎样保证两者一致 | 允许任意顺序，树只保留同级的相对顺序；`order` 始终按目录树连续（同一个分类的资源连在一起） | 按目录树连续：否则树上看到的顺序和地图对不上。合并目录（包括恢复偏好）时整理一次，之后的调整都保持连续 |
| "已选择图层"跨分类的移动 | 不允许跨分类，到分类边界时按钮不可用；在两者分开的那一层整个分类一起挪 | 整个分类一起挪：按钮和拖动一直可用，结果和树一致；代价是同一分类里其他勾选的资源会跟着一起挪 |
| 拥有者的接口 | 保留 `move(code, index)`；改成目录树里的同级调整 `move({ parentId, keys, from, to })` | 同级调整：平铺的位置在有层级时不一定排得出来；"已选择图层"的上移、下移、拖动由 `moveTarget`、`checkedDropTarget` 换成同级调整 |

## 决定

- 资源图层的 `order` 是唯一的顺序，含没勾选的资源，排在前面的画在上面；`treeOrder`（`catalog-order.ts`）按目录树整理：同一个父节点下的子节点按它们最靠前的资源排（一样时保持目录的顺序），再深度优先列出资源。`mergeDisplayState` 合并目录时整理，以前存下的不连续的顺序也在这里整理
- `panelTree` 按 `order` 排每个父节点下的子节点；目录树的拖动手柄、上移下移、手柄上的方向键都交给拥有者的 `move`，地图、"已选择图层"和图例跟着变
- "已选择图层"的上移、下移、拖动：找到它和目标资源在目录树里分开的那一层，把它所在的分支挪到目标所在分支的位置。同一个分类下就是两个资源换位；跨分类时整个分类一起挪
- 去掉 `useCatalogOrder` 和偏好 `resource-catalog-order`；顺序随资源图层的偏好（`resource-layers` 的 `order`）记住。两处上移、下移的无障碍名称不变（"目录里上移""上移一层"），树的拖动手柄改叫"调整图层顺序"

## 后果

- 树上看到的顺序、"已选择图层"、图例和地图的叠放始终一致；搜索期间同样不能调整
- 以前单独调过的目录顺序不再使用（偏好里的 `resource-catalog-order` 不再读写）；以前的叠放顺序按目录树整理后继续使用
- "已选择图层"里跨分类移动一位时，同一分类里其他勾选的资源会一起挪，这是层级带来的约束
- 测试：`catalog-order.test.ts`（整理与同级调整）、`layer-panel.test.ts`（树按叠放顺序、跨分类整个分类一起挪、合并时整理）、`ResourceLayerPanel.test.tsx`（树的拖动、按钮、方向键改叠放顺序，"已选择图层"跨分类后树跟着变）
