# 0165. 内网的服务器底图：浏览器直接读 ArcGIS 紧凑缓存，进入地图页前探测

- 状态：已接受（2026-11-17 用户确认：浏览器读、4 套都接、每套一个英文前缀；看过原型后定了面板排法、标注开关，二维有标准时默认标准）
- 日期：2026-11-17
- 补充：ADR 0031 第 1 节（内网可以有随服务器提供的影像和矢量底图，同源、不请求公网）、ADR 0133 第 1 节（内网的底图目录按探测结果多出几种，有标准时二维默认标准）、ADR 0133 第 5 节和 ADR 0042（底图偏好多三项透明度，没有时按 1，版本不变）、ADR 0078 第 2 节（三维切二维时选这台服务器的二维默认）、ADR 0146 第 1、3 节（面板两行；印着地名的底图标注开关置灰）、ADR 0053 第 4 节（服务器底图的缩略图）、ADR 0061 第 2 节（进入地图页多等一次探测）

## 背景

- 内网底图现在只有"静态""无底图"两种（ADR 0133）。自己批量下载天地图瓦片的做法因为授权放弃了（ADR 0133 背景）。
- 2026-11-17 接入的内网服务器 192.168.15.111 随服务器提供了 `D:\02Data\3dtiles\天地图3857`，用户说明这是数据方给的数据，授权不用我们考虑。里面有 4 套 ArcGIS 切片缓存：
  - 影像：江苏省 2025 年 0.5 米影像（脱密后切图），图上没有地名
  - 标准版、黑色版、极夜蓝版：江苏省 2026 年的三种矢量地图，地名、道路、地铁线都印在图上
- 4 套是同一种切法，2026-11-17 在服务器上读 `conf.xml` 并从开发机实际读瓦片核对过：
  - Web 墨卡托，原点和分辨率与 MapLibre 的切法一致，级别号就是 z；瓦片 256 像素
  - 有数据的是 7～18 级，只有省内有图，省外透明
  - 格式 MIXED：省界附近和低级别是带透明的 PNG，其余是 JPEG
  - 存储是第一代紧凑缓存（`esriMapCacheStorageModeCompact`）：每 128 × 128 块打成一对文件 `_alllayers/L<两位级别>/R<行>C<列>.bundle` 和 `.bundlx`，行列是 128 的倍数，写成至少 4 位的小写十六进制
- 规模（读全部索引统计）：影像 728 个 bundle、965 万块、91 GB；三套矢量各 840 个 bundle、1128 万块、38～49 GB；合计约 4350 万块、226 GB。
- 浏览器和 MapLibre 不能按 `{z}/{x}/{y}` 直接取这种缓存。
- 用户已定的（2026-11-17）：
  - 三维默认影像；二维先定的是静态，看过原型后改为有标准时用标准，没有时用静态
  - 影像上叠静态底图的市、区县地名，跟着标注开关
  - 仓库里列全可能的底图，每台服务器运行时探测有哪些，都没有时和现在一样
  - 浏览器直接读紧凑缓存，不在服务器上转换
  - 4 套都接
  - nginx 给每套一个英文前缀
  - 面板按原型 `local/design/intranet-basemap/` 的两行三列（第 7 节）

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 怎么读 | 服务器上一次性转成 `z/x/y` 文件；在服务器上起瓦片服务；转成 PMTiles；浏览器读紧凑缓存 | **浏览器读**（用户决定）。转成文件只影像就要另存 965 万个小文件、91 GB，四套 4350 万个、226 GB，数据方每次更新、每台新服务器都要重转；瓦片服务要在 Windows 服务器上多维护一个进程；PMTiles 一样靠 Range 读，还要转换、多一个依赖 |
| 每台服务器有哪些 | 按站点写（ADR 0164 的 `sites.json`）；运行时探测 | **探测**（用户决定）：底图不进清单，各台 nginx 配了哪几套，页面就显示哪几套；漏配只是少几张卡片 |
| 什么时候探测 | 进入地图页之前；先进页面，结果到了再长出选项 | **进入之前**：选项在拥有者创建时就确定，偏好恢复、面板、二三维切换都不用处理"结果晚到"；登录页空闲预加载时通常已经探完 |
| 缺瓦片怎么告诉 MapLibre | 返回空数据；抛 `status` 为 404 的错误 | **404**：MapLibre 6 对 404 不发错误事件，改用上一级的瓦片放大（`tile_manager.ts`），仓库的请求状态把它算作已到；空数据会画成透明，这一级缺块的地方挖一个洞 |
| `.bundle` 的浏览器缓存 | 按 nginx 的缓存头；`cache: 'no-store'` | **no-store**：Windows 上的 Chrome、Edge 对同一个文件的 Range 请求，磁盘缓存有过返回全零的故障（Chromium 40542704），PMTiles 3.1.0 起在 Windows 的 Chromium 上一律 no-store。`.bundlx` 是整份 GET，照常缓存 |
| nginx 地址 | 一个 `/basemap/` 指向整个 `天地图3857`；每套一个英文前缀 | **每套一个前缀**（用户决定）：带年份的中文目录名只出现在 nginx 配置里，数据方换目录只改 nginx |
| 底图的 ID | 标准版沿用公网的 `vector`；新加 ID | **影像沿用 `imagery`，三套矢量新加 `standard`、`black`、`night-blue`**：标准版的地名印在图上、标注开关不起作用，名称也不同，和公网矢量（注记单独一层）是两种底图；没有标准时内网的二维默认要退回静态，按 ID 判断更直接 |

## 决定

### 1. 底图目录

内网（关闭天地图）的可选底图按探测结果，按下表的顺序，没有的不占位：

| 底图 | 什么时候有 | `basemap` 分组 | `basemap-labels` 分组 |
|---|---|---|---|
| 标准 | 探测到 `/basemap/standard/` | 背景 `#F3F5F8` + `basemap-standard` | 空：地名印在图上 |
| 影像 | 探测到 `/basemap/imagery/` | 背景 + `basemap-imagery` | 静态地名，跟着开关，透明度取影像的 |
| 静态 | 一直有 | 不变（ADR 0133） | 静态地名，跟着开关 |
| 黑色、极夜蓝 | 探测到对应前缀 | 背景 + `basemap-<id>` | 空：地名印在图上 |
| 无底图 | 一直有 | 背景 | 空 |

- 公网不变，不探测
- 二维默认：内网有标准时是标准，没有时是静态；公网是矢量。初始的底图、三维切回二维时选的都是它
- 二维切三维时有影像就选影像，三维切二维时选二维默认；没有影像的服务器上两个方向都不变（同 ADR 0133），自动切换不改用户自己选的底图（ADR 0114）
- 标准、黑色、极夜蓝的地名印在图上，标注开关对它们不起作用（第 7 节）
- 数据源：`{ type: 'raster', tiles: ['arcgis-compact://…/{z}/{x}/{y}'], tileSize: 256, minzoom: 7, maxzoom: 18, bounds }`，`bounds` 取 `conf.cdi` 的范围向外取整，范围外不请求
- ID 前缀照旧以 `basemap` 开头，请求状态自动并进"底图"一项（ADR 0158）
- 偏好不升版本：底图的 ID 多了三个，透明度多三项，缺的透明度按 1

### 2. 可能的底图写在代码里

`apps/yzt/src/shared/config/server-basemap-options.ts`，属于"代码里的产品开关"（所有部署一样）：

- 每项：底图 ID、地址前缀（`imagery`、`standard`、`black`、`night-blue`）、级别范围 7～18、`bounds`、地名的来源（`'static'` 或 `'baked'`）
- 缓存的固定前提（Web 墨卡托、256 像素、级别号就是 z、第一代紧凑缓存、每个 bundle 128 × 128）不进表：格式写在读取器里，切法是使用方的前提（`tileSize` 在样式的数据源里），换数据时按 docs/deployment.md 核对 conf.xml
- 数据方换了切法（第二代紧凑缓存、别的原点或瓦片大小）时，读取器不支持，要改代码

### 3. 读取

- **读取器**：`@mx/map-core` 的 `tiles/arcgis-compact.ts`，不依赖框架和 MapLibre，`fetch` 由参数传入
  - `.bundlx` 整份 GET：要求 200、81952 字节、16 字节头是 `03 00 00 00 10 00 00 00 00 40 00 00 05 00 00 00`；404 记为"整块没有"，之后不再请求；返回网页或其他长度算读取失败
  - 条目按列存：`slot = 128 × (x mod 128) + (y mod 128)`，每条 5 字节小端偏移，指向 `.bundle` 里的 4 字节小端长度
  - 偏移是 0 或小于 65596（头 60 字节 + 16384 × 4 字节的占位区）就是空瓦片，不请求 `.bundle`
  - 一块瓦片只发一个 Range：从偏移读到"下一个更大的有效偏移"之前，最多 256 KiB，`cache: 'no-store'`；要求 206、`Content-Range` 的起点对；按读到的长度截取，长度超过已取的字节时再补读一次
  - 有效偏移处读到长度 0、开头不是 JPEG（`FF D8 FF`）或 PNG（`89 50 4E 47`）时，丢掉这个 bundle 的索引、重读一次，还不对就报读取失败
  - 每个 bundle 的索引按地址缓存，几块瓦片共用一个请求；共用的请求不跟任何一块瓦片的取消信号走，有自己的超时；缓存有上限（LRU）
- **MapLibre 协议**：`map-core/src/maplibre/compact-protocol.ts` 把读取器包成自定义协议的处理函数：空瓦片和整块没有时抛 `status` 为 404 的 `Error`，读取失败抛别的错误（显示为数据源错误）；尊重瓦片的取消信号；不返回缓存头（避免 MapLibre 定时重载）
- **注册**：`app/map-runtime.ts` 的 `setupMapRuntime()` 里 `addProtocol` 一次，和 `setWorkerUrl` 放在一起；协议对整个页面生效，不随地图销毁移除
- 三维是同一张 MapLibre 地图，栅格底图走同一个数据源，不用另外处理

### 4. 探测

- 在地图页的加载函数里（`withMapRuntime` 的 `Promise.all`），整个文档探一次，各地图页共用；公网构建不探
- 每套用读取器读南京那块缩略图瓦片（z10 的 849/415，同天地图的缩略图），4 套并行，总共最多等 3 秒；读到图片才算有，404、返回网页、超时都算没有。不拒绝：任何错误都只是少几种底图，地图页照常加载
- 网络错误、超时、5xx 记一条 `console.warn`；404 和返回网页不记，没有这些底图的服务器本来就会这样
- 结果由 app 用 provide 交给 `useBasemap`，选项在拥有者创建时确定
- 缩略图用探测读到的那块瓦片做成 data URL，不另外请求

### 5. 部署

nginx 在前端那个 `server` 里，每套一个 `location`，`alias` 指到缓存的 `Layers/`，两端都以 `/` 结尾：

```nginx
location /basemap/ {
    return 404;
}
location /basemap/imagery/ {
    alias D:/02Data/3dtiles/天地图3857/江苏省2025年0_5米影像脱密后切图3857L7_18/Layers/;
    add_header Cache-Control "no-cache";
}
# standard、black、night-blue 同样写
```

- `/basemap/` 下没配的前缀回 404，不回落到 `index.html`
- 不对 `.bundle`、`.bundlx` 开 gzip（压缩后不能 Range）
- 数据方更新时可以原地替换：`.bundlx` 带 `no-cache` 和 ETag，换了文件浏览器会重新取；`.bundle` 本来就不缓存
- 验收：`.bundlx` 200、81952 字节；`.bundle` 的 Range 是 206；不存在的文件和没配的前缀是 404。2026-11-17 在 15.111 上按这几项核对，4 套都通过，中文出现在 `alias` 的磁盘路径里也正常

### 6. 开发和测试

- 开发服务器：`YZT_BASEMAP_PROXY` 把 `/basemap/` 代理到一台服务器（同 `YZT_3DT_PROXY`）；没设时挂 `local/basemap/`，找不到的文件回 404，不回落到 `index.html`
- 构建检查：产物里有 `basemap/` 目录或 `.bundle`、`.bundlx` 文件就失败
- 测试只用临时生成的 bundle，真实瓦片不入库（数据方的数据，仓库在 GitHub 上）：读取器的单元测试（按列存、空瓦片、404、返回网页、200 代替 206、长度不对、补读、取消、共用请求的超时）；协议的浏览器测试；冒烟里 route `/basemap/**` 返回 206

### 7. 面板

用户 2026-11-17 看过原型 `local/design/intranet-basemap/` 后确定：

- 仍是三列，卡片按第 1 节的顺序排：4 套都有时第一行标准、影像、静态，第二行黑色、极夜蓝、无底图，收起时面板高 158（一行时仍是 86）
- 选中标准、黑色、极夜蓝时，入口展开后的标注开关置灰、不能操作，旁边写一句说明（暂定"地名印在底图上"，用户之后再定）；透明度照常
- 尺寸和交互的细节写进 docs/design/current-map-reference.md

原型里另外发现缩略图名称和底图卡的按钮没有继承页面字体（没写 `font: inherit`，用的是浏览器给按钮的默认字体），用户要求一起修掉。

## 后果

- 服务器上只加 nginx 配置，不另存数据；数据方更新、换服务器都不用转换
- Windows 上的 Chrome、Edge 不缓存底图瓦片：刷新页面或拖回已经被 MapLibre 内存缓存淘汰的区域，要重新下载。局域网里每屏约 1～3 MB
- 进入一个新的 bundle 时，先取 80 KB 的索引；换一级要一次，z18 下大约每 16 km 一次
- 没有 7 级以下的瓦片：地图级别低于 5.5（最小是 5）、三维倾斜时靠近地平线的一带，服务器底图那里只有背景色，记进 backlog，不伪造低级别。地图级别 17.5 起用 18 级的瓦片放大
- 第一次进入地图页要等探测，局域网里通常几十毫秒，服务器挂住时最多多等 3 秒，这次浏览就没有服务器底图，刷新重试
- `measure:map-load` 按天地图的地址数瓦片，接入后对服务器底图数出 0 张，要改
- 业务图层的配色是按浅色底图定的，在黑色版、极夜蓝版上看不看得清没有核对
- 读取器依赖第一代紧凑缓存的格式。Esri 没有公开这个格式，结论来自 MapProxy、GeoWebCache 等四个开源读取器和这台服务器上的实际文件
- 有标准的服务器上，内网二维默认从静态变成标准；静态底图仍可选，没有服务器底图的部署和现在一样
