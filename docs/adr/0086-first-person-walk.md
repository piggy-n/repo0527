# 0086. 第一人称步行：会话里的步行意图、map-core 的步行者、场景接管键鼠

- 状态：已接受
- 日期：2026-10-27
- 落实 ADR 0078 第 6 节的步行漫游（3D.4c，第一人称）；补充 ADR 0083（漫游意图多一种、路线和步行之间换手）和 ADR 0085（导航网格由拥有者构建、交给会话，按模型缓存）

## 背景

旧项目的站内漫游在 `cesium/FirstPersonRoam.js`（第一、第三人称在一个类里，约 1300 行）：

- 碰撞查导航网格，不靠 GPU 拾取：键盘每挪 0.1 米做一次碰撞，前方被挡时依次偏转 0、±0.5、±1 弧度再试，斜墙也能顺着滑过去；视点平滑跟随地板，相对"地板 + 眼高"的偏差夹在 -0.4～+0.15 米，快速上下扶梯不切进台阶和顶板
- 左键点地面以深度拾取的点为准：附近有高度差不多的地板算直接点中，否则（扶梯侧板、墙根）在点击点下 0.6 米到上 0.3 米之间找最近的地板；同一区域里 A* 寻路后按步行速度走过去；隔着闸机、栏杆的，同一层、10 米内、中间站不住的不超过 3 米、视点高度这一段没东西挡着就直线滑过去，否则黑屏闪切；悬停时用同一套判断给出禁用光标
- 右键拖动转向，滚轮改视场角（相机不动，不会穿模）；面板上有回到出生点、脱困（挪到附近开阔的地面）和 7 档速度（0.5～8 m/s，默认 1.6）
- 出生点依次按四条规则找：相机已在站内地下、贴近地面对着模型、配置的出生点、模型中心
- 进站分两段飞，配合它自己的钻地"观察窗"；步行时压暗远处，增加纵深

原型 `/dev/map-3d` 在 3D.1 确认（ADR 0078）：已加载的模型行有"步行漫游"，操作条依次是"正在分析站内空间 N%"、"正在进入站内…"（都可以取消），进到站内后是速度、回到出生点、脱困、操作提示和退出；状态栏是"第一视角 · 眼高 1.6 m · 朝向 N°"。

用户 2026-10-27 选定：导航网格由拥有者建好放进会话；退出步行时飞回开始前的位置；清单里配置了出生点的模型才有入口；第一人称一次做完，速度先不记进偏好；第三人称和小地图在 3D.4d。

实测 Cesium 1.146：`camera.flyTo` 结束、取消时，`CameraFlightPath` 在调用回调之后把 `screenSpaceCameraController.enableInputs` 设回 `true`。路线漫游（ADR 0083）飞到起点以后 Cesium 的相机控制其实是开着的；路线每帧都把相机设回路线上，所以看不出来。

## 决定

### 1. 分层

- map-core（`scene/nav/walker.ts`，node 下测试）：`Walker` 持有局部系里的位置、楼层、视点高度和朝向，做键盘行走（逐段碰撞、顺墙滑）、沿路径走、视点跟随；`resolveClick`、`planMove`、`unstuckSpot`、`chooseSpawn`、`walkAxes` 是纯函数。遮挡判断要读深度，由调用方注入（`VisibilityTest`）
- map-cesium（`scene-walk.ts`）：`SceneWalk` 接管相机、读键鼠、深度拾取、判断遮挡、闪切的黑幕、悬停光标，每帧按 `Walker` 设相机；落点光环在 `scene-walk-marker.ts`；参数和判定规则沿用旧项目
- 会话：`SceneRoam` 加一种 `WalkRoam`；视图报告的 `RoamStatus` 改成按 `kind` 区分的联合类型（路线的加上 `kind: 'route'`）
- 拥有者（`features/scene-models`）：构建、缓存导航网格，持有步行的意图，显示进度和失败

### 2. 会话的步行意图

```ts
interface WalkRoam {
  readonly kind: 'walk';
  /** 每次开始换一个 */
  readonly id: string;
  /** 建好后不再修改 */
  readonly navigation: Navigation;
  /** 清单的出生点：脚下地板的经纬度、椭球高和朝向 */
  readonly spawn: WalkSpawnPoint | null;
  readonly speed: number;
  /** 回到出生点、脱困：一次性的命令写成计数，加 1 就做一次（同 ADR 0083 的 run） */
  readonly respawn: number;
  readonly unstuck: number;
}
```

- 校验：速度是正数、两个计数是非负整数、出生点的坐标是数
- 视图报告 `{ kind: 'walk', id, phase, notice, notices }`：`phase` 是 `entering`（飞进站内）、`walking`、`failed`（附近找不到能站的地方）；`notice` 是最近一条提示（没点到能站的地面、落点被挡住、途中受阻、不用脱困、附近没有开阔的地面），`notices` 每来一条加 1
- 换了一次漫游（ID 或种类变了）时直接开始新的，场景结束上一个；路线和步行之间换手时交出开始前记下的相机，结束新的那一个时回到最初的位置
- 别的定位接管时立即结束、不飞回；撤掉步行时飞回开始前的位置，恢复视场角、相机控制和工具的光标

### 3. 视图的做法

- 出生点按旧规则在局部系里选（`chooseSpawn`）：相机已在站内地下，落到脚下附近的地板；相机贴近地面（椭球面以上 200 米内）、画布中心对着模型，下到最上面一层室内地面；清单的出生点；模型中心附近最上面一层。"最上面一层"按地面高度往下 2 米以内算
- 进场直接飞到出生点的视点（2 秒），视场角 60°，关掉 Cesium 的相机控制。旧项目分两段飞是为了配合它的观察窗；这里进入步行时已经在钻地，地表是半透明的
- 每帧：方向键转向（90°/秒），沿点击的路径或按键盘走这一帧，视点跟随地板，视场角趋向滚轮调到的值，判断悬停光标，最后设相机；相机的方向和上方向按局部系的轴换到地心坐标，局部系不朝北也对。场景是按需渲染，有按键、在走、视点或视场角没到位、光环在动时请求下一帧
- 键盘在窗口上监听（焦点在输入框、按着修饰键时不算），切走窗口、页面停用时忘掉按着的键；鼠标在容器上按捕获阶段拦下，不传到画布：Cesium 的相机控制关掉后照样记录拖动和滚轮，交还时会当惯性补放出来，场景转给工具的鼠标事件也一并挡掉
- 漫游（路线和步行）期间每帧把 Cesium 的相机控制关掉，对付 flyTo 结束时被重新打开
- 步行时打开头灯着色器里的远处压暗（3D.3 迁来的 `uFog`），结束时关掉
- 就绪视图新增 `heading()`（视点的朝向）：步行时的状态栏用；会话的方位按画布中心对着的地面点算，视点在地下时不可靠

### 4. 点击移动

- 点击处的地面以深度拾取的点为准（`resolveClick`），优先找和脚下同一区域的；同一区域就走过去，和脚下高差超过 0.5 米的小区域（100 平方米以下，柜顶、电梯井底）不去，点墙根反推出来的、在别的区域的落点要看得见才去
- 怎么过去（`planMove`）：同一区域里寻路（最多展开 150 万个节点）、拉直后沿路径走，找不到就闪切；走不到的按旧规则直线穿过闸机或闪切
- 落点在按下时定下来；按住不超过 300 毫秒的挪动 30 像素以内、其余 5 像素以内才算点击。落点亮起光环，走到了或被按键打断就淡出
- 闪切 160 毫秒变黑、挪过去、260 毫秒亮回来，以最后一次操作为准；挪过去后新画面画出来之前不接受点击
- 悬停光标：能去的地方是默认光标，去不了的是禁用光标；每 80 毫秒最多判断一次

### 5. 拥有者与界面

- 清单里有 `spawn` 的模型显示"步行漫游"，只有加载完成的能开始；开始时是一次新的相机操作（被别的定位中止就退出），地下的模型进入钻地
- 导航网格按模型缓存：没建过就建，进度里下载占八成、之后在 Worker 里构建；建不出来时操作条显示失败、可以重试；取消、退出、换一次漫游、卸载模型时中止正在建的，晚到的结果不写入；卸载模型时丢掉缓存
- 速度 7 档，几次步行之间沿用；不记进偏好
- 操作条按原型：分析进度、进入站内时只有"取消"；进到站内后是速度（减、当前、加、默认）、回到出生点、脱困和操作提示，提示 3.5 秒后消失；附近找不到能站的地方时只能退出。小地图在 3D.4d
- Esc 退出路线和步行，空格只管路线漫游
- 状态栏步行时是"第一视角 · 眼高 1.6 m · 朝向 N°"，放不下时同样先去掉后面的段

## 后果

- 好处：行走、点击、出生点、脱困的规则都能在 node 下测，Cesium 这一层只做输入、拾取和相机
- 好处：导航网格建一次按模型留着，再次步行直接进站；碰撞、寻路和 3D.4d 的平面图用同一份
- 代价：会话的三维内容里放着导航网格（几十兆的类型化数组），校验不检查它；A* 在主线程，远距离点击可能要几十毫秒
- 待定：速度、人称是否记进偏好；第三人称和小地图（3D.4d）；路线漫游是否也压暗远处
