# 0025. Worker 通信契约与瓦片数据服务的约束

- 状态：已接受
- 日期：2026-10-09
- 补充 ADR 0021 第 3、4 条

## 背景

ADR 0021 决定：所有自建 Worker 使用 `@yzt/utils` 里统一的通信层；瓦片数据服务独立于引擎，放在 map-core。评审指出几处需要先规定清楚：

1. **"停止等待"不等于"停止计算"。** 取消消息要等 Worker 的事件循环处理到它；Worker 正在做长时间的同步解码时，取消消息不会打断它
2. **故障时等待中的请求怎么结束。** 旧项目（yzt `master-demo` 836f03b）的 `worker.onerror` 只打印一条日志，等待中的请求永远不会结束
3. **瓦片数据服务的缓存身份和数据所有权。** 它要同时服务渲染、标注、统计和点选，缓存键、字段、共用的下载以及数据归谁所有都要先说清楚。尤其是 `ArrayBuffer` 转移之后，发送方原来的缓冲区就不能再用了，不能一边转移出去，一边还当作缓存继续读取
4. **实现节奏。** Worker 池的调度、缓存淘汰和内存预算，需要真实的瓦片任务来验证

## 决定

### 1. 取消分三层

| 层次 | 做法 |
|---|---|
| 调用方 | 一取消就以 `AbortError` 结束等待，同时向 Worker 发出取消消息；之后到达的结果直接丢弃，其中可转移的资源要释放（例如 `ImageBitmap.close()`） |
| Worker 中排队的任务 | 直接从队列里移除 |
| 下载 | 每个任务一个 `AbortController`，取消时中止请求 |
| 计算 | 分段执行，每段之间让出事件循环（用 `MessageChannel` 实现，不依赖兼容性不确定的 `scheduler.yield`），并检查是否已取消；处理函数会收到 `signal` |

### 2. 故障语义

| 情况 | 处理 |
|---|---|
| 处理函数自己抛错 | 把错误序列化后作为这个请求的结果回复，不算 Worker 崩溃 |
| 未捕获的错误（`error` 事件） | 这个 Worker 上所有等待中的请求都以"Worker 崩溃"错误结束；终止这个 Worker，下次请求时新建；限制重建次数，防止反复崩溃 |
| 消息无法反序列化（`messageerror` 事件） | 拿不到请求 ID，无法定位是哪个请求，按崩溃处理 |
| 实例释放 | 所有等待中的请求以 `AbortError` 结束，然后终止 Worker（ADR 0023） |

- 默认不设超时，解码大瓦片本来就可能很慢。需要时由调用方传入 `AbortSignal.timeout()`
- 直接 `terminate()` 强制中止计算只作为最后手段，因为会丢掉这个 Worker 里的全部缓存

### 3. 瓦片数据服务的缓存身份

缓存键由四部分组成：

- 数据源：瓦片地址模板，加上年份这类会改变数据的参数
- 数据版本
- 权限范围：瓦片是否因用户或权限而不同，要先向后端确认；如果不同，会话结束时清掉与用户相关的缓存，接到 `app/session-end.ts` 的 `endSession()` 里
- 瓦片坐标 `z/x/y`

### 4. 字段

- 每个数据源保留各使用方登记字段的并集：渲染和过滤用到的字段（由 style-spec 从表达式中提取）、标注字段、统计字段，以及点选需要的稳定业务 ID
- 字段集合变化后，在下次使用时重新解码（旧项目的做法）

### 5. 共用请求按使用方计数

- 多个使用方需要同一张瓦片时，共用同一次下载和解码，按缓存键计数
- 每个使用方的 `signal` 只撤销自己的那一份；没有使用方时，才真正中止下载或解码

### 6. 数据所有权

- 解码后的缓存只属于 Worker，永远不转移出去
- 对外只传两种东西：
  - 复制品：统计结果、点选结果等，通过结构化克隆传递
  - 一次性产物：例如 `ImageBitmap`，转移所有权，Worker 自己不再保留
- 如果通过 MapLibre 的 `addProtocol` 获取它已经下载的瓦片数据（ADR 0021 第 4 条），先 `slice()` 复制一份再转移，原来的缓冲区 MapLibre 还要用

### 7. 推进顺序

- 阶段四只实现通信层：有类型的协议、请求与响应配对、三层取消、故障语义、可转移的数据。测试中用 `MessageChannel` 的两端代替主线程和 Worker
- Worker 池的调度、缓存淘汰、内存预算，等第一个真实使用方（三维栅格化或二维统计）出现后，用真实瓦片验证再定。ADR 0021 第 4 条列出的旧算法（字节预算、LRU、父瓦片固定给同一个 Worker）是起点，不是定论

## 后果

- 好处：取消会立即结束等待，晚到的结果不会写进共享状态，也不会泄漏资源；Worker 崩溃时等待中的请求都有明确的结局
- 好处：缓存身份包含版本和权限范围，换数据或换用户时不会读到旧数据
- 代价：计算密集的处理函数要按分段的方式编写，比一次跑完复杂
- 待定：瓦片是否因用户或权限而不同，需要向后端确认
