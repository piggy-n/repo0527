# 0092. 系统管理：页面内菜单、两个路由与打开的申请

- 状态：已接受
- 日期：2026-10-27

## 背景

旧的系统管理是左栏两项（资源审核、统计报表）加右侧列表，两项都由 `ApplicationListSection`（817 行）按 `role="admin"`、`statisticsReport` 区分；它同时服务用户侧的"数据下载"，审核与详情共用 `ResourceDetailDialog`。消息中心跳过来时，用一组一次性的查询参数（`applicationId`、`dialogMode`、`openApplicationDialog` 等）让列表页自动打开弹窗，打开后再清掉。

上一版迁移合入后因写法不达标由 `6dda705` 撤回，这次从 `6e2d606` 重新开始，不沿用它的代码和结论。2026-10-27 只读核对真实接口（[migration.md](../migration.md)"系统管理与消息中心：接口实测"）：申请列表是标准分页，没有值的字段整个键都不出现；状态里混有 13 条 `status: 'table'` 的基本统计任务；现在没有被驳回和准备完成的申请；统计报表分页为空。[page-layout.md](../design/page-layout.md) 留下的待定项"页面内菜单用 `ElMenu` 加变体还是做 `MxSideMenu`"在这里决定。

用户在 `/dev/system-management` 的原型里比较了下面的方案，2026-10-27 确认按推荐的定；页面内菜单在实测后改选（见候选方案第 1 条）。

## 候选方案

1. **页面内菜单**：三种都能做出规范的外观（项高 44、16 号字、图标 18、圆角 4、项之间 4）
   - `ElMenu` 加 `element-theme.scss` 的变体：原型阶段推荐过它，理由是键盘和无障碍属性由 Element 负责。实现前在 `/dev/theme` 实测发现，Element 只在横向模式下创建菜单的键盘处理（`menu.mjs` 只对 `horizontal` 调用），竖排的菜单项都是 `tabindex="-1"`，用 Tab 到不了，这个理由不成立
   - `libs/ui` 的 `MxSideMenu`：`libs/ui` 不能用路由和 `SvgIcon`，菜单项只能做成按钮、由页面跳转，不能在新标签页打开，图标要由使用方传入
   - `shared` 的 `SideNav`：菜单项就是路由，用 `RouterLink` 渲染成链接
2. **栏目和打开的申请**：一个路由加页面内状态；两个路由加查询参数；沿用旧项目的一次性参数
3. **申请表里的统计任务**：照旧显示为"审核通过"、"查看"置灰；标成"统计任务"；请后端在审核列表里排除
4. **拆分 `ApplicationListSection`**：按角色分支的一个大组件；按领域放进 feature，列和操作按用途传入

## 决定

1. **页面内菜单用 `shared` 的 `SideNav`**（用户 2026-10-27 在 `ElMenu` 的问题查明后改选）：菜单项按路由名渲染成 `RouterLink`，能用 Tab 聚焦、回车打开，也能在新标签页打开；当前项按路由名判断，加 `aria-current="page"`；图标用 `SvgIcon`。外观按 [page-layout.md](../design/page-layout.md) 的"菜单型左栏"，样式写在组件自己的 module 里，只用令牌，不改 Element。放在 `shared` 而不是 `libs/ui`，因为它要用路由和项目图标
2. **两个路由，沿用旧地址**：`/system-management` 是资源审核，`/system-management/statistical-report` 是统计报表，同一个页面组件，栏目由路由 `props` 传入；顶栏的"系统管理"在两个路由上都显示为选中
3. **打开的申请是路由状态**：资源审核路由的查询参数 `apply` 由 `props` 传入，有这个参数就打开它的弹窗，关闭时用 `replace` 去掉。消息跳转、刷新页面、后退、再次点同一条消息都是同一件事，不需要一次性参数（能写成状态收敛的不写成操作，ADR 0039）。弹窗的模式由申请当前的状态决定：待审核的填审核意见，其余只查看；从"去审核"进来、但已经审核过的申请也只能查看
4. **分层**：
   - `features/data-application`：申请的接口（列表、详情、审核、下载）、状态与文案、查询和审核的 mutation、表格与弹窗。这次只做管理员审核；用户侧"数据下载"以后在这里扩展，列名和操作由使用方按用途传入，不在组件里判断角色
   - `features/statistics-report`：报表的分页、下载与表格
   - `pages/system-management`：`MxSplitLayout asideType="menu"`、页面内菜单，组合上面两个 feature
   - 图层代码和名称的对照（`DATA_LAYERS`）移到 `shared`，资源管理的下载申请和这里共用。资源管理里已有的 `/api/apply/create` 不搬动，做用户侧时再评估
5. **列表**：`QueryForm` 的条件是数据名称、审核状态、数据准备状态。列是序号、数据名称、申请人（`user_name`，旧页面没有显示）、行政区划、申请时间、审核状态、数据准备状态、操作；操作固定两格（审核或查看、下载），各行上下对齐。数据准备状态只有审核通过的申请和统计任务才有，没有 `storage_status` 时是"未开始处理"。管理员文案里的"申核"改为"审核"
6. **统计任务标成"统计任务"**：审核状态列显示"统计任务"标签，不显示"查看"，准备完成时可以下载。同时请后端在审核列表里排除它们（记在 migration.md），排除后删掉这一分支
7. **详情与审核弹窗**：`dialog-panel-header` 加 `MxTitle`，宽 640（窄屏为视口宽减 32），内容在弹窗里滚动。上面是"申请信息"（`ElDescriptions` 两列，窄于 640 时一列；标签至少 4 个字宽，值在自己的位置换行）；下面是"审核意见"（通过 / 不通过，不通过必须填原因，最多 200 字）或"审核结果"（审核状态、数据准备状态与下载、不通过的原因）。审核按 `useSessionGuard` 核对会话，提交期间不能关闭；成功后刷新列表和详情并关闭
8. **下载**：审核通过且准备完成才能下载，进度在行内显示（"下载 35%"），按行防重复，复用 `shared/file-transfer`。申请的下载是 `POST /api/apply/download/{id}`，`shared/http` 目前只有 GET 的二进制请求，实现时补上 POST 并同步 [file-transfer.md](../modules/file-transfer.md)；报表的下载是 `GET /statistics/download?id=`
9. **窄屏分页**：资源管理页里写的窄屏分页样式提成 `element-theme.scss` 的公共变体，系统管理和资源管理共用，资源管理的外观不变

## 后果

- 消息只需要给出路由和一个查询参数；弹窗的开关跟着地址走，浏览器的后退能关闭弹窗
- 申请人列让表格多 100 宽，1200 宽时数据名称更早省略
- 统计任务的显示依赖后端修改；改之前分页的总数里包含它们
- 准备完成的下载、驳回原因、统计报表都没有真实样本，先用固定接口验证，联调记在 migration.md
- 页面内菜单由 `SideNav` 自己负责外观和交互；用户侧的"数据下载"迁移时复用。以后需要分组、折叠时在 `SideNav` 上扩展，不再回到竖排的 `ElMenu`
