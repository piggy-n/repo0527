# 0085. 导航网格：map-core 里的纯 TS 实现、Worker 构建、按区域着色的平面图

- 状态：已接受
- 日期：2026-10-27
- 落实 ADR 0078 第 6 节步行漫游的导航网格（3D.4b）；解决 ADR 0018 的待定事项（自己写的 Worker 怎么做类型检查）

## 背景

旧项目的步行漫游靠导航网格判断碰撞和楼层（`cesium/navGrid.js`、`navGridWorker.js`，室内地图的数据层 `indoorMap/levels.js`）：

- 思路同 Recast 的高度场：把模型的三角形按 0.2 米的水平网格逐格裁剪，得到每格的实体区间；顶面坡度够缓、上方净空不少于 1.8 米的是一层地板，墙的顶面不可站立，自然成为障碍
- 每格最多 4 层地板，存成稀疏分块的 Int16（高度按 2 厘米量化，最低位是"头顶有遮盖"），净空另存 Uint8
- 连通分量（区域）：身体半径 0.3 米的圆盘覆盖到的格子都有台阶（0.45 米）内的室内地板才能站人，相邻格落差在台阶内就连通；闸机、站台边缘把空间切成不同区域
- 进入步行时在 Worker 里下载最精细一级的瓦片、解析、构建、算区域（旧代码注释：解析加光栅化约 1.3 秒、区域约 0.6 秒），结果转移回主线程，主线程做查询（行走碰撞、寻路、出生点）
- 室内地图从导航网格自动分楼层（高度直方图、层高 2 米以上算不同楼层），每层画成单色的俯视图

苏州站瓦片集根节点的局部系就是原点处的东、北、天（实测），所以旧地图在代码里是正北朝上；站体本身的主轴偏东北约 10°，看起来是斜的。

用户 2026-10-27 选定：平面图正北朝上；按区域自动着色、同一区域按高度渐变（路线规划草案的效果）；3D.4b 用开发页实测，真实页面的小地图和完整地图在 3D.4d 先出原型再做。

在苏州站的真实数据上试过着色规则（全模型 814 个区域，10 平方米以上的 72 个）：模型里除了车站还有相邻的大空间，按面积全局分配颜色会让付费区和同一层的大区域撞色，所以同一层出现的区域要取不同颜色。

## 决定

### 1. 位置与拆分

- 放在 `libs/map-core/scene/nav/`：不依赖 Cesium、DOM，Worker 和主线程都能用；三维步行（map-cesium）和界面（feature、页面）都从 `@yzt/map-core` 取
- 3D Tiles 索引的整理 `prepareTileset` 是纯函数，从 map-cesium 移到 `map-core/scene`：导航网格要按整理后的索引找叶节点，不应依赖 map-cesium
- 按旧代码的结构拆成模块：b3dm 解析、高度场构建、`NavGrid` 查询、区域、出生点、楼层、平面图、叶节点与坐标系、构建流程；参数和判定规则不变，迁移后在苏州站的数据上和旧代码逐格比对（地板、区域、面积一致）

### 2. 坐标系

- 导航网格用瓦片集根节点的局部系（米）；`navigationFrame(root.transform)` 给出局部系与经纬度、椭球高的互换，局部 y 轴相对正北的方位角，以及地面（原点处的椭球面）在局部系里的高度
- 平面图按这个方位角旋转，保证正北朝上；苏州站的方位角是 0

### 3. 构建与 Worker

- 主线程下载叶节点瓦片（最多同时 4 个、报告进度、可以中止），把 ArrayBuffer 转移给 Worker；Worker 解析、构建、算区域，结果的类型化数组转移回来。`@yzt/utils` 的 Worker 通信层只有请求和响应，下载放在主线程才能报进度，下载是 I/O，不占主线程的计算
- 每次构建创建一个 `WorkerHost`，结束（包括失败、中止）后释放，和旧代码构建完就关掉 Worker 一样
- Worker 入口 `*.worker.ts` 用单独的 `tsconfig.worker.json` 检查（`lib` 是 `webworker`，不含 `dom`），应用和 libs 的 tsconfig 排除它；入口只调用 `serveWorker`，处理函数在普通模块里，测试用 MessageChannel 直接跑

### 4. 楼层

- 自动分楼层的规则同旧代码；名称按地面高度：地面以下从上往下 -1F、-2F……，地面及以上从下往上 1F、2F……
- 苏州站的模型包含车站旁的大空间，分出 -1F（-1.3 米）、-2F（-6.1 米，含站厅）、-3F（-11.1 米，含站台）；清单里配置楼层名以后再定

### 5. 按区域着色的平面图

- 每层一张，正北朝上；这一层能站的地面按所属区域着色，台阶内的地板但人站不下的（贴墙半个身位、闸机、栏杆）灰色，其他透明
- 着色：10 平方米以上、面积不小于 100 平方米的区域按面积从大到小分配调色板里的颜色，跳过已分给同一层其他区域的颜色；分不到的和更小的区域用中性色
- 同一区域在各层是同一种色相，按自己的高度范围从浅到深渐变（楼梯是过渡色）
- 调色板 10 组（浅、深两端），默认值在 map-core，界面可以换；颜色是按数据画的，不是 CSS 令牌，写进 `docs/design/color-and-typography.md`
- 每层的图例：区域的颜色、这一层的面积、高度范围

### 6. 开发页

- `/dev/nav-grid`：选清单里的模型，构建导航网格（进度、耗时），按楼层显示平面图和图例，鼠标处的局部坐标、经纬度、地板高度和区域，叠加清单里的预置路线核对坐标系
- 步行（3D.4c）时导航网格由谁构建、怎样交给三维视图，到时再定

## 后果

- 好处：导航网格不依赖 Cesium，构建在 Worker 里不卡渲染；平面图和行走碰撞用同一套区域判定
- 好处：平面图正北朝上、按区域着色，任何模型都能直接用
- 代价：叶节点瓦片要重新下载一次（浏览器缓存通常能命中）；大模型的网格占几十兆内存
- 待定：楼层名的配置；导航网格是否缓存（每次进入步行都重新构建约 2 秒）
