# 0169. 现状底图的二维、三维各自维护已添加的资源：.env 开关，默认打开

- 状态：已接受（2026-11-22 用户要求：在 `.env` 加配置项，默认启用，开启后二维、三维各自维护已添加的资源、互相隔离；二维模式下资源目录隐藏三维模型，去掉"全部、二维资源、三维模型"的标签。下面七处细节用户都选了推荐的做法）
- 日期：2026-11-22
- 修改：ADR 0157 第 1 节（二维的资源目录也有标签）、第 2、3 节（二三维共用一套、二维里也能加入模型）；ADR 0161 第 1 节（一个列表）、第 5 节（二维里的模型行）；ADR 0167 第 2、3 节（偏好记的是哪一套）。开关关着时这几处照旧
- 补充：ADR 0042（偏好 `resource-layers` 多一项可选的 `scene`，版本不变）、ADR 0116（批量设置的年份按套记）

## 背景

- ADR 0157 起二三维共用资源图层面板；下段"图层"是二维资源和三维模型平铺成的一个列表（ADR 0161），按账号记住（ADR 0167）。三维里加入的资源二维里也有，二维里加入的模型行变淡，切到三维才显示。
- 用户 2026-11-22：二维、三维各自维护已添加的资源，互相隔离；二维的资源目录不列出三维模型，也不要"全部、二维资源、三维模型"这一行标签；做成 `.env` 的配置，默认打开。
- 代码的现状：资源的拥有者（`useResourceLayers`）只有一份显示状态，资源分组、标注、点选、图例、请求状态、模型层的插槽都读它；列表的穿插（`useCurrentLayers`）也只有一份。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 两套放在哪 | 两个资源拥有者；一个拥有者按套保存 | 一个拥有者按套：`state` 是当前维度那一套，点选、图例、请求状态、标注、插槽、面板都不用改；两个拥有者会重复校验目录、重复报配置错误，页面上每处都要选用哪一个 |
| 分开哪些 | 全部显示状态（加入、顺序、显隐、透明度、年份、标注开关、批量年份）；只分开加入和顺序 | 全部（用户按推荐）：一维里的操作不影响另一维 |
| 三维那一套一开始是什么 | 老用户复制现在共用的列表；三维从默认开始 | 复制（用户按推荐），之后各改各的；新用户两套都默认加入地类图斑（用户按推荐） |
| 样式 | 符号和标注的样式二三维共用；也按维度分开 | 共用（用户按推荐）：样式是"这个资源长什么样"；偏好 `resource-symbols` 的版本和格式也不能改（ADR 0154） |
| 模型 | 只在三维那一套；二维也能加模型 | 只在三维：用户要二维的目录不列出模型；`useSceneModels` 和偏好 `scene-models` 不改 |
| 三维里的标签 | 保留；三维也去掉 | 保留（用户按推荐，原话只说二维）：资源段的三个标签和图层段的筛选行照旧 |
| 切换维度时 | 另一套也有的行保持选中，点选详情只在资源不在新一套里时关闭；切换就清掉 | 前者（用户按推荐）：都是面板和点选原有的规则 |
| 偏好 | 新的偏好名；升版本；顶层加可选的 `scene` | 加可选的 `scene`、版本不变：同 ADR 0157、0160 加字段的做法，开关来回切也不丢 |
| 开关 | `.env` 的 `VITE_LAYERS_PER_DIMENSION`，内网继承；内网关着 | 前者（用户按推荐） |

## 决定

### 1. 开关

- `.env` 的 `VITE_LAYERS_PER_DIMENSION`，提交的是 true，`.env.intranet` 不写、继承；只在 `shared/config/app-config.ts` 读（`appConfig.layersPerDimension`），写错、漏写时启动就报错。改了要重新构建，所有用户一样，界面上没有开关。
- 只有现状底图的页面读它，作为选项 `perDimension` 交给资源图层的拥有者；开发页不传，二三维共用一套。`/dev/map-ui` 上可以切换"二三维共用""二三维各一套"，看两种面板。
- `vite.config.ts` 的 `test.env` 固定为 false：多数用例按共用一套写；开着的行为在用例里 `vi.stubEnv` 后重新导入页面。
- 关着时和以前完全一样（ADR 0157、0161、0167）。

### 2. 资源的拥有者按套

- `useResourceLayers` 的选项 `perDimension`：为 false 时只有一套 `shared`；为 true 时有 `2d`、`3d` 两套，各有完整的显示状态（ADR 0041 第 3 节）和最后一次批量设置的年份（ADR 0116）。
- `state` 是当前维度那一套；显隐、透明度、年份、标注开关、批量设置年份、加入、移出、移动、`batchYear`，以及资源分组、标注、插槽、点的高亮这些推导都对着它。切换维度时资源分组整组换成另一套；两套都有的资源数据源 ID 一样。
- `currentSet` 是当前那一套的名字，`forSet(set)` 按套读写，不管当前维度（给列表用），没有这一套时抛错。
- 目录到了以后每一套各自合并；目录只校验一次，配置错误只报一次。

### 3. 列表

- 模型只在三维那一套：二维的列表只有资源，先后就是资源拥有者里的先后，不穿插。
- `useCurrentLayers` 记下的穿插、它的合并和清理（ADR 0167 第 3 节）固定对着有模型的那一套（关着是共用的，开着是三维的），不随当前维度：在二维里不会因为二维那一套没有某个资源，就把它从三维的穿插里删掉、写回偏好。
- 二维里加入模型的键时抛错（目录里没有模型，界面上走不到）；移出时模型的键忽略。
- `overModels`、`shownModel` 按当前的列表算，二维里没有模型，都为空。新增 `holdsModels`：当前的列表能不能有模型，面板按它决定目录。

### 4. 面板

- 当前的列表不能有模型时（开着、二维）：上段"资源"固定显示二维资源，没有标签，外壳不显示标签行；资源目录还没到、读不到时整段说明（同"二维资源"），不提示模型清单读不到。下段同以前的二维，没有筛选标签。
- 三维照旧：上段三个标签，进入三维是"三维模型"；下段有筛选标签。
- 资源段没有标签行时，资源的最小高度少这一行：拖到最小时仍是标题、搜索行和 3 行（176）。`splitLists`、`ratioForCheckedHeight` 加 `treeExtra`（外壳量到的标签行高度），同 ADR 0161 给图层的 `checkedExtra`。
- 切换维度时选中的行在另一套里也有就保持选中，没有就不再选中（面板原有的规则）；点选的详情按 `useFeaturePick` 原有的规则，资源在新的一套里没画出来时关闭。

### 5. 偏好

- `resource-layers` 的版本仍是 1：顶层仍是一套，加可选的 `scene`，形状同顶层（各资源的设置、顺序、批量设置的年份），同样要自洽，不自洽时整条当作没有存过。
- 开着：顶层是二维那一套，`scene` 是三维那一套。存下的没有 `scene`（老用户第一次）时三维复制顶层；复制只在恢复时做，下一次写入时一起写下。
- 关着：顶层是共用的那一套；读到的 `scene` 原样写回，再打开时还在。从开改回关时，共用的就是二维那一套加上三维模型（用户 2026-11-22 同意）。
- `current-layers` 的格式不变，记的总是有模型的那一套的穿插：关着是共用的，开着是三维的。从开改回关时，按三维的穿插合并二维那一套和模型（穿插里没有的资源接在最后，清理后写回）；再打开时，三维那一套里不在穿插里的资源接在最后。
- `resource-symbols`、`scene-models` 不变。

### 6. 这次不做的

- 把一维的列表复制到另一维之类的操作（用户 2026-11-22）。

## 后果

- 开着时二维、三维各自维护已添加的资源：二维里加的资源三维里没有，反过来也一样；二维的目录只有资源。
- 切换维度时资源分组整组换成另一套，两套不同的资源要重新请求瓦片。切换的耗时本机（软件渲染）测不出，要在有显卡的机器上看。
- 回退到这之前的版本时，旧代码读得出带 `scene` 的偏好（多出的一项被忽略），下一次写入时 `scene` 丢掉，三维那一套回到共用的。
