# 0172. 高斯泼溅的补的地板：扫描采不到的步行表面沿扫描轨迹补上，写进清单

- 状态：已接受（2026-11-23 用户看过龟山汉墓的复测报告，选"沿轨迹补地板"，请数据方在碰撞网格里补上栈道的表面记进待办，补好以后删掉补的地板）
- 日期：2026-11-23
- 补充：ADR 0156（第 2 节建导航网格时多一组三角形；第 4 节离线工具多生成一项；第 1 节"不清理网格、走下来发现问题再加"的第一处）、ADR 0081 第 1 节（`splat` 模型可以写 `walkways`）

## 背景

用户 2026-11-23：龟山汉墓（`xz-gshm`）外面看正常，入口广场和展厅不能漫游，问采样缺在哪里、要不要补充采样或调整采样策略。复测（本地代码连 180 测试服务器，报告见下面"实测"）的结论：

- 采样本身不缺：碰撞网格覆盖了数据范围里的入口广场、上下两层展厅，建出来是一片 1444 ㎡ 的可走区域，扫描轨迹 54% 走在里面；配准（`placement` 重跑逐位一致）、导航参数都不是原因。
- 原因一：泼溅只留出生点所在的一片（ADR 0156 第 1 节的 `keepMainRegion`），出生点为了能进墓放在南甬道口，留下墓（399 ㎡），入口建筑整片丢掉。
- 原因二：入口建筑和墓本来就断开。南北甬道口各有 10～13 米（轨迹 269～282 米、644～654 米）人走的表面不在碰撞网格里：网格里只有一排下沉 0.7～0.95 米的格子（约 0.8 × 2 米）和格子间的窄梁；扫描仪离梁 1.3 米，和前后一样，离格子底 2 米多。多半是透明的玻璃栈道（激光和照片都采不到玻璃），没看现场照片确认。
- 调参数连不上：身高、台阶、坡度、每格层数怎么调都不行，身体半径要降到 0.05 米（等于不判断离边多远）才连上。
- 同样的统计：土山墓、驮篮山1号、东洞山的轨迹 90% 以上在留下的一片里；彭城有一块 622 ㎡ 走过的区域隔着 16 米的断口；没有出生点的楚王山3号、狮子山、驮篮山2号也有走过却被丢掉的区域。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 怎么连上 | 只换出生点；一个模型留几片（片之间点击闪切）；沿轨迹补地板；改 `SCAN_NAV_OPTIONS`；请数据方补采样 | **沿轨迹补地板，同时请数据方补**（用户定）。换出生点只能走另一边；留几片走不过去，甬道口两边落差约 0.8 米，超过直接滑过去的 0.5 米，只能闪切；半径 0.05 米时人能站在 0.1 米宽的梁上、贴墙 5 厘米走，所有泼溅都跟着变；数据方补是根本的办法，但要等 |
| 补的地板从哪来 | 运行时读轨迹；离线算好写进清单；运行时在高度场里补洞 | **离线写进清单**：同 ADR 0156 第 4 节，运行时不读轨迹、不知道配准修正；补洞分不清"玻璃下的坑"和真的坑（楼梯井、墓坑），人走过的地方才一定能走 |
| 地板的高度 | 扫描仪高度减离地的中位数；网格里实际的表面 | **实际的表面**：扫描仪离地在矮甬道口会降一米（人弯腰），按它推的地板一米内跳 0.4～0.8 米；推出的地板只用来挑脚下那一层（两头的地板、栈道的梁），中间按米数插值 |
| 断口怎么找 | 人工在 `/dev/nav-grid` 上看；工具按扫描仪离地推地板、看脚下缺不缺；工具按脚下表面的"断"找 | **工具按"断"列候选，在 `/dev/nav-grid` 上确认**：配准工具导入不了 map-core，没有导航网格；按离地推地板在坡上（驮篮山1号的下坡离地 1.9～2 米）误报很多；"断"是脚下没有表面、和前一个点差一级台阶以上、陷在坑里，坡和楼梯是连续变化的，不算 |
| 宽度 | 按轨迹两边各 0.6 米；量栈道实际的宽度 | **默认 1.2 米，可以按段改**：栈道多宽量不出来（玻璃没扫到）；1.2 米减去两边的身体半径还有约 0.9 米能走 |

## 决定

### 1. 清单

- `splat` 模型可以写 `walkways: [{ width, path }]`：`width` 是米（大于 0、不超过 5），`path` 是沿线地板上的点 `[经度, 纬度, 椭球高]`，至少两个；其他种类不能写，写了整份清单不合法。
- 由配准工具生成（下面第 3 节），和出生点、路线一样写在清单里，[3dt-manifest.md](../config/3dt-manifest.md) 记每个模型补在哪、为什么。

### 2. 建导航网格

- 拥有者（`features/scene-models`）把 `walkways` 按清单的摆放换到导航网格的局部系，和出生点一起交给 map-core 的 `buildScanNavigation`（`ScanSource.walkways`）。
- map-core 把每一段铺成水平宽 `width`、从起点的高度斜到终点高度的矩形，两头各伸出半个宽度（拐弯处不留缝），三角形随碰撞网格一起送进 Worker 构建（`walkwayTriangles`）。参数、区域、只留一片的规则都不变：补的地板盖在坑上，坑底的净空不够，不再是地板；两边的地板和它在一级台阶以内就连上。
- 行走、寻路、平面图、小地图用同一份网格，不用另外处理。点到玻璃下面的坑底时找不到能站的地方，照旧拒绝；补的地板只有轨迹两边，玻璃栈道的其余部分走不上去。

### 3. 配准工具

- `lcc2:register --roam` 列出断口候选和建议的范围（两头各往外留 2 米）；`--walkway 起-止[:宽]` 按轨迹的米数生成一段，打印清单的写法，`--plan` 的平面图上画出补的地板和断口候选。
- 候选只是提示：工具没有导航网格，要把补的地板写进清单以后在 `/dev/nav-grid` 上看是不是连成了一片。规则见 [commands.md](../commands.md) 的 `--walkway`。

### 4. 龟山汉墓

- 补两段：`--walkway 266-300 --walkway 625-662`（南北两段玻璃栈道，各到甬道里的实地），宽 1.2 米。出生点、路线不变。
- 结果（180 的数据）：留下的区域 399 → 1876 ㎡，轨迹在里面 34.7% → 91.2%；剩下的主要是广场往西的数据外（轨迹最后约 30 米）。
- 数据方在碰撞网格里补上栈道的表面以后，重跑配准、删掉这两段（backlog）。

## 后果

- **好处：** 只改清单就能接上扫描采不到的表面，别的模型不受影响；运行时仍不读轨迹；数据方补好以后删掉就行。
- **代价：** 清单多一种手工确认的数据，数据方重新导出后要重做；工具的断口候选有误报（楼梯口、露天没有网格的地方），要在开发页上逐个确认。
- **风险：** 补的地板的高度来自梁和两头的地板，梁也有起伏（龟山汉墓北甬道口有一处约 0.3 米），在显卡机器上走一遍才知道脚下贴不贴；"玻璃栈道"是推断。
