# 0080. 三维的覆盖物、测量、临时拖动与状态栏

- 状态：已接受
- 日期：2026-10-26
- 落实 ADR 0078 第 7、8 节和 ADR 0079 第 6、7 节留给 3D.2 的部分；补充 ADR 0056 第 2 节"三维"；三维期间暂停 ADR 0048、0049 中三维的识别

## 背景

3D.1 让三维视图显示了栅格底图，GeoJSON 覆盖物都按"不支持"跳过。3D.2 要让这些覆盖物在三维里出现，并完成 ADR 0078 定下的三维工具栏和状态栏。

二维现在的 GeoJSON 覆盖物（2026-10-26 盘点）：

| 分组 | 图层 | 数据 |
|---|---|---|
| 行政区边界 `boundary` | line：按级别插值的线宽，县界虚线 `[3, 2]`，省界的光带带 `line-blur` | 数据源的 `data` 是静态文件的地址 |
| 区划高亮 `region` | 两层 line，外层 `line-blur: 5` 的光晕 | 内联 |
| 区划遮罩 `region-clip` | fill，限定为面 | 内联的 MultiPolygon，第一个面的外环是整个世界 |
| 测量 `measure` | fill、line（画线中虚线）、circle（顶点） | 内联，画线时每次移动都换数据 |
| 选择高亮 `selection` | line、fill、circle | 内联的完整几何；三维里不会产生新的选择 |

测量的标签、位置点的卡片是 DOM 浮层，靠视图的 `project` 摆放，三维已经能用。

旧项目 `GeoJsonOverlayLayer.js` 用 Cesium 的 Entity 把 GeoJSON 图层镜像过去，注释里记了三个实测问题：

- 外环横跨整个世界的面交给 Cesium，会在跨 180° 经线的处理（`GeometryPipeline.splitLongitude`）里抛错，整个场景停止渲染。旧项目把这种外环收成"洞的包围盒放大若干倍"的方框
- 贴地折线遇到相邻的重复点，Worker 里同样抛错并停掉渲染，要先去重
- 测量的橡皮筋线每次移动都重建实体太慢，几何不变的部分只改坐标

用户 2026-10-26 选定：覆盖物用 Entity API 画；区划遮罩收成方框的贴地面。

## 决定

### 1. 覆盖物的镜像（map-cesium）

- 分两步，和影像一样（ADR 0079 第 3 节）：纯函数 `planOverlays` 从样式、整数级别和各数据源的数据推导出与 Cesium 无关的"形状"；`CesiumScene` 只按形状增删改 Entity。纯函数在 node 下测，画法在浏览器测试里验证
- 级别按 `Math.round(zoom)` 取整求值，整级变化时重新推导：二维的线宽按级别插值，整级已经足够接近；按小数级别求值会让上万个点的县界在缩放中不停重建
- 过滤条件用 style-spec 的 `featureFilter`，样式属性用 `normalizePropertyExpression` 按要素求值（ADR 0024 第 10 节），不手写求值器
- 叠放顺序：贴地的线和面按样式里图层的顺序设 `zIndex`；点画在线和面上面
- 支持清单（补充 ADR 0079 第 7 节）：

| 二维 | 三维 |
|---|---|
| `line`：`line-color`、`line-width`、`line-opacity` | 贴地折线（`clampToGround`），像素线宽 |
| `line-dasharray` | 虚线材质：一个周期的长度是线宽乘以虚实之和，虚实比例照样式 |
| `line-blur` | 没有对应的效果：按 `线宽 / (线宽 + 模糊)` 降低不透明度，近似光晕 |
| `fill`（限定为面）：`fill-color`、`fill-opacity` | 按地表分类贴地的面（`ClassificationType.TERRAIN`），有洞 |
| `circle`：`circle-radius`、`circle-color`、`circle-opacity`、`circle-stroke-*` | 屏幕上固定大小的点，不被地球遮挡 |
| `line-join`、`line-cap`、`fill-antialias`、`fill-outline-color` | 忽略 |
| `symbol` 等其他图层、`fill-pattern`、`line-gradient` | 不支持，按 ADR 0079 第 7 节报告 |

- 数据源的 `data` 是地址时，由视图下载（结果按地址缓存，视图释放时取消下载）；下载或解析失败记进视图的数据源错误，按二维的数据源 ID（ADR 0041）。下载函数可以由构造参数换掉，测试不发网络请求
- 交给会话的数据不能原地修改（ADR 0022），所以坐标换算的结果按环的数组缓存
- 同一个图层再次推导时，样式不变、形状个数相同就只改坐标，不重建实体：测量画线时每次移动都是这种情况
- 要重建的图层（样式变了、换了一级），旧的实体留到新的全部画好（`dataSourceDisplay.ready`）再移除：贴地的几何在 Worker 里异步生成，先删后建会空白几秒；新旧同时在的那一会儿，半透明的线叠得深一些
- 画面稳定（`settle`）要等影像瓦片和覆盖物都画好，被替换的实体也已移除

### 2. 区划遮罩与几何的清理

- 横跨 359° 经度以上的外环收成方框：方框是所有洞的包围盒向四周扩大（各边至少 5°，或包围盒宽高的 4 倍，取大的），夹在 ±179.9° 经度、Web 墨卡托纬度范围内。观感和二维相同；代价是很斜地看向地平线时，方框外的远处没有遮罩
- 环里相邻的重复点去掉；去重后不到 2 个点的线、闭合后不到 4 个点的环丢弃
- 按这一级的半个像素（`360 / 512 / 2^级别 / 2` 度）简化线和面（`@turf/simplify`），和二维 MapLibre 按瓦片简化的效果一致。2026-10-26 实测（软件 WebGL）：省界 20829 个点的一条贴地线约 4 秒才画出，默认视角的省界三条线、市界两条线要十几到二十几秒；简化到 6 级的半个像素后约 1 千个点，第一次切到三维 6 秒内画出，其中约 3 秒是 Cesium 第一次建贴地几何的准备
- 三条都在 map-cesium 的纯函数里，按旧项目记下的问题和实测各写测试

### 3. 测量

- 三维直接使用现有的测距、测面工具：工具收到的输入和二维格式相同（ADR 0079 第 6 节），拾取打在椭球上
- 测量方式仍是 `geodesic`（ADR 0024 第 4 节），不计高度。本阶段到 3D.3 之前没有地形和模型，拾取的高度都是 0；有了模型以后再定是否加 `spatial`
- 测量中切换二三维：已经确定的顶点在会话里，切换后继续（ADR 0024 第 5 节）

### 4. 三维的临时拖动（补充 ADR 0056 第 2 节"三维"）

- 规则和二维完全相同：声明了 `panModifier` 的工具，按住修饰键左键按下就是一次临时拖动；这次按下、松开和派生的单击都不交给工具，指针移动照常交给工具；光标 `grab` / `grabbing`；拖动中松开修饰键继续拖到松手
- 由场景自己平移，不借用 Cesium 的修饰键手势：Cesium 的相机控制只认 Shift、Ctrl、Alt，不认 Mac 的 ⌘；而且它把 Ctrl + 左键拖动当作倾斜
- 做法：在画布容器的捕获阶段截下这次按下，Cesium 的手势和工具都收不到；移动时取上一个、这一个指针位置打到椭球上的点，绕地心把相机转过这两点之间的角度，按下时抓住的地面点始终在指针下面；打不到椭球（指向天空）的那一下不动。相机事件的来源是 `user`

### 5. 点/框选与图例（落实 ADR 0078 第 7 节）

- 三维期间点/框选不识别：工具拿到的 `ToolView.kind` 是 `3d` 时，单击和框选什么也不做，不发请求、不改选择。资源图层（MVT）本阶段不在三维显示，识别看不见的要素会让人困惑；ADR 0048、0049 中三维走后端识别的规则保留，等资源图层能在三维显示后恢复
- 当前工具是点选时，鼠标在三维画布上就用 `PointerHint` 显示两行："三维模式暂不支持点/框选"，"切换到二维后使用，按住 Ctrl（Mac 上 ⌘）拖动地图"，代替二维的操作提示。点选工具在三维同样关掉了拖动平移（直接拖动在二维是框选），所以要写出怎样拖动；提示不会因为单击而关闭
- 图例面板在三维里只显示"三维模式暂不显示资源图层，图例在切回二维后可用。"（和确认的原型一致），不显示"全部恢复默认"。图例组件不卸载：条目和编辑器像隐藏时一样卸载、丢弃取色预览，浏览和编辑目标保留，切回二维后照旧

### 6. 三维状态栏（落实 ADR 0078 第 8 节）

- 视点高度来自三维相机（相机位置在椭球面以上的高度），不从会话的相机推算：推算要用画布高度和地球曲率，和三维实际的相机也对不上
- `MapView` 加一个可选的能力 `eyeHeight()`，只有三维视图实现；上下文的就绪视图入口（`MapViewport`）加 `eyeHeight()`，当前视图没有这项能力时为 `null`。状态栏在相机变化时读取，和比例尺读取拾取结果的方式一样
- 三维的状态栏：视点高度（代替比例尺，格式同比例尺的长度）、经纬度、不为 0 的旋转和俯仰；排不下时的取舍和二维相同（`fitStatusLayout`）
- 步行、路线漫游时的状态栏在 3D.4

### 7. 验收

- 纯函数（node）：各类图层的求值和过滤、整级取整、虚线和模糊的换算、支持清单外的报告、世界外环收成方框、去重与丢弃
- `CesiumView`（假场景）：覆盖物随样式和整级变化推导、地址数据的下载与缓存、下载失败记进数据源错误、释放时取消下载、暂停期间不推导；临时拖动的输入规则
- `CesiumScene`（浏览器，真实 Cesium）：覆盖物增删改与只改坐标、遮罩不让场景停止渲染、临时拖动后抓住的点仍在指针下
- 页面（真实页面，本地瓦片）：边界、区划高亮与遮罩、测距测面在三维里的样子，Ctrl + 拖动，点选提示，图例说明，状态栏

## 后果

- 好处：二维加的 GeoJSON 覆盖物在三维自动出现，不用逐个功能接；Cesium 仍只在 `CesiumScene` 里出现
- 好处：临时拖动在二三维和各平台上是同一套规则
- 代价：线的光晕、虚线的观感和二维不完全一样；遮罩在很斜的视角下盖不到远处
- 待查：软件 WebGL 下区划遮罩上偶尔有一像素宽的细缝（沿区划外缘的纬度、指向方框角的斜线），单独用 Cesium 画同样的遮罩没有复现；在有显卡的机器、真实影像下再确认
- 代价：Entity 由 Cesium 自己合批，重建的时机控制得不如直接用 Primitive 细；县界这类上万个点的数据在整级变化时重建一次。以后要换成 Primitive 只改 `CesiumScene`
- 待定：三维里资源图层的显示与识别（MVT 不在本阶段）；有模型以后是否加 `spatial` 测量（3D.3）；步行、路线漫游的状态栏（3D.4）
