# 0035. 测量：椭球面计算、测量的状态与标签

- 状态：已接受
- 日期：2026-10-10
- 落实 ADR 0024 第 4 条（测量记录各点、方式和数值，`geodesic` 按椭球面计算）与第 5 条（已确定的顶点属于工具状态）；补充 ADR 0034 的输入事件

## 背景

5B.4 做测距、测面和清除，是 ADR 0034 工具模型的第一批真实工具。

旧项目（yzt `master-demo` 836f03b）的测距、测面建在一个 925 行的 `GeometryDrawManager` 上（测量与数据查询的框选、多边形共用）：

- 单击加点、双击结束，双击中的第二次单击（`originalEvent.detail > 1`）被忽略；点数不够时双击就取消。可以连续测多条，每条结果带一个关闭按钮，工具栏的"清除"清掉全部测量结果
- 测量时不锁平移，只关掉双击放大；光标是十字；鼠标旁有提示（"单击开始测距" / "单击添加节点，双击结束测距"）
- 测距：中间节点显示累计距离，末点显示"总长 x.xx km"（固定 km、两位小数）。测面：形心处显示"总面积"，满 1 km² 用 km²，否则用 m²，两位小数
- 用 turf 按球面计算；节点、标签、提示都是挂在原生地图上的 DOM 标记；鼠标移动时的预览线用 `requestAnimationFrame` 合并更新

新项目的约束：只有适配器写二维地图，工具只拿到 `ToolView`（`kind`、`pick`、`project`）；拥有者给出推导函数，页面统一绑定；`computed` 不抛异常；界面在 5D 专门设计，状态和文案是数据。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 椭球面计算 | geographiclib-geodesic；geodesy（Vincenty）；turf | geographiclib-geodesic：Karney 算法的作者维护，距离和面积都按椭球面计算，MIT 许可，自带类型；geodesy 的 Vincenty 公式个别情况不收敛，也没有椭球面积；turf 是球面算法（ADR 0024 已否定） |
| 标签与提示 | 样式里的文字图层；DOM 浮层 | DOM 浮层：文字图层要提供字形文件（中文很大），也做不了可点击的关闭按钮；浮层用视图的 `project` 定位，三维同样适用 |
| 测量的状态放在哪 | 每个工具各自保存；map-core 的一份状态，两个工具共用 | 共用一份：清除、单独删除、标签都面对同一组结果 |
| 双击里的第二次单击 | 工具自己去掉位置重复的点；输入事件带上连击次数 | 带上连击次数：意图明确，三维也能给出同样的值 |

## 决定

### 1. 椭球面计算（map-core）

- 依赖 `geographiclib-geodesic`，用 `Geodesic.WGS84`：`Inverse` 求两点间的距离，`Polygon` 求面积。CGCS2000 与 WGS84 的椭球按 ADR 0024 第 3 条视为相同
- 封装成纯函数，输入 `LngLat`（先经度后纬度），在内部换成它要求的先纬度后经度；结果的单位是米和平方米
- 测量方式记为 `geodesic`；数值在完成时算一次，存在结果里

### 2. 测量的状态与两个工具（map-core）

- `MeasureStore` 持有已完成的测量（ID、类型、各点、测量方式、数值）和正在画的那一条（已确定的点、跟随鼠标的预览点），变化时发出 `change`；`remove(id)` 删除一条，`clear()` 清除全部
- 测距、测面是两个临时任务工具，共用一份状态：
  - 单击（左键、`clickCount` 为 1）时用 `pick` 取经纬度并加点；移动时更新预览点；鼠标离开画布时清掉预览点
  - 双击完成；点数不够（测距少于 2 个，测面少于 3 个）时取消这一条
  - Esc：正在画时取消这一条并返回"已处理"，留在工具里；没在画时不处理，由工具模型退回常驻模式
  - 退出工具时丢掉没画完的那一条，已完成的保留
  - 光标为十字，只关掉双击放大，测量中可以拖动地图
- 输入事件的指针部分增加 `clickCount`（二维取 `MouseEvent.detail`）

### 3. 接进 Vue 与样式（shared/map）

- `useMeasure()` 创建 `MeasureStore` 和两个工具，订阅变化并桥接成 `shallowRef`；页面 `registerTools(measure.tools)`、`bindStyle({ measure: measure.deriveGroup })`
- `measure` 分组从下到上：面的填充、线、预览线（虚线）、节点；数据源和图层 ID 以 `measure-` 开头
- 鼠标位置只用来放提示，单独保存，不进推导：没在画时移动鼠标不会提交样式

### 4. 标签、关闭按钮与提示（shared/map）

- 显示什么由纯函数推导：每条结果的标签（中间节点的累计距离、末点的总长、形心处的总面积）和关闭按钮的位置、鼠标旁的提示文字；单位格式沿用旧项目
- `MeasureOverlay` 组件用 `useCamera()` 和视图的 `project` 把它们放到屏幕上，组件只负责显示和调用 `remove`；5D 可以整体替换
- 面积标签放在多边形的形心，按经纬度平面近似计算即可；凹多边形的形心可能落在外面，与旧项目相同

### 5. 工具栏

表里加上测距、测面（工具）和清除（动作），现状底图页加进工具栏。

### 6. 预览线的性能先实测

鼠标每移动一次，预览点变化一次，经过整份样式的对比再提交（ADR 0020 第 1 条提醒过高频更新）。先照直实现，在开发页用接近资源图层数量（200 个图层）的样式实测一次提交的耗时；明显拖慢时再在 `useMeasure` 里按动画帧合并，结果记进文档。

## 后果

- 好处：距离和面积按椭球面计算；测量逻辑与框架无关，三维阶段只需要提供自己的 `ToolView`；标签和关闭按钮可以整体替换
- 好处：两个工具共用一份结果，清除和单独删除都很直接
- 代价：多一个依赖（压缩后 32 KB，只有 CommonJS 格式，由 Vite 预构建处理）；标签每帧随相机重新投影，结果很多时要注意
- 待定：预览线的合并（实测后）；阶段六数据查询的空间绘制出现后，再看测量的绘制部分能否抽成通用的绘制工具
