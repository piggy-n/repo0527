# 0122. 工具接管按下的拖动：逐点编辑范围

- 状态：已接受
- 日期：2026-10-31
- 修改：ADR 0034 第 3 条（工具的手势只能静态声明）

## 背景

自定义监测范围（ADR 0121）要能逐点编辑：拖动节点、拖动边的中点插入节点。工具的手势是激活时静态声明的（ADR 0034 第 3 条）：要么一直关掉拖动平移（框选的做法，按住修饰键临时拖动，ADR 0056），要么一直开着。编辑时大部分时间要平移地图，只有按在节点上的那一次拖动要交给工具。

MapLibre 的地图事件 `mousedown` 支持 `preventDefault()`：处理这个事件的手势（MapEventHandler）会把自己标成活动的，同一次按下的拖动平移、框选放大都不再开始。原型 v6 用它实现了拖动节点。

## 候选方案

| 方案 | 问题 |
|---|---|
| 编辑工具关掉拖动平移，按住修饰键临时拖动（同框选） | 编辑时要频繁移动地图，每次都要按键，和常见的 GIS 编辑习惯不同 |
| 工具在 `handleInput` 的 `down` 返回 `true` 时取消平移 | 改变了现有工具的含义：框选、测量等在 `down` 返回 `true` 只表示处理过，会意外地不能平移 |
| 工具声明 `capturesPress(point, view)`，按下时由视图先问再决定 | 显式、可选，不影响现有工具 |

## 决定

1. `MapTool` 可以声明 `capturesPress(point, view): boolean`；`ToolModel.capturesPress` 转问当前工具，没有声明时为 `false`
2. MapLibre 适配器在左键 `mousedown`、视图就绪时问当前工具；接管时调用地图事件的 `preventDefault()`，这次按下照样交给工具。`MapMouseEventLike` 加上 `preventDefault()`
3. 只在二维生效：三维没有逐点编辑；按住修饰键临时拖动（ADR 0056）在捕获阶段截下按下，不会走到这里
4. 逐点编辑在 `shared/map/draw`：`useShapeEdit` 持有拖动、悬停、选中，拖完才把新的范围交给拥有者；节点优先于边的中点；单击选中节点后按 Delete 删除，环只剩 3 个节点时不删；Esc 依次取消拖动、取消选中、退出编辑

## 后果

- 工具接管只影响按在它认领的位置上的那一次拖动，滚轮缩放、别处的拖动不变
- 浏览器测试用真实的 MapLibre 验证：按在接管的位置拖动时相机不变，按在别处时平移
- 光标仍是工具静态声明的（编辑工具不改光标），悬停节点时用放大的节点和鼠标旁的提示表示可以拖动
