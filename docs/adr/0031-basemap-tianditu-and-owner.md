# 0031. 底图：天地图的配置与底图的拥有者

- 状态：已接受（待定的"公网和内网两套构建、部署命令"由 0032 决定）
- 日期：2026-10-10

## 背景

5B.1 做底图，它是 `shared/map` 里的第一个拥有者（ADR 0027 第 2 条的"底图切换"），之后的行政区边界等公共能力会沿用它的写法。

旧项目（yzt `master-demo` 836f03b）的底图：

- `BaseLayerManager` 在创建地图时写入天地图矢量 `vec_w` 和注记 `cva_w`（WMTS，`t0`～`t7` 八个子域名，256 像素瓦片）。图层设了 `maxzoom: 18`，到 z18 整层隐藏；样式里还声明了一个没用到的 `osm-tiles` 数据源
- 影像底图是图层树里的静态节点，取内网瓦片服务 `http://192.168.1.180:8080/tiles/{z}/{x}/{y}.jpg`
- 地图控制栏三选一：矢量底图、影像底图、无底图。显隐用 `setLayoutProperty` 改 `visibility`；矢量和注记共用一个透明度，影像另有一个。选影像时矢量留在下面"兜底"
- 叠放：边界创建时插在注记下面，但每次业务图层显隐、透明度、排序变化后又被移到最顶；业务图层也在注记上面。实际从下到上是底图、注记、业务图层、边界（5B.2 读代码时更正）
- 提交 `d768c66` 加了天地图的总开关 `TIANDITU_LOAD_ENABLED`，给不能访问公网的内网部署用。关闭时底图样式里不放天地图数据源（只隐藏的话，加载时已经发出了请求），区划边界改用本地 GeoJSON，天地图行政区接口直接抛错兜底。开关是源码里的常量，关闭后控制栏仍然显示"矢量底图"，选了也看不到

2026-10-10 实测：

- 天地图 `vec`、`cva`、`img`、`cia` 的有效级别是 z1～z18；z0 和 z19 也返回 200，内容是占位图。返回头有 `Access-Control-Allow-Origin: *`、`Cache-Control: max-age=432000`；key 不对时返回 418；不带 Referer 也能取到瓦片
- 内网影像只有 z1～z9，z10 以上全部 404

已有的约束：`VITE_` 变量会写进构建产物，自定义环境变量只在 `shared/config/app-config.ts` 读取（[config/env.md](../config/env.md)）；拥有者只给推导函数，页面统一绑定，ID 以分组名为前缀，推导不依赖相机，`computed` 不抛异常（ADR 0027、0028）；公共能力的接口只做现有使用方需要的（ADR 0027 第 6 条）。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 影像底图 | 迁移内网影像（只有 z1～z9）；改用天地图影像 `img` | 天地图影像 |
| 注记放在哪 | 和底图同一个分组；单独一个分组 | 单独的分组：注记压在哪些图层上由页面决定。旧项目的注记在业务图层下面，不透明的地类图斑会盖住地名，要不要改到上面在 5C 决定；放在底图分组里就只能在最下面 |
| 透明度 | 所有底图共用一个；每种底图各记一个 | 各记一个，和旧版一致；切换底图时不会突然换成另一种透明度 |
| 无底图时的背景 | 画布容器的 CSS 背景；样式里的 `background` 图层 | `background` 图层：它是会话状态，三维以后能用同一个颜色 |
| 状态放在哪 | Pinia store；页面里的组合式函数 | 组合式函数（见决定第 3 条） |
| 内网开关 | 源码里的常量（旧做法）；没有 key 就当作关闭；明确的开关变量 | 明确的开关变量：漏写 key 时报错，不会悄悄变成没有底图 |

## 决定

### 1. 底图目录

| 底图 | `basemap` 分组 | `basemap-labels` 分组 |
|---|---|---|
| 矢量底图 | 背景 + 天地图 `vec` | 天地图 `cva` |
| 影像底图 | 背景 + 天地图 `img` | 天地图 `cia` |
| 无底图 | 背景 | 空 |

- 全部用天地图，不迁移内网影像
- 天地图数据源设 `minzoom: 1`、`maxzoom: 18`，超过 18 级时放大使用 18 级的瓦片，不请求占位图；图层不设缩放范围
- 背景是 `basemap` 分组最底下的 `background` 图层，颜色 `#F3F5F8`（旧项目注明它接近天地图矢量的底色），无论选哪种底图都在：无底图时显示它，瓦片加载中和调低透明度时和它混合
- 没选中的底图，数据源不在样式里（不是隐藏），只有选中的底图请求瓦片
- 不显示天地图的版权信息

### 2. 天地图的配置

| 环境变量 | 值 | 校验 |
|---|---|---|
| `VITE_TIANDITU_ENABLED` | `true` / `false` | 只接受这两个值 |
| `VITE_TIANDITU_KEY` | 32 位十六进制 | 开启时必填；关闭时不读 |

- `appConfig.tianditu` 的类型是 `{ key } | null`，关闭时为 `null`：两个变量在读取时合成一个值，"开启了却没有 key"在类型上就不存在；使用方必须处理 `null`，不用像旧代码那样在每条调用路径上各写一次判断。5B.2 的边界、5B.5 的区划定位用同一个开关，天地图行政区服务的 key 到时加进这个对象
- 关闭时（内网部署）：底图目录只剩"无底图"，默认就选它；所有推导结果里都没有天地图的数据源，从源头不发公网请求（与旧提交 `d768c66` 的做法一致），由测试断言
- key 提交进 `.env`：天地图的浏览器端 key 本来就要写在每个瓦片地址里，任何人都能看到；防止盗用靠天地图控制台的域名白名单和每日配额。实测不带 Referer 也能取到瓦片，这个 key 可能没有设白名单，要找账号负责人确认
- 待定：公网和内网各用一套构建、部署命令（用户 2026-10-10 提出），具体用环境变量、构建模式还是其他方案，做到时一起评估。无论用哪种，改变的只是 `appConfig.tianditu` 从哪里读取，使用方不变

### 3. 底图的拥有者

```ts
// 页面 setup
const map = provideMap({ groups: ['basemap', 'basemap-labels'], camera: JIANGSU_CAMERA });
const basemap = useBasemap();
map.bindStyle({ basemap: basemap.deriveGroup, 'basemap-labels': basemap.deriveLabelsGroup });
```

- `shared/map/basemap/` 的组合式函数 `useBasemap()` 持有状态：选中的底图、每种底图的透明度（默认 1）。它提供：可选的底图（按配置得出）、选择与修改透明度的操作（不合法的值在这里拒绝，推导时直接信任状态）、两个推导函数
- 推导是纯函数，输入是状态和天地图配置；改透明度时只产生 `setPaintProperty`，不重新加载瓦片。这由 style-spec 的 `diff` 对数据源做深比较保证，与数据源是不是同一个对象无关（5B.1b 改坏验证时确认）
- 透明度作用于所选底图的底图层和注记，不影响背景
- 不用 Pinia：底图状态只在一个页面里共享，旧项目每次进入页面都重新从矢量底图开始；放进 store 会带到其他地图页，同一页面上的两张地图也会共用一份，会话结束时还要另外重置
- 联调面板通过 props 拿到 `useBasemap()` 的返回值，组件只显示和调用
- 暂不记住选择：状态只有底图 ID 和数字，可以直接序列化，5C.3 做持久化时再加初始值或存储
- 之后 `shared/map` 的拥有者沿用这种写法：组合式函数持有状态和操作，纯函数推导分组，界面通过 props 拿到它

### 4. 分组与叠放

- 页面声明 `basemap` 和 `basemap-labels` 两个分组，注记在哪一层由页面决定。复现旧项目的叠放：`['basemap', 'basemap-labels', 'resources', …, 'boundaries']`，完整的顺序见 ADR 0033
- 数据源和图层 ID 分别以 `basemap-`、`basemap-labels-` 开头；两个分组从同一份状态推导，切换底图时在同一轮里一起提交

### 5. 联调面板

`shared/map/basemap/BasemapPanel` 用 Element 的单选按钮组和滑块，位置由页面的 class 决定。它是角落里的小控件，不用 `useMapOverlay` 登记（ADR 0029）。界面在 5D 重新设计。

## 后果

- 好处：内网部署时从源头不请求天地图，而且由类型和测试保证，不靠每个调用方记得判断；关闭后界面上也没有用不了的选项
- 好处：改透明度只改一个绘制属性；切换底图只请求选中的那一种
- 好处：注记单独成组，页面可以决定它压在哪些图层上
- 代价：底图要绑定两个分组，页面多写一个；改环境变量要重新构建
- 代价：底图状态随页面重置，从数据查询回到现状底图时不会保留上次的选择（与旧项目相同）
- 待定：公网、内网两套命令的做法；天地图 key 的白名单；接入天地图后第一帧是否明显（roadmap 5B.1）
