# 0083. 三维路线漫游：清单里的路线、会话的漫游意图

- 状态：已接受
- 日期：2026-10-27
- 落实 ADR 0078 第 6 节的路线漫游（3D.4a）；补充 ADR 0081：漫游意图和瓦片集、钻地一样放在会话的三维内容里

## 背景

3D.4 按用户 2026-10-27 的选择先做路线漫游，再迁移导航网格、做第一人称步行、小地图和第三人称的代码。旧项目没有路线漫游，也没有预置路线。

用户没有现成的路线，请我规划。做法：用旧项目的 `navGrid`（纯 JS，从 b3dm 的三角形建 2.5D 高度场）离线算出苏州站的导航网格，看清楼层和连通区域，再在网格上寻路：

- 站厅（-5.1 米）的非付费区和付费区之间隔着闸机，模型里闸机是关着的，付费区、楼梯和站台（-10.06 米）是另一个连通区域
- 每段在一个连通区域里按离墙距离加权寻路（尽量走通道中间）、拉直时不比原路径更贴墙；穿闸机的一段沿车站轴线、走西侧宽通道的中线直线穿过；最后每半米取一次脚下的地板高度再做三维简化，下楼梯时贴着台阶
- 规划结果用户确认：进站乘车 120.6 米（出生点 → 西侧闸机 → 付费区 → 西侧楼梯 → 站台东段）、站厅巡览 132.6 米（大厅西头 → 东北出口通道）、站台漫步 57.7 米（站台西头 → 东头）

用户同时选定：漫游的状态放在会话里，拥有者持有意图，视图逐帧推进并报告进度。

## 决定

### 1. 路线数据

- 清单的 `routes`：`{ id, name, path }`，`path` 是 `[经度, 纬度, 地板的椭球高]`，至少两个点；高度是脚下的地板，视点在它上面 1.6 米（眼高）
- 长度按三维折线算（楼梯的高差也算），剩余时间按长度和速度算，清单不写长度和时长
- 1× 是 1.6 m/s，和步行漫游的默认速度一样；另有 0.5×、2×

### 2. 会话的漫游意图（map-core）

- `SceneContent` 加 `roam`：

  ```ts
  interface RouteRoam {
    readonly kind: 'route';
    /** 这一次漫游：换路线时换一个 */
    readonly id: string;
    readonly path: readonly (readonly [lng: number, lat: number, floor: number])[];
    readonly playing: boolean;
    readonly rate: number;
    /** 重新开始时加 1，视图回到起点 */
    readonly run: number;
  }
  ```

- 没有漫游时为 `null`；3D.4c 的步行漫游再加一种 `kind`
- 校验：至少两个点、坐标有限、`rate` 大于 0、`run` 是非负整数
- 视图通过可选的 `roamStatus` / `onRoamStatusChange` 报告进度：`{ id, run, distance, total, finished }`，最多 10 次每秒，暂停、到终点、换路线时立即报告；上下文的 `roamStatus` 只反映当前视图（同 `sceneStatus`）

### 3. 视图的做法（map-cesium）

- 路线的几何是纯函数（`route-path.ts`，node 下测试）：累计长度、按走过的距离取位置，朝向看前方 4 米的点（俯仰按高差，最多 ±30°），朝向和俯仰按时间常数 0.4 秒平滑，路线上的小折角看不出来
- `CesiumScene` 的漫游控制（`scene-route.ts`）：开始时飞到起点并停住；播放时每帧按真实流逝的时间推进（一帧最多按 0.1 秒算，页面停用回来不会跳一大段）；视场角换成室内用的 60°；关掉 Cesium 自己的拖动、缩放
- 暂停时左键拖动在原地转头看四周，继续后在 0.6 秒内转回路线的朝向
- 漫游移动相机按 `program` 写回会话，不开始新的相机操作；结束时恢复视场角、相机的拖动和缩放，飞回开始漫游前的位置
- 页面开始别的定位（`flyTo`、`fitBounds`）时，路线立即停下、不飞回，相机交给这次定位；拥有者随后撤掉漫游时不再结束一次
- 暂停期间撤掉的漫游在恢复时结束：视图先恢复相机，再应用暂停期间的三维内容变化（钻地、漫游）；相机能还原（没被别的视图移动过）时才飞回开始前的位置，否则停在从会话同步来的位置

### 4. 拥有者与界面（features/scene-models）

- 拥有者负责开始、播放、暂停、倍速、重新开始、退出；开始时 `beginCameraOperation()`，拿到的 `signal` 中止（有了新的定位）就退出漫游
- 只有加载完成（`ready`）的模型能开始；地下的模型开始漫游时进入钻地（关掉碰撞，相机能到地表以下），漫游期间钻地条不显示；退出后保留钻地、钻地条回来：结束漫游要飞回开始前的位置，同时退出钻地的话，"相机在地下时先飞回地表上方"会和它抢相机
- 退出：操作条的"退出漫游"、Esc、切到二维、选工具栏的工具、卸载这个模型、开始新的定位
- 界面按原型（`/dev/map-3d`）：已加载的模型有路线时显示"路线漫游"下拉（路线名和长度），漫游中的行标"漫游中"并有蓝条；漫游操作条在地图下方居中、状态栏上方，手机宽度时横跨左边两列；空格开始、暂停或继续，到终点后重新开始
- 状态栏在路线漫游时照常显示视点高度；视点在地表以下时按原型写"视点在地表以下 N m"、不显示画布中心的经纬度（钻地时同样）：原来显示成 0 m，中心是视线穿出椭球面的远处

## 后果

- 好处：漫游和瓦片集、钻地一样由会话持有，视图重建、页面缓存后能继续；二维、拥有者都不碰相机
- 好处：路线来自模型的几何，不穿墙、贴着楼梯；规划用的脚本以后可以迁到 `tools/`，模型更新后重新生成
- 代价：会话的三维内容多了一种状态；路线漫游时 Cesium 的相机控制被接管，暂停时只能转头、不能移动
- 待定：步行漫游（3D.4c）的意图怎么表达；路线是否需要在途经点停留或讲解
