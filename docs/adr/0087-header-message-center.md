# 0087. Header 下方的消息弹框

- 状态：已接受
- 日期：2026-10-23
- 分支上原编号 0078，合入 main 前与三维的 ADR 0078 撞号，2026-10-27 改为 0087（见[合入前的整理与整改](../stages/ai-system-management-merge-review.md)）

## 背景

旧消息中心是独立页面，查看通知会离开当前工作。用户要求改为 Header 下方弹框，并确认 `/dev/message-center` 的交互稿。旧全局消息服务同时维护接口副本、每 5 秒轮询和路由跳转，不符合当前分层与查询约定。

## 候选方案

- 保留独立页面：可容纳更多内容，但查看消息需要离开业务页面，不符合本次要求
- 全屏遮罩对话框：复用容易，但阻断当前页面，且视觉重于通知查看
- Header 下非模态弹框：在当前页面查看消息，详情与列表在同一容器切换

## 决定

1. 使用已确认的非模态弹框；宽 480、最大高 640，Header 下留 8、窗口右 / 下留 16。窄屏左右各 16，标题与底栏固定，仅内容滚动；详情最大高 320
2. 复用 `MxPanel headerTone="muted"` 与 `MxTitle`，样式遵循项目令牌。用浏览器标准 Popover，按钮通过 `popovertarget` 关联，原生处理重复点击、外部点击和 Esc；不增加第三方弹层库或旧浏览器兼容层
3. Header 用 `useElementBounding` 提供真实底边位置，经 `actions` 插槽交给消息组件，不在 feature 写死 Header 高度
4. 消息接口、已读操作和组件在 `features/message-center`；查询数据只存在 Vue Query 缓存。真实接口返回全量数组，前端筛选并按 20 条递增展示
5. 应用进入时读取一次未读数量，弹框打开时刷新；不复制旧全局定时器或新增通知提示。后续有明确实时性要求再单独决定
6. 已读写入成功才更新红点；按行 ID 防重复，全部已读与单条写入互斥。写成功后取消旧列表读取，防止迟到结果覆盖；写操作使用会话保护，不随组件卸载取消。切换账号重新建立弹框操作状态
7. app 负责角色与业务跳转；消息 feature 仅提供有类型的业务目标，不导入系统管理。管理员报表消息进入报表列表；申请消息按旧契约用 `taskId` 打开申请详情，无 ID 时明确进入审核列表。用户侧关联页面尚未迁移，入口禁用并说明原因
8. 移除独立 `message-center` 路由与常量，不另建兼容页面。`/dev/message-center` 继续使用固定数据驱动正式组件，只在开发模式注册

## 后果

- 查看消息不切换当前路由，只有点击详情中的业务按钮才导航
- 关闭状态下的未读数是最近读取的结果，不承诺实时推送
- 标记已读、会话竞争和失败重试可用固定接口测试；真实后端写入及用户侧业务依赖分别记录，不把前端验证当作后端验收
- 实际字段、验证结果和待办见 [消息中心迁移](../stages/message-center-migration.md)
