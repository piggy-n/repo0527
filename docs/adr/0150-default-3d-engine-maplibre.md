# 0150. 三维默认引擎改为 MapLibre + Three.js

- 状态：已接受（2026-11-10 用户确认；后果里待定的 Cesium 下的资源图层（方案 B）由 0151、叠画布的 LCC2 由 0152 定为不做；后果里的署名和 `gaussian-splat-lite` 的 LICENSE、NOTICE 见 0149 的状态行；`cesium` 仍可选、CI 的另一种引擎、`test.env` 固定 `cesium` 由 0153 取代，Cesium 引擎已移除）
- 日期：2026-11-10
- 修改：ADR 0147 第 1 节的默认值（`.env`）、第 7 节 CI 里"默认以外的那一种"

## 背景

ADR 0147 第 9 节规定通过五条门槛后 `.env` 的默认值才改为 `maplibre`，改的时候另写一份 ADR。2026-11-10 逐条核对，结果记在 [map-three.md](../modules/map-three.md)"改为默认引擎的门槛"：

| 条 | 结果 | 接受的差距 |
|---|---|---|
| 1 第 3 节的契约测试 | 两种引擎都通过 | |
| 2 3C.1～3C.4 的验收 | 通过 | 三维里显示资源图层由 `SCENE_OPTIONS.resourceLayers` 关着，用户确认算在门槛之外，放开时单独验收 |
| 3 现有三维功能 | 真实页面逐项通过；星海广场站的轨道俯视时消失已修（远裁剪面） | 第三人称的人物模型没做（入口没开放），用户确认不挡门槛 |
| 4 人工检查 | 有记录，用户接受，第一人称继续用抬高（ADR 0147 的待定项），拖动时模型相对底图滑动在业务页的上限 z18 接受 | 右键转向、和 Cesium 同位置对照、z12 和二三维切换的逐帧录像没有做；和天地图的对齐是目视 |
| 5 生产包在显卡机器上复测 | RTX 3060，提交 `8d231735`，z17 全部通过，z19 帧时间、到稳定、画质都通过 | z19 两遍飞行的三角形中位数 88.6%、87.5%（线是 90%），和 2026-11-09 接受的 88% 同一水平。业务页的上限是 z18，z19 只在测量页和漫游里出现 |

用户看过这些结果后决定切换。

## 决定

- `apps/yzt/.env` 的 `VITE_MAP_3D_ENGINE` 改为 `maplibre`。内网、公网相同，`.env.intranet` 不覆盖。
- `cesium` 仍是可选的取值，按 ADR 0147 第 6 节维护：修缺陷、跟版本，新功能只在 `maplibre` 下做。部署要回到 Cesium 时设 `VITE_MAP_3D_ENGINE=cesium` 重新构建，产物里才有 `cesium/`。
- CI 里"默认以外的那一种"换成 `cesium`：内网构建一次，跑 `scene.spec`、`static-basemap` 两个冒烟（ADR 0147 第 7 节）。默认的产物跑全部冒烟，其中 `scene.spec.ts` 跳过、`scene-maplibre.spec.ts` 运行。
- 单元测试的 `test.env` 仍固定 `cesium`：这些用例不依赖部署的取值，两种引擎的行为由契约测试和冒烟覆盖。

## 后果

- 三维不再下载 Cesium，二三维共用一块画布；默认产物少约 7 MB 的 `cesium/`。
- 飞行中明显更流畅：z19 第一遍飞行每帧工作量 p99 33 对 125 毫秒，其中一部分来自飞行中画得更粗、没开多重采样。
- 代价：渲染进程的私有内存比 Cesium 多（z17 稳定时 1,891 对 872 MB，z19 2,659 对 1,871 MB），小内存的机器要留意。只在 RTX 3060、15 GB 内存的机器上测过。
- LCC2 高斯泼溅从这里起对默认构建的用户可见（入库的清单里有楚王山1号）。署名、`gaussian-splat-lite` 的 LICENSE 和 NOTICE 随产物提供还没做，要等法务（ADR 0149 第 8 节，backlog），对外发布前要解决。
- 多重采样还是不开，用户之后自己对照再定。
- 显卡机器上现状底图的控制台有 109 条 `[map] Error`，没有查原因（backlog）。
- 待定：业务页三维是否放开到 z19；Cesium 下的资源图层（方案 B）和叠画布的 LCC2 按 backlog 的顺序继续。
