# 0088. 数据查询的条件快照与公共地图工具

- 状态：已接受
- 日期：2026-10-24

## 背景

迁移数据查询的四个入口。用户确认高级查询与属性、空间、自然语言同级切换，并确认森林草原湿地荒漠、水资源先迁移旧版地图壳。旧查询页将字段、接口、地图及导出集中在一个组件中，编辑条件后容易使已显示结果、翻页与导出的条件不同步。

## 候选方案

继续保留高级查询侧挂浮窗会重复布局与查询状态；直接用编辑中的表单驱动翻页和导出会让未执行的条件影响旧结果。因此采用统一模式切换及独立执行快照。

## 决定

1. 一个业务页按路由 props 接收模块。`features/data-query` 持有旧图层配置、条件、接口与交互；页面组合公共地图能力，features 之间不互相导入
2. 表单草稿与不可变的查询快照分开。提交先作废旧查询，再验证新条件；分页、地图和导出只用快照。查询结果由 TanStack Query 管理，并带查询身份 / 页码核对，避免下一轮调度前读到旧结果
3. GET 和 POST 查询都是可取消的读取。切换或离开时取消，响应后核对会话；导出使用公共 `useDownloads`，POST 请求体交给 `fetchFile`，不另写文件名解析和 Blob 保存
4. 框选 / 多边形由 map-core 的通用 `PolygonDrawTool` 处理输入与几何有效性，feature 持有范围、推导样式。底图、边界、定位、工具栏沿用 shared/map。现状底图和查询共用 GUID 几何读取及 schema
5. 高级查询只编辑条件，图层和区划显式选择。前端格式检查不替代后端的权限与表达式校验。自然语言只支持既有示例，不制造通用解析能力；固定演示统计不作为业务结果迁移
6. 前两个模块接入查询，后两个只保留地图壳。缺失或有歧义的旧字段、真实 SHP 解析和导出联调记录在迁移文档，不靠兼容分支猜测

## 后果

用户改条件后需要重新查询，界面提示这一点；旧结果翻页与导出保持一致。页面离开即释放，不新增 KeepAlive。桌面左侧条件、底部结果，窄屏改用抽屉；结果表只在自身区域滚动。实现与实际验证见 [迁移记录](../stages/data-query-migration.md)。
