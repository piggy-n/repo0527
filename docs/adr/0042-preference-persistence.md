# 0042. 偏好的持久化：IndexedDB + idb-keyval 的键值存储

- 状态：已接受
- 日期：2026-10-11
- 补充 ADR 0041 第 3 节（持久化恢复的显示状态按资源合并）；定下 AGENTS.md 里待定的持久化方案

## 背景

现状底图的偏好现在都只在内存里：资源图层的勾选、透明度、顺序、年份（ADR 0041），底图的选择和透明度（ADR 0031），行政区边界的级别和透明度（ADR 0033），刷新页面就回到默认值。

旧项目（yzt `master-demo` 836f03b）和现状底图有关的持久化都在 localStorage，键是"基础键::角色_用户ID"，退出登录时不清除：

- 图层排序 `current-map-new-layer-order`：按父节点记录的同级顺序
- 地类配色的覆盖 `landuse-color-overrides`、符号覆盖 `layer-symbol-overrides`（符号编辑在 5C.5）
- 勾选和透明度不保存，每次打开都是默认的地类图斑

阶段二只有会话需要持久化，会话要同步读取，所以直接用了 localStorage（ADR 0015），IndexedDB 留到"有需要持久化的大块数据时"再定（roadmap）。现在要存的偏好只有几 KB，但 5C.4、5C.5 可能有较大的数据（地类统计、图例的初始化数据），持久化的接口这次定下来，以后的使用方不再换写法。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 存在哪里 | localStorage；IndexedDB | IndexedDB：写入不阻塞主线程，容量大，能直接存结构化数据；以后较大的数据也能放在这里，不同时维护两套机制。代价是读取是异步的（见第 5 节） |
| IndexedDB 的用法 | 原生 API；idb（完整的 Promise 封装）；idb-keyval | idb-keyval（Apache-2.0）：只需要按键读写，它只提供 get、set、del 这类最简单的操作，体积很小；用到事务、索引时再换 |
| 使用方怎样调用 | 直接调用 idb-keyval；自己定义异步的键值接口 | 自己定义接口：测试注入内存实现，不需要 fake-indexeddb；以后换实现不改使用方 |
| 资源图层存什么 | 只存顺序（旧项目）；勾选、透明度、顺序、年份 | 都存，下次打开时恢复成上次的地图 |
| 底图和边界 | 不存；一起存 | 一起存：数据很小，机制相同（shared-map.md 留到 5C.3 的事项） |
| 按什么区分 | 角色 + 用户 ID（旧项目）；登录名 | 登录名：会话里一定有（用户 ID 是可选的），一个用户只有一个角色 |
| 退出登录时 | 清除；保留 | 保留：是偏好，不是敏感数据，同一台电脑上不同用户各存各的（同旧项目） |
| 多个标签页 | 同步（BroadcastChannel 等）；不同步 | 不同步，后写入的覆盖先写入的（旧项目也不同步） |
| 首屏 | 不等，读到后替换；资源图层等目录和存储都就绪；整页等读取 | 资源图层等两边都就绪，读取有上限；底图、边界读到后替换（第 5 节） |
| 写入时机 | 每次变化；防抖；只在离开页面时 | 防抖；离开页面（路由离开、身份失效）时立即写入还没写的那一次 |
| 刷新、关闭标签页 | 只靠组件销毁时保存；页面隐藏时尽力提交；另用同步的 localStorage 兜底 | 页面隐藏时尽力提交，接受最后一次修改可能丢失（第 6 节）：刷新、关闭不走 Vue 的卸载流程，异步的 IndexedDB 写入也不保证在浏览器退出前完成；为几百毫秒内的修改再维护一份 localStorage 不值得 |
| 公共的流程放在哪里 | 每个拥有者各写一套；共用一套流程，各自给出格式和合并规则 | 共用（第 4 节）：等待上限、防抖、身份失效和销毁时的清理只写一次，三个拥有者只关心自己的数据 |
| 用户身份从哪里来 | 拥有者自己读会话；页面装配时提供 | 页面装配时提供（第 2 节）：开发页不提供就不启用持久化；身份在创建时固定，不在写入时才去读会话 |
| 存下的格式 | 原样存状态（含 `Map`）；带版本号的普通数据，读出时用 zod 校验 | 后者：存储里的数据是外部数据，可能来自旧版本或被改坏 |

## 决定

### 1. 键值存储（`shared/storage`）

- 接口 `KeyValueStore`：`get(key)`（没有时为 `undefined`）、`set(key, value)`、`delete(key)`，都返回 Promise；值是可以结构化克隆的普通数据（对象、数组、字符串、数字、布尔），不存 `Map`、类实例
- IndexedDB 的实现用 idb-keyval 的 `createStore`，数据库和对象仓库用项目自己的名字（不用它默认的 `keyval-store`）；第一次读写时才打开数据库
- 内存实现给测试用；整个应用共用一个 IndexedDB 的实现，使用方的选项里可以换掉（同区划边界的加载器）
- 浏览器不支持或禁用 IndexedDB 时，读写以失败结束，按第 5、6 节的规则处理，页面照常可用

### 2. 偏好的范围：页面装配时提供，身份在创建时固定

- 页面在 setup 中按当前会话创建偏好的范围，交给要持久化的拥有者；范围里有存储、固定的用户和一个生命期。没有登录时不创建，拥有者就不读不写；开发页不提供，同样不启用
- 键是 `<登录名>/<名称>`，登录名在创建时固定、用 `encodeURIComponent` 编码；名称如 `resource-layers`、`basemap`、`boundaries`。之后的读写都用这个键，不在写入时才去读会话
- 生命期在两种情况下结束：页面的作用域销毁（路由离开）；会话里的用户不再是创建时的那个（本标签页退出、会话过期、其他标签页退出时，`endSession` 先清空会话，再跳转、卸载页面）。其他标签页登录了另一个账号时整页重新加载，按第 6 节的页面隐藏处理
- 生命期结束时：已经排队、还没写入的那一次立即写入原用户的键（退出前最后的调整也保留下来）；之后不再接受新的写入，还没到的读取结果不再应用
- 退出登录、会话过期时不清除存下的偏好；换了用户就是另一组键

### 3. 存下的格式与校验

- 每一项存成 `{ version, value }`，`value` 是普通数据，例如资源图层存每个资源的勾选、透明度、年份和面板顺序（数组和对象，不是 `Map`）
- 读出时用 zod 校验；版本不对、格式不对就当作没有存过，之后由新的写入覆盖；格式变化时升版本号，需要时写迁移
- 校验不只看字段的类型和范围，还要保证数据本身自洽，不满足时整条当作没有存过。资源图层的面板顺序不能有重复，并且和各资源的设置一一对应（正常的状态总是如此）：重复的顺序项会被合并函数保留下来，推导出重复的图层 ID，整次样式提交都会被拒绝。目录的增删、年份的变化仍由合并函数处理
- 存下的值不直接使用，按各自的规则和当前的数据合并：
  - 资源图层按 ADR 0041 第 3 节合并：目录里没有了的资源丢掉，新资源用默认值，失效的年份改用最新的一年
  - 底图：选中的底图当前不可用时（没有配置天地图，ADR 0031、0032）用默认值；透明度要在 0～1 之间
  - 边界：三个级别是否显示、透明度在 0～1 之间

### 4. 共用的流程与各自的规则

- 共用的流程（`shared/storage`）负责：开始读取与等待上限、恢复只应用一次、恢复前已有操作时放弃恢复、防抖写入、生命期结束和页面隐藏时提交、读写失败的上报
- 各拥有者只给出自己的部分：名称、版本号、zod schema（含第 3 节的自洽检查）、把状态转成存储格式的函数、把存下的值合并进当前状态的规则
- 拥有者的选项里接收偏好的范围；没有范围时行为和现在一样

### 5. 恢复：读取与等待

- 拥有者创建时开始读取，最多等 1 秒；超时、读取失败、格式不对都按默认值继续，超时之后才到的结果丢弃（ADR 0039：等待返回后再确认）
- 资源图层等目录和存储都就绪后才合并出显示状态：不先按默认值显示地类图斑、再换成上次的选择，也不白白请求一轮瓦片。读存储和请求资源树同时进行，资源树通常更慢，实际看不出额外的等待
- 底图、边界先用默认值，读到后整体替换一次：IndexedDB 的读取通常在地图加载完样式之前就结束，替换在会话里只是一次样式提交
- 恢复结束之前用户已经操作过这个拥有者（勾选、切换底图等）：放弃恢复，以用户的操作为准

### 6. 写入

- 恢复结束之后才写入：否则默认值会覆盖存下的状态
- 状态变化后防抖约 300 ms 写入（拖动透明度滑块时连续变化）
- 路由离开、身份失效：生命期结束，立即写入还没写的那一次（第 2 节）
- 刷新、关闭标签页不走 Vue 的卸载流程：页面变为隐藏（`visibilitychange` 到 `hidden`）和 `pagehide` 时尽力提交还没写的那一次，两者可能都触发，提交是幂等的。IndexedDB 的写入是异步的，浏览器退出前不保证完成（MDN"浏览器关闭时的警告"），所以明确接受：最后一次修改在防抖窗口内、或提交没来得及完成时就关闭页面，这次修改可能丢失
- 写入失败交给 `onError`（默认打印到控制台），不弹提示，不影响页面

### 7. 测试

- 恢复、合并、等待上限、写入时机用内存实现测试；包括存下的顺序有重复、和设置对不上时整条作废，身份失效时排队的写入落到原用户的键、之后的读取结果不应用，页面隐藏时提交
- IndexedDB 的实现放在 Vitest 浏览器测试里，在真实的 Chromium 中测（ADR 0040）；不引入 fake-indexeddb

## 后果

- 好处：刷新页面、下次打开时回到上次的资源图层、底图和边界；读取不阻塞主线程，以后较大的数据也有了统一的接口
- 好处：恢复的值经过校验和合并，旧版本的数据、目录的变化、内网没有天地图都不会让页面出错
- 代价：读取是异步的，资源图层的首屏要等存储读完（有上限）；底图、边界在极少数情况下会先显示默认值再切换
- 代价：多个标签页之间不同步，同时在两个标签页里调整时，后写入的为准
- 代价：刷新、关闭标签页前几百毫秒内的修改可能没有保存下来
- 待定：地类配色和符号的覆盖（5C.5）、图例等初始化数据（5C.5）是否、怎样用这里的存储，到时决定
