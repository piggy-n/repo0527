# 0056. 点/框选的交互：十字光标、跟随提示、按住 Ctrl / ⌘ 临时拖动地图

- 状态：已接受
- 日期：2026-10-16
- 修正 ADR 0047 第 6 节（点选的光标）、ADR 0049 第 1 节和后果（点选模式下不能拖动平移）；补充 ADR 0034 第 2、3 节（工具声明临时拖动的修饰键，视图应用临时的光标）

## 背景

用户在 5D 打标签之后的优化意见（2026-10-16）里，对点/框选提出以下要求：

- 激活后显示十字光标
- 鼠标旁边显示跟随提示
- 按住 Ctrl 时光标变成手型，可以拖动地图；松开后恢复十字光标和点/框选；拖动地图时不触发框选

讨论后已定的几点：

- Windows 用 Ctrl，Mac 用 ⌘：Mac 上 Ctrl + 单击会被系统当成右键
- 提示在每次进入点/框选时显示，单击或框选过一次后不再显示，直到下次进入
- Esc 的含义不变
- 十字光标在优化第一步已经改了（`f013897`），这里补记决定

### 现状

- 点/框选关掉了拖动平移和 Shift 框选放大（ADR 0049 第 1 节），要平移只能切到"移动"或用滚轮（ADR 0049 的后果）
- 工具只声明固定的光标和要关掉的手势，由适配器应用（ADR 0034 第 2、3 节）。ADR 0034 的后果写明：光标需要随状态变化时，"以后有使用方时再扩展"
- 二维允许右键拖动旋转和俯仰，状态栏会显示角度，这项要保留
- libs 不读全局对象（AGENTS.md），map-core 不能自己判断平台

### MapLibre 6.12 的鼠标手势（`src/ui/handler/mouse.ts`、`handler_manager.ts`）

- 拖动平移只认没按 Ctrl 的左键（`button === 0 && !ctrlKey`）
- 左键加 Ctrl、右键拖动是旋转和俯仰
- 是哪种手势只在按下时判断一次
- 按下的监听挂在画布容器上，在冒泡阶段

这带来三个问题：

- Windows 上即使打开 MapLibre 的拖动平移，按住 Ctrl 也拖不动，反而会旋转
- 点/框选里按住 Ctrl 拖动，地图旋转，点/框选工具同时开始框选；地图一动，框选就被取消
- Mac 上 MapLibre 不使用 ⌘，但点/框选关了拖动平移，所以 ⌘ 加拖动现在就是普通的框选

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 临时拖动用哪个键 | 空格（设计软件的习惯）；Ctrl / ⌘；中键拖动 | Ctrl / ⌘，这是用户的要求。空格只有地图获得焦点时才收得到，而点/框选不抢焦点；中键不好发现 |
| 由谁平移 | 按住修饰键时临时打开 MapLibre 的拖动平移；适配器自己按指针位移平移 | 适配器自己平移。MapLibre 的拖动平移不认 Ctrl，打开了也拖不动；自己平移时 Windows 和 Mac 是同一套 |
| 怎样挡住 Ctrl 旋转 | 点/框选时关掉 `dragRotate`；适配器在捕获阶段截下这次按下 | 截下这次按下：MapLibre 和工具都收不到它，旋转和框选都不会开始；右键旋转不受影响 |
| 由谁判断平台 | map-core 读 `navigator`；`shared/map` 判断后交给工具 | `shared/map` 判断：libs 不读全局对象，提示文字也要用这个结果 |
| 怎样声明 | 让 `Gestures.dragPan` 可以写成修饰键；工具单独声明 `panModifier` | 单独声明：`Gestures` 只是 MapLibre 默认手势的开关，含义不变 |
| 手型光标什么时候出现 | 只在拖动时出现；按住修饰键就出现 | 按住修饰键就出现（用户的要求），拖动中换成 `grabbing` |
| 提示什么时候消失 | 一直显示；每次进入后用过一次就消失；只在第一次使用时显示（存进偏好） | 每次进入后用过一次就消失（已定） |

## 决定

### 1. 工具声明临时拖动的修饰键（map-core，补充 ADR 0034 第 2 节）

```ts
type PanModifier = 'ctrl' | 'meta';

interface MapTool {
  // ……
  /** 按住这个修饰键时，左键拖动平移地图，这次拖动不交给工具；供关掉了拖动平移的工具使用 */
  readonly panModifier?: PanModifier;
}
```

- map-core 不判断平台。`shared/map` 根据平台给出修饰键和它在提示里的写法：Mac 用 `meta`，写作"⌘"；其他平台用 `ctrl`，写作"Ctrl"
- 判断平台的纯函数单独测试

### 2. 视图的临时拖动（MapLibre 适配器，补充 ADR 0034 第 3 节）

**开始**

- 当前工具声明了 `panModifier`，左键按下时按着这个键，就是一次临时拖动
- 适配器在画布容器的捕获阶段截下这次按下：停止传播，但不阻止默认行为，画布照常获得焦点
- MapLibre 的手势和地图事件都收不到这次按下，所以不旋转、不俯仰；工具也收不到，不会开始框选
- 只有就绪、没有暂停的视图才做临时拖动，和转交输入的条件一样（ADR 0034 第 3 节）

**拖动中**

- 指针移动时按位移平移，没有惯性，相机事件的来源是 `user`
- 移动的监听挂在文档上，所以指针移出画布也能继续拖
- 松开左键时结束；窗口失焦、视图暂停或释放、切换工具时也结束
- 是不是临时拖动只在按下时判断，和 MapLibre 一样：
  - 拖动中松开修饰键，继续拖到松手为止
  - 框选中按下修饰键，仍然是框选

**交给工具的输入**

- 这次按下、松开和松开后派生的单击都不交给工具
- 指针移动照常经过工具模型，上下文的 `pointer` 和状态栏的经纬度跟着更新
- 工具没有处于按下状态，所以这些移动不会进入框选

**光标**

当前工具声明了 `panModifier` 时，适配器按下面的规则显示光标：

| 状态 | 光标 |
|---|---|
| 按住修饰键、左键没有按下 | `grab` |
| 临时拖动中 | `grabbing` |
| 其他情况 | 工具声明的光标 |

- 修饰键的状态从文档的 `keydown` / `keyup` 和指针事件的修饰键得知；窗口失焦时当作已松开
- 光标仍然只由适配器写

**三维**

- map-cesium 以后按同一份声明实现；Cesium 的默认手势和 MapLibre 不同，具体做法到三维阶段再定

### 3. 点/框选工具（修正 ADR 0047 第 6 节、ADR 0049 第 1 节）

- 光标是十字（`crosshair`），原来是默认箭头（2026-10-16 用户要求，优化第一步已改）
- 声明 `panModifier`，值由 `shared/map` 给出：按住 Ctrl（Mac 上是 ⌘）拖动地图，松开后回到十字光标和点/框选
- ADR 0049 后果里"点选模式下不能拖动平移，要切到移动或用滚轮"不再成立
- 单击、拖动框选、Esc 和取消的规则不变（ADR 0049 第 1 节）

### 4. 跟随提示

**何时显示**

- 是否显示提示由拥有者 `useFeaturePick` 持有
- 工具激活时打开提示
- 第一次单击识别，或第一次框选识别（松手时得出了框）之后关闭，直到下次激活
- 离开工具时关闭
- 临时拖动、按 Esc、取消的框选都不算用过

**显示条件**

需要同时满足：

- 提示是打开的
- 视图就绪
- 指针在画布上（上下文的 `pointer` 不为 `null`）
- 没有在框选：框选中显示的是矩形

**内容**

- 用 `PointerHint` 显示，靠边时翻到另一侧（ADR 0055），不拦截鼠标
- 共两行，第二行里的修饰键按平台写：
  - 第一行：单击查看要素，拖动框选
  - 第二行：按住 Ctrl 拖动地图，Esc 取消或清除结果（Mac 上写 ⌘）
- 触屏没有指针位置，所以不显示提示；临时拖动也只对鼠标有效

### 5. 验收

**单元测试**

- 适配器（假的 `MapLike`），对声明了修饰键的工具：
  - 按住修饰键按下左键时，工具收不到按下、松开和派生的单击
  - 拖动时按位移平移，相机事件的来源是 `user`
  - 拖动中松开修饰键，继续拖动
  - 失焦、切换工具、暂停时结束
  - 光标在工具的光标、`grab`、`grabbing` 之间正确切换
  - 没按修饰键时照常交给工具；没声明修饰键的工具不受影响
- `shared/map`：平台到修饰键和写法的对应
- 拥有者：
  - 激活时打开提示；单击识别、框选识别之后关闭
  - 临时拖动、Esc、取消的框选之后仍然打开
  - 再次激活时重新打开
- 页面：提示跟着指针显示，框选中不显示，离开画布时隐藏

**浏览器测试（真实的 MapLibre）**

- 按住 Ctrl 拖动时地图平移，方位角不变
- 右键拖动照常旋转

**真实页面**

- Windows 上按住 Ctrl 拖动可以平移，不旋转、不框选
- 松开 Ctrl 后恢复十字光标，单击和框选照常
- Mac 没有实测条件，记进待办

## 后果

**好处**

- 点/框选下不切换工具就能平移
- Ctrl 拖动时旋转和框选同时开始的问题一起消失
- 光标和平移仍然只由适配器写地图，工具只做声明（ADR 0034）

**代价**

- 适配器多了一套自己的拖动：没有惯性；地图倾斜时，位移按画面中心换算，离中心远的地方不完全跟手
- 两种模式下 Ctrl 的含义不同：
  - 点/框选里，Windows 上左键加 Ctrl 不再旋转（右键拖动仍然可以）
  - "移动"里，Ctrl 加拖动仍是 MapLibre 的旋转
- 适配器要在文档上监听按键，才能在不移动鼠标时更新光标
- Mac 上的 ⌘ 没有实测
