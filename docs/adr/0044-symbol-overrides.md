# 0044. 符号覆盖：模型、推导与保存

- 状态：已接受
- 日期：2026-10-12
- 补充 ADR 0041 第 2 节（登记表给出的默认样式改为默认符号，用户的调整作为覆盖叠加）、ADR 0043（图例由只读变为可以编辑）；更正 ADR 0043 背景中旧地类图例的说法（见下）；面的多图层与纹理另写 ADR（5C.5c）

## 背景

旧项目（yzt `master-demo` 836f03b）的图例可以编辑符号，由 `LayerSymbolStyleManager`、`layerSymbolModel.js` 和图例里的 `LayerLegendGroup`、`LayerSymbolEditor` 实现：

- 统一符号：点有大小（S、M、L、XL 四档或自定义半径）、填充色、描边色、描边宽度；线有颜色、线宽（四档或自定义）、线型（实线、虚线、点线、点划线）；面有填充色（带透明度）、10 种填充方式（无填充、均匀填充、8 种花纹）、纹理颜色、描边色、描边宽度、描边线型
- 分类资源（按属性配色、地类图斑）可以在"统一样式"和"分类样式"之间切换；分类时每个取值单独一整套符号，可以搜索、按分组（表 A.2 或表 A.1）筛选
- 可以恢复单个分组、单个图层、全部的默认样式；覆盖只记和默认不同的字段，存在 localStorage（按角色和用户 ID）；拖动调色时实时预览，写入有防抖

更正：ADR 0043 背景说旧图例里地类图斑显示 `LanduseLegendSection`，不对。这个组件从旧仓库的提交 `acb46f8`（图层符号样式管理）起就没有组件引用了，地类图斑实际走的是 `LayerLegendGroup` 的分类样式。5C.4 的地类图例（按表 A.1、表 A.2 分组、搜索）和实际的功能基本一致，含义说明和"全部"平铺来自那段不再使用的代码；ADR 0043 不做地类统计的结论不受影响（那项统计只由这个组件触发）。

现在的样式登记表（ADR 0041 第 2 节）直接给出图层的 paint，图例（ADR 0043）从同一份数据推导、只读。要支持编辑，需要一个"符号"层面的模型：默认符号来自登记表，用户的调整作为覆盖叠加，图层和图例都从叠加后的符号推导。

MapLibre 6.12 的线宽、线型（`line-dasharray`）、纹理（`fill-pattern`）、点的各项都支持按要素属性变化（数据驱动），分类时逐项不同的符号可以用 `match` 表达式在一个图层里表达；面的描边宽度、描边线型和纹理在一个 fill 图层里做不到，要拆成多个图层并注册纹理图片（5C.5c）。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 范围 | 全部迁移；简化（分类只改颜色、不做纹理） | 全部迁移，旧页面都在用；分三步：5C.5a 模型、保存与统一符号，5C.5b 分类样式，5C.5c 面的描边宽度、线型与纹理（2026-10-12 讨论确定） |
| 覆盖的形式 | 存完整的符号；只记和默认不同的字段 | 只记差异：默认符号调整时（如配色板），没改过的字段跟着变（同旧项目） |
| 分类时逐项不同的符号 | 每个取值一个图层；一个图层里各属性用 `match` | `match`：只对各项确实不同的属性生成；图层数不随取值增长 |
| 分类的大小与缩放曲线 | 曲线放进 `match` 的分支；曲线外乘分类倍率；外层缩放插值、各断点的输出里做 `match` | 最后一种：前两种实测通不过样式校验（第 4 节），MapLibre 只允许 `zoom` 作为顶层 `step` 或 `interpolate` 的输入；旧项目的 `combineValues` 也是这样组合的 |
| 拖动调色时 | 每次拖动直接写入覆盖并保存；只在确认后更新，没有实时预览；拖动时临时预览，确认后写入 | 临时预览：`ElColorPicker` 区分拖动中的 `active-change` 和确认，关闭或按 Esc 时恢复到原来的值；直接写入的话取消时已经没有原值，停顿超过防抖还会存下没确认的颜色 |
| 差异怎样比较 | 直接比较字符串；规范化后比较 | 规范化后比较：`#D9433F`、`rgb(217, 67, 63)`、`rgba(217, 67, 63, 1)` 是同一个颜色，直接比较会留下多余的覆盖，这个字段以后就不再跟随默认配色 |
| 纹理 | SDF 纹理（固定的几张图片，颜色由样式给出）；canvas 按颜色现画 | SDF，5C.5c 先在浏览器测试里验证，另写 ADR |
| 拥有者 | 并进 `useResourceLayers`；单独的 `useResourceSymbols` | 单独：显示状态（勾选、透明度、顺序、年份）和符号是两件事，分别保存；`resources` 分组的推导读两者 |
| 保存 | localStorage（旧项目）；ADR 0042 的偏好 | ADR 0042，名称 `resource-symbols` |
| 目录里没有了的资源、规则里没有了的取值 | 删掉它们的覆盖；保留，不参与推导 | 保留：目录暂时少了某个资源时不丢用户的调整，数据很小 |
| 编辑器放在哪里 | 图层面板；图例 | 图例的条目里（同旧项目），5C.4 的图例由只读变为可以编辑 |
| 颜色选择器 | 迁移旧的自定义组件；Element 的 `ElColorPicker` | `ElColorPicker`（带透明度、预设色），优先用组件库 |

## 决定

### 1. 符号模型（按几何类型）

| 几何 | 字段 | 取值 |
|---|---|---|
| 点 | 大小、填充色、描边色、描边宽度 | 大小是四档或自定义半径（以 12 级为参考，1～20 px，步长 0.5）；描边宽度 0～3 px，步长 1 |
| 线 | 颜色、线宽、线型 | 线宽是四档或自定义（以 14 级为参考，0.5～12 px，步长 0.1）；线型是实线、虚线 `[3, 2]`、点线 `[1, 2]`、点划线 `[4, 2, 1, 2]` |
| 面 | 填充色、描边色 | 描边宽度、描边线型、填充方式和纹理颜色在 5C.5c 加入 |

- 四档作用于整条随缩放插值的曲线（倍率 0.6、1、1.6、2.4），缩放断点不变；自定义值按"参考级别下的像素 ÷ M 档的像素"换成倍率（点 4 px，线 1.8 px），同旧项目
- 颜色可以带透明度，用 style-spec 的 `Color.parse` 校验
- 规范化：颜色统一成 `rgba(r, g, b, a)`（r、g、b 是 0～255 的整数，a 保留两位小数，取色器的透明度按百分比调）；自定义大小按步长取整（点半径 0.5，线宽 0.1）。保存、比较差异都用规范化后的值

### 2. 默认符号由登记表给出

- 统一符号的默认值和现在推导出的样式相同：配色板颜色，面是 0.35 透明度的填充加同色描边，线是实线、M 档，点是 M 档、白色 1 px 描边
- 分类资源每个取值的默认符号：取值的颜色作为主色（面的填充和描边同色，线的颜色，点的填充色），其余同统一符号
- 地类的取值是 69 个地类、6 个历史地类和"未匹配的地类"，颜色来自 `landuse.ts`；按编码（地类图斑）、按名称（城镇村）的匹配结构不变
- 分类资源的样式方式默认是"分类样式"

### 3. 覆盖

- 按资源记：统一样式的覆盖、样式方式、分类时每个取值的覆盖；都只记和默认不同的字段，规范化后与默认相同的字段不记（写入时发现相同就删掉这个字段）
- 取值的键：按取值配色的资源用取值本身；地类用地类编码，历史地类用 `legacy:名称`，未匹配用 `$other`
- 恢复默认就是删掉对应的覆盖：单个取值、单个资源、全部

### 4. 推导

- 叠加后的符号 = 默认符号 + 覆盖（拖动调色时再叠加临时预览，见第 6 节）
- 统一样式没有按属性的分类，但大小（点半径、线宽）仍是随缩放插值的表达式
- 分类样式：不随缩放的属性（颜色、点的描边宽度、线型）各生成一个 `match`；随缩放的大小保留外层的缩放插值，在各断点的输出值里做 `match`。直接把曲线放进 `match` 的分支、在曲线外乘分类倍率，style-spec 校验分别报"只能有一个基于缩放的 step 或 interpolate""zoom 只能作为顶层 step 或 interpolate 的输入"（2026-10-12 实测）
- 所有取值在某个属性上都相同时，这个属性不生成 `match`；数组值（线型）在 `match` 里用 `literal` 包起来；地类按编码、按名称的匹配结构（编码没命中再按名称查历史地类）在每个属性上都保持
- 图层和图例都从叠加后的符号推导（延续 ADR 0043 的同源原则）：图例的预览、地类图例的颜色都反映用户的调整
- 推导是纯函数，输入是目录、显示状态、符号覆盖和临时预览；`resources` 分组的推导读显示状态和符号两个拥有者，任一变化都重新推导
- 目录里没有的资源、规则里没有的取值，它们的覆盖不参与推导

### 5. 拥有者 `useResourceSymbols`

- 持有全部资源的符号覆盖，`shallowRef` 整体替换，值没变时不替换；操作的参数不合法（字段不属于该几何、数值越界、颜色解析不了）时抛错
- 按 ADR 0042 保存：名称 `resource-symbols`、带版本号，schema 校验字段、范围和颜色，不合法的整条作废；读到后替换一次（同底图、边界），恢复之前已有操作时放弃恢复
- 临时预览是拥有者的另一份状态，不在覆盖里，也不保存；见第 6 节

### 6. 界面

- 编辑器放在图例的条目里：统一符号的条目展开后是符号编辑器；分类资源的条目有样式方式的切换，分类时列出各取值，展开某一项编辑它的符号（5C.5b）
- 颜色用 `ElColorPicker`（带透明度、预设色）；界面在 5D 再设计
- 预览与确认：拖动中（`active-change`）只设临时预览，它参与地图和图例的推导，不写入覆盖、不保存；确认（`change`）时写入覆盖，按 ADR 0042 保存，同时清掉预览；关闭取色器或按 Esc（取消）时丢弃预览，回到原来的颜色。`ElColorPicker` 没有专门的取消事件，按取色器面板的关闭来丢弃预览，用哪个事件在实现时核对。同一时间只有一个预览
- 取色器不允许清空（`clearable` 关掉），空值不会进入颜色校验；恢复默认用专门的按钮
- 档位、描边宽度、线型这类点选的操作，点下就确认；自定义数值在回车或失焦时确认，不合法的值不提交，留在输入框里提示范围（拥有者的操作仍然对不合法的参数抛错，界面先校验）

### 7. 分步

- 5C.5a：符号模型、默认符号、覆盖与推导、`useResourceSymbols` 与保存；统一符号的编辑（点、线的全部字段，面的填充色和描边色）
- 5C.5b：分类样式（样式方式、逐项符号、搜索与按分组筛选）
- 5C.5c：面的描边宽度、描边线型和纹理：一个面资源拆成多个图层，地图内核支持样式图片，另写 ADR

### 8. 其他

- 路线图里"图例等初始化数据是否打包后写入 IndexedDB"关闭：地类表等数据随代码打包，只有几 KB，不需要初始化

## 后果

- 好处：用户调整的符号在图层和图例上一致，按用户保存；默认符号调整时没改过的字段跟着变
- 好处：分类时逐项不同的符号不增加图层，换取值、改符号只是 paint 的变化
- 代价：面的描边宽度、线型和纹理要等到 5C.5c，在那之前面只能改填充色和描边色
- 代价：目录里没有了的资源的覆盖会一直留在存储里，直到用户恢复全部默认
