# 0123. 资源分类：字典加规则，探查后人工确认

- 状态：已接受
- 日期：2026-11-02
- 补充 ADR 0041 第 2 节（按属性配色的规则）、ADR 0043（图例从登记表推导，不读地图）、ADR 0044（取值的键）；修改 ADR 0044 第 3 节（样式方式的存法）

## 背景

现状底图的 80 个资源里只有 5 个按属性配色，其余是统一样式。要把分类扩展到更多资源，先要回答按什么分、切片要不要改、配置怎么维护。

后端可以查到每个瓦片集的字段和取值，所以写了只读的探查脚本（`pnpm --filter @yzt/web probe:resource-classes`），跑了全部 80 个资源的最新一年，再对选定的 37 个资源跑了全部年份和准确分布，结果见 [docs/archive/migration.md](../archive/migration.md)"现状底图：资源分类的探查"。对方案有影响的结论：

1. 32 个资源有 `cc` 字段，共 44 个编码，没有一个编码对应两个名称。其中 14 个资源有多个取值，18 个只有一个取值（如体育场馆），后者按 `cc` 分不出类别
2. 方案用到的字段都是字符串，字段名小写，各级瓦片都保留，所以切片不用为分类加字段
3. 字段名没有跨年变化；只有福利机构（2022）、应急避难场所（2022～2024）的早期年份缺字段
4. `type` 的含义因资源而异，学校、医疗的 `type` 有"初级中学/小学"这样的复合值，不能直接当分类
5. 监测图层的 `dlbm` 是变化（或细化）前的地类：16.8% 的学校在"城镇住宅用地"上，不能代表资源自身的类型

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 分类从哪里来 | 前端加载瓦片时统计；脚本探查后人工确认，写成配置 | 探查后确认：瓦片只有视野内的要素，颜色会随视野变化；全省统计一次几百毫秒（ADR 0043）。字段的业务含义也要人判断 |
| 配置放在哪里 | 后端接口下发；前端的 TS 数据；JSON | TS 数据，和 `landuse.ts` 一样：类型检查能发现写错的键，可以写注释。渲染细节归前端，沿用 ADR 0041 的分工；以后要后端下发时，结构不用变 |
| 配置的结构 | 每个资源写一份取值和颜色；字典加规则 | 字典加规则：同一取值在点层和面层同色，改颜色只改一处 |
| 字段跨年变化 | 规则里加按年份的字段；不加 | 不加：实测字段名没有变化。缺字段的年份全部归入"其他"，记进待办，不为这个调整方案（AGENTS.md 迁移规则） |
| 取值数少于字典的资源 | 都列全部字典；只列实际有的 | 只列实际有的：图例不出现没有数据的类别。后来多出的取值归入"其他"，重新探查时能看出来 |
| 颜色 | 从表 A.2 的上级地类继承；配色板 | 配色板：继承时同一资源的类别颜色太接近，分不清。水域沿用已有的蓝色系 |
| 调过统一样式的资源变成分类 | 直接按分类显示；保持统一样式 | 保持：用户调的是它的统一样式，不该因为上线了分类就看不到 |

## 决定

### 1. 字典和规则

- 字典在 `features/resource-map/class-dictionaries.ts`：每项是取值（`value`）、名称（`label`）、颜色（`color`）；地图样式里的颜色是数据，不走 CSS 令牌
- 规则是字段加字典里的若干项，登记在 `style-registry.ts`，按 `code`，新增资源只加一行
- 取值的键仍是取值本身（ADR 0044 第 3 节），名称只用于显示，改名称不影响已保存的符号覆盖
- 去掉"按取值顺序从配色板取色"这种规则（城镇村等用地），颜色写进字典，和原来逐项相同
- 地类的两种规则（按编码、按名称）不动：75 项有和旧项目逐条对照的测试，草地、湿地直接复用

### 2. 分类依据的优先级

1. 有编码表的标准字段：监测类型代码 `cc`（名称 `ccn`）、表 A.2 的 `dlbm`、城镇村属性 `czclx`
2. 取值干净的业务枚举：`type`、`hxlx` 等，按资源判断
3. 都没有就保持统一样式。`cc` 只有一个取值、数据太少的资源属于这一类

### 3. 样式方式（修改 ADR 0044 第 3 节）

- 用户没选过方式时：调过统一样式的资源按统一样式，否则按分类样式
- 用户选了分类样式、又有统一样式的覆盖时，要记下 `mode: 'classified'`，否则下次打开会变成统一样式；存储版本不变，旧数据仍能读取

### 4. 不在前端识别分类

沿用 ADR 0043：图例不统计瓦片，只列字典。探查脚本负责发现字典外的取值。

## 后果

- 好处：新增资源只加一行，统一改色只改字典；地图、图例、符号编辑都从同一份规则推导，不用新界面
- 好处：探查脚本可以重复跑，切片调整或数据更新后用来核对
- 代价：字典要人维护，新的取值在重新探查之前都显示为"其他"
- 代价：以前把 5 个老资源从统一样式切回分类样式、并留着统一样式覆盖的用户，升级后会看到统一样式，要再切一次；这种情况很少，切一次后就记住了
- 待办：缺名称对照的编码、要业务决定字段的资源、切片同事要确认的低级别合并，见 [docs/archive/migration.md](../archive/migration.md)
