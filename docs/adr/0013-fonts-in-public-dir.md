# 0013. 字体文件统一放在 apps/web/public/fonts/

- 状态：已接受
- 日期：2026-09-29
- 取代：ADR 0012 中"两个 TTF 原文件放在 `.gitignore` 中的 `local-assets/fonts/`"这一条，0012 的其余内容不变

## 背景

ADR 0012 落地后，字体分散在两个不入库的目录：

| 目录 | 内容 |
|---|---|
| `local-assets/fonts/` | 普惠体 2.0（35 Thin，已被 3.0 取代）、优设标题黑 TTF（只给生成系统名称轮廓用） |
| `apps/web/public/fonts/` | 普惠体 3.0 的两个 WOFF2（页面加载） |

希望统一整理：普惠体只保留 3.x，字体集中在一个目录。

## 候选方案

1. 全部放进 `apps/web/public/fonts/`：不写代码。代价是 `public/` 下的文件会原样复制进构建产物，优设标题黑的 TTF 也会被部署，可以被公开下载，但页面并不使用它
2. 新建 `apps/web/fonts/`，写一个小 Vite 插件只发布 `.woff2`：TTF 不会被部署，代价是多约 40 行插件代码
3. 按用途分两处，只删除普惠体 2.0：改动最小，但仍然分散

## 决定

选方案 1：

- 删除普惠体 2.0，普惠体只使用 3.x
- 优设标题黑 TTF 移到 `apps/web/public/fonts/`，生成工具从这里读取
- 删除 `local-assets/` 目录及其 `.gitignore` 规则

## 后果

- 好处：所有字体只有一个位置，新 clone 后只需要往这一个目录放文件
- 代价：构建产物 `dist/fonts/` 中包含约 1.4 MB 的优设标题黑 TTF，部署后可以被直接下载；它的授权对这种分发没有明确说明。需要时可在 nginx 中禁止访问 `/fonts/*.ttf`（见 `docs/deployment.md`），页面不受影响
- 以后如果要求产物中不含 TTF，改为方案 2
