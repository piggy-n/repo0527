# 0012. 字体：普惠体 3.0 自托管且不入库，系统名称用 SVG 轮廓

- 状态：已接受（TTF 原文件的存放位置已被 0013 取代）
- 日期：2026-09-29

## 背景

设计规范要求标题用优设标题黑、正文用阿里巴巴普惠体。阶段二检查了字体文件和旧项目：

| | 普惠体 2.0（规范中的文件） | 优设标题黑 |
|---|---|---|
| 文件 | `ALiBaBaPuHuiTi2.0.ttf` 实际是 **35 Thin**（字重值 250），8.4 MB | 常规体，1.4 MB，收录 6763 个汉字 |
| 旧项目 | 文件在 `public/fonts/`，但**代码中没有引用**，正文实际显示为系统字体 | 顶栏和登录页的系统名称，直接加载原始 TTF |

授权方面（据第三方转述的许可协议条款，官方原文以阿里巴巴官网为准）：

- 普惠体：永久免费商用；禁止上传、发布、转载字体文件；禁止修改、转换、拆分；企业需下载字体包自行发布使用
- 优设标题黑：作者声明免费商用；对放进公开仓库、子集化、格式转换没有找到明确说明

仓库在 GitHub 上公开。

## 候选方案

正文字体：

1. 系统字体（微软雅黑等）：零下载，和旧系统实际效果一致
2. 普惠体 3.0：官方提供每个字重的 WOFF2（无需自己转换），常规体约 5.1 MB；按授权不能子集化或切片

标题字体：

1. 生成 SVG 文字轮廓：系统名称是固定文字；不分发字体文件，几 KB
2. 子集化为 WOFF2：几 KB，仍是文字；授权未明确允许修改和转换
3. 原样加载 TTF：1.4 MB，字体文件进入公开仓库

## 决定

正文：

- 使用普惠体 3.0 官方 WOFF2，原样使用，不子集化、不转换
- 只声明 400（55 Regular）和 600（75 SemiBold）；500 按 CSS 字重匹配规则显示为 400，700 显示为 600
- `font-display: swap`，`src` 先写 `local()`
- 字体文件不提交：放在 `.gitignore` 中的 `apps/web/public/fonts/`；缺失时回退到微软雅黑，构建不失败

标题：

- 用优设标题黑把 `VITE_APP_TITLE` 生成 SVG 轮廓，提交生成结果（JSON），不加载标题字体，删除 `--font-family-title` 令牌
- Vite 插件在开发服务器启动（修改 `.env` 后会自动重启）和构建开始时自动重新生成；也可手动运行 `pnpm title:generate`
- 测试检查轮廓文字与 `VITE_APP_TITLE` 一致，CI 中没有字体文件也能发现"改了文字没重新生成"
- 两个 TTF 原文件放在 `.gitignore` 中的 `local-assets/fonts/`

## 实测结果

- 只含常规体文字的页面只请求 Regular，600 的状态为未加载；用 canvas 测量同一段英文，400 与 500 宽度相同、600 与 700 宽度相同，没有发生人工加粗
- `SystemTitle` 在 `font-size: 28px` 下高 28px，颜色随 `color` 变化
- 修改 `.env` 的系统名称约 4 秒后，插件自动重新生成轮廓，页面随之更新；改回后生成结果与最初版本逐字节相同
- 把轮廓换成旧版本时测试失败，并提示运行 `pnpm title:generate`
- 在没有任何字体文件的干净目录中，安装、类型检查、lint、测试、构建全部通过；本机构建时字体被复制到 `dist/fonts/`

## 后果

- 好处：公开仓库中没有任何字体文件；标题只有约 4.7 KB，不需要为标题下载 1.4 MB
- 好处：开发者只改 `font-weight`，浏览器自动选择对应字重
- 代价：每个字重首次访问约 5 MB，之后缓存；字体到达前会有一次从雅黑到普惠体的切换
- 代价：新 clone 的仓库、CI 构建的产物中没有正文字体，部署构建前要手动放入字体文件
- 代价：系统名称之外需要标题字体的文字（例如动态标题）无法用这套方案，届时再评估
- 待确认：两款字体授权的官方原文
