# 0124. 林草湿荒的分类：图例和地图只用资源实际有的类别

- 状态：已接受
- 日期：2026-11-02
- 补充 ADR 0123：地类规则也能只列实际有的类别（ADR 0123 只对按取值配色的规则这样做），新增枚举取值的探查；把森林、荒漠从"等编码表"改为已分类

## 背景

ADR 0123 让草地、湿地分布图斑直接复用地类规则，打开图例看到的是表 A.2 的全部 69 个地类、6 个历史地类和"未匹配的地类"，实际没有这么多类型，用户验收时提出了问题。后端同时给了分类字段（草、湿 `dlbm`，林 `lin_zhong`，荒 `tu_rang_lx`）和林种、土壤类型的代码表。

探查的结果（瓦片和属性抽样，都是字符串，各级瓦片都保留）：

| 资源 | 字段 | 取值 | 说明 |
|---|---|---|---|
| 森林分布图斑 | `lin_zhong` | 18 个 | 都在代码表里；约四分之一是空字符串 |
| 草地分布图斑 | `dlbm` | 54 个 | 其他草地占 75%，其余是长尾；1208 不在表 A.2，名称是历史地类"后备耕地" |
| 湿地分布图斑 | `dlbm` | 32 个 | 内陆滩涂占 63% |
| 荒漠分布图斑 | `tu_rang_lx` | 13 个 | 120、122 不在代码表里 |

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 怎样只列实际类别 | 只在图例组件里过滤；规则里写明，地图和图例都按它；运行时统计瓦片 | 写在规则里（`only`）：只过滤图例时，没列出的地类地图上还是原来的颜色，图例里却找不到，两边不一致。统计瓦片的问题见 ADR 0043 |
| 草、湿用哪种规则 | 换成按取值配色的规则，名称和颜色从地类表取；地类规则加 `only` | 地类规则加 `only`：保留搜索、双列平铺和含义提示，50 多项放在单列里太长；符号覆盖的键和地类图斑一致 |
| 字典放全部代码还是用到的 | 代码表全放；只放探查到的 | 只放探查到的，和 ADR 0123 一致；全表记在 docs/archive/migration.md，发现新取值时加一行 |
| 怎样确认列全了 | 只看抽样；逐个取值 COUNT；排除已知取值再查 | 排除已知取值再查（`--enumerate`）：还有记录就从这一页取新值，直到没有。轮数约等于抽样漏掉的取值数，比逐个 COUNT 省请求，不用深分页，千万行的表也能查 |
| 不在代码表里的 120、122 | 归入"其他"；先显示编码 | 先显示编码，同城镇村属性的 `201A`、`202A`：它们有数据（约 3%），归入"其他"看不出来 |
| 颜色 | 配色板；按大类定色相 | 按大类定色相（林种、土纲）：配色板只有 10 色，林种有 18 个；同一大类颜色相近，能看出归属 |

## 决定

- 地类规则加 `only`（取值的键）：`classItems`、地图的表达式、图例都只用列出的，顺序仍按编码表；没列出的归入"未匹配的地类"，图例上有这一行，所以地图上不会出现图例里找不到的颜色。不写 `only` 时仍是全表，地类图斑不变
- 森林按 `lin_zhong`、荒漠按 `tu_rang_lx`，用按取值配色的规则；草地、湿地按 `dlbm`，用带 `only` 的地类规则。配置都在 `class-dictionaries.ts`
- 探查脚本加 `--enumerate=资源:字段`，确认实际有哪些取值；取值列表来自探查，写进配置前用它核对
- 其他资源暂不调整（用户要求先做完这四类）；已有规则的资源里，地类图斑、地类图斑（城镇村）仍是全表

## 后果

- 好处：图例只列资源有的类别，和地图一致；新取值出现时地图和图例都显示为"未匹配的地类"或"其他"，不会有对不上的颜色
- 代价：新取值在加进配置之前没有自己的颜色，要重新枚举才能发现
- 代价：草地仍有 55 项、湿地 33 项，是数据本身就有这么多地类；要更少只能合并类别，这是业务决定
- 森林的低级别瓦片疑似把要素合并了（docs/archive/migration.md 的待办）：全省视图下颜色可能只代表其中一个要素，放大后才准确
