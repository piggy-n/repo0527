# 0100. 城市国土空间监测基本统计：拥有者分工、轮询与提交跟踪、宽屏收起侧栏

- 状态：已接受
- 日期：2026-10-28

## 背景

旧页面 `views/space-monitoring-statistics/index.vue`（2056 行）加两个组合式函数（轮询 1058 行、总览 213 行）：左栏"统计报表计算"选年度和报表、等级后提交统计任务；右边是查看条件、当前报表进度、全年的总览矩阵和统计表列表。轮询、提交后的跟踪（每个组合一条记录：提交中、等待生成、处理中、完成、失败、超时、"已查到但不能确认是本次的"）、骨架屏延迟、条件切换防抖、标签页隐藏时暂停都写在两个组合式函数里，用递增版本号判断过期。

2026-10-28 只读核对了两个查询接口（[migration.md](../migration.md)"城市国土空间监测基本统计：接口实测"）：两个接口返回同一个结构；只按年份查状态会返回全年 9499 行、约 1 MB，而可选的报表类型和等级随每次查询返回；没有任务时百分比是字符串 `"NaN"`。[page-layout.md](../design/page-layout.md) 留了一项"宽屏时手动把侧栏收成窄条（基本统计页）"。用户当天在 `/dev/monitoring-statistics` 确认了布局和取舍。

## 候选方案

1. **轮询**：照旧用定时器和版本号；用查询库的 `refetchInterval`，按拥有者的判断给出间隔
2. **提交后的跟踪**：照搬旧的状态机和结果签名；保留"等任务出现、截止超时"，去掉签名比较和"不能确认是本次的"
3. **宽屏收起侧栏**：页面自己放按钮和窄条；做成 `MxSplitLayout` 的能力，复用窄屏的窄条
4. **切换年份**：照旧先只按年份查一次拿选项；直接按条件查，条件不在返回的选项里再换

## 决定

1. **三个拥有者，页面组合**（`features/monitoring-statistics`）：
   - `useStatisticsReport`：查看条件、当前报表的状态与轮询、提交后的跟踪、监控列表的状态筛选、初次进入时落到有结果的组合
   - `useStatisticsOverview`：一年的总览矩阵
   - `useStatisticsCalculation`：左栏的年度和勾选、提交前检查、提交

   接口通过 `StatisticsApi` 传入；组件只显示和调用。纯规则（报表配置、状态文字的归类、总览矩阵、请求体、处理到头的判断、条件的换算、跟踪的状态机和提示）是纯函数
2. **轮询用查询库**：状态和总览都在查询缓存里，`refetchInterval` 由拥有者按数据给出：当前报表没处理完、或当前组合还在跟踪时每 5 秒；总览有处理中的组合、或这一年有还在跟踪的组合时每 30 秒。失败时按间隔退避（5、10 秒；30、60 秒），连续 3 次停下等用户重新查询；最近一次失败时即使显示着上一次的结果也提示。标签页隐藏时由查询库停止按间隔查（`refetchIntervalInBackground` 默认关）。跟踪按每次成功的查询推进（结果没变也算），截止时间才能按时检查
3. **提交后的跟踪**：确认后先切到第一项开始跟踪，再发出创建请求（写操作，按会话核对，不随卸载取消）。每个组合一条：提交中 → 已提交等待（新统计 90 秒、重新统计 15 秒）→ 查到在处理 → 查到结果就结束；新统计查到结果就算本次的，重新统计要先见过处理中；等到截止还没有就超时。业务码和 4xx（408 除外）算被拒绝；网络错误、超时、5xx、返回格式不对都不能证明没有创建，按"提交响应未确认"继续跟踪。不迁移结果签名比较和"已查到结果但不能确认是本次的"状态
4. **提交前检查**：逐个组合查一次状态，有表或没处理完就是已有任务；查不到的、正在跟踪的按"未确认"提示可能覆盖或重复。确认框逐条列出（最多 8 条），有处理中的另外提醒，内容用组件渲染、不拼 HTML 字符串
5. **切换年份不再单独查一次**：默认按基本统计省级查，返回的选项里没有当前的报表或等级时换成第一个可选的（刚提交还在跟踪的组合不换）；汇总统计只有省、市级。条件切换不防抖，同一轮里先后改的条件只请求最后一个
6. **宽屏收起侧栏是 `MxSplitLayout` 的能力**：`collapsible` 开启、`collapsed` 加 `onUpdate:collapsed` 受控；宽屏时侧栏最外层的面板在标题栏右边出现收起按钮，收起后侧栏只隐藏、换成窄屏用的那条窄条，点击在原位展开（不用抽屉）；窄屏时照常进抽屉，收起状态不起作用。图标暂用 Element 的 `Fold`、`Expand`
7. **布局**：分栏型，侧栏 320、默认收起（同旧页面），提交后收起；主区上面两列（查看条件和进度、总览），下面的监控表格占满剩下的高度。监控面板的状态筛选在标题下面单独一行，窄时换行；统计表用 `ElTableV2`，放得下时按比例撑满，放不下时列宽固定、横向滚动。主区窄于 760 时排成一列、整体滚动
8. **不迁移**：没挂路由的旧版 `SpaceMonitoringStatisticsPage.vue` 和只被它引用的 6 个组件；`public/images/TongJi` 的标题图标和数量图标（标题统一用 `MxTitle`，数量用 Element 的图标）；条件切换的 250 毫秒防抖。普通用户的"去下载"指向的"数据下载"还没迁移，按钮置灰并说明（同消息弹框）

## 后果

- 旧页面一千多行的定时器、版本号和状态记录变成查询库的间隔加一个纯函数的状态机，测试用假定时器推进
- 去掉了"不能确认是本次的"这一种提示：重新统计时，如果后台很快算完、轮询没看到处理中，等 15 秒后提示"暂未查询到本次提交的统计任务"，用户可以重新查询
- `MxSplitLayout` 多了一种用法，别的分栏页面不开启就不受影响；收起、展开的图标以后换成设计图标时，所有开启的页面一起变
- 开始统计是写操作，没有实测过成功的返回；后端的几个数量对不上（处理中常是 1，但列表里没有在处理的行），按返回的显示，记进 migration.md
