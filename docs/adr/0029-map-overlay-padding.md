# 0029. 定位可视区域：悬浮元素登记、定位时现量现算

- 状态：已接受
- 日期：2026-10-09
- 补充 ADR 0028 的待定事项"被悬浮面板占用的区域怎样进入定位的 padding"

## 背景

画布型页面的地图铺满内容区，面板和工具栏悬浮在地图上（[design/page-layout.md](../design/page-layout.md)）。程序定位（`fitBounds`，以后还有区划定位、坐标定位）要把目标放进没被盖住的区域，规范要求"页面不自己计算"。

- 旧项目各页面自己算：数据查询页的 `getSpatialQueryFitPadding`、指标页的 padding 判断各写一份，注释里还记着"padding 不能超过画布尺寸，否则 fitBounds 会静默不动"
- 5A.2c 实测：画布 420 宽、左右 padding 共 400 时，`fitBounds` 只剩 20px 可用，缩到 z1.33、中心偏到 163.9°
- 5A.3 决定画布型的界面后置到 5D 专门设计（[roadmap.md](../roadmap.md)"阶段五"），这套计算不能依赖任何一种具体布局
- map-core 的 `fitBounds` 不保留 padding，会话相机的中心就是画布的几何中心（ADR 0024）；padding 每次定位时传入

## 候选方案

| | 做法 | 问题 |
|---|---|---|
| A | 布局按自己的尺寸常量算（如左侧面板 16 + 320 + 16） | 换了设计就失效；面板收起、隐藏时要另外处理 |
| B | 每个页面自己算，定位时传入 | 旧项目的做法，各写一份，容易漏 |
| C | 悬浮元素登记自己贴着哪一边，定位时量出实际占用 | — |
| D | 同 C，但用 `ResizeObserver` 持续测量，结果放进响应式状态 | 元素移动而尺寸不变时测不到；没有需要实时显示可视区域的使用方 |

## 决定

采用 C。

### 1. 悬浮元素登记自己贴着的边

```ts
const panel = ref<HTMLElement>();
useMapOverlay(panel, 'left');
```

- 只登记贴边、会挡住定位的元素（侧面板、横向工具栏）；角落里的小控件、弹出层、抽屉不登记
- 边显式写明，不按位置推断：右上角的工具栏推断不出算"上"还是"右"
- 元素引用为空（`v-if` 隐藏）、尺寸为 0（`v-show` 隐藏）、不在文档里、和画布不相交时都不算
- 所在作用域销毁时注销；不在组件 setup 或 `effectScope` 里调用、或者不在 `provideMap` 的组件里面时抛错

### 2. 定位时现量现算

- 在调用的那一刻用 `getBoundingClientRect` 量画布和各个登记的元素，不持续测量。面板展开、收起、改尺寸都不用另外监听，量到的总是当下的状态
- 每一边的占用：贴左边的元素是它的右边缘到画布左边缘的距离，其余三边同理；同一边取最大值，限制在画布尺寸以内
- 每一边的 padding 取 `max(边距, 占用 + 间隔)`：边距让目标不贴画布边，间隔让目标不贴面板；没有占用的边只用边距
- 可视区域的宽、高至少保留画布的 1/3，超出时两侧按比例缩小
- 计算是纯函数，输入是画布和各元素的矩形，单独测试；测量和登记在 map-vue 的上下文里
- 默认值：边距 16、间隔 16、至少保留 1/3，作为 `provideMap` 的选项，页面可以改

### 3. 定位默认避开悬浮元素

- 视图入口（`MapViewport`）的 `fitBounds` 没传 `padding` 时，使用上面算出的 padding；明确传了（包括 `0`）就以传入的为准
- 上下文和页面句柄同时提供 `overlayPadding()`，需要自己组合时使用
- 不要求调用方每次传入：容易漏，漏了目标就会被面板挡住。代价是视图入口的 `fitBounds` 比 `MapView.fitBounds` 多了一层默认行为，写进 map-vue 的文档

### 4. 暂不做的

- `flyTo` 到一个点并放在可视区域中心（区划定位、坐标定位）：要给 `MapView.flyTo` 加 `padding`，适配器里用 MapLibre 不会保留的 `offset` 实现，以免破坏"会话相机的中心就是画布中心"。5B.5 用到时再做
- 响应式的可视区域（在界面上画出来）：没有使用方

## 后果

- 好处：布局怎么改、面板怎么收都不影响定位的计算；页面不再自己算 padding；窄画布上不会出现几乎没有可视区域的情况
- 代价：悬浮组件要记得登记，漏了只是定位时不避开它；视图入口的 `fitBounds` 带了默认行为
- 代价：只能表达矩形的 padding，L 形的占用（例如只占右上角的工具栏）按整条边处理，可视区域会比实际可见的小一些
