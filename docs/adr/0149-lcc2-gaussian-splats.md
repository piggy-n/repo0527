# 0149. LCC2 高斯泼溅：只在 `maplibre` 引擎下用 gaussian-splat-lite 加载，位置按数据集配准

- 状态：已接受（2026-11-09 用户确认）
- 日期：2026-11-09
- 关联：ADR 0147（第 3～6 节，第 8 节"之后"一行）；ADR 0081（模型清单）；ADR 0005（依赖维护）；ADR 0143（catalog）

## 背景

ADR 0147 把 LCC2 列为 `maplibre` 引擎之后的一步，要求另写一份 ADR。用户 2026-11-09 定的顺序：`feat/map-three` 合入 main → `maplibre` 三维先不显示资源图层 → LCC2 → 过 ADR 0147 第 9 节的门槛。

**证据的位置：**

- PoC：分支 `poc/maplibre-three-gpu` 的 `tools/poc/maplibre-three/lcc2/`；报告在 `local/poc/maplibre-three/REPORT.md` 第 9 节。
- 配准偏差的调查：`local/poc/maplibre-three/lcc2/offset-check/`，包括脚本、拟合输出和叠在影像上的截图，不入库。
- 样例是彭城广场（`20260922地下城.lcc2`）：1.66 亿个高斯，9 级 LOD，2.3 GB。它和倾斜摄影 `XZ_GC_3DT` 是同一个地方。
- 之后数据方又给了"楚王山1号"：299 MB，2334 万个高斯，6 级 LOD，EPSG:4548，在徐州。目录层级是以后的约定（见第 3 节），开发主要用它。

**PoC 已经验证的**（软件渲染，性能不算数）：

- 泼溅能和 b3dm、二维图层共用一块画布和一个 Three 场景，遮挡和排序都正确；
- 流式加载到 295 万个高斯，没有报错；
- 库会在渲染回调以外调用 GL。守住每帧的两头以后，GL 错误为 0；这条已写进 ADR 0147 第 5 节；
- `.ply`、`.btree` 能读出来做碰撞，也能直接交给 `buildNavGrid`。

没有解决的是位置。按索引里的 `epsg` 和 `offset` 摆放后，和 XZ 水平差约 85 米，高度差 29.58 米。

**偏差的调查（2026-11-09）：**

- **EPSG:4548 的理解没错。**
  - 中央经线 117°E、`x_0 = 500000`、不带带号，和 XZ 的 `metadata.xml` 一致。
  - `offset` 的水平值就是 XZ 的原点（差 2.5 毫米和 3.8 毫米），说明数据方按 XZ 的原点导出。
  - 如果理解错了，偏差是几百公里，不会只有 85 米。
- **只差一个平移。** PoC 配准得到的旋转是 0.05°，平移后残差 0.12 米，所以坐标轴方向和比例都对。
- **换坐标系的猜测都对不上。** 此处 GCJ-02 的偏移约 (+532, −135) 米；北京 54、西安 80 的方向和大小也都不符。
- **倾斜模型的位置是对的：** XZ 和 ArcGIS 影像只差约 2 米。
- **错在 LCC2 数据内部。**
  - 同一个包里有扫描轨迹 `info/poses.json`。按 `offset` 摆放后，它和影像、XZ 都对得上：和 XZ 差约 0.5 米，在拟合精度以内。
  - 泼溅和碰撞网格相对这条轨迹整体平移了约 (+15.5, −83.0, −24.8) 米，顺序是东、北、上。
  - 轨迹必须走在扫描到的空间里，所以按"轨迹点下方 0.3～2.5 米有地面"拟合。最优平移下 90% 的点满足，不平移时只有 21%。
  - 把 PoC 从 XZ 配出来的修正量反过来套在轨迹上，得分和最优解一样。
  - 叠在影像上看，轨迹沿着广场的步道走；网格的轮廓平移以后，才和树丛、路缘对上。
- **成因没有查到。**
  - 不是"减去场景中心、导出时忘了加回"：轨迹的均值和中心都对不上这个平移量。
  - 白皮书把 `offset`、`shift`、`scale` 标为保留字段，没有定义含义；`gaussian-splat-lite` 也不应用这些字段。
  - 要问数据方。
- **竖直方向还有约 4.8 米说不清。**
  - 轨迹按 `offset` 的 z 摆放时，地面约 28.9 米；XZ 的地面约 33.7 米。
  - 两份数据都没有声明高程基准，XZ 的转换报告写着"未做大地水准面改正"，可能是基准不同。

**不用官方 LCC Web SDK：** 这一点已记在 backlog，用户 2026-11-09 确认。

- SDK 的 AppKey 绑定 `location.hostname`；
- 在线授权要访问 `api-gw.xgrids.com`，内网访问不到；
- 离线授权会过期；
- 它没有 npm 包，碰撞接口只在 Three.js 路径下有，Cesium 路径只有 `raycast`。

| 加载库 | `gaussian-splat-lite`；XGRIDS LCC Web SDK；自己写读取和渲染 | **gaussian-splat-lite。** Apache-2.0，基于 Three.js，支持 LCC2 的流式 LOD，PoC 已验证能放进自写层。SDK 的授权方式在内网用不了（见背景）。自己写要重做排序、LOD 调度和 SOG 解码，工作量远大于接入 |

| 数据放哪、怎么读 | 复制到我们的 `3dt/`；运行时经 nginx 同源转发，读数据方的服务器；页面直接跨域读 | **同源转发**（用户的要求）。一份数据 2.3 GB，不复制。跨域要数据方配 CORS，内网和公网的地址也不同。用户 2026-11-09 定：模型平铺在 `3dt/` 下，沿用现有的 `/3dt/` 转发，不另开前缀、不建子目录 |
| 位置从哪来 | 运行时用 proj4 按 `epsg`、`offset` 换算，清单只存修正量；清单直接存配准后的摆放（原点的经纬高和朝向），由工具离线算好 | **清单存配准后的摆放。** `offset` 不可信，每个数据集本来就要配准一次。这样运行时不需要 proj4 和 EPSG 表（约 126 KB），摆放和清单里其他模型一样是真实坐标。代价是数据方重新导出后要重算，不过偏差变了本来也要重配。用户 2026-11-09 确认 |

| 第一版做到哪 | 只做显示和拾取；连同碰撞、步行、第一人称一起做 | **只做显示和拾取。** 扫描网格很碎，PoC 里一个连通区只有约 168 平方米，寻路前要清理网格或调参数。步行的手感在没有显卡的机器上也判断不了。用户 2026-11-09 确认 |

## 决定

### 1. 范围

- LCC2 只在 `maplibre` 引擎下支持。`cesium` 下按能力声明不支持（ADR 0147 第 3、6 节），三维模型面板不列出这类模型。
- 第一版只做两件事：
  - 在三维地图上显示 LCC2，可以和倾斜摄影、二维图层同时显示；
  - 能拾取，供测量和定位使用。
- 碰撞、步行、第一人称第一版不做，见第 6 节。

### 2. 加载库

- 用 `gaussian-splat-lite`，精确锁版本，只由 `@mx/map-three` 导入（ADR 0147 第 5 节）。
- 单独分块：清单里第一次加载 LCC2 模型时才下载（约 2.1 MB，gzip 后 0.75 MB）。只看瓦片集的页面没有这部分开销。
- 用 WebGL2，和 MapLibre 共用上下文，不用库的 WebGPU。
- **升级：**
  - 每次升级都要重跑 GL 监听，确认渲染回调以外的 GL 调用仍被每帧两头的保护盖住。PoC 的 `gl-watch` 到时候移到 map-three 的测试或开发页。
  - 这个库由一个人维护，2.5 个月发了 49 个版本，所以按仓库"发布满 3 天"的规则升级，不跟最新版。

### 3. 清单和运行时读取

- **清单：** `public/3dt/manifest.json` 加一种模型 `kind: 'splat'`，字段草案：
  - `lcc2`：`.lcc2` 索引的地址，和 `tileset` 一样，写相对清单的路径；
  - `placement`：配准后的摆放 `{ lng, lat, height, heading }`。
    - LCC2 的局部坐标是网格的东、北、上（Z 向上），原点放在 (`lng`, `lat`, `height`)；
    - `height` 的口径和其他模型相同；
    - `heading` 是局部 x 轴从正东逆时针转的角度，包括子午线收敛角；
  - 其余字段（`id`、`name`、`cityCode`、`underground`）和现有模型相同。
- **局部坐标换到地心：** 用一个刚体矩阵，东、北、上的比例按 WGS84 椭球算（ADR 0147 第 5 节）。3 度带内投影的比例误差每 100 米最多约 2.4 厘米（在带边），样例处约 0.3 毫米，所以清单不存比例。
- **目录层级**（用户 2026-11-09 定）：所有模型平铺在 `3dt/` 下，不另建 `lcc` 之类的子目录。LCC2 模型参照"楚王山1号"：
  - 索引是 `3dt/<模型名>/lcc2-sog-result/<模型名>.lcc2`；
  - 同级有 `data/3dgs/*.sog`（泼溅）、`data/mesh/*.ply`、`data/mesh/*.btree`（碰撞）、`info/attrs.json`、`info/poses.json`（扫描轨迹）、`info/media/`；
  - 清单里写相对清单的路径。文件名有中文，清单里的地址按 URL 编码写。
- **数据的位置：** 数据留在数据方的服务器上，不复制。nginx 沿用现有的 `/3dt/` 转发，不另开前缀，页面看到的仍是同源的 `/3dt/...`。转发的要求写进 `docs/deployment.md`：
  - 支持 Range。库读 `.sog` 时先请求 `bytes=0-4095`，再按段读；收到 200 时整个文件下载，能用，但慢，也更占内存；
  - 这些文件不压缩，不加进 `gzip_types`。`Content-Encoding` 不是 identity 时，库不用 Range；
  - 同一个文件的 `ETag` 保持不变，库会比较；
  - 转发上要加缓存时用 `slice`，否则不缓存；
  - 文件名有中文，地址按 URL 编码；
  - 验收：`curl -r 0-4095` 得到 206。
- **开发时：** 数据放在 `local/3dt/` 下，或者用现有的 `YZT_3DT_PROXY` 转发。
- 索引文件开头有 BOM，读索引（例如取碰撞文件名）时要去掉。

### 4. 定位和配准

- 不用 `offset` 摆放（库本来也不应用它），用清单里的 `placement`。
- **配准工具**放在 `apps/yzt/tools/`：
  - 输入：`.lcc2` 索引、`info/poses.json`、碰撞网格，以及人工配准得到的修正量；
  - 输出：`placement` 的四个值，同时打印按 `offset` 原样换算的位置作对照；
  - 核对：把轨迹套上同一个变换，地面一层的轨迹应当在碰撞网格的地面以上 1～1.5 米；
  - 轨迹可信时，用这次的拟合（`offset-check/fit3d.mjs`）直接算出轨迹和网格之间的平移，代替人工的水平配准；
  - 换算要用 EPSG 的投影参数：工具用 proj4，只作为工具的开发依赖，运行时不用。
- **样例的值：**
  - 原点：`offset` 平移 (−15.3, +83.4) 米，约 117.18053379°E、34.26640458°N；
  - 高度：29.87 + 29.58 = 59.45 米，和 XZ 现在显示的高度对齐；
  - `heading`：子午线收敛角，约 −0.10°。
- 竖直方向对齐的是同一处倾斜模型现在的高度；XZ 的高程基准改了，这里跟着改。
- **楚王山1号在 L.1 的临时摆放（未配准）：** 配准工具是 L.2 的事。L.1 先按索引的 `offset` 原样换算，用一次性的脚本（proj4 不进运行时）：
  - 原点约 117.0623886°E、34.2699335°N；高度直接取 `offset` 的 z，59.74 米；`heading` 是子午线收敛角，约 −0.035°；
  - 清单的说明（`docs/config/3dt-manifest.md`，L.1 新建）注明"未配准"，L.2 配准后换成工具算出的值。
- 地下漫游时的抬高只在渲染适配器内部（ADR 0147 第 4 节），拾取等对外的结果仍是真实坐标。导航用的 4×4 矩阵用同一个摆放来算。

### 5. 资源占用

- **默认配置：** `splatBudget` 300 万，`splatBudgetMode: 'limit'`，`maxSh: 0`，并发 2，不加载环境层。按库的文档，这个预算不是内存上限：最粗一级的覆盖、加载中保留的细节，都可能超出它。
- **PoC 的估算**（库自己报的数，软件渲染）：
  - 120 万个高斯：CPU 78～132 MB，GPU 41～69 MB；
  - 300 万个高斯：CPU 437 MB，GPU 226 MB；
  - 官方 SDK 建议 PC 上用 90 万～1000 万。
  - 默认值等显卡机器上按 300 万、600 万、1000 万测过帧时间和显存后再定。
- **和瓦片集的关系：**
  - 两者分开管理：瓦片集用 map-three 里共用的 LRU（`feat/map-three` 上是 1 GB + 1 GB），泼溅由库按个数管。
  - 同时显示 XZ 和 LCC2 时，GPU 最多是瓦片集的 2 GB 加泼溅约 0.23 GB，CPU 另有约 0.45 GB。
  - 诊断读数（`inspect()`）里两者都报。
  - 只有核显或显存小的机器有丢失 WebGL 上下文的风险，同 map-cesium 的预算说明。
- **CPU 内存：** 437 MB 在 8 GB 内存的机器上不算小。要在显卡机器上确认，库上传到 GPU 以后是否还保留 CPU 上的副本。
- **上下文丢失：** GL 上下文的丢失和恢复（ADR 0147 第 2 节）也要覆盖泼溅：恢复后重新上传，契约测试里加上这一项。

### 6. 第一版不做的

- **碰撞（`.ply`、`.btree`）和步行：**
  - 库不读这两种文件。PoC 已写了读取和射线求交（约 200 行），结果能交给 `buildNavGrid`。
  - 扫描网格里有人、桌子、花架，连通区很碎。
  - 79 个节点全部读要 15 秒、423 MB，只能按相机附近按需读取。
  - 等在显卡机器上看过观感、决定要步行时再做，届时按需读取、设上限。
- **第一人称、地下：** 依赖碰撞网格取地板，和上一条一起做，用 ADR 0147 第 4 节的抬高。
- **环境层：** `env.sog` 约 2.7 万个高斯，是几公里大小的天空盒，和底图冲突，不加载。
- **球谐：** `portable` 类型的数据本来就没有。

### 7. 依赖

- **`three`：** 从 0.183.2 升到 0.187 以上，用届时满足"发布满 3 天"的最新补丁；`@types/three` 跟着升。两者都在 catalog 里（ADR 0143）。按 ADR 0005 单独提交，不和 LCC2 的代码混在一起。
- **升级时验证驾驶舱：** `features/city-dashboard/map/` 用 `three` 画江苏地图。要跑类型检查、驾驶舱的测试和冒烟，再人工看一遍入场和发光的边界。同时确认 `3d-tiles-renderer` 的测试在新版本下通过（PoC 里 0.5.4 配 0.187 正常）。
- **`gaussian-splat-lite`：** 精确锁版本。
- **proj4：** 只作为配准工具的开发依赖。

### 8. 授权（待用户和法务确认）

- **`gaussian-splat-lite`：** Apache-2.0。分发构建产物时要带上它的 LICENSE 和 NOTICE。NOTICE 里列了 SparkJS、SuperSplat、ruzstd、flate2（都是 MIT）和 zlib-rs（zlib 许可）。项目现在怎么随产物提供第三方许可，要一起确认。
- **LCC2 格式：** 白皮书 `github.com/xgrids/LCC2Whitepaper` 的 README 里有 License and Restrictions。它不是开源许可证，授权附带条件，摘要如下：
  - 在产品界面或文档里署名 "Data Organization Format originated from XGRIDS"；
  - 给第三方提供白皮书的链接或副本；再分发时说明使用经 XGRIDS 授权、XGRIDS 保留权利；
  - 派生的格式或作品，要以不低于白皮书的开放条件发布。我们的读取和显示算不算"派生作品"，不清楚；
  - 禁止的用途里有"损害 XGRIDS 利益"这类宽泛的条款；违约或起诉 XGRIDS，授权都会自动终止；
  - 适用中国大陆法律，由深圳国际仲裁院仲裁。
- **打算的做法：** 显示 LCC2 模型时，在地图的署名控件里加上这句署名和白皮书的链接，`docs/` 里也写一处。这样够不够、派生作品那一条怎么理解，要法务看。
- **开始时机**（用户 2026-11-09 定）：不等答复，先按本 ADR 实施 L.1。法务的问题（署名、派生作品）和数据方的问题（偏差成因、高程基准、数据权属）记在 `docs/backlog.md`；答复回来以后只改摆放的数值和署名的文字，不改方案。
- **数据的权属：** 样例索引的 `description` 写着 "XGrids all rights reserved"，可能是导出软件的默认文字。数据归谁、能不能在内网和公网发布，要问数据方。

## 后果

- **好处：**
  - 泼溅、倾斜摄影、资源图层画在一块画布里，遮挡正确；
  - 不依赖 XGRIDS 的授权服务，内网能用；
  - 位置写在清单里，数据带的 `offset` 对不对都不影响显示。
- **代价：**
  - 每个 LCC2 数据集都要配准一次，数据方重新导出后要重算；
  - 多一个单人维护、变动快、会在回调外调用 GL 的依赖，每次升级都要重跑 GL 监听；
  - `three` 升级要单独验证驾驶舱；
  - 包体积多约 2.1 MB，只在加载 LCC2 时下载。
- **风险：**
  - 性能和时序都没有在显卡机器上测过，300 万以上的预算也没测；
  - 亮处偏白的原因没有查清，可能来自数据、库或软件渲染；
  - 授权条款可能要求在界面上署名，甚至限制发布方式。
- **用户 2026-11-09 定的：**
  - 地址：模型平铺在 `3dt/` 下，沿用 `/3dt/` 的转发，层级参照楚王山1号（第 3 节）；
  - 清单存配准后的最终摆放，配准工具用 proj4 开发依赖，运行时不换算（第 4 节）；
  - 第一版只做显示和拾取，碰撞、步行、第一人称以后再定（第 6 节）；
  - 不等法务和数据方的答复，先实施 L.1；答复回来只改数值和署名文字。
- **待答复**（记在 `docs/backlog.md`）：
  - 授权：界面署名是否足够，"派生作品"一条怎么理解（法务）；
  - 问数据方：泼溅为什么和自己的轨迹差一个平移，两份数据各用什么高程基准，能否重新导出、让 `offset` 直接可用，数据归谁、能否在内网和公网发布。即使重新导出，配准和轨迹核对仍然保留；
  - 默认预算等显卡机器的实测结果（L.3）。
