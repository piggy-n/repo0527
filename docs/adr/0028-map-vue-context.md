# 0028. map-vue：会话与视图分开的地图上下文

- 状态：已接受
- 日期：2026-10-09

## 背景

ADR 0027 定了 map-vue 的职责：把地图会话和视图接到 Vue 的组件树和响应式系统上。路线图原来的设想是一个 `<MapProvider>` 组件加 `useMap()`。动手前要先面对这些约束：

1. **provide / inject 只往下传**：页面要在 setup 里组装各个拥有者，就得在 setup 里拿到会话；但页面拿不到它的子组件 provide 的值
2. **子组件先挂载**：视图要等 DOM 挂载后才能创建；子组件的 `onMounted` 先于父组件执行，子组件挂载时父组件里的视图一定还不存在
3. **挂载和卸载的顺序**（Vue 3.5.43 的 `componentUpdateFn`、`unmountComponent`，读源码确认）：父组件的 `onBeforeMount` 在渲染子树之前执行，早于子组件的 setup。卸载时父组件先执行 `onBeforeUnmount`，再 `scope.stop()`（`onScopeDispose` 在这里执行、侦听器在这里停止），然后才卸载子组件，最后在子组件的 `onUnmounted` 之后执行自己的 `onUnmounted`
4. **清理回调不能抛错**：`scope.stop()` 依次执行清理回调，没有逐个捕获异常。评审中验证过：父组件作用域的清理回调抛错后，子组件里的视图和父组件的 `onUnmounted` 都没有执行，资源全部泄漏
5. **每次提交都会立即校验**：`StyleModel` 的 `setGroup` 当场校验组合后的样式（ADR 0022），微任务只负责合并通知。资源分组提供数据源、高亮分组引用它时，切换年份要同时改两个分组，分两次 `setGroup` 提交，不管先提交哪个，中间状态都引用了不存在的数据源，提交会抛错。所以 ADR 0022 要求跨分组的修改用一次 `setGroups` 提交；合并通知替代不了原子提交
6. **响应式代理**：会话和视图持有 MapLibre 的内部对象，放进 `ref()`、`reactive()` 或 Pinia 的 state 会被深层代理（map-core.md"用法"）；深层的 `readonly()` 同样是代理，评审中验证过它让内核类的私有字段访问报错。相机拖动时每帧都变，所有组件都跟着更新代价很高
7. **分组的类型**：`MapSession<const G>` 在页面里能检查组名（ADR 0022），但 map-vue 只有一个注入键，不知道各页面的分组
8. **`computed` 抛错之后的行为**（2026-10-09 在 Vue 3.5.43 上验证）：`computed` 的函数抛错时，异常在调度器检查依赖是否变化时就抛出，读取它的一方即使包了 `try/catch` 也接不住，侦听器这一轮不执行；之后依赖没变时再读取，它不再抛错，而是返回上一次成功的旧值。反过来，在 `computed` 自己的函数里用 `try/catch` 调用一个普通函数，失败会作为普通的值缓存起来，直到这个函数用到的依赖变化才重新计算

## 候选方案

会话和视图放在哪里：

| | A. `<MapProvider>` 组件 | B. 页面创建会话，画布组件创建视图 | C. 会话放进 Pinia |
|---|---|---|---|
| 页面怎样组装拥有者 | 拿不到注入，只能把拥有者包成不渲染内容的子组件（`<ResourceLayers group="resources" />`） | setup 里直接组装 | 从 store 取 |
| 组名的类型检查 | 组名是字符串 prop，查不到 | 有 | 有，但 store 不知道页面的分组 |
| 视图与会话的生命周期 | 绑在一起 | 分开：会话随页面，视图随画布组件 | 会话随 store，脱离页面 |
| 以后挂三维视图 | 要改组件 | 再放一个三维画布组件，读同一个会话 | 同 B |
| 响应式 | 要注意不进响应式 | 同左 | store 的 state 深层响应式，要 `markRaw`；同一时间只能有一张地图 |

样式怎样提交：

| | a. 每个拥有者提交自己的分组 | b. 页面声明"一起提交的分组"，分成几个提交单元 | c. 页面把所有推导函数绑定到一个提交器 |
|---|---|---|---|
| 跨分组引用 | 分开提交，中间状态校验失败（背景第 5 条） | 同一单元内原子；跨单元的引用仍会失败 | 同一轮的变化一次提交，原子 |
| 拥有者卸载时 | 要逐组清空，跨组引用时同样失败；清理回调抛错会中断卸载（背景第 4 条） | 按单元清空，单元之间仍要协调 | 拥有者不随组件卸载，"不在了"用推导结果表达 |
| 页面要做的 | 把写入权交给各个拥有者 | 划分单元，要理解引用关系 | 绑定一次 |

## 决定

采用 B 和 c。

### 1. `provideMap()`：页面创建会话

```ts
// 页面 setup
const map = provideMap({ groups: ['basemap', 'boundaries', 'resources', 'highlight', 'measure'], camera: JIANGSU_CAMERA });
const basemap = useBasemap();                      // shared/map：底图状态和推导函数
const resources = useResourceLayers();             // feature：显示状态和推导函数
const highlight = useResourceHighlight(resources); // 高亮引用资源分组的数据源，从资源的状态推导
map.bindStyle({ basemap: basemap.deriveGroup, resources: resources.deriveGroup, highlight: highlight.deriveGroup });
```

- 只能在组件的 setup 里同步调用，否则抛错；同步创建 `MapSession`（构造失败照常抛出，属于编程错误），provide 给子孙组件，并返回给页面自己使用
- 返回的对象（下称"页面句柄"）只交给页面：它能绑定样式，也包含子孙组件通过 `useMap()` 能拿到的全部内容；不直接暴露会话，避免绕过绑定写样式
- 选项里的 `onError` 接收提交失败和视图运行中的错误，默认打印到控制台
- 一个组件作用域一个会话。需要两张地图时，各自在自己的组件里调用 `provideMap()`，子孙组件拿到的是最近的那一个（provide 的就近规则）

### 2. 样式绑定：拥有者给出推导函数，页面统一提交

- **拥有者不提交样式**，只给出推导函数（`() => StyleGroup`）。页面用 `map.bindStyle()` 把推导函数绑定到分组，组名受页面声明的分组约束，写错报类型错误。只接受函数，不接受 `ref` 或 `computed`，原因见下面的"推导的缓存与失败"
- **只能在 `provideMap()` 所在组件的 setup 里绑定**：`provideMap()` 在该组件的 `onBeforeMount` 关闭登记，之后再绑定直接抛错。子孙组件、feature 都没有提交样式的入口
- **一个分组只能绑定一次**：同一次或多次 `bindStyle()` 里重复绑定同一个分组，在绑定时抛错。登记在组件挂载前关闭、随页面结束，不需要解除占用。没有绑定的分组保持为空
- **推导的缓存与失败**：登记时，提交器把每个推导函数包进自己的 `computed`，在里面用 `try/catch` 调用它，结果是"成功的分组"或"失败"两种值之一。于是：
  - 每个绑定只在自己用到的依赖变化时重新推导。测量时鼠标每动一下只重新推导测量分组，资源图层的推导不会跟着执行
  - 失败作为值缓存，直到这个推导函数用到的依赖变化：之后无关的变化不会把失败的分组当成成功，也不会读到旧值（背景第 8 条）
- **拥有者内部的 `computed` 不抛异常**：按背景第 8 条，`computed` 一旦抛错，异常会绕过提交器的 `try/catch`，之后还会返回旧值。可能失败的计算放在推导函数里直接做，或者把失败表示成数据（例如校验结果），不从 `computed` 里抛出。类型检查拦不住这一点，靠约定和代码评审
- **初始提交**：`onBeforeMount` 时把所有绑定的初始值用一次 `setGroups` 提交。这时画布组件还没有创建视图，视图创建时直接加载完整的快照
- **之后的提交**：一个侦听器同时读取所有绑定的结果（默认的 `flush: 'pre'`），同一轮里变化的分组用一次 `setGroups` 提交。校验针对组合后的结果，跨分组的修改是原子的
- **失败时整批跳过**：同一轮里只要有一个推导失败，或者组合后的校验不通过，这一轮整批都不提交，交给 `onError`（同一个失败只报告一次），会话保持上一份完整的快照。推导失败和校验失败的处理相同。提交器记下每个分组上次提交成功的结果，之后的变化会重新求值，连同上次没提交成功的分组一起提交；中间不合法或不完整的组合被跳过，最终收敛到最新的合法组合
- **跨分组引用**：引用方的推导要依赖被引用方的状态（上例中高亮从资源的状态推导），这样两者在同一轮变化、一起提交。如果引用方晚一轮才变，前一轮的提交会因为引用不存在被拒绝并报告，下一轮才收敛，这个报告说明数据流写得不对。引用合法但业务上不配套（例如资源换了年份、高亮还是旧年份的规则）校验发现不了，同样靠"同一轮变化"保证
- **拥有者"不在了"用状态表达**：推导结果返回空分组，不靠组件卸载。为什么不允许局部拥有者：它卸载时要清空自己的分组，涉及跨分组引用时又要和别的分组协调提交，并且清理回调失败会中断卸载（背景第 4 条）。以后确实需要随组件出现和消失的图层时，另写 ADR
- 推导只依赖拥有者自己的状态，不依赖相机：相机每帧都变，依赖它就会每帧重新推导、提交一次
- 来自后端配置的图层，由拥有者在配置变化时先校验，坏配置不进入推导结果（ADR 0026 第 5 条，5C.1 实现）

### 3. 卸载：先停止提交，不逐组清空

- `provideMap()` 所在组件的 `onBeforeUnmount`（早于它自己的 `scope.stop()` 和子组件卸载）把页面句柄标记为关闭：停止侦听，不再提交，也不逐组清空
- 会话在该组件的 `onUnmounted` 释放（晚于子组件的 `onUnmounted`），不用 `onScopeDispose`：后者早于子组件卸载，会话会先于画布里的视图被释放
- 卸载路径上 map-vue 的回调都不抛错：释放出错时交给 `onError`，保证子组件和后续的卸载钩子照常执行

### 4. `<MapCanvas>`：画布组件创建视图

- 渲染两层元素：外层可以加页面的 class；内层交给 MapLibre，只用静态 class（map-core.md"MapLibre 6 的实测行为"）
- `onMounted` 时用当前会话创建 `MapLibreView`；`onUnmounted` 时释放视图。卸载时等待中的 `whenReady()` 以 `AbortError` 结束（ADR 0023）
- props：传给 MapLibre 的选项（如 `minZoom`）、测试时替换地图的工厂。运行中的错误交给 `provideMap()` 的 `onError`
- 视图失败（`failed`）时，画布组件不弹提示；提示由 `shared/map` 的组件读视图状态决定。引擎失败不能恢复（ADR 0026 第 4 条），要重新创建时给画布组件换一个 `key`
- 目前只有二维画布。三维画布将来读同一个会话，上下文里哪个视图是当前显示的，在三维阶段决定

### 5. `useMap()`：子孙组件只读地图状态

返回只读的地图上下文，找不到 `provideMap()` 时抛错：

| 内容 | 类型 | 说明 |
|---|---|---|
| `view` | `Readonly<ShallowRef<MapViewport \| null>>` | 当前显示的视图的受限入口；画布还没挂载、已卸载时为 `null` |
| `viewState` | `Readonly<Ref<ViewState \| 'idle'>>` | 没有视图时是 `idle`（ADR 0022 第 5 条）；变化很少，直接放进 `ref` |
| `whenReady(signal?)` | `Promise<void>` | 等到有视图且这一轮加载完成；视图失败时以原因结束；提供上下文的组件卸载或 `signal` 中止时以 `AbortError` 结束。用于"进入页面后定位"这类操作 |
| `useCamera()` | `Readonly<ShallowRef<CameraState>>` | 在调用方的作用域里订阅相机，作用域销毁时取消。只有用到相机的组件才会每帧更新 |

**受限的视图入口 `MapViewport`**：画布组件为每个视图创建一个冻结的普通对象，只转发使用方需要的方法：`kind`、`flyTo`、`fitBounds`，以后加上查询、拾取、投影。`pause()`、`resume()`、`[Symbol.dispose]()`、`on()` 都不在上面：暂停和恢复由框架切换负责，释放由画布组件负责，状态从 `viewState` 读。这是运行时的限制，不只是类型上的：拿到它的代码在 JS 里也调不到释放。

**只读的引用**：`view`、`viewState`、`useCamera()` 的返回值在内部是可写的 `ref` / `shallowRef`，对外用 `shallowReadonly` 包一层。2026-10-09 在 Vue 3.5.43 上验证：依赖追踪照常；对 `.value` 赋值被忽略，开发环境给出警告；里面的对象不会被代理，私有字段照常访问。不对视图、会话这类引擎对象使用深层的 `readonly()`（背景第 6 条）。

- 不提供写样式和直接写相机的入口：样式只由页面绑定，定位通过 `view.value` 的 `flyTo`、`fitBounds` 发起（ADR 0024：定位由当前显示的视图发起，只在 `ready` 时可用）
- 当前工具、选择状态的读写在 5B.3、5C.6 加入上下文

### 6. 响应式的边界

- 会话、视图都是普通对象：provide 的是普通对象；视图的受限入口放在 `shallowRef` 里，只追踪"换了一个视图"；不放进 `ref()`、`reactive()`、`readonly()`，也不放进 Pinia
- 要显示的值才进响应式：视图状态是 `ref`；相机按需订阅（第 5 条）
- 万不得已要把这类对象放进响应式容器时用 `markRaw`；按上面的写法，目前不需要

### 7. 生命周期与释放顺序

```
页面 setup          provideMap 创建会话 → 组装拥有者 → bindStyle 登记绑定
页面 onBeforeMount  关闭登记 → 一次 setGroups 提交所有初始值 → 开始侦听
子组件 setup        useMap() 拿到上下文（view 还是 null）
MapCanvas 挂载      用完整快照创建视图 → view、viewState 更新
……                  同一轮变化的分组一次提交；任一推导或校验失败时整批跳过并报告，之后的变化时一起重新提交
页面 onBeforeUnmount 停止侦听和提交，不逐组清空
页面 scope.stop     页面里的侦听器、计算属性停止
子组件卸载          MapCanvas 释放视图，等待中的 whenReady 以 AbortError 结束
页面 onUnmounted    释放会话，丢掉待发的通知
```

页面被 `<KeepAlive>` 缓存时不会卸载，会话和视图都保留；是否缓存地图页在 5D 决定。

### 8. 测试

map-vue 的测试在 jsdom 里挂载一个调用 `provideMap()` 和 `<MapCanvas>` 的测试组件，通过画布组件的工厂 prop 注入实现 `MapLike` 的假地图，不用 `vi.mock('maplibre-gl')`。要覆盖：

- 跨分组引用：资源分组换数据源、高亮分组改引用，在同一轮里一次提交成功；高亮晚一轮变化时，第一轮提交被拒绝并交给 `onError`、不抛出，第二轮收敛
- 推导失败：资源换年份、高亮推导失败时整批不提交，会话保持上一份快照，只报告一次；之后无关的变化不会提交资源的新年份配高亮的旧结果；高亮修好后两者一起提交
- 缓存：一个绑定的依赖变化时，其他绑定的推导函数不执行
- 初始值在视图创建之前一次提交
- 登记关闭后绑定、同一个分组重复绑定时抛错
- 页面卸载时不再提交，视图先于会话释放；卸载路径上的错误不中断卸载
- `whenReady` 在卸载时以 `AbortError` 结束；`useCamera` 在作用域销毁后不再更新
- 对 `view`、`viewState`、相机引用赋值不生效；受限入口上没有 `pause`、`resume`、释放方法

## 后果

- 好处：页面在 setup 里就能组装拥有者，组名有类型检查；拥有者只给出推导函数，是普通的组合式函数，不挂地图就能测
- 好处：跨分组的修改是原子的，校验失败不会把地图留在只改了一半的状态，之后的变化会收敛到合法的组合；卸载路径上不再提交样式，也不会因为清理失败而泄漏
- 好处：子孙组件拿到的上下文在类型和运行时上都是只读的，释放、暂停只由 map-vue 自己做；相机只在用到的组件里每帧更新
- 代价：样式只能在页面里绑定，不能有随组件出现和消失的局部拥有者；要用状态表达"不显示"
- 代价：一致优先于及时。只要有一个推导失败，所有分组（包括测量这类高频更新）都停在上一份快照，直到它修好；失败会通过 `onError` 报告
- 代价：拥有者内部的 `computed` 不能抛异常，类型检查拦不住，靠约定和评审
- 代价：页面要写 `provideMap`、`bindStyle` 和 `<MapCanvas>` 三处，比一个 `<MapProvider>` 多几步
- 代价：依赖 Vue 的挂载、卸载顺序（背景第 3 条）。父组件的 `onUnmounted` 晚于子组件是 Vue 文档描述的行为；`onBeforeMount` 早于子组件 setup、`onScopeDispose` 早于子组件卸载来自源码，由测试覆盖，Vue 升级时由测试发现变化
- 待定：被悬浮面板占用的区域怎样进入定位的 padding（5A.3）；地图运行时的注入方式（5D）；三维画布与"当前显示的视图"（三维阶段）
