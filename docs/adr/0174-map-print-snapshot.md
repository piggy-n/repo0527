## 背景

- 用户要在现状底图右侧工具栏加"地图打印"：把当前视角导出成图片，保留范围、级别和图层的显示效果；图片只有地图和图例，不要页面上的面板、工具栏和控件；图例和地图上显示的图层一致。
- 只有 MapLibre 适配器能碰原生地图（ADR 0024、0047），页面拿不到画布。二维和三维（Three.js 画在 MapLibre 的 custom layer 里，ADR 0147）是同一块 WebGL 画布，盖在上面的面板、测量的读数、位置点是页面元素，不在画布里。
- WebGL 默认不保留绘图缓冲：一帧交给合成器以后再读画布是空的。
- 图例现在从样式登记表推导，列资源实际有的全部取值，不统计画面里出现的（ADR 0043 第 3 节，留了"按需统计"的口子）。

## 候选方案

做法（原型里三种都能操作）：

| 做法 | 内容 | 结论 |
|---|---|---|
| 一 一键导出 | 点了就等加载完、下载，图例固定在右侧，清晰度同屏幕 | 没有任何选项 |
| 二 导出浮层 | 底图同款的浮层：预览、图例位置、清晰度、导出 | 采用 |
| 三 打印版式 | 选纸张、方向、精度，加标题、比例尺、指北针 | 要在后台另建一张地图按纸张尺寸重新加载，只能二维，范围和当前视角不同，导 PDF 要新依赖 |

截图的技术（一次性的 Vitest 浏览器测试，真实 MapLibre 6.12 + Three，软件 WebGL）：

| 问题 | 候选 | 实测与选择 |
|---|---|---|
| 读画布 | 创建地图时 `preserveDrawingBuffer: true`；`redraw()` 同步画一帧后立刻拷贝 | 两者逐像素相同（三种视野都差 0 个像素），拷贝 2～23 毫秒；保留缓冲要在创建时定、每帧都有代价，选后者。空闲以后再读是空的（0 个不透明像素） |
| 等加载完 | MapLibre 的 `idle`；再加三维模型这一轮的统计 | 泼溅还在加载时 MapLibre 照样发 `idle`；泼溅这一轮刚结束就截，泼溅还没画出（绿色像素 0），再等一次 `idle` 才完整。两者都要 |
| 这一帧不画某些分组 | 改 `visibility`；改不透明度 | 改 `visibility` 会让数据源重新解析瓦片：选中高亮画在资源的瓦片上，还原以后要等解析完才画出来（实测下一帧还是空的）。改不透明度只重新求值，过渡临时设成 0，选后者 |
| 跨域污染 | — | 不会：MapLibre 跨域的图片设 `crossOrigin="anonymous"`、瓦片多用 fetch，没有 CORS 的直接加载失败；WebGL 的 `texImage2D` 也拒收被污染的图片。后端带 token 的瓦片、天地图、服务器底图的自定义协议、静态底图都一样 |

## 决定

### 1. 视图的截图能力（map-core）

- `MapView` 多两项可选的能力，只有 MapLibre 适配器实现：
  - `whenComplete(signal)`：等到画面完整。三维先等会话里的模型都有了状态（刚交给会话时视图还没登记）、读完索引、这一轮加载完（`sceneStatus`、`sceneActivity`），再请求重画一帧、等 MapLibre 的 `idle`，三维再确认一帧（读完索引以后下一帧选瓦片时才开始这一轮）；其间模型又开始了新的一轮就再来一遍。已经稳定时也重画一帧确认；不在 `ready`、等待中离开 `ready`、释放时以 `AbortError` 结束。一直有东西在加载时一直等，由调用方决定不等。
  - `snapshot({ omitGroups, pixelRatio })`：同步画一帧、立刻拷进新的二维画布，返回 `MapSnapshot`（图片和地图的 CSS 尺寸，两者相除是这一帧实际的像素比）。截的是整块画布。
- `omitGroups` 的图层这一帧不透明度为 0（各种图层的不透明度属性，过渡临时设成 0），截完还原、再同步画一帧（屏幕上不淡入），最后还原过渡；本来隐藏的图层、漫游抬高期间隐藏的二维图层不动。不认识的分组抛错（样式模型的 `layerIdsOf`）。
- `pixelRatio` 只在二维生效：临时 `setPixelRatio`，截完还原成页面指定的值（没指定时跟随设备）、再同步画一帧（调整画布会清空它）。三维照屏幕：模型按屏幕误差选精度，像素翻倍会去加载更细的一级。实际的像素比还受 MapLibre 的画布上限约束。
- 改了什么就在还原后同步再画一帧，下一次合成之前地图已经按原样画好，用户看不到截图的那一帧：导出时截图常在 MapLibre 的 requestAnimationFrame 回调之后的微任务里执行，这时请求重画赶不上这一次合成。`MapLike` 多了 `redraw`、`getPixelRatio`、`setPixelRatio`。

### 2. 上下文（map-vue）

- 就绪的 `view` 多了 `snapshot`（视图没有这项能力时抛错）；上下文多了 `whenComplete(signal)`：先等当前视图就绪，再等它的画面完整，等待绑定这一个视图，卸下、替换、切换二三维、上下文释放时以 `AbortError` 结束，并结束视图自己的等待。

### 3. 图例

- 从上到下是三个来源，页面拼起来：资源（`features/resource-map/print-legend.ts`）、三维里显示着的模型（`features/scene-models/print-legend.ts`，加入了、没隐藏、没加载失败的，名称后面写种类）、打开着的行政区边界（`shared/map/boundary/boundary-print.ts`）。底图、区划不进图例。
- 资源只列画面里画出来的：画在地图上、当前级别显示、没被校验拦下、透明度大于 0 的资源，整屏查一次渲染要素（有区划范围时带几何、只算范围里的，同点选、框选），没画出要素的不列；按属性配色的只列出现的取值，取值用和图层同一个 `match` 表达式求（`classKeyOf`），次序同右侧图例；统一样式的是一行。名称后面带年份，符号按图层的透明度变淡。要素过滤着的资源（ADR 0173）类别只有勾着的（画出来的要素已经按条件过滤），名称下面写出全部条件"只显示 地类：水田、水浇地"，浅蓝底加漏斗，按列宽换行、跨列时不重复（用户 2026-11-24 选了示意 `local/design/map-print/filter-note.html` 的写法 A）；分类字段的条件也写，和右侧图例不同：打印的类别只列画面里出现的，看不出勾了哪些（用户 2026-11-24）。查询在截图之后同步做，和截下的画面是同一个状态。
- 符号在 canvas 上画，画法和页面上的 `LegendSwatchIcon` 同一套几何（`legend-swatch-geometry.ts`），花纹用同一份图块（`patternPreviewTile`）。
- 排版是纯函数（`shared/map/print/print-legend.ts`）：一列宽 232，按最高的高度分列，组的标题不和第一行分开，一组跨列时新的一列开头写"（续）"，文字按字形宽度分行。

### 4. 合成和导出

- `composePrintImage`：地图原样放在左上角，像素比同截图。图例放在右侧一栏（和地图一样高、按高度分列，中间一条分隔线），或者叠在右下角（半透明白底和边框，最高占地图的 60%、最宽 45%，放不下时改放右侧并在提示里说明），或者不带。排法是纯函数 `arrangePrint`。图片里的颜色和字体是固定的数据（普惠体，取值同设计令牌），缺字体时用后备字体。
- 编码成 PNG（`shared/file-transfer` 的 `canvasBlob`，驾驶舱共用），文件名"现状底图-年月日-时分秒.png"，交给浏览器保存，成功时提示文件名。
- 组合式函数 `useMapPrint`（`shared/map/print`）：等画面完整（可以"不等了"）、截图、推导图例、合成、编码；同一时间只有一次，作用域销毁、取消时作废，晚到的结果不交出；失败时记下原因，等待时地图变了提示重新导出。保存和提示由浮层组件做。

### 5. 交互

- 业务组在"图例"后面单独一组"地图打印"，在"清除"前面；图标是 Tabler 的 `printer`（`map-print`）。业务组多一个按钮，分两列的高度阈值从 692 改成 733：阈值改成按页面业务组的按钮和分组数算（`mapPageLayout` 的第三个参数），没有打印的三维原型仍是 692。
- 入口上挂底图同款的浮层（`MapOptionsPopover` 经工具栏的插槽），算作右边打开着的，入口显示为按下。内容 `MapPrintPanel`：预览（打开时、相机变了以后等画面完整截一次，带图例时紧接着推导图例；只改图例的位置时按上一次截下的重新合成，只改清晰度时不变，从"不带"换成带图例时重新截；截图会请求重画但不改相机，不循环）、导出的像素（选了 2 倍时是按 2 倍像素比算的尺寸，地图受 MapLibre 的画布上限 4096 约束）、图例（右侧一栏、右下角、不带）、清晰度（同屏幕、2 倍；三维、屏幕已经是 2 倍时只有同屏幕）、导出。等待时显示"等待地图加载完成"和"不等了"。导出完关掉浮层；浮层关掉时放弃没完成的导出。
- 截图时不画测量和选中高亮（`measure`、`selection`）；测量的读数、位置点本来就是页面元素。选中要素的加强标注在打印浮层开着时就撤掉（`selection-labels` 推导成空分组，`resource-labels` 不再滤掉这个要素），导出的图里它是普通标注，同没有选中时的地图：换回普通标注要重新排版，不能只在截图的这一帧处理，等画面完整时一起等到。
- 设置只在这次打开页面期间记住，不进偏好。漫游时工具栏隐藏，不提供打印，开着的浮层关掉。

## 后果

- 截图不改 WebGL 的创建参数，平时没有代价；省略分组或 2 倍时多画一帧，2 倍时画布临时变大（1920×1080 的地图编码约 0.9 秒、1 MB，影像底图更大）。
- 带图例时整屏查一次渲染要素：浮层开着时打开和每次相机停下各一次（预览），导出时再一次；不带图例时不查。只查画着的资源，13 级左右几毫秒；地类图斑默认勾选、不限最小显示级别（ADR 0132），全省视图一次 0.3～0.6 秒、南京 10 级 0.2～0.3 秒（ADR 0043 的实测），这时打开浮层、导出会卡一下。有区划范围时先把区划裁到画面里，区划整个在画面里时不裁，要素求交前再把区划裁到要素附近（南京市界约 1 万个坐标，范围外的要素每个从 5～8 毫秒降到约 0.1 毫秒，`region-scope` 的测试保证结果和直接求交相同）。
- 测试：适配器的单元测试（调用的先后、还原、等待）和真实 MapLibre 的浏览器测试（不保留缓冲也截得到、省略的分组只在这一帧不画、2 倍的尺寸）；三维契约测试里截下的图有瓦片集和高斯泼溅；应用里的真实 MapLibre 测试（图例只有画面里的取值、颜色在图里）。
- 已知的缺口：高斯泼溅的加载统计在库第一次选细节之前就报完成（ADR 0162 的 `detailLoad` 分不开"还没选"和"视野里没有"），刚加上泼溅就导出时"等画面完整"可能早于它画出来（三维契约测试里实测，记在 `docs/backlog.md`）；预览按同样的等待截图，用户在预览里看得到。瓦片集、二维瓦片没有这个问题。
- 没验证：本机没有 GPU，以上都是软件渲染；真实显卡上的耗时、泼溅排序的时机没测。
- 没做的：标题、比例尺、指北针、导出时间（用户 2026-11-24 先不要）；打印版式、PDF。
