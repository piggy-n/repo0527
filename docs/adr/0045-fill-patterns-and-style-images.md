# 0045. 面的描边与纹理：按需拆层、SDF 纹理与样式图片

- 状态：已接受
- 日期：2026-10-12
- 补充 ADR 0044（第 1 节面的字段、第 7 节 5C.5c）、ADR 0022（分组加上样式图片）、ADR 0041 第 4 节（一个面资源可以有多个图层）

## 背景

ADR 0044 把面的描边宽度、描边线型和纹理留到 5C.5c：它们在一个 fill 图层里做不到，要拆成多个图层并注册纹理图片。

旧项目（yzt `master-demo` 836f03b）的做法：

- 面的字段：填充色、填充方式（无填充、均匀填充、8 种花纹：水平、垂直、十字、斜线、反斜线、X 斜线、紧凑、点阵）、纹理颜色、描边色、描边线型、描边宽度（S、M、L、XL 四档或自定义，0～8 像素，步长 0.1，0 表示无描边，固定屏幕像素、不随缩放）
- 每个面资源固定三个图层：底色的 fill、纹理的 fill（`fill-pattern`）、描边的 line；描边内收半个线宽（`line-offset`，MVT 外环顺时针，正偏移朝内），不压到相邻图斑上；描边和填充的颜色不同时，描边颜色随缩放从填充色（10 级）过渡到描边色（14 级），概览时小图斑看到的是主色
- 纹理用 canvas 按（花纹、颜色、疏密档）现画位图，`addImage` 注册；疏密分三档（8、16、32 像素，按缩放 10、14 级切换）；每改一次颜色就多一套位图，最多留 64 张，超出后回收没被图层引用的

MapLibre 6.12 支持 SDF 纹理（2026-10-12 读源码）：图片注册时带 `sdf: true`，着色器只用图片的透明度通道作距离场（边缘在 0.75），颜色取图层的 `fill-color`；按要素变化的 `fill-pattern` 也能识别 SDF；同一个图层里不能混用 SDF 和普通图片。所以纹理图片只描述形状，和颜色无关。

地图内核的分组（ADR 0022）只有数据源和图层，样式模型用 style-spec 的 `diff` 对比快照，没有图片的命令；MapLibre 的图片也不在样式规范里（只有 `sprite` 地址）。

### 实测（2026-10-12，Vitest 浏览器模式，真实 MapLibre，只用内联数据）

自己按距离场生成 8 种花纹 × 3 档疏密和一张透明占位图（设备像素比 2），一个 GeoJSON 数据源上叠主图层、纹理图层、描边图层：

- 8 种花纹都画得出来，线条清晰；纹理颜色按取值 `match` 生效（同一图层里一块黑、其他红）
- `fill-pattern` 外层按缩放 `step`、里面按取值 `match` 生效，没有报错；没有花纹的取值用透明占位图，只露出底色
- 描边图层按取值的线宽、内收（`line-offset` 为线宽一半）、线型（`literal` 数组，实线 `[1, 0]`）都生效
- 紧凑网格在 8 像素档糊成实心，疏档要换参数；第一次加载时有一次没画出水平线，之后在 9、9.5、10.6 级都复现不出（实验里图片是在样式加载完成前加的）；斜线上隐约有规则的浅色小点，实现时在浏览器测试里再看

审阅时补充的实测（2026-10-12，Edge 无头模式，项目安装的 MapLibre 6.12）：

- 纹理图层默认也画抗锯齿的边线，会盖住下面主图层的 1 像素描边：白色填充、黑色描边上叠红色 SDF 条纹，黑色边线出现红色的间断；纹理图层设 `fill-antialias: false` 后描边恢复
- `updateImage` 只能换像素：宽高和原图不同时报错（源码 `Map.updateImage`："The width and height of the updated image must be that same as the previous version of the image"），也没有修改像素比、SDF 标记的参数

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 图层 | 每个面资源固定三层（同旧项目）；按需拆层 | 按需：默认样式仍是一个图层（ADR 0041 的实测都基于一个资源一个图层）；描边图层要给每个面多建一份线几何，地类图斑全省 18.9 万个要素，只在用到时才加 |
| 简单描边 | 总用描边图层；0 像素、1 像素实线时用 fill 图层的 `fill-outline-color` | 后者：和现在一样，不多一个图层；1 像素居中和内收看不出差别；关掉描边（0 像素）不应反而多建一整层线几何 |
| 纹理图层的边线 | 默认（抗锯齿边线）；`fill-antialias: false` | 关掉：默认的边线会盖住主图层的描边，边界交给主图层或描边图层 |
| 描边颜色随缩放 | 迁移；固定描边色 | 迁移：描边颜色和填充不同时，概览下细小图斑会被描边色盖住，主色看不出来 |
| 纹理图片 | 按颜色用 canvas 现画（同旧项目）；SDF，颜色由样式给出 | SDF：只要固定的 8 种花纹 × 3 档加一张占位图，改颜色不生成新图片，不用回收；用纯函数按距离场生成，不依赖 canvas，测试里和 Worker 里都能用 |
| 疏密 | 一档；三档按缩放切换（同旧项目） | 三档：概览时图斑很小，间距大了看不出花纹；图片固定，多两档只是多两倍张数 |
| 图片的替换 | 一律 `updateImage`；按变化的属性区分 | 区分：宽高、像素比、SDF 标记都不变时换像素，有变化时删除后重新添加；`updateImage` 做不到后者 |
| 图片怎样交给地图 | 分组带上样式图片，进入会话；样式根属性 `sprite` 指向构建时生成的雪碧图；适配器提供注册图片的方法 | 分组带图片：会话是唯一真相源（ADR 0020），三维以后从同一份数据栅格化；不需要构建工具和二进制文件，内网也能用。雪碧图要生成并托管图片、三维另外解析；注册方法绕过会话，也违反 ADR 0024 不提供原生出口的约定 |
| 无填充 | 填充色的透明度调到 0；填充方式里的一项（同旧项目） | 填充方式里的一项：填充色保留，换回来时还是原来的颜色 |
| 图例的预览 | 只反映颜色；画出纹理 | 画出纹理：编辑器里选了花纹，图例上要看得出来；描边的宽度、线型和线、点的大小一起在 5D 画 |

## 决定

### 1. 面的字段

在 ADR 0044 第 1 节的填充色、描边色之外加上：

| 字段 | 取值 | 默认 |
|---|---|---|
| 填充方式 `fillStyle` | 无填充 `none`、均匀填充 `solid`、8 种花纹 | 均匀填充 |
| 纹理颜色 `patternColor` | 颜色，可以带透明度 | 主色（统一样式是配色板颜色，分类样式是取值的颜色） |
| 描边宽度 `outlineWidth` | 四档或自定义像素：M 档 1 像素，倍率同 ADR 0044（0.6、1、1.6、2.4）；自定义 0～8，步长 0.1；0 表示无描边；固定屏幕像素，不随缩放 | M |
| 描边线型 `outlineDash` | 同线的线型 | 实线 |

- 无填充：不画填充色和花纹，只有描边；花纹：填充色打底，花纹叠在上面
- 规范化、只记差异、保存的规则同 ADR 0044；新字段在存储格式里是可选的，`resource-symbols` 版本不变

### 2. 图层按需拆分

一个面资源最多三个图层，都用这个资源的数据源和面的几何过滤，从下到上：

| 图层 | ID | 什么时候有 | 内容 |
|---|---|---|---|
| 主图层（fill） | `resources-<code>` | 总有 | 填充色，无填充时透明；`fill-outline-color` 见下 |
| 纹理图层（fill） | `resources-<code>-pattern` | 有符号用了花纹 | `fill-pattern` 是 SDF 图片，`fill-color` 是纹理颜色，`fill-antialias: false`（不画边线）；没有花纹的取值用透明占位图 |
| 描边图层（line） | `resources-<code>-outline` | 有符号的描边是复杂描边 | 线宽、线型按符号，`line-offset` 为线宽的一半（内收） |

- 描边分两种：简单描边是 0 像素，或 1 像素实线；复杂描边是宽度不为 0、且不是 1 像素实线（宽度不是 1，或线型不是实线）
- 所有符号都是简单描边时没有描边图层，主图层的 `fill-outline-color` 表达描边：1 像素实线是描边色，0 像素是透明
- 有符号是复杂描边时建描边图层，主图层的 `fill-outline-color` 透明，边界都由描边图层画：1 像素实线照常画，0 像素的取值线宽为 0
- "所有符号"在统一样式是那一个符号，在分类样式是全部取值；有一个取值需要，这一层就为整个资源建
- 描边颜色和填充颜色的 RGB 不同时，颜色随缩放插值：10 级用填充色的 RGB 配描边的透明度，14 级用描边色（同旧项目）；`fill-outline-color` 和描边图层都这样
- 透明度（显示状态）乘在三个图层上；数据源只有一个，点选（5C.6）按数据源判断资源

### 3. 纹理：SDF 图片

- 8 种花纹的形状（方向、间距、线宽、点的半径）是一份数据，由纯函数按距离场生成图片（透明度通道，边缘 0.75），设备像素比 2；疏密三档 8、16、32 像素，按缩放 10、14 级切换（`step`）；紧凑网格的疏档参数在实现时调到不糊成实心
- 透明占位图一张，给没有花纹的取值
- 图片由 feature 生成，常量，不随颜色变化；颜色由图层的 `fill-color` 给出
- 图例的预览用 SVG 按同一份形状数据画花纹，和地图上的花纹同源

### 4. 样式图片进入地图会话

- 分组（`StyleGroup`）加上可选的 `images`：按 ID 的图片（宽、高、RGBA 数据、像素比、是否 SDF）；ID 以分组名为前缀，跨分组不能重复（同数据源和图层）；数据不可变，变化时换新对象，按引用比较（同 GeoJSON 数据）
- 图片是样式快照的一部分：样式模型的快照、变化通知、适配器记录的"地图上的样式"都带图片；只有图片变化也是一次提交（修订号加 1）。暂停后恢复、重建期间再次提交时，适配器按记录的快照和当前快照对比追上，图片和数据源、图层一样处理
- 样式模型对比出图片的命令，和数据源、图层的命令一起提交：新出现的添加，没有了的删除；同一 ID 的图片换了对象时，宽高、像素比、SDF 标记都不变就更新像素（`updateImage`），有变化就先删除再添加
- 适配器先加图片，再加引用它的图层；删除时先删掉或改掉引用它的图层，再删图片；整体重建时按当前快照重新加上全部图片，加的时机按 MapLibre 的加载时序核对，由浏览器测试覆盖
- 推导只放当前图层用到的图片（用到的花纹的三档和占位图）
- 三维接入时从同一份图片数据栅格化，支持范围按 ADR 0024 的清单降级

### 5. 分类样式

- 纹理按取值 `match`，外层按缩放 `step`；纹理颜色、描边的宽度、内收、线型、颜色同样按取值；所有取值相同的属性不生成 `match`（沿用 5C.5b 的组合规则）
- 需要哪个图层看全部取值；某个取值不需要时，在这一层里用透明占位图表达没有花纹，描边图层里照常画它的简单描边（0 像素线宽为 0）

### 6. 界面

- 面的编辑器加上填充方式（选项带花纹的预览）、纹理颜色（选了花纹时才显示）、描边宽度（四档、自定义）、描边线型；取色器的预览、确认规则同 ADR 0044 第 6 节
- 图例中面的预览画出纹理；描边宽度、线型的预览和线、点的大小一起在 5D 再做

### 7. 验收要点

- 默认样式（一个图层）和三层样式之间来回切换：拆层、合层后图层顺序、透明度、点选的数据源都对
- 分类样式里只有部分取值有纹理、有复杂描边
- 图片第一次加载、整体重建后恢复、暂停后恢复；只改图片的提交也能追上
- 真实 MVT 上的孔洞（内环的描边也内收）和瓦片边界（纹理、描边在边界处不断开、不出现接缝），以及实测中斜线上的浅色小点

### 8. 分步

- 5C.5c-1：地图内核的样式图片（分组、快照、样式模型的命令、适配器的追赶与重建、浏览器测试）
- 5C.5c-2：面的新字段、SDF 图片、按需拆层的推导（统一样式和分类样式）
- 5C.5c-3：编辑器、图例的纹理预览、浏览器里用真实数据验证

## 后果

- 好处：默认样式不变，只有用到描边或纹理的资源才多图层；改纹理颜色不生成新图片
- 好处：图片是会话状态，整体重建、三维镜像都从同一份数据来
- 代价：地图内核的样式模型和适配器要支持图片；一个资源可能有三个图层，图层 ID 不再一一对应资源（数据源仍然一一对应）
- 代价：用了复杂描边的面资源，每个面要多建一份线几何；关掉描边（0 像素）不增加图层
