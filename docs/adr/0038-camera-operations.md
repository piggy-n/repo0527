# 0038. 相机操作：用操作的信号判断等待中的定位是否作废

- 状态：已接受
- 日期：2026-10-10
- 补充 ADR 0024（相机变化的原因）、ADR 0033（默认视角）、ADR 0036（区划定位）、ADR 0037（坐标定位）；取代 5B 之后加入的 map-vue `cameraIntent`

## 背景

区划定位要先加载边界才能定位，等待期间用户可能做了别的相机操作。`stage-5b` 之后的修复（`6f101f2`）用 map-vue 的 `cameraIntent` 判断：它是会话相机的 `intentRevision`，即用户操作和程序定位造成的相机变化次数；区划定位开始时记下它，边界到位时变了就只高亮、不定位。

复测发现它表示的是"相机的数值变了几次"，不是"之后有没有开始新的操作"，三种情况判断错：

1. 加载期间点"默认视角"，相机本来就在默认视角：数值没变，计数不变，旧的区划定位仍然覆盖它
2. 上一次定位的动画还在进行时选中新的区县：动画的每一帧都让计数加 1，新的选择被当成过期，只高亮、不定位
3. 地图加载期间选中区划：就绪时页面的初始适配也是一次程序移动，区划被当成过期，最后停在全省

相机变化是操作的结果：一次操作会变化很多次（动画、拖动的每一帧），也可能一次都不变（目标就是当前视角）。要判断的是"之后有没有开始新的操作"。

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 怎样表示一次操作 | 版本号（开始时记下，到时比较）；`AbortSignal`（开始新的操作时中止上一次的） | `AbortSignal`：和项目里其他的取消一样（ADR 0023、0025），能直接交给 `whenReady(signal)`，等待中的定位在新的操作开始时立即结束，调用方也不会忘了比较 |
| 放在哪里 | map-vue 上下文；map-core 的相机模型 | 相机模型：二三维共用，用户的手势由各视图的适配器报告，和 Vue 无关 |
| 用户拖动、缩放怎样算 | 每一次原因为 `user` 的相机变化都中止当前的操作；手势开始时开始一次新的操作 | 手势开始时：拖动的每一帧、松手后的惯性不会作废用户随后发起的定位 |
| 程序定位是否自动算操作 | 视口的 `flyTo` / `fitBounds` 自动开始；发起定位的拥有者显式开始 | 显式：只有拥有者知道这是不是用户发起的操作，页面的初始适配就不是 |
| 页面的初始适配 | 也开始一次操作；不开始，只在就绪之前没有操作时执行 | 不开始：它不能作废用户已经开始的操作 |
| 就绪之前发起的定位 | 什么也不做（原来的默认视角、坐标定位）；等到就绪再执行 | 等到就绪：初始适配已经让给它，什么也不做会停在会话的初始相机上 |

## 决定

1. 相机模型（map-core）持有当前这次相机操作的 `AbortController`：`beginOperation()` 中止上一次的信号，返回这一次的；`operation` 读当前的信号；释放时中止。相机的变化（`set`）不开始、也不中止操作。`intentRevision` 保持原样，只用于三维还原视角
2. 用户的手势开始时，适配器开始一次操作：MapLibre 适配器在就绪状态下收到带原始事件的 `movestart` 时调用 `beginOperation()`；程序定位的开始（带 `cause`）和动画的每一帧（只有 `move`）都不算。MapLibre 的惯性在松手时发一次 `movestart`，之后只有 `move`。三维视图接入时按同样的规则报告
3. map-vue 上下文提供三个入口：
   - `runCameraOperation(action)`：开始一次操作并执行；视图就绪时立即执行，还没就绪时等到就绪，期间有新的操作、视图失败或被替换时放弃；执行时抛出的错误交给 `onError`
   - `beginCameraOperation()`：要先异步准备数据的定位在开始时调用，准备好后用 `whenReady(信号)` 等视图
   - `currentCameraOperation()`：读当前的信号，不开始新的操作
4. 用户发起的定位都是一次操作：区划定位在选择（和重试）时开始，和自己选择的信号合并（`AbortSignal.any`），边界到位后照常高亮，信号没中止才定位；"默认视角"和坐标定位用 `runCameraOperation`
5. 页面的初始适配（ADR 0033）在 setup 时读当前的信号；第一次就绪时它已经中止（用户已经开始了操作），就不再适配，之后也不补做

## 后果

- 好处：三种情况都按用户最后一次操作的意图结束。默认视角作废之前的区划定位，即使相机没变；动画不作废新的选择；初始适配让给加载期间的选择
- 好处：以后的定位（5C 的搜索结果、查询结果）用 `runCameraOperation`，异步的用 `beginCameraOperation` 加 `whenReady`，就和已有的定位互相作废
- 代价：拥有者要记得通过上下文发起用户的定位，直接调用视口的 `flyTo` / `fitBounds` 不会作废等待中的定位；写进 AGENTS.md 的地图规则
- 代价：用户的手势要由适配器报告，三维视图接入时要补上同样的报告和测试
- 页面测试为三种情况各写了一个完整的组合场景；区划边界的加载器是整个应用共用的，这几个用例每次重新导入页面，从没有缓存的状态开始
