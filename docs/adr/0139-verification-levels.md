# 0139. 迭代期的验证分级与协作方式

- 状态：已接受（`test:changed` 的范围由 0143 修改）
- 日期：2026-11-04
- 修改：`AGENTS.md` 里"每一步先说明再动手""测试写完都要改坏验证"的做法；CI 的内容（ADR 0005、0040、0065）不变

## 背景

迁移基本完成，后面以迭代开发为主。之前习惯每次改动都在本地跑全量，等待约 10 分钟以上，而 CI 每次 push 到 main 已经跑一遍相同的检查。用户 2026-11-04 提出：由 AI 根据修改范围和风险判断验证方式，只在必要时跑全量。

实测（2026-11-04）：

| 步骤 | CI（最近 3 次成功） | 本机 |
|---|---|---|
| 类型检查 | 8～9 秒 | 8 秒 |
| lint | 10～13 秒 | 14 秒 |
| `pnpm test` | 295～375 秒 | 单元测试约 10 分钟（2 个 worker，此前的记录，这次没有重跑） |
| 公网、内网构建 | 两次合计 7～10 秒 | 23 秒、39 秒 |
| 生产冒烟 | 213～287 秒 | 单个文件 14～54 秒 |

只跑相关的测试（本机，单元测试 2 个 worker）：

| 改动的文件 | 单元测试 | 浏览器测试 |
|---|---|---|
| message-center 的 `api.ts` | 13 个文件，43 秒 | 2 个文件，9 秒 |
| `shared/map` 的 `useBasemap` | 16 个文件，49 秒 | 1 个文件，8 秒 |
| `map-core` 入口 | 91 个文件，128 秒 | 9 个文件，131 秒 |
| `shared/http` 客户端 | 64 个文件，134 秒 | 没有测 |

慢的是测试和冒烟，不是构建。`vitest --changed` 的选择范围：

- `.module.scss` 和被 import 的 JSON 选得到（实测选中 17、29 个文件）
- `tokens.scss`、`element-theme.scss` 选不到任何测试（`No affected test files`）
- `package.json`、`vite.config.*` 变化时跑全部测试（Vitest 5.0.5 默认的 `forceRerunTriggers`，读源码确认）
- `.env` 没有确认：试跑超过 2.5 分钟没有结束就停掉了，所以规则里直接按全量处理
- 基准是 `main...HEAD` 加暂存、未暂存、未跟踪的文件（读源码确认）；只改文档时 7 秒结束、退出码 0

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 本地跑多少 | 每次全量；按目录固定；按范围和风险分级 | 分级。目录不能代表影响面：同在 `shared` 下，`useBasemap` 只选中 16 个文件，`http` 选中 64 个 |
| 怎么选测试 | `vitest --changed main`；手写"文件到测试"的映射；`vitest related` 手动列文件 | `--changed main`：不用维护映射，在 main 和分支上用法相同，也不用手动列文件 |
| 谁来定级 | 脚本按路径自动定级；AI 按规则判断 | AI 按规则判断：路径看不出风险（如改鉴权的一行），定级的依据和结果在交付时说明 |
| CI | 保持全量；也按范围跑 | 保持全量：这是本地敢少跑的前提 |
| 协作方式 | 每一步都先讲再做；小改直接做 | 小改直接做：迁移期为了学习而每步讲解，迭代期成本过高。涉及选型、架构或不容易回退的决定仍然先讨论 |
| 改坏验证 | 所有测试都做；只用于修 bug 和关键逻辑 | 后者：指标计算的一个步骤曾改坏 27 处，成本高，普通用例的收益不值得 |

## 决定

- 改完按影响范围和风险选一级，拿不准就升一级；规则和级别表在 `AGENTS.md` 的"验证分级"，这里不重复
- 新增 `pnpm --filter @yzt/web test:changed`（`vitest run --changed main --passWithNoTests`），同时覆盖单元测试和浏览器测试；冒烟可以只跑单个文件
- 没选中测试不等于通过：全局样式、`.env`、运行时才请求的文件要按规则升级
- 交付时说明跑了哪一级、哪些命令、哪些没验证
- UI 验证仍按 `docs/design/ui-workflow.md`，和分级互不代替
- CI 不变，每次 push 到 main 跑全量

## 后果

- 常见的局部改动约 1 分钟验证完（类型检查 8 秒、lint 14 秒、相关测试 41 秒），影响面大的改动约 6 分钟
- 代价：本地漏掉的问题要等 push 之后由 CI 发现，main 偶尔会变红，再修复
- `test:changed` 只看 `apps/web` 的测试，改 `packages/*` 要加上该包自己的测试；以后拆包时要重新看这条
- 文档里的命令耗时（如 `commands.md`）是当时的实测，会随测试增多变化
