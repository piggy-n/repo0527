## 背景

ADR 0078～0086 的三维用 Cesium：单独一块画布，二维的覆盖物镜像过去，资源图层（MVT）在三维里不显示（ADR 0078 第 1 节）。

要在三维里显示资源图层，有三条路：

- **Cesium 原生 MVT：** 1.146 只能画纯色的面和线，没有花纹和虚线，而且在主线程解码。
- **方案 B：** 迁移旧项目的 Worker 栅格化，约 2100 行。
- **方案 C：** 二三维都用 MapLibre，三维模型用 Three.js 画在 MapLibre 的 custom layer 里，资源图层由 MapLibre 原生绘制。

2026-11-05 做了方案 C 的验证。

**证据的位置：**

- 测量工程：分支 `poc/maplibre-three-gpu`（提交 `08c4eac`）的 `tools/poc/maplibre-three/`。
- 完整记录和显卡机器的原始结果不入库，在 `local/poc/maplibre-three/` 的 `REPORT.md` 和 `results/gpu-20261105-173612/`。

PoC 里有两种层。一种是第三方库 `maplibre-gl-three` 的层；另一种是自写层，即 `own-layer.ts` 和 LCC2 页面的 `SplatLayer`。综合测试页的拾取和 glTF 只接在第三方层上，所以两种层要分开看：

| 能力 | 自写层 | 第三方层 | 说明 |
|---|---|---|---|
| 3D Tiles 加载（白模、车站、倾斜摄影） | 已验证 | 已验证 | 自写层在显卡机器上和 Cesium 同视角对比，显示的瓦片数、三角形数基本相同 |
| z<12 的地球阶段 | 已验证，模型处误差小于 0.003 像素 | 不画 | 第三方层在投影过渡未完成时不画模型 |
| z≥12 的对齐 | 用同一套修正后的矩阵，像素误差没有单独测 | 修正比例后小于 0.07 像素 | 和 Cesium 同视角的截图一致 |
| 和二维图层叠放、深度遮挡 | 已验证（LCC2 页面：线、标注、b3dm、不透明物体） | 已验证 | |
| 拾取（射线 → 经纬度、高度） | 只对泼溅和 b3dm 打过射线，返回局部坐标；**反投影误差没有测** | 已验证，反投影误差 0 像素 | |
| glTF 和骨骼动画 | **没有测** | 已验证 | |
| 投影切换时没有空白帧 | 只确认过 LCC2 从 z12.2 到 z9 没有报错；**逐帧空白检测没有做** | 已验证 | |
| 第一人称、地下（模型抬高 20 米） | 已验证：测量页的站内路线，LCC2 页面相机局部 z 为 -31.72 米 | 已验证（`setOffset`） | |
| 取地板、导航网格 | 不涉及 | 不涉及 | 已验证的是独立 Three 场景（和清单最多差 1.1 厘米）和 LCC2 的 `.ply` 接 `buildNavGrid` |
| LCC2 高斯泼溅 | 已验证 | 版本冲突，装不上 | 泼溅库要求 `three >= 0.187`，`maplibre-gl-three` 锁在 `^0.186` |

不用 `maplibre-gl-three` 的理由：

- 它在 z<12 不画模型；
- 默认比例有 0.2%～0.3% 的误差；
- 只有一个维护者；
- 和泼溅库的版本冲突。

但自写层的拾取、glTF 和动画、切换时的空白帧**还没有验证**，要在 3C.1、3C.2 补上，在那之前不能说去掉它的条件都已经成立。

**显卡实测：** RTX 3060 笔记本，Edge 浏览器，1600×900，每个场景跑 1 次。和 Cesium 用同样的模型、视角、底图对比，Cesium 一侧用 `packages/map-cesium` 的真实缓存配置。方案 C 的测试页用的是 PoC 的 `OwnTilesLayer`，倾斜摄影另有写在测试页里的自适应缓存，**不是生产代码**。

- **静止时的每帧 GPU（中位数）：** 方案 C 0.4～4 毫秒，Cesium 8～10 毫秒。每帧 JS 相近，都是 2～3 毫秒；站内的 Cesium 是 6.4 毫秒。
- **主线程：**
  - 加载期 long task 的总时长，方案 C 0.7～1.8 秒，Cesium 2.7～4.0 秒。
  - 两边都有一次 0.5～1.4 秒的长任务（方案 C 倾斜摄影 z19 自适应是 1404 毫秒）。long animation frame 只能把它归到页面脚本本身，是模块执行、MapLibre 初始化还是着色器编译，没有拆开。
- **飞行中的帧时间：** 新内容多时方案 C 更差。倾斜摄影，自适应缓存一列，第一遍飞行：

| 场景 | p95：C / Cesium | ≥50 毫秒的帧：C / Cesium | 每帧 GPU 的 p99：C / Cesium |
|---|---|---|---|
| z17 | 31.3 / 22.6 毫秒 | 8 / 2 | 32.9 / 12.9 毫秒 |
| z19 | 40.6 / 26.4 毫秒 | 8 / 13 | 32.2 / 17.3 毫秒 |

这时主线程是空的，推测是第一次绘制时集中上传纹理和几何体，没有验证。

- **缓存：** 固定 LRU 满了就拒绝加载。z19 默认缓存有 183 块瓦片没有加载，900 MB 仍有 134 块，画面变糊。自适应缓存的画质和显存与 Cesium 相当，但 z19 到稳定要 15.9 秒，Cesium 是 6.9 秒。
- **测量的局限：**
  - 测量脚本每帧等上一帧在 GPU 上执行完，所以帧间隔有约 20 毫秒的下限，看不出余量。
  - 每个场景只跑了 1 次，没有核对供电和温度。
  - 人工检查都没有做：第一人称手感、z12 的过渡、泼溅闪烁、天地图对齐。

**包体积：** 新增 0.76～1.15 MB JS；Cesium 是 3.85 MB JS，另有 6.9 MB 运行时文件。

用户 2026-11-05 决定：做方案 C；`packages/map-cesium` 作为包保留，以后迁移旧项目的 Cesium MVT 加载；最终通过 `.env` 选择引擎。

评审意见（2026-11-05）：

- 默认引擎改为方案 C，要放在契约、现有功能和人工检查都通过之后。
- 性能验收必须测生产代码。
- 第一人称、地下时把模型抬高，要规定坐标的边界。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 引擎 | Cesium 加方案 B；方案 C；Cesium 原生 MVT | **加入方案 C，最终作为默认。** 资源图层二三维共用一套绘制，不用镜像；包体积和静止时的 GPU 都更小。代价是漫游、地下、模型加载要用 Three.js 重写；飞行中的上传卡顿还要解决 |
| 什么时候改默认值 | 现在就改；通过验收后再改 | **通过第 9 节的门槛后再改。** 实施期间保持 `cesium`，现有用户不受影响 |
| Cesium 怎么处理 | 删除；保留为可选的引擎，只保证现有功能；和方案 C 同等维护 | **保留为可选引擎**（用户的要求）。同等维护要把每个新功能做两遍 |
| 在什么时候选择 | 构建时（`.env`）；部署时（发布目录里的配置文件，同 ADR 0137）；用户在界面上选 | **构建时**，用户提出的做法。和 `.env.intranet` 区分公网、内网的约定一致（ADR 0032）。部署时选择要在运行时多读一份配置，确有需要时再改 |
| 由谁选择 | 页面判断；map-vue 读配置；app 注入 | **app 注入。** 包不读 env（ADR 0143），页面不知道用的是哪种引擎 |
| 方案 C 下的画布和视图 | ① 一个 MapLibre 视图同时担任二维和三维，种类随维度变化；② 两个视图对象共用一个 MapLibre 地图；③ 三维另开一块画布、另一个 MapLibre 实例 | **①。** ② 和现有的"切走的视图暂停"冲突：暂停二维视图就停掉了三维在用的地图。③ 最贴合现有契约，但有两个 WebGL 上下文，资源图层的瓦片下载两份，丢掉方案 C 的主要好处 |
| 方案 C 的三维代码放在哪 | map-core 的 MapLibre 适配器里；新包；应用里 | **新包 `@mx/map-three`。** 放进 map-core，所有用地图的页面都会背上 `three`；放在应用里，以后的地图项目不能复用。只有适配器能导入 maplibre-gl（ADR 0024），所以 custom layer 的外壳留在适配器里，三维内容在新包里，两边用窄接口，同 `CesiumView` 和 `SceneLike`（ADR 0079 第 3 节） |
| 地下和第一人称 | 把模型抬高，用 MapLibre 的相机；独立的 Three 画布；用 `transformCameraUpdate` 硬改相机 | **先用抬高，独立画布作为备选。** PoC 里两种做法每帧 GPU 都约 0.6 毫秒，抬高能和二维共用一块画布。坐标边界见第 4 节。最后由步行的手感决定 |

| 性能验收用什么页面 | 继续用 PoC 的测试页；测试页改为调用生产包 | **调用生产包。** 现在的测试页直接用 PoC 的 `OwnTilesLayer`、`RoamScene` 和写在页面里的缓存算法，以后优化生产包，这个测试页仍然测的是旧代码 |

## 决定

### 1. 引擎和选择

- **变量：** `VITE_MAP_3D_ENGINE` 选择三维引擎，取值 `cesium`（现状）和 `maplibre`（方案 C）。
  - 只在 `shared/config/app-config.ts` 里读取和校验，取值写进 `docs/config/env.md`。
  - 公网和内网要不同时，写在 `.env.intranet`。
  - 换引擎要重新构建。
- **默认值：** 实施期间 `.env` 提交的是 `cesium`，通过第 9 节的门槛后改为 `maplibre`。
- **注入：** app 按这个值把引擎的描述注入 map-vue，扩展 ADR 0079 第 2 节的运行时注入。描述包括：
  - 三维由哪块画布承担；
  - 三维的运行时怎样加载；
  - 能力声明。
- **页面：** 页面和各个拥有者不判断引擎，照常放 `MapCanvas`、`CesiumCanvas`，照常调用 `setDimension`、`bindScene`、相机操作和漫游。
  - 引擎是 `maplibre` 时，`CesiumCanvas` 什么也不挂；
  - 引擎是 `cesium` 时，行为和现在完全相同。

### 2. 方案 C 的画布和视图

- **持有：** `MapCanvas` 持有唯一的 MapLibre 地图和视图。`maplibre` 引擎下，这个视图同时登记为二维和三维。
- **视图的种类：**
  - `MapView.kind` 改为当前的种类，视图另外声明自己支持哪些种类；
  - 只支持一种的视图（MapLibre 的二维视图、`CesiumView`）行为不变。
- **切换：**
  - 当前视图支持目标种类时，上下文不再"暂停旧视图、恢复新视图"，而是通知这个视图切换。
  - 视图切换投影和俯仰限制，按需加载三维模块，加上或撤下三维的层。
  - 切到三维时 `MapCanvas` 不再隐藏。
  - 相机按会话同步，不需要 ADR 0079 第 4 节的精确还原：画布和相机都是同一个。
- **工具入口：**
  - `dimension`、`ToolView.kind` 照旧随维度变化。
  - 工具栏、点选、图例按 `dimension` 和能力声明决定显示什么，不看引擎。
  - ADR 0080 第 5 节"三维期间点/框选不识别"，在 `maplibre` 下声明为能识别，实施 3C.2 时另定。
- **加载失败和重试：**
  - 三维模块（`@mx/map-three` 和 `three`）在第一次切到三维时加载。
  - 加载失败只让三维这一种类失败：`failure` 只反映当前种类，二维照常可用。
  - 三维时调用 `retry()` 只重新加载三维模块，不重建 MapLibre 地图。
- **GL 上下文丢失：**
  - MapLibre 要求 custom layer 处理 `webglcontextlost` 和 `webglcontextrestored`。
  - 丢失时，`@mx/map-three` 丢掉 Three 的渲染器和 GPU 资源，保留会话里的三维内容。
  - 恢复后重建渲染器，重新上传，瓦片从缓存取，缓存里没有的重新下载。
  - 这一条进契约测试，用 `WEBGL_lose_context` 模拟丢失和恢复。

### 3. 两种引擎的契约

- **要实现的接口：** 两种引擎都实现会话的三维内容（`SceneContent`、`sceneStatus`、`roamStatus`，ADR 0081、0083、0086），以及 `MapView` 和 `ToolView`（ADR 0024、0034）。
- **共用的部分：** map-core 里的瓦片集整理、路线、导航网格、`Walker`、第三人称挂法和引擎无关，两种引擎共用，不改。
- **能力声明：** 一种引擎做不到的功能按能力声明（ADR 0020 第 4 节），页面按能力决定显示还是隐藏入口。
- **契约测试：** 写一组两种实现都要通过的测试，防止没被选中的引擎悄悄坏掉。至少覆盖：
  - 三维内容的增删、状态报告、失败和重试；
  - 相机读写和定位；
  - 拾取—投影往返；
  - 维度切换；
  - 漫游的开始、暂停、退出；
  - GL 上下文的丢失和恢复（只有 `maplibre`，Cesium 不支持恢复）。

### 4. 抬高模型的坐标边界

MapLibre 把相机限制在 0 米以上，所以在地下的模型里步行或钻地时，要把模型和相机一起抬高。

- **抬高只存在于渲染适配器内部，也就是 `@mx/map-three` 和它驱动的 MapLibre 相机换算。** 对外一律是真实的椭球高：
  - 拾取结果；
  - 投影的输入；
  - 会话的相机；
  - `eyeHeight()`；
  - 漫游状态里人的位置、路线进度；
  - 室内地图上的位置；
  - 定位用的建议相机。
- **不改的数据：** 清单的出生点、路线，导航网格，`Walker` 都按真实高度工作，不知道有抬高。
- **抬高量：** 进入时按这个模型的包围盒算。抬高后，模型的最低处加上视点高度，要高于 0 米并留出余量，取整到米。同一次漫游、钻地期间不变。
- **只抬高这一个模型：**
  - 抬高期间隐藏其他模型和二维图层（同现在钻地时隐藏白模）。
  - 进入和退出时用黑幕盖住（`scene-blackout` 的做法）。
- **退出：**
  - 去掉抬高，恢复隐藏的内容。
  - 相机还在模型里时，先换到地表以上的位置（同 ADR 0081 第 6 节"退出时相机在地下的先飞回地表上方"）。
- **验收：**
  - **拾取—投影往返：** 抬高时拾取模型表面得到真实坐标，再投影回屏幕，误差小于 1 像素。
  - **楼层：** 沿清单的路线取地板，和清单高度相差不超过 2 厘米。PoC 的独立场景最多差 1.1 厘米。
  - **瞬移：** 室内地图双击瞬移后，真实坐标落在目标楼层，视点高 1.6 米。
  - **一致性：** 出生点、路线进度、室内地图上的位置和不抬高时一致。
  - **退出：** 模型、二维图层、相机都恢复。

### 5. 方案 C 的实现要求（来自 PoC）

- **包：** 新包 `@mx/map-three`。
  - 只有它导入 `three`、`3d-tiles-renderer`，以及以后的 `gaussian-splat-lite`；
  - 只能由 map-vue 动态导入，依赖方向和 map-cesium 相同，由 lint 检查。
- **custom layer：**
  - 外壳在 map-core 的 MapLibre 适配器里，每帧通过窄接口把矩阵、投影过渡值和 GL 上下文交给 map-three。
  - 只用一个 Three 的 `WebGLRenderer`，和 MapLibre 共用一个 WebGL 上下文。
  - 每帧画之前和画之后都要 `resetState`、清深度。
  - 泼溅库会在 render 回调以外调用 GL，所以 `render` 事件里也要 `resetState`，并给层一个空的 `prerender`。
- **坐标：**
  - 东、北两个方向按 WGS84 椭球算比例。
  - 地球投影的过渡段，在裁剪空间里按 MapLibre 着色器的 `mix(flat, globe, t)` 插值，z<12 也画。
- **相机：**
  - 地图的 `centerClampedToGround` 设为 `false`，`maxZoom` 不超过 24。
  - 地球投影在第一帧以前，`calculateCameraOptionsFromTo` 的结果不对，要等第一个 `render` 事件以后再设第一人称相机。
- **瓦片集：**
  - 加载前经 `prepareTileset` 整理。
  - 光照分 `sun` 和 `headlight`，头灯从 `scene-tilesets` 移植。PoC 里站内的明暗是平的。
- **缓存：** 按内存放宽屏幕误差。到预算还有瓦片要加载时逐步放宽，低于收回线时逐步收紧。收敛速度要调：PoC 每帧变 2%，太慢。
- **上传：** 新瓦片的纹理和几何体按每帧预算上传。
- **依赖：** `three` 和驾驶舱共用一个版本，写进 catalog（ADR 0143）。驾驶舱现在是 0.183.2，要加 LCC2 就要升到 0.187 以上，按 ADR 0005 单独提交。

### 6. Cesium 的维护范围

- 保证 ADR 0078～0086、0090 等已有的功能：修缺陷，跟着 Cesium 的版本升级。
- 新的三维功能（LCC2、三维里的识别等）只在 `maplibre` 下做，`cesium` 下声明为不支持。
- 迁移旧项目的 Worker 栅格化（方案 B），让 `cesium` 下也显示资源图层。这件事排在第 9 节的门槛之后，单独写一份 ADR。

### 7. 构建和验证

- **构建：**
  - 两种引擎的代码都是动态分块，没有选中的那种不会下载。
  - Cesium 的运行时文件（`cesium/`，约 7 MB）只在 `cesium` 时复制：`vite.config.ts` 用 `loadEnv` 读同一个变量。
  - 构建检查（入口里不能有 maplibre-gl、cesium，ADR 0023）对两种取值都要成立。
- **CI：** 默认值以外的那一种取值，也要构建一次，并跑三维相关的冒烟用例；具体用例实施时定。
- **性能验收必须测生产代码：**
  - 测量页改为导入 `packages/map-three` 和 `packages/map-cesium`，和现在的 Cesium 对照组相同的做法。
  - PoC 只保留场景、参数、采样和报告，不再有自己的层、场景和缓存算法。
  - 改好以前，`pnpm measure` 的结果只能说明 PoC。

### 8. 实施步骤

| 步骤 | 内容 | 验收 |
|---|---|---|
| 3C.1 | `@mx/map-three`、custom layer 外壳、瓦片集加载、光照、`VITE_MAP_3D_ENGINE` 和注入、契约测试的框架 | 三维模型面板在 `maplibre` 下能加载、定位、换白模效果；`cesium` 下不变；自写层的拾取（反投影误差小于 1 像素）、glTF 和动画、GL 上下文丢失恢复通过 |
| 3C.2 | 一个视图两种种类、切换、相机、覆盖物和资源图层在三维里的显示、加载失败和重试 | 现状底图在三维下能看到资源图层；测量、位置点可用；投影切换和缩放穿过 z12 时，逐帧检测没有空白帧；三维模块加载失败时二维可用，重试成功 |
| 3C.3 | 地下（第 4 节）、步行、路线漫游、室内地图、头灯 | ADR 0083、0086 的验收项和第 4 节的验收全部通过 |
| 3C.4 | 自适应缓存、上传预算；测量页改为测生产包 | 在显卡机器上，和 Cesium 同模型同视角，倾斜摄影 z17、z19 都满足下面全部条件 |
| 之后 | LCC2；`cesium` 下的资源图层（方案 B） | 各写一份 ADR |

3C.4 的条件要同时满足，不能靠降低画质换取帧率：

- **画质：**
  - 没有被拒绝的瓦片；
  - 稳定后显示的三角形不少于 Cesium 的 90%；
  - 截图对比不比 Cesium 糊。
- **到稳定：**
  - 从开始加载到稳定的时间不超过 Cesium 的 1.2 倍；
  - 飞行后补齐的时间不超过 Cesium。
- **帧时间：**
  - 第一遍飞行（边走边加载）的 p50、p95、p99 都不超过 Cesium 的 1.1 倍；
  - ≥50 毫秒的帧不多于 Cesium；
  - 第二遍飞行（大多在缓存里）同样比较。
- **主线程：** 加载期和飞行中最长的单次长任务不超过 Cesium，归因要拆到模块。

阈值可以在复测前调整，但这几类必须同时约束。复测时要先处理测量本身的帧间隔下限：放宽 fence 的等待，或者另用不限帧的统计方式。每个场景至少跑 3 次。

### 9. 改为默认引擎的门槛

下面都通过以后，`.env` 的默认值才改为 `maplibre`：

1. 第 3 节的契约测试，两种引擎都通过；
2. 3C.1～3C.4 的验收全部通过；
3. 现有三维功能在 `maplibre` 下逐项可用，以 ADR 0078～0086、0090、0146 的验收项为准；
4. 人工检查有记录：第一人称手感、z12 上下的过渡、站内观感、和天地图的对齐；
5. 用生产包在显卡机器上复测，满足 3C.4 的条件。

改默认值时另写一份 ADR，把它在总览里的结论替换掉。

## 后果

- **好处：**
  - `maplibre` 下，资源图层二三维用同一套绘制，花纹、虚线、标注在三维里和二维一样，不用镜像。
  - 地图页只有一块画布、一个 WebGL 上下文。
  - 切到三维不用下载 Cesium。
  - PoC 测得静止时的 GPU、加载期主线程、显存都比 Cesium 省。
- **好处：**
  - 页面和拥有者不知道用的是哪种引擎，以后换引擎或去掉一种，只动 app 的注入和对应的包。
  - 实施期间默认仍是 Cesium，用户不受影响。
- **代价：**
  - 三维的视图、模型加载、漫游、地下要用 Three.js 重写。PoC 估算新写约 1800～2700 行，自适应缓存和上传预算另加约 250～400 行。
  - `MapView` 的种类可变，上下文的切换要多处理一种情况。
  - 步行的手感要调，这是最不确定的部分。
- **代价：**
  - 两种引擎要一起维护：契约测试、CI 多一次构建、Cesium 和 `three` 两套依赖的升级。
  - 两种引擎下的功能会不一样，要在 `docs/config/env.md` 和 `map-cesium.md` 里写清楚。
- **代价：** 换引擎要重新构建。
- **风险：**
  - 飞行中的上传卡顿是 PoC 里方案 C 唯一明显比 Cesium 差的地方，要靠上传预算解决，效果没有验证。
  - 自写层的拾取、glTF、切换时的空白帧还没有验证。
- **待定：**
  - 第一人称最后用抬高还是独立画布；
  - `maplibre` 下三维期间的点/框选和图例；
  - LCC2 的引入，以及 `three` 升到 0.187 以后驾驶舱的验证；
  - 方案 B 的迁移；
  - 是否改成部署时选择。
- **已同步：**
  - ADR 0002、0020、0024、0078、0079 的状态行；
  - [地图架构总览](../modules/map-overview.md)里引擎和三维的几行；
  - `.claude/rules/map-3d.md`。
- **实施时同步：** 3C.1 加上变量以后，更新 `docs/config/env.md` 和 `.env`。
