# 0092. 消息：顶栏按钮下方的弹框

- 状态：已接受
- 日期：2026-10-27

## 背景

旧项目的消息是一个独立页面：顶栏右侧的铃铛显示未读数，点击跳到 `/message-center`，页面里有已读筛选和类型页签，点"立即处理 / 查看详情"带着一组一次性参数跳到系统管理或数据下载。`messageService` 是全局单例，每 5 秒拉一次全量列表，未读数变多时弹出 `ElNotification`，并直接操作路由。

用户要求消息不再是独立页面，而是在当前页面里点按钮、在按钮下方弹出，不新建路由。2026-10-27 只读核对真实接口（[migration.md](../migration.md)"系统管理与消息中心：接口实测"）：

- `POST /api/message/list` 一次返回全部消息（当时 505 条、约 225 KB），不分页，没有未读数接口；`isRead: 'false'` 的过滤有效
- 497 条是"报表分析通知"（`table`），业务消息只有 8 条（`approval`、`resource`）
- 消息里没有申请编号，`taskId` 就是申请的 `apply_id`

撤回的上一版也做过弹框（宽 480、浏览器原生 Popover、不轮询），这次不沿用，重新做了原型。用户在 `/dev/message-center` 比较后，2026-10-27 确认按推荐的定。

## 候选方案

1. **按钮的位置**：顶栏右侧、用户菜单左边（旧位置）；放进用户菜单（看不到未读数）
2. **浮层**：`ElPopover`（和"查询统计"下拉一致）；浏览器原生 Popover；抽屉
3. **列表与详情**：A，列表里直接显示全文、业务按钮在行内；B，列表只显示摘要，点开在弹框里看详情
4. **未读数的刷新**：不轮询；页面可见时每 60 秒；保持旧的 5 秒
5. **普通用户的业务按钮**（"数据下载"还没有迁移）：禁用并说明；不显示

## 决定

1. **按钮**：顶栏右侧、用户菜单左边，32 的圆形图标按钮，图标 `header-bell`（Tabler 的 `bell`），悬停和打开时加白色半透明底。`ElBadge` 显示未读数，超过 99 显示 99+，0 时不显示；按钮的无障碍名称带上未读数。加按钮后重新测量顶栏的三档断点（[layout.md](../modules/layout.md)）
2. **弹框用 `ElPopover`**，点击触发、非模态，`bottom-end` 对齐按钮右边：
   - 顶边离顶栏下沿 8，打开时现量顶栏和按钮的位置算出偏移
   - 宽 `min(400px, 100vw - 32px)`，最高 `min(640px, 视口高 - 顶栏下沿 - 24px)`；窄屏时由 Popper 的 `preventOverflow` 让左右至少离窗口 16
   - 关闭：再点按钮、点外面、按 Esc、点业务按钮跳转。`ElPopover` 不把 `update:visible` 传给内部的 tooltip，`visible` 不能受控，所以用它暴露的 `hide()` 关闭，按 `before-enter`、`before-leave` 记下开关状态；点击触发的弹框不响应 Esc，自己处理，关闭后焦点回到按钮
3. **内容**：浅灰标题栏写"消息"、未读条数和"全部已读"；下面是固定的筛选（全部 / 未读，类型：全部、审批提醒、资源消息、统计报表），只有列表滚动。数据一次取回，在前端筛选，列表一次显示 20 条，滚到底再接着显示。每条有未读红点、类型标签、标题、时间（今天写时分，今年写月日和时分，更早写日期，悬浮看完整时间）、完整正文和业务按钮（方案 A：真实正文都是一句话，方案 B 每条都要多点一次）。点一行标为已读，点业务按钮标为已读并跳转
4. **已读**：请求成功后才去掉红点，失败时提示并保留未读；同一条防重复；"全部已读"和单条已读互斥，只改提交时看到的未读，之后到达的新消息保持未读。写操作按 `useSessionGuard` 核对会话
5. **未读数**：取 `isRead: 'false'` 的列表长度（单独的查询，当时 135 条）。进入应用时取一次，页面可见时每 60 秒刷新一次（标签页隐藏时不取）；打开弹框时取全量列表；已读成功后两个查询都刷新。角标计入报表通知。不做右上角的通知和新消息动画
6. **业务目标**：消息 feature 只给出有类型的目标，不跳转：审批提醒、资源消息是 `{ kind: 'application', applyId }`（`applyId` 取接口的 `taskId`），报表通知是 `{ kind: 'reports' }`，没有 `taskId` 的业务消息没有按钮。app 按角色把目标换成路由：管理员到系统管理（`?apply=`，或统计报表，ADR 0091）；普通用户的"数据下载"还没有迁移，按钮禁用，旁边写"数据下载页面迁移后可用"。按钮文案：审批提醒"去审核"，资源消息"查看申请"，报表通知"查看报表"
7. **分层**：`features/message-center` 放接口、查询、已读的 mutation、筛选与显示的组合式函数和弹框里的组件，不导入别的 feature、不跳转；`app/layout` 的 `HeaderMessages` 装配按钮、弹框和跳转。删掉 `message-center` 的占位路由和路由名

## 后果

- 查看消息不离开当前页面，只有点业务按钮才跳转
- 弹框关着时，角标最多晚 60 秒；每次轮询传输未读的整个列表，打开弹框再传一次全量。后端加上计数接口或分页后可以减少传输（记在 migration.md）
- 报表通知占了绝大多数，未读角标常年是 99+，用户可以"全部已读"清掉
- 普通用户的业务按钮等"数据下载"迁移后打开
- 审批提醒正文里的"nullnull"是后端没填申请人，前端不处理
