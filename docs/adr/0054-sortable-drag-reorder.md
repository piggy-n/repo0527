# 0054. 拖动排序用 SortableJS

- 状态：已接受
- 日期：2026-10-15
- 落实 ADR 0053 第 6 节留到 5D.2 的"是否引入拖动的库"

## 背景

资源图层面板有两处拖动排序（ADR 0053 第 6 节）：

- 目录树：同一个分类下的子节点（分类和资源）调整展示顺序，存成单独的偏好；搜索期间不能拖
- "已勾选"：平铺的列表，调整地图上的叠放顺序（拥有者的 `move`）

两处都只能用拖动手柄拖，手柄也能用键盘的上下方向键移动。顺序都在拥有者里，列表由 Vue 按顺序渲染。

## 候选方案

| 方案 | 好处 | 问题 |
|---|---|---|
| A. SortableJS | 成熟（MIT，无依赖），支持只认手柄（`handle`）、停用（`disabled`）、动画；一个列表一个实例，嵌套的树里每个分类的子列表各一个，天然只能在同一个分类里排序 | 拖动时自己移动 DOM，和 Vue 按数据渲染冲突：放下后要先把 DOM 还原，再交给拥有者改顺序；新增约 45 KB（gzip 约 14 KB） |
| B. ElTree 自带的拖放 | 不加依赖 | 整行都能拖；放下时 ElTree 改自己的数据，要和推导出的树对齐；"已勾选"是平铺的列表，用树来做别扭 |
| C. 自己用指针事件写 | 不加依赖，行为完全可控 | 自动滚动、边界、落点线都要自己写和测试；拖动排序是通用问题，AGENTS.md 要求优先用成熟的库 |

5D.2 设计稿里由用户选了 A。

## 决定

1. 用 `sortablejs`（1.15.x）和 `@types/sortablejs`，不用 `@vueuse/integrations` 的 `useSortable`：它默认直接改传入的数组，我们的顺序在拥有者里；自己包一层更直接，也少一个依赖
2. `shared/composables/useSortableList`：给一个列表元素建 Sortable 实例，只认手柄、可以停用；放下时把被拖的元素放回原位，再调用 `onMove(from, to)`（列表里的旧序号和新序号），由调用方交给拥有者；作用域销毁时销毁实例
3. 键盘不经过 SortableJS：手柄上按上下方向键，由组件直接调用拥有者同样的操作
4. 只在 `shared/composables/useSortableList.ts` 中导入 `sortablejs`；测试为了模拟放下，可以用 `SortableJS.get(element)` 取到实例、调用它的 `onEnd`

## 后果

- 好处：拖动的手势、动画、边界由成熟的库处理；顺序仍只在拥有者里，Vue 照常按数据渲染
- 代价：新增一个运行时依赖；"放下后先还原 DOM"是和 Vue 配合的约定，写在组合式函数里并有测试
- 代价：SortableJS 在桌面浏览器上用 HTML5 拖放，拖影是浏览器生成的；触屏不验收（ADR 0034 第 1 节，不是目标设备）
