# 0043. 只读图例：从样式登记表推导，不做地类统计

- 状态：已接受
- 日期：2026-10-11
- 定下 ADR 0021 第 2 条留下的"图例统计"做法（不做）；补充 ADR 0041 第 2 节（图例读样式登记表的同一份数据）

## 背景

旧项目（yzt `master-demo` 836f03b）的图例 `MapLegendPanel` 只列已上图的图层，每层一条：统一符号的图层显示一个符号预览，按属性配色的图层列出"取值 → 颜色"，地类图斑显示 `LanduseLegendSection`：表 A.1 现状分类、表 A.2 工作分类、全部平铺三种展示，按编码或名称搜索，每个地类有含义说明，还能调色。面板默认收起成右下角的"图例"按钮；面板里的条目在条目的集合变化、且只剩一条时自动展开那一条（侦听的是条目 key 的拼接，透明度、顺序变化不会触发）。

图例打开时，旧项目在地图空闲后对地类图斑做整屏 `queryRenderedFeatures`，统计"当前出现的地类"（`LanduseStyleManager.requestPresence`、`BusinessLayerManager.discoverLanduseTypes`）。ADR 0021 把它记为唯一确认的主线程热点，要求阶段五用真实数据测出 MapLibre 6 的耗时，再在后端聚合、Worker 解码属性、按需统计三者中选。

读旧代码发现，这项统计的结果只有一个用处：把表 A.2 之外的编码放进"其他地类"分组；图例本身一直列出全表，并不按统计结果过滤，出现过的编码也只增不减。ADR 0041 已经把表外的情况写成静态规则：编码没命中时按名称查历史地类，再用兜底色。

5C.4 的实测（migration.md"图例统计实测"）：

| 视野 | `queryRenderedFeatures` | 不同的编码 | 表外编码 |
|---|---|---|---|
| 全省 z6.5 | 18.9 万个要素，327～563 ms | 57 | 无 |
| 南京 z10 | 10.7 万个，205～334 ms | 55 | 无 |
| 南京 z13 | 2481 个，5～8 ms | 26 | 无 |

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| "当前出现的地类"统计 | 沿用旧做法（图例打开时整屏统计）；后端按范围聚合；自建 Worker 解码瓦片属性；不统计 | 不统计：它唯一的用处（发现表外编码）已由 ADR 0041 的静态规则代替，实测也没有表外编码；全省和 z10 时每次几百毫秒的主线程阻塞换不来任何显示上的差别 |
| 图例的数据从哪里来 | 运行时读地图上的样式；样式登记表和显示状态 | 登记表和显示状态：和分组推导是同一份数据，图例显示的就是推导出的颜色；不依赖视图，二三维一致 |
| 条目的顺序 | 图层树的顺序（旧项目）；叠放顺序 | 叠放顺序，从上到下，和图层面板的"已勾选"区一致 |
| 两个地类图层 | 地类图斑显示完整的地类图例、城镇村只列名称（旧项目）；都显示完整的地类图例 | 都显示完整的：两者用同一套颜色，城镇村按名称配色，只是取值方式不同 |
| 表外地类 | 运行时发现，放进"其他地类"（旧项目）；固定列出 | 固定列出"历史地类"分组（6 个名称）和"未匹配的地类"（兜底色） |
| 调色、恢复默认 | 现在做；5C.5 | 5C.5 符号编辑时做，本次只读 |

## 决定

### 1. 面板与条目

- 面板的开关和条目的展开是两件事，都是图例自己的界面状态，不进显示状态，也不持久化
- 面板：进入页面时总是收起，只显示"图例"按钮，由用户打开、收起；勾选、取消勾选都不会自动打开面板（默认勾选地类图斑时面板仍是收起的）
- 条目：每个勾选且配置合法（ADR 0041 第 4 节）的资源一条，按叠放顺序从上到下；配置错误的资源不画在地图上，也不进图例（图层面板上已有提示）。条目可以单独展开、收起
- 自动展开只看条目的集合：集合变化（勾选、取消勾选、目录刷新）后只剩一条时，展开这一条；透明度、顺序、年份的变化不改变集合，不会把用户手动收起的条目再展开
- 没有勾选任何资源时提示"勾选资源后查看图例"

### 2. 内容从样式登记表推导

- 统一符号：按几何类型的默认样式画预览（面是半透明填充加同色描边，线是一段实线，点是带白边的圆点），颜色就是推导时用的配色板颜色
- 按取值配色（ADR 0041 第 2 节）：列出"取值 → 颜色"，最后一项"其他"是兜底色；按取值顺序取色的规则同样列出实际颜色
- 地类（地类图斑按编码、地类图斑（城镇村）按名称）：完整的地类图例
  - 三种展示：表 A.1 现状分类、表 A.2 工作分类、全部平铺；按编码或名称搜索
  - 每个地类有含义说明，可调整地类加上标注
  - 最后是"历史地类"分组（表 A.2 之外的 6 个名称）和"未匹配的地类"（兜底色）
- 推导是纯函数，输入是显示状态和登记表，不读地图；测试放在推导上
- 复用分组推导已有的来源：符号预览取 `resourceLayerStyle`，取值的颜色取 `valueColors`，地类取 `landuse.ts` 的表，不在图例里另算配色板的序号、填充的透明度。配色板的颜色按资源在目录里的序号取，与叠放顺序无关；测试要保证调整叠放顺序不改变图例上的颜色
- 图例表示配置的符号规则，不等视图就绪或 `idle`：瓦片加载失败、低于最小显示级别、视图还在加载时照样显示
- 只读：调色、恢复默认在 5C.5

### 3. 不做"当前出现的地类"统计

- 不在主线程上做整屏查询，也不为它建后端接口或 Worker
- 以后如果业务上需要"只显示当前视野里出现的地类"，按上表的实测选做法：高层级（z13 左右）时整屏查询只要几毫秒，可以按需统计；全省、z10 时要几百毫秒，要放到后端或 Worker

### 4. 数据

- 表 A.1 的分组（12 个一级类，9 个地类的归属要特别指定，如红树林地归林地）和 69 条地类含义迁到 `landuse.ts`，测试与从旧仓库生成的 fixture 逐条对照（同 ADR 0041 第 2 节的做法）

### 5. 位置

- 图例放在地图右下角，登记为贴右边的悬浮元素（ADR 0029），定位时避开；外观在 5D 设计
- 右下角给 MapLibre 的版权控件留出位置：`useMapOverlay` 只负责定位时避开悬浮元素，不负责悬浮元素之间的排布，图例和版权控件的重叠要在布局里避开（5A.3 设计稿时记下的问题，roadmap 5D）

## 后果

- 好处：图例显示的颜色和地图上推导出的颜色来自同一份数据，不会对不上；不占主线程，全省视图打开图例也不卡
- 好处：ADR 0021 唯一确认的主线程热点不存在了，二维仍然不需要自建 Worker
- 代价：图例总是列出全表，不能只看当前视野里出现的地类（旧项目也不能）
- 代价：不再动态列出表外的编码。表外编码出现时仍按既定规则配色：名称是历史地类就用历史地类的颜色（例如表外编码配"城市用地"），所有规则都没命中才是"未匹配的地类"的灰色；落进灰色的要素在图例上看不出具体是哪个编码，以后发现这类数据再看
