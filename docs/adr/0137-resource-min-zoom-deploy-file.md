# 0137. 资源的最小显示级别放进部署文件

- 状态：已接受
- 日期：2026-11-04
- 修改：ADR 0132（层级写进代码、改层级要重新构建）

## 背景

ADR 0132 把层级写进代码，理由之一是配置文件"要在 9 个同步读取登记表的文件之前异步加载"。这个估计是错的：实际只有 4 处读层级（瓦片的数据源和图层、点选的范围、点选的目标、面板的提示），这 4 处都拿得到目录，目录本来就是异步查询，等目录时界面已经能处理"还没有数据"。不用改启动流程。

后端切片和缓存还在变，换环境要重测（ADR 0132、0136），每次都重新构建不值得。用户确定做这个方案。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 文件放哪 | `public/`；feature 目录加构建复制 | feature 目录（`features/resource-map/resource-min-zooms.json`）：内置的层级要 `import` 它，Vite 不让源码导入 `public/` 的文件；构建时用现有的 `vite-plugin-static-copy` 复制到产物根目录。仓库里只有一份，内置和部署的默认值不会不一致 |
| 什么时候读 | 启动时先读完；和目录一起读 | 和目录一起：目录查询的 `queryFn` 同时取两份，`select` 得出带层级的目录。不碰启动流程和路由；查询的缓存、刷新、结构共享不用另写 |
| 层级放哪 | 模块级变量，登记表继续同步读取；目录的 `Resource.minzoom` | 目录：模块级变量等于把异步结果藏进全局状态，什么时候读到什么值说不清；读取处都有目录。登记表只留样式 |
| 读不到或不合法 | 目录一起失败；用内置的层级 | 用内置的层级并 `console.warn`：一个可选的配置文件不该拦住整个地图。nginx 对不存在的文件回退到 `index.html`，返回 200 的网页，也走这条路。取消不算失败，照常抛出 |
| 一项不合法 | 忽略这一项；整份不用 | 整份不用：写错的文件通常不止错一项，部分生效更难发现。超过数据源最大级别的层级算不合法，否则资源永远画不出来 |
| 换了文件怎么及时生效 | 要求 nginx 配 `no-cache`；请求带时间戳 | 带时间戳：部署还没验证过缓存头（`docs/deployment.md`），不增加一条 nginx 规则，也不依赖它 |
| 关闭开关时 | 照常读、不用；不读 | 不读：只用于排查和应急，不多发一个请求，层级都是不限制 |
| 脚本建议和 ADR 0136 冲突 | 人工记得保留；脚本保留 | 脚本保留：建议文件现在可以直接替换部署文件，靠人记不住。村级调查区、界线、路面范围的建议不低于现在的值，报告里写明例外 |

## 决定

- 层级写在 `features/resource-map/resource-min-zooms.json`（`{ code: 级别 }`，没写的不限制），构建时带上一份，同时复制到产物根目录
- `fetchResourceMinZooms` 随目录查询读发布目录的文件，zod 校验：级别是 0 到数据源最大级别的整数
- 目录的 `Resource.minzoom` 是唯一的读取来源，瓦片请求、提示、点选都读它；`resourceStyle` 不再含层级
- `VITE_RESOURCE_MIN_ZOOM_ENABLED` 的含义不变：`false` 时不读文件、都不限制；改开关仍要重新构建
- `--tile-cost` 输出的 `resource-min-zooms.json` 和部署文件同格式，保留 ADR 0136 的三个资源
- 脚本的 `ZOOM_FLOORS` 仍是单独一份（目录可以单独拷走运行，不依赖 `src`），由测试保证和文件一致

## 后果

- 好处：重测后换一个文件、刷新页面就生效，不用重新构建；构建产物里的默认值还在，文件丢了也不会放开重瓦片
- 代价：目录查询多一个请求，要等它回来才有目录。文件很小、走同源静态服务，这个等待可以忽略；如果静态服务卡住，目录也跟着卡
- 代价：已经打开的页面要刷新才生效，目录查询没有轮询
- 代价：`dist` 每次发布整体替换，部署时改的文件会被覆盖，确定下来的值要同步回仓库
- 文件里写了目录没有的 `code` 不报错、不生效，写错 `code` 只能靠看页面发现；这个文件换环境就可能和目录不同步，校验目录反而会误报
- CI 用 `.env` 的开关构建，现在是 `false`：生产冒烟只跑关闭时的用例，打开时的用例要用环境变量覆盖后构建（`docs/commands.md`）
