# 0114. 离开页面后是否重置：环境变量 VITE_PAGE_STATE_RESET，默认保留

- 状态：已接受
- 日期：2026-10-29
- 修改：ADR 0063（标了 keepAlive 的页面切走时缓存）、ADR 0042（现状底图记住底图）的部分做法

## 背景

用户 2026-10-29 提出：部分页面切换路由后仍保留上次的操作状态，尤其是现状底图和指标 AI 计算；希望评估是否离开后重置（例如现状底图每次进入都是二维加矢量底图，不继承上次的三维），要求先列清单、确认范围，并加可配置的开关或环境变量，默认关闭，即保留页面状态。

排查结果：

| 页面 | 怎么保留 | 离开后保留的状态 |
|---|---|---|
| 现状底图 | 页面缓存（`keepAlive`，ADR 0063） | 二维 / 三维、相机位置、当前工具和它的结果（测量、坐标定位点、点选 / 框选与详情窗）、功能面板（行政区、图例、区划定位与裁剪、坐标定位）的开合与内容、资源树的搜索与展开；三维的已加载模型、白膜效果、漫游 |
| 现状底图 | 偏好（IndexedDB，按登录名，ADR 0042） | 底图与透明度、行政区显示、资源图层的勾选 / 透明度 / 顺序 / 年份、符号样式、目录顺序、资源面板的收起和高度比例 |
| 指标 AI 计算 | 页面缓存 | 阶段、条件（年份、范围、指标、参数与自定义口径）、AI 指令的文字、计算进度（切走时暂停）、推理时间线、结果的选择、结果地图的视角与底图 |
| 其他业务页面 | 不缓存 | 离开就重置；回来时列表可能先显示查询缓存（接口数据，不是界面状态） |
| 全局 | Pinia、localStorage | 登录会话、AI 服务的 token、资源管理的图层服务记录、接口数据的查询缓存：必须保留，不受开关影响 |

另外发现：切到三维时 `selectForDimension` 自动换成影像，这个选择也写进了底图偏好；刷新页面（回到二维）时恢复成影像。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 开关放在哪里 | 环境变量；界面上的用户设置；按页面列出 | 环境变量 `VITE_PAGE_STATE_RESET`（`true` / `false`），部署时决定；两个缓存的页面一起生效，不再按页面细分 |
| 重置时偏好怎么办 | 全部恢复；全部不恢复；底图不恢复、其余照常 | 底图不恢复：每次进入都是矢量底图（用户举的例子）。资源图层、符号、行政区是用户配置的内容，不是"上次的操作"，照常恢复 |
| 三维自动换的底图 | 照旧写进偏好；不写 | 不写：偏好只存用户自己选的底图，透明度照常存 |

## 决定

- `.env` 加 `VITE_PAGE_STATE_RESET=false`；`appConfig.pageStateReset`（只接受 `true`、`false`）
- `AppLayout` 的 `pageStateReset`（默认取 `appConfig`）：为 `true` 时不把标了 `keepAlive` 的页面放进 `KeepAlive`，每次进入重新创建；路由 meta 的 `keepAlive` 不变
- 现状底图：`pageStateReset` 为 `true` 时底图的拥有者不接偏好（不读不写），每次进入都是矢量底图；其余偏好照常
- `useBasemap`：另记用户自己选的底图（`select`），偏好只存它；`selectForDimension` 只换显示的底图

## 后果

- 默认行为不变；打开后两个页面每次进入都要重新创建地图（约 1～2 秒、重新取瓦片），计算到一半离开会丢掉这次计算
- 关掉时（默认）刷新页面不会再因为离开前在三维而回到影像底图
- 测试：`AppLayout` 打开重置时写了 `keepAlive` 的页面每次进入都重新创建；`appConfig` 默认关闭、开关只能是 `true` / `false`；三维自动换的影像不写进偏好。生产构建上用临时的检查确认：打开重置时离开再回来面板关上，关掉时还开着（检查没有入库）
