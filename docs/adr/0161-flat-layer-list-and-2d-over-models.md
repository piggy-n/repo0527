# 0161. 图层平铺成一个列表，顺序就是叠放：二维可以画在三维模型上面

- 状态：已接受
- 日期：2026-11-16
- 取代：ADR 0157 第 1 节的"当前图层两组、各自拖动排序，不能跨组""三维里三维模型组在上（方案乙）""模型的移动只改列表的先后"，第 3 节的"二维里模型组变淡、组标题旁标一次'仅三维'""上下方向键在两组之间连着走"；ADR 0147 第 2 节随 3C.2 落地的叠放做法"模型层只有一个由页面静态声明的位置（`sceneBelow`）"，以及由此带来的区划遮罩被模型挡住（[map-three.md](../modules/map-three.md)"叠放"）
- 修改：ADR 0157 第 2 节"`withAdded` 把没加入过的整批放到最前"、第 4 节"点到模型上时查模型脚下"（现在只对画在模型下面的资源）
- 补充：ADR 0054（图层只有一个拖动实例，筛选时按看得见的行排序）、ADR 0048（三维里画在模型上面的资源怎样识别）、ADR 0051（三维里遮罩画在模型上面，漫游时撤掉，点选按鼠标下的地面判断是否点在遮罩上；0051 把三维的遮罩留给了三维阶段）

## 背景

用户 2026-11-15 提出现状底图改版的需求 7：三维里二维资源要能叠在模型上面，在图层列表里调它们的先后。调研和原型在 `local/design-src/current-map-revamp/scout.md` 的 scene-overlay 一节、`local/design/current-map-panel-v4/`（不入库）。用户 2026-11-16 的答复（`local/design-src/current-map-revamp/batch1-decisions.md`）：S1 选方案 C 的简化版"傻瓜模式"，取消"二维图层""三维模型"两组，平铺成一个列表、顺序就是叠放，两个模型之间的先后不管；S4～S7 按推荐，加上会话提议、用户"按建议定"的平铺列表的规则。

技术前提（调研已核实，MapLibre 6.12）：

- 所有模型（瓦片集、glTF、泼溅）由一个 custom layer 在一次渲染里画完，画前画后清深度，不和 MapLibre 共用深度。第一个三维层以上的样式图层一律不做深度测试，按画家算法盖在模型上面；以下的被模型整片盖住。所以一个二维图层只有两种状态：整个盖在模型上面，或者整个被模型盖住；"贴在模型表面"在现有架构下做不到
- 把模型拆成多个层（每个模型一个）会让模型之间失去遮挡，泼溅靠瓦片的深度做遮挡也要在同一层，不可行；所以二维不能夹在两个模型之间，只能以一个位置为界
- 模型层原来的位置由页面在 `provideMap` 里静态声明的 `sceneBelow` 分组决定（现状底图是 `basemap-labels`）。`StyleModel` 每次组合都算出 `sceneBefore`，视图按它 `moveLayer`；但只改 `sceneBefore` 时快照的样式没变，原来的通知会因为"没有命令"而不发出
- 模型按真实的椭球高摆（徐州地面约 40 米），二维在 0 米；二维盖到模型上以后，斜着看会和模型的地面错开约"高差 × tan(俯仰角)"

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 粒度 | A 全局开关（二维整体盖上去）；B 每个二维图层一个标记；C 合并列表，模型是一块；C 的简化版：资源和模型平铺 | 平铺（用户 2026-11-16）：列表顺序就是叠放，一句话说得清；A 粒度太粗，B 最后会收敛成 C 的分区 |
| 二维和多个模型 | 以最上面的模型为界；每个模型一个层 | 以最上面的模型为界：模型只有一个层（见背景），模型之间的先后不影响二维 |
| 地图内核的做法 | 页面多声明"模型上方"的分组，拥有者分流；运行时改 `sceneBelow`；层级的插槽 | 插槽，`sceneBelow` 留作上限：分流要换图层 ID，违背"ID 以分组名为前缀"（ADR 0027），框选估数、点选都靠 `resources-<code>` 识别图层；改分组的位置只能整组上下，插槽能放在资源分组中间 |
| 新加入的位置 | 都放在最上面；模型在最上面、资源在最上面那个模型的下面 | 后者（用户 2026-11-16）：默认的样子和以前一样，二维在模型下面，要盖上去自己挪 |
| 区划遮罩 | 留在模型下面（盖上去的二维不再按区划裁剪）；跟着二维一起盖上去；一直在模型上面 | 一直在模型上面：遮罩只有一份，跟着二维时要按图层拆成两份；用户 S5 同意了"跟着二维一起盖上去"，这里扩成一直在上面（主会话向用户说明） |
| 漫游时的遮罩 | 照常画；回到模型下面；漫游期间撤掉 | 撤掉：地上的瓦片集漫游时二维照常显示，视点比 0 米的遮罩高几十米、视线几乎水平，区划里的模型会被盖住一整条；页面本来就认为漫游时区划不适用（区划条隐藏）。回到模型下面要在漫游时改上限，多一套位置规则 |
| 不透明的面盖住模型 | 提示一行加"调成半透明"按钮；盖上去时自动半透明；名称后面只写文字 | 名称后面只写文字（用户 S4）：不自动改透明度，不加按钮、不在头部加一行 |
| 高度 | H0 不处理；H1 显示用下沉量；H3 斜着看时提示并一键俯视 | 先做 H3（用户 S6）；H1 单独排期（`docs/backlog.md` 已有） |
| 点选 | 照旧查模型脚下；盖在模型上的图层按鼠标下的地面 | 按鼠标下的地面（用户 S7），画在下面的照旧查模型脚下 |

## 决定

### 1. 图层平铺成一个列表

- 资源图层面板下段"图层"不再分"二维图层""三维模型"两组：二维资源和三维模型平铺成一个列表、一个拖动实例，从上到下就是叠放。两个模型之间的先后不管、不提示、不处理（遮挡仍按模型在空间里的位置）
- 键盘（上下换行、Alt 加上下移动、手柄上按上下、空格、回车、Delete、Shift+F10）、新加入的滑入、定位到的闪两下、浮层的箭头都照旧，按一个列表算。工具栏的上移、下移、置顶、置底对模型和资源一样，提示不再写"（只改列表顺序）"
- 平铺的顺序在页面的 `useCurrentLayers`（`pages/current-map/layer-panel`）：资源之间的先后仍在资源的拥有者里（记在偏好里），模型之间的先后在模型的拥有者里，两者怎样穿插只记在这里，不持久化。合并的规则是纯函数 `mergedOrder`：按上次的穿插，内容按各自拥有者的先后；上次没有的模型放在最上面，上次没有的资源放在最上面那个模型的下面
- 移动一行只改变它在同类里的位置：移动后按新的平铺顺序算出它在资源或模型里的位置，交给对应的拥有者

### 2. 叠放：以最上面的模型为界

- 排在最上面那个模型上面的二维资源画在所有模型上面；排在它下面的（包括夹在模型中间的）都被模型盖住。没有模型、或者没有资源排在它上面时，模型层在 `resources` 分组的最后，和以前一样
- 高亮（`selection`）、资源的标注（`resource-labels`，ADR 0160）、区划遮罩（`region-clip`）及以上永远画在模型上面：页面的 `sceneBelow` 从 `basemap-labels` 改成 `selection`
- 地图内核：`sceneBelow` 改成模型层的上限，这个分组和以上永远在模型上面；新增运行时的插槽 `StyleModel.setSceneSlot(layerId)`，模型层插在这个图层下面。插槽的图层不在样式里（还没提交、已经删掉）或者在上限及以上时不生效，按上限放；之后的提交让它出现时生效。位置单独变化也算一次提交（修订号加 1），通知里没有命令也发出，视图按现有的 `place` 挪层；位置没变时只记下插槽
- map-vue：`MapHandle.bindSceneSlot(() => layerId | undefined)`，由 `StyleBinder` 和分组同一轮提交，推导失败时整批跳过
- 页面的插槽是画在模型上面的资源里最下面那个资源的最下面一层（资源拥有者的 `sceneSlot`，图层 ID 同 `resourcesGroup`）；它们都没画（隐藏、校验没通过）时为 undefined

### 3. 新加入的位置

- 新加入的模型放在最上面；新加入的二维资源放在最上面那个模型的下面（没有模型时在最上面），同一批里先放模型。`withAdded` 多一个参数 `at`：整批插在已加入的资源里的第 at 位，默认 0
- 模型清单不持久化（ADR 0157）不变；资源之间的顺序照旧记在偏好里，偏好的版本和格式不变。进页面时没有模型，列表就是资源的先后

### 4. 三维里的筛选标签，筛选时也能排序

- 三维里"图层"标题下面一行带数量的标签"全部 N · 二维资源 N · 三维模型 N"，写法、样式和"资源"一段的标签一样（同一个部件 `PanelTabs`），默认"全部"，切换维度时回到"全部"；二维里不显示。筛掉了全部的行时写"图层里没有二维资源""图层里没有三维模型"
- 筛选时移动按看得见的行算：往上挪放到越过的那一行的正上方，往下挪放到越过的那一行的正下方，被筛掉的行原地不动（`movedOrder`）。拖动、工具栏的四个移动、Alt 加上下都一样
- 选中的行被筛掉时没有选中、浮层关闭；加入的行会被筛掉、在目录里定位筛掉的行时回到"全部"

### 5. 二维里

- 模型行留在原来的位置、变淡（符号、名称 50%），悬停名称说明"切换到三维后显示"；不再在行上或组标题旁写"仅三维"。只剩模型时列表上面一行说明"三维模型切换到三维后显示，可以定位、漫游"
- 定位、漫游不可用的规则照旧（ADR 0157 第 3 节）

### 6. 盖住模型的提示（S4）

- 三维里，面资源排在最上面那个模型上面、画在地图上（显示着、到了最小显示级别）、图层里有显示着的模型，并且有效不透明度不低于 0.8 时，这一行名称后面跟橙色小字"盖住模型"，悬停说明"调低透明度可以透出模型"。只有文字，不在头部加一行、不加按钮
- 有效不透明度 = 图层透明度 × 画出的填充色里最大的不透明度（统一符号看统一的填充，按属性配色看各个取值；无填充为 0；花纹不算）。0.8 时透过去的不到两成，模型基本看不出来

### 7. 区划遮罩（S5）

- `region-clip` 一直画在模型上面：选了区划时，区划外的模型也被遮罩盖住。这是把用户同意的"跟着二维一起盖上去"扩成了一直在上面，不管有没有二维盖上去
- 后果：区划边上的高楼在屏幕上伸出区划边界的部分会被遮罩切掉（[map-three.md](../modules/map-three.md)"叠放"记过这个问题，原来正因为它才把遮罩放在模型下面）
- 漫游时撤掉遮罩：页面推导 `region-clip` 时，漫游期间按没有区划算（返回空分组），区划的选择不变，退出漫游原样回来。地上的瓦片集漫游时二维照常显示，视点在模型的地面上（徐州约 40 米），视线几乎水平，落到 0 米平面时已在区划外的那一条像素都会被遮罩盖住，被盖住的模型其实在区划里；页面在漫游时本来就认为区划不适用（区划条隐藏，`.claude/rules/map-3d.md` 的漫游规则：只隐藏，不改各拥有者的状态）

### 8. 斜着看时的提示（S6）

- 三维里有二维资源画在模型上面、图层里有显示着的模型、俯仰角不小于 15° 时，地图下方居中提示"倾斜时二维图层和模型会错开"，后面的"俯视"开始一次相机操作，把俯仰角转到 0。40 米的高差在 15° 时错开约 11 米，到了 z17 约十几个像素，已经看得出来
- 只减轻倾斜造成的错开：俯视时画面边上仍有径向的视差。"显示用下沉量"（H1）留在 `docs/backlog.md`，做了以后这个提示可以去掉

### 9. 点选（S7）

- 三维里点到模型上时，画在模型上面的资源按鼠标下的地面识别：渲染要素、容差框围着点击位置；画在模型下面的照旧查模型脚下（ADR 0157 的规则甲）。同一次点选里两类资源分别取锚点，求交、整理的缓存按（锚点，几何类型）区分
- 有区划时先看鼠标下的地面（只打地面的拾取）：它在区划外，这个像素就是盖在模型上面的遮罩，等于点在空白处，整次不识别（ADR 0051 第 3 节），模型脚下在区划里也一样；它在区划里时，画在模型下面的资源再看模型脚下，在区划外（区划外的楼伸进来）时跳过这一类
- 框选的四角本来就只打地面，盖在上面和压在下面的都对得上，不变。鼠标旁的提示本来就不提模型，不用改

## 后果

- 列表顺序就是叠放，用户不用再理解"两组各自排序、模型组在上"；代价是三维里不再先看到模型（ADR 0157 的方案乙），三维里靠"三维模型"标签只看模型
- 二维盖到模型上以后，斜着看会和模型的地面错开，提示只能减轻；不透明的面会整片盖住模型，靠"盖住模型"的提示让用户自己调透明度
- 区划遮罩一直盖在模型上面：区划外的模型看不到，区划边上的高楼会被切掉一截
- 选中高亮从此画在模型上面，ADR 0157 记下的"高亮被模型挡住"不再出现
- 地图内核的模型层位置从"页面静态声明一个分组"变成"上限加运行时的插槽"：`.claude/rules/map-3d.md`、[map-core.md](../modules/map-core.md)、[map-vue.md](../modules/map-vue.md)、[map-three.md](../modules/map-three.md)"叠放"跟着改；契约测试 `scene-contract.browser.test.tsx` 加了插槽的用例
- 平铺的穿插不持久化：刷新页面后模型都不在列表里（同以前），资源的顺序保留
- 只在软件 WebGL 上看过叠放的画面；盖上去以后模型层以上的不透明面不进 MapLibre 的不透明 pass，过度绘制可能多一些，要在显卡机器上看（`docs/backlog.md`）
