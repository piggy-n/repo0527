# 0064. 三维接入：先完成现状底图的切换与样式镜像

- 状态：已接受（2026-10-18）
- 日期：2026-10-17
- 依据：[3D.0 盘点与小样记录](../stages/stage-3d-0-plan.md)
- 本文未接受前不替代已有 ADR，也不表示 Cesium 已经接入

## 背景

阶段五已完成二维现状底图。会话、视图接口和工具流程已有实现，但 `map-cesium` 尚不存在，`MapCanvas` 直接创建 `MapLibreView`，地图上下文只挂一个活动视图。三维需要补齐运行时、视图实现和切换拥有者。

旧项目的三维不仅有现状底图，还接入了白膜、本地 3D Tiles、钻地、第一/第三人称漫游和室内地图。一次全部迁移会把样式兼容、相机、模型和导航混在一起，难以逐项验收。

3D.0 核对了 Cesium 1.145.0 的实际发布代码，并用真实的面、线、点瓦片执行了解码与 glTF 转换。原生 `MVTDataProvider` 确实可用，但标记为实验性，其样式入口不能直接接收 MapLibre 样式；当前花纹、虚线、面描边和分组层序均需要额外处理。小样没有创建 WebGL 场景，不能据此认定显示效果或性能合格。

## 候选方案

| 问题 | 候选 | 建议与理由 |
|---|---|---|
| 迁移范围 | 全量迁移旧三维；先完成现状底图，再分批接独有功能 | 先现状底图，先验证会话能否支撑两个真实视图 |
| MVT 显示 | Cesium 原生 MVT；按 ADR 0021 的 Worker 栅格化；两种长期混用 | 保留 Worker 栅格化主线：复用 style-spec 求值，覆盖已有符号与层序需求；原生 MVT 暂作独立候选，避免首期维护两套样式管线 |
| 默认视图 | 默认三维；保留二维默认值并支持按框架加载 | 首期保留二维默认值，加载器仍按 `defaultMapFramework()` 的结果工作，不把二维写死到公共模块 |
| 视图驻留 | 每次切换销毁重建；首次访问后缓存、隐藏时暂停 | 建议缓存已创建视图，页面卸载时一起释放；验收时记录内存代价，再决定是否需要回收策略 |
| 模块位置 | 接入同时拆包；先放 `libs/map-cesium` | 先留在 libs，现有依赖方向已容纳它；拆包不作为三维接入的前置任务 |

## 建议决定

### 1. 首期范围和版本

- 3D.1～3D.4 完成底图、行政区、业务资源、已有符号、选择高亮、区划裁剪、定位与椭球面测量的三维显示及二三维切换
- Cesium 从 ADR 0002 指定的 `1.145.0` 开始，精确锁定；3D.0 只借用旧项目已安装的包作检查，没有修改本项目依赖
- 地形、本地 3D Tiles、白膜、钻地、漫游、室内地图以及空间/贴地测量分开定范围，不能因为已有旧代码就自动进入首期
- 新增三维状态栏内容或独有功能面板，仍先出设计稿确认

### 2. 状态、运行时与切换

- 会话仍是唯一真相源。map-cesium 镜像样式、读写相机、适配输入/拾取/投影，不另存资源勾选、年份、符号或选择列表
- app 管部署配置和运行时装配，map-vue 动态加载 map-cesium；沿用 ADR 0061 的路由包装和预加载入口
- 建议由 map-vue 的切换拥有者缓存视图，现有上下文只暴露当前活动视图。目标视图准备时不接收输入，准备完成后再交接；失败保留原视图，晚到的切换结果不得覆盖较新的意图
- 隐藏视图不实时跟随；恢复时先调整尺寸，再应用最新会话。三维精确视角是否还原按隐藏期间的相机 `cause` 判断，不恢复旧的时间窗口或 `intentRevision`
- 视图切换丢弃鼠标提示和框选草稿，保留测量已确定的点。目标不支持的工具暂停，不能用切回浏览工具来间接清掉状态

### 3. 样式与查询

- 按 3D.0 的支持矩阵逐项实现。表达式与过滤继续由 style-spec 求值；相同语义不等于相同像素，抗锯齿等差异单独验收
- 花纹、虚线、透明度、层序、年份和选择身份影响业务含义，不能静默改为默认色或实线。阶段中尚未支持的能力应明确标记，不能计为现状底图三维验收完成
- 查询继续按 ADR 0047～0050：三维 `queryRendered()` 返回空数组，登记的数据集由后端识别。原生 MVT 的 SDK 拾取能力不自动改变项目契约
- ADR 0021 的瓦片数据服务仍可作为以后补齐三维查询的基础；要扩大查询范围或改变框选估数规则，另写 ADR，不恢复旧项目的隐藏二维查询依赖
- 区划裁剪仍按几何，三维不能直接照搬二维世界矩形的遮罩。显示和查询必须使用同一 `readyBoundary`；球面遮罩的实现与验收在 3D.3 单独落实

### 4. 验收和未定事项

- 每步的交付、学习点和验收条件见 3D.0 记录；首期完成需验证切换、失败恢复、样式效果、工具状态和资源释放
- Cesium 的 Workers、ThirdParty、Assets、Widgets 纳入本地部署，内网不因 SDK 默认配置产生公网请求
- 栅格化的缓存键、取消和数据所有权沿用 ADR 0025；Worker 数量、内存预算、图层合成粒度和重复下载策略由真实任务决定
- 保留上一轮二维修复的回归和性能复测待办；构建通过不能代替这些验收

## 后果

- 业务拥有者与页面状态可以继续复用，先把两个视图的生命周期和职责验证清楚
- 首期需要实现矢量瓦片栅格化，原生 MVT 暂不能省掉这部分工作；旧 Worker 的算法可以参考，手写表达式求值器和模块级全局池不照搬
- 缓存两个已创建的视图会增加内存与显存占用，必须在三维验收中记录
- 原生 MVT 若后续能满足样式、层序和规模要求，再用独立 ADR 评估替换或增加使用场景
