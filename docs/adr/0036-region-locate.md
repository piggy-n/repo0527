# 0036. 区划定位：本地区划目录、边界的加载与定位

- 状态：已接受
- 日期：2026-10-10
- 补充 ADR 0033（边界数据）与 ADR 0034（工具栏）；ADR 0031 预留的天地图行政区服务 key 不再需要

## 背景

5B.5 做区划定位：选一个市或区县，地图定位到它并高亮边界。

旧项目（yzt `master-demo` 836f03b）的行为：

- 面板列出 13 个市；点一个市，下面列出它的区县；搜索框按名称或"省 / 市 / 区县"路径匹配，精确匹配在前，最多 20 条
- 选中后取边界、定位（四边留 96 像素，1100ms，最大 14.5 级），用红色光晕（8 宽、模糊）加实线（2 宽）高亮边界，并在行政中心显示名称标签
- 再点已选中的市退回全省，再点已选中的区县退回所在的市；从市或区县退回全省时清掉高亮，回到页面的初始视角
- 新版页面里关闭面板不清掉选择（`independentPanelVisibility`）；区划裁剪也挂在这次选择上（5C.7）

读代码时发现：

- 面板的区划列表来自 `region.js`，其中无锡 5 个区、南通 4 个、淮安涟水县的代码是旧的或错位的（如梁溪区写成 320205，那是锡山区的代码）。找边界时先按代码、再按名称匹配，所以选梁溪区高亮的是锡山区，选新吴区高亮的是惠山区
- 找边界时先查本地的市界、县界数据（`preferLocalBoundary: true`），查不到才请求天地图行政区接口。本地数据覆盖全部 13 个市、95 个区县，接口实际不会被请求
- 名称标签的坐标表 `regionLabelPoints.ts`（109 条）用的是现行代码，代码和名称与 5B.2 生成的边界数据逐条一致
- 标签用文字图层画，需要样式提供字形文件（`glyphs`）；新项目的样式没有，内网也取不到外部的字形
- 坐标定位在旧项目里只是占位按钮，点击只会关掉区划面板，另行设计

## 候选方案

| 问题 | 候选 | 选择 |
|---|---|---|
| 区划目录 | 迁移 `region.js`；从边界数据生成；用标签坐标表 | 标签坐标表：代码现行、顺序经过整理；用测试保证它和边界数据一致 |
| 边界来源 | 天地图行政区接口，本地数据兜底；只用本地数据 | 只用本地数据：本地数据完整，内网可用，不需要第二个 key |
| 名称标签 | 文字图层；DOM 浮层；不迁移 | 不迁移：旧效果一般，天地图注记已经显示地名；以后需要时在 5D 重新设计 |
| 工具栏上的面板开关 | 第三种表项"开关"；动作加上按下状态 | 动作加上按下状态：和动作只差显示，不值得多一张表 |
| 定位时的俯角 | 保持（旧）；归零 | 归零：MapLibre 6 的 `fitBounds` 按俯角 0 计算缩放，保持俯角时区划可能显示不全 |

## 决定

### 1. 区划目录

- `shared/map/region/data/jiangsu-regions.json` 由旧项目的标签坐标表转换，只保留代码（6 位）、名称、级别（市、区县）和所在的市；顺序沿用原表
- 测试检查目录和边界数据逐条对应：每个市、区县在市界或县界数据里都有同代码、同名称的要素，数据里的每个要素也都在目录里
- 纯函数提供市的列表、某个市的区县、按代码查找和搜索（规则同旧项目）；"全省"不是目录里的一项，没有选择就是全省

### 2. 边界的几何

- 用 `fetch` 取 5B.2 的市界、县界文件（同一个 `?url` 地址，命中 HTTP 缓存，ADR 0033 第 4 条），解析结果按地址缓存，同时发起的加载共用一次；失败不缓存
- 按代码取要素：市界的代码是 12 位、取前 6 位，县界的代码去掉 `156` 前缀。一个区划有多个要素时（连云港）合并成一个 `MultiPolygon`
- 外包范围用一个小函数从坐标算出，不为它引入 turf

### 3. 拥有者 `useRegionLocate`

- 页面调用 `useRegionLocate(map, { goToDefaultView })`，状态是已选的区划和边界的加载状态（加载中、成功、失败，失败原因是数据）
- `select(code)`：换选时取消上一次加载，作用域销毁时也取消，晚到的结果不写入状态；边界到位并且视图就绪后定位一次：`fitBounds(范围, { duration: 1100, maxZoom: 14.5, pitch: 0 })`，四边的留白由登记的悬浮元素决定（ADR 0029），不再写死 96 像素
- `select(null)` 回到全省：清掉选择和高亮；之前选过市或区县时调用页面传入的 `goToDefaultView`
- 加载失败时可以重试；加载中不显示上一个区划的高亮
- `deriveGroup` 推导 `region` 分组：光晕（`#FF0000`，宽 8、模糊 5、不透明度 0.8）和实线（`#FF0000`，宽 2、不透明度 0.9）；没有边界时是空分组。叠放在边界之上、测量之下

### 4. 面板与工具栏

- `RegionLocatePanel` 是联调用的界面，通过 props 拿到拥有者；面板里"再点已选中的退回上一级"由纯函数把点击换成 `select` 的参数
- 面板登记为贴右边的悬浮元素，定位时避开它
- 工具栏的动作增加按下状态：页面通过 `pressed` 告诉工具栏哪些动作显示为按下，工具栏不保存面板开关；区划定位按钮开关面板，和当前工具互不影响（ADR 0034）。关闭面板不清掉选择

## 后果

- 好处：区划列表和边界来自同一套代码，旧项目高亮错区县的问题随之消失；内网可用，不需要天地图行政区服务
- 好处：区划裁剪（5C.7）读取同一个拥有者的选择和几何，不再另外加载
- 代价：第一次按市定位要下载并解析 1.4 MB 的市界（之后用缓存），在主线程解析，浏览器验证时实测耗时；县界简化过，高亮和县界线一样，放大后与市界对不齐（ADR 0033）
- 代价：选中的区划没有名称标签
