# 0121. 城市国土空间监测指标AI计算：自定义监测范围

- 状态：已接受
- 日期：2026-10-31
- 修改：ADR 0105 的计算条件（监测范围只能选市）、ADR 0108 的结果排行

## 背景

监测范围原来只能在 13 个市里选。用户 2026-10-31 要求增加自定义范围：上传 Shapefile 或 GeoJSON、在地图上绘制和编辑，AI 分析范围涉及的省、市、县和覆盖方式（全部 / 部分），自定义范围参与计算并与条件配置、地图、结果同步。交互方案先做了原型 v6（`apps/web/public/design.local/indicator-simulation-v6/`，不入库），用户确认按推荐方案开发，并要求补全文件校验、绘制限制、大范围的分级展示、覆盖关系的边界情况和性能。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 入口 | 只在监测范围；只在 AI 对话框；两处联动 | 两处联动：监测范围是主入口（上传、绘制、编辑、移除、切换）；对话框只放"上传范围"附件按钮和范围卡片——上传像对话里加附件，绘制不是说话能完成的动作 |
| 编辑的地方 | 主区就地换成地图；弹窗 | 弹窗：条件配置阶段没有地图（地图在第一次计算完成时创建），弹窗有明确的确定 / 取消，草稿不影响已有条件 |
| 条件里的范围 | 保留 `cityCodes`，另加可选的 `area`；判别联合 | 判别联合 `scope: { kind: 'cities' } \| { kind: 'area' }`：两种范围互斥，类型上表达得出来；"涉及哪些市"用 `scopeCityCodes` 取 |
| 两种范围之间切换 | 切换时清掉另一种；各留一份 | 各留一份：编排里另存没在用的那种（`altScope`），切回来时恢复 |
| 部分覆盖的区县怎么算 | 按区县整体算；按范围内面积占比折算 | 折算：区县的值不变（模型按区县算），汇总权重（住宅用地、面积、人口）乘以面积占比；人口、用地、设施点同样只算范围内的部分 |
| 全部 / 部分 / 边界相交的判定 | 只看面积比例；比例加周长带 | 比例加周长带：县界简化过（95 个区县约 8400 个节点），精确的边界和它有出入；判定规则见下文 |
| 分析在哪里算 | 主线程；Worker | Worker：几十万个节点的整理和求交要几秒，在主线程会卡住页面；用 `@yzt/utils` 的通信层 |
| Worker 放在哪 | libs；shared | `shared/map/area/`：读文件、整理范围、求交不属于某个业务域，是项目级的地图能力；这些模块只用相对导入和 npm 包，按 `tsconfig.worker.json` 检查（此前的文档写"Worker 入口只放在 libs 里"，是因为 Worker 的检查没有 `@/`，不依赖 `@/` 的 shared 模块同样可以） |
| 解析 Shapefile | 自己写；shpjs；shapefile | shpjs 6（MIT）：读 .shp，按 .prj 用 proj4 转为经纬度；不带类型声明，只声明用到的 `parseShp` |
| 读压缩包 | shpjs 自带的解压；fflate | fflate 0.8（MIT，依赖树里已有同版本）：先只读目录、按解压后的大小拦下过大的压缩包，再解压用得上的文件；能分别说明缺 .shp、缺 .prj、几个图层 |
| 自相交、重叠 | 拒绝；修正 | 修正并提示：自己和自己求交（`@turf/intersect`）得到有效的面，不另加 `@turf/union` |

## 决定

1. **入口**：条件库"监测范围"分"行政区划 / 自定义范围"两种；自定义范围没有时是"上传文件""地图绘制"，有了是范围卡片（缩略图、名称、来源、涉及的市县、面积、估算人口，编辑 / 重新上传 / 移除）。条件配置图的范围节点可以点开编辑。对话栏有"上传范围"，有自定义范围时输入框上方是范围卡片；指令里说"自定义范围""上传的范围""绘制的范围"时用自定义范围，说出城市名时改为行政区划（自定义范围保留）
2. **弹窗**：地图（工具：上传文件、绘制多边形、绘制矩形、编辑节点、撤销、清除；文件也可以拖到地图上）和右侧的"AI 范围分析"（分步的进度、摘要、四个数、提示、按省 → 市 → 县分级的列表，可以按覆盖方式筛选、搜索、展开）；确定后才写入条件
3. **限值**：文件（一组 Shapefile 合计）不超过 50 MB，压缩包解压后不超过 200 MB；节点不超过 50 万个；面积不小于 1 公顷、不大于 15 万平方千米；逐点编辑最多 1000 个节点。节点多于 5000 个时，按约 1 米起、最多约 100 米的容差逐步简化后再分析，并提示精度和面积变化
4. **覆盖判定**（`COVER_RULES`）：交集小于 1 公顷，或平均宽度（2 × 面积 ÷ 周长）小于 25 米的细条，算边界相交（未覆盖；范围本身平均宽度不到 300 米时不按宽度判断）；行政区在范围外的部分不超过"面积的 0.5%"与"周长 × 25 米"中大的一个，算全部覆盖；其余是部分覆盖。不在任何区县里的面积同时超过 0.1 平方千米和范围的 0.5% 时算省外，不参与计算
5. **计算**：区县的值不变，汇总到市、范围时权重乘以面积占比；结果的排行一个市时列区县（标全部 / 部分），跨市时列市、点一个市看它的区县；地图只显示范围内的部分，范围外遮罩，范围边界虚线
6. **逐点编辑**需要按在节点上时由工具接管拖动，map-core 的改动另见 ADR 0122

## 后果

- 新增依赖 shpjs、fflate；`tsconfig.worker.json` 加上 `src/shared/map/area/shpjs.d.ts`
- 计算条件的形状变了，编排、指令、对话、预估、流程图、结果、地图都按范围的种类处理；只按行政区划时的行为不变
- 范围在条件里带着覆盖分析的结果（确定时算好），计算和显示直接用，不重复求交
