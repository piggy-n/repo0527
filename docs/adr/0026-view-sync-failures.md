# 0026. 视图同步的失败处理：错误事件、加载失败与恢复

- 状态：已接受（第 4 条"原因从 `whenReady()` 取得，不另加 API"由 0030 修正）
- 日期：2026-10-09
- 修正 ADR 0022 第 4 条"整体重建后把当前快照记为已应用"，以及第 5 条中 `failed` 的含义（见下文第 2、4 条）

## 背景

阶段四结束后的独立评审指出，二维视图（`MapLibreView`）在两种情况下会和会话状态长期不一致。在 MapLibre 6.12 的源码中逐一确认，并写出了在原实现上失败的测试：

- **整份样式校验失败时卡住**：`Style._load` 先校验整份样式，失败时只触发 `error` 事件，然后直接返回，不会触发 `style.load`。视图一直停在 `initializing`，`whenReady()` 永远不结束；之后即使修正了配置，视图仍在等 `style.load`，不会再处理样式变化。适配器自己的整体重建（`setStyle(…, { diff: false })`）走的是同一条加载路径，运行中重建失败也会这样卡住
- **方法失败但不抛错**：`addLayer` 遇到校验失败、图层重名、前置图层不存在，`addSource`、`setPaintProperty`、`setFilter` 遇到校验失败，都只同步触发 `error` 事件，不抛错。原实现只在抛错时重建，于是把图层根本没有加上的版本记为已应用，之后的增量更新都建立在错误的记录上

ADR 0022 只考虑了"命令抛错"一种失败，并且在发起整体重建时就把当前快照记为已应用，没有考虑整体加载本身也会失败。

## 决定

### 1. 加载失败是一种明确的结果

地图上的样式有三种结果，每种都对应一个快照版本：

| 结果 | 含义 |
|---|---|
| 加载中 | 正在整体加载某个快照（创建地图、整体重建、重新加载） |
| 已加载 | 已应用到地图的快照，增量更新和追上都从它对比 |
| 加载失败 | 这个版本整体加载失败 |

加载中收到 `error` 事件，就判定这次加载失败。以 `style.load` 为准：如果之前的错误并不致命、`style.load` 仍然到达，照常完成加载。

### 2. 应用增量命令期间的 `error` 事件同样算失败

应用一次通知的命令期间，同步收到的 `error` 事件说明地图和记录可能已经不一致，和命令抛错、命令不支持一样，命令应用完后用当前快照整体重建。

"已应用"只在两种时候更新：一次通知的命令全部成功应用，且期间没有 `error` 事件；或者整体加载完成（收到 `style.load`）。**修正 ADR 0022 第 4 条**：发起整体重建时不再把当前快照记为已应用。

### 3. 每个版本最多整体加载一次

加载失败后，只有会话中出现更新的版本才重新整体加载；暂停、恢复、之后的其他错误事件都不会触发。增量更新出错只会触发一次整体重建，重建失败就停在"加载失败"，所以不会无限重建。

视图处于暂停意图时也照样重新加载，和以 `active: false` 创建时照常加载一致（ADR 0020 第 7 条：三维期间二维仍充当查询后端）。

### 4. `failed` 分两种，样式失败可以恢复

**修正 ADR 0022 第 5 条**：`failed` 不再都是终止状态。

| 原因 | 例子 | 恢复方式 |
|---|---|---|
| 引擎失败 | 不支持 WebGL2（`GPUInitializationError`）、`setStyle` 本身抛错 | 不能恢复；释放后重新创建视图。之后的样式变化、`error`、`style.load` 都不再改变状态 |
| 样式失败 | 整份样式通不过校验 | 样式出现新版本时自动重新加载：`failed → initializing → ready`（暂停意图时为 `paused`） |

两种失败共用 `failed` 状态，原因从 `whenReady()` 取得，不另加 API。`whenReady()` 表示当前这一轮加载的结果：失败后重新加载、或运行中重建失败时，它早已有了结果，这时换一个新的 Promise；先换 Promise 再发出 `statechange`，监听者拿到的就是这一轮的。

### 5. 一个图层不合法，整个视图进入 `failed`

这是"从完整快照恢复"的直接结果，与首次加载的行为一致：MapLibre 校验不通过时拒绝整份样式。地图状态始终等于某个快照，不会出现记录之外的状态。

| | 本决定：整体失败 | 保留残缺的地图，标记为不一致 | 跳过出错的图层 |
|---|---|---|---|
| 地图状态 | 等于某个快照，或空白 | 记录之外的状态，直到下一次变化 | 视图自行改写了会话状态 |
| 和首次加载一致 | 是 | 否 | 否 |
| 用户看到的 | 空白地图和错误 | 少一个图层 | 少一个图层 |

代价是一个坏图层会让整张地图空白。图层配置由后端驱动后（阶段五），由业务图层的拥有者在配置变化时校验自己的分组，坏配置不进入会话；只在配置变化时校验，不在每次提交时校验（高频更新下的耗时见 [modules/map-core.md](../modules/map-core.md)"测试"）。

## 后果

- 好处：初始化失败、运行中重建失败都有明确的状态和原因，修正配置后自动恢复；SDK 只发事件不抛错的失败也能发现；不会无限重建
- 代价：一个不合法的图层会让整个二维视图进入 `failed`；视图内部多了"地图上的样式"这一层状态
- 仍然存在的风险：MapLibre 在校验通过之后的加载过程中抛出的异常，会被它自己静默吞掉（`loadJSON` 的 `.catch(() => {})`），既没有 `error` 也没有 `style.load`，视图会停在加载中。拿不到信号，暂不处理；`StyleModel` 提交前的结构校验（ID 重复、数据源不存在等）能挡住大部分
- 同一轮评审的另外两项不改变已有决策，只是补上实现：首次进入 ready 与恢复显示统一同步相机（ADR 0024 第 6 条的范围内）；Worker 一侧的 `messageerror` 按崩溃处理（ADR 0025 第 2 条已有规定）
