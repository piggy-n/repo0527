# 0157. 资源图层面板改成"资源目录 + 当前图层"，二三维共用，三维里照常显示和点选资源图层

- 状态：已接受（2026-11-14 用户确认原型和 17 项，第 1 项点到模型时的规则选甲；同一天分步实现。2026-11-15 用户看过实现后提了 7 条修改意见，第 7 条"三维模式优先体现三维模型"选了原型里的方案乙，一并记在这里）
- 日期：2026-11-14
- 取代：ADR 0118（目录树的顺序就是叠放顺序）；ADR 0081 第 7 节"三维时左侧换成三维模型面板"
- 修改：ADR 0153 第 4 条（app 注入的三维能力不再收窄）；ADR 0080 第 5 节（三维里的点/框选和图例恢复正常）
- 补充：ADR 0048、0049（恢复三维的识别规则，加上点到模型时的规则）；ADR 0042（资源图层的偏好多一项"已加入"）；ADR 0054（两组各自拖动排序）；请求状态见 ADR 0158

## 背景

改版前的现状底图（2026-11-13）：

- 二维时左侧是资源图层面板：目录树勾选即显示，下面的"已选择图层"按叠放顺序列出勾选的资源。目录树的顺序就是叠放顺序（ADR 0118），"已选择图层"跨分类移动时整个分类一起挪。
- 三维时左侧换成三维模型面板（ADR 0081 第 7 节），勾选即加载。
- 三维里不显示资源图层、点/框选不识别：app 注入的引擎能力把 `styleLayers`、`identify` 收成 false（ADR 0153 第 4 条）。用户 2026-11-09 的决定是"放开前先重新设计页面"。

用户 2026-11-13 要求重新设计这块面板：一个面板二三维共用，同时管二维图层和三维模型。原型在 `local/design/current-map-layers/`（不入库，`DESIGN.md` 记了每一句反馈怎样落到原型上）。2026-11-14 用户确认的 17 项里和架构有关的有：

- 面板分两段：上段"资源目录"找资源、加入和移出，下段"当前图层"管地图上的图层；加入和显隐分开。
- 新加入的放在所属组的最上面；一次加入几个时整批放在最上面，批内保持目录的先后；移出后再加入也放到最上面。
- 当前图层分"二维图层""三维模型"两组。二维里模型组变淡、标一次"仅三维"；二维里不能定位模型（用户的原话是"肯定不能定位"），其余怎样表现交给会话定。
- 行里只放漫游、重试、移除三种操作；透明度、图例、上下移、定位在工具栏和右键菜单里。
- 三维模型以后都不支持点选、框选；三维模式下二维资源图层照常点选、框选。
- 点到模型上时用规则甲：查模型脚下。
- 老用户以前勾选的资源算作已加入，顺序不变，偏好不升版本；新用户只加入地类图斑。三维模型的列表不持久化。

点到模型上时，原来的代码有两处说法不一（2026-11-14 核实）：

- `MapLibreView.pick` 先打模型，打到了返回模型表面那一点的经纬度。后端识别用它，查到的是"模型脚下"。
- `queryRendered` 把屏幕点交给 MapLibre，只认地面。渲染要素查到的是视线穿过模型以后落到的地面，也就是"模型后面"。
- 视角越斜、模型越高，两处离得越远。线、点的容差框和框选的四角也用 `pick`，落在模型上时同样偏。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 面板的结构 | 保留"目录树勾选即显示 + 已选择图层"；改成"资源目录 + 当前图层"两段，加入和显隐分开 | **两段。** 用户确认的原型。隐藏的图层留在当前图层里，透明度、年份、顺序还在 |
| 叠放顺序 | 目录树的顺序就是叠放顺序（ADR 0118）；当前图层有自己的顺序，和目录脱钩 | **当前图层自己的顺序。** 新加入的要放在最上面，目录的顺序要稳定，两者不能是同一份 |
| 二三维 | 各一个面板，切换时换；一个面板两组 | **一个面板。** 用户的要求；切换维度时搜索、展开、选中这些界面状态自然保留 |
| 二维里的模型行 | 只是不能定位、不能漫游，其余照常；整组禁用 | **只是不能定位。** 目录在二维里也能加入模型，下面的行不能操作时加错的只能回目录移除；二维里就能把模型整理好；用户不用记两套规则 |
| 三维里怎样先体现模型（2026-11-15 用户的第 7 条） | 甲：三维里"三维模型"分类排到目录最上面、当前图层模型组在上；乙：三维里目录分"三维模型""二维资源"两页，当前图层同甲 | **乙**（用户 2026-11-15）。甲只换顺序，二维的分类一展开模型就被挤到一小段；乙让三维里的目录就是模型列表，二维资源随时能切过去。代价是多一个控件，三维里加二维资源要先切页 |
| 点到模型上 | 甲：查模型脚下；乙：穿过模型，查后面的地面；丙：挡住，不识别 | **甲**（用户 2026-11-14）。点在楼上的人想知道的通常是"这里是什么地"；乙查到的东西被模型挡着、看不见；丙在白模、倾斜摄影铺满城区时基本点不了 |
| 面板代码放在哪 | 一个 feature；`shared/map/layer-panel` 放和业务无关的部件，页面拼起来 | **shared 加页面。** 面板同时用到 `resource-map`、`scene-models`，feature 之间不能互相导入 |
| 偏好 | 升版本号；不升，没有"已加入"时按勾选算 | **不升。** 升版本会把别人存下的偏好当成没存过 |

## 决定

### 1. 资源目录和当前图层

- 资源目录：标题右边常驻添加、移除、全部展开、全部收起；只有项能选中，Ctrl、Shift 多选，分类单击是展开、收起（2026-11-15 用户：父节点不支持选中）；行尾一列平时是分类的项数、已加入的项的勾，悬停时换成添加或移除（分类作用于下面全部的项）；双击已加入的项，在当前图层里选中、滚到中间、闪两下；右键菜单是添加、移除、定位（右键分类时作用于它下面的项，没有定位）。添加在选中的项都已加入时不可用，移除同理。
- 二维里三维模型是目录最后一个分类，下面按市分组，名称后面是类型；关键字匹配模型名、市名或"三维模型"。
- 三维里目录分"三维模型""二维资源"两页（2026-11-15 用户选的方案乙），进入三维时回到"三维模型"页。三维模型页直接按市分组（没有"三维模型"这一层），第一次显示时各市展开；"筛选年份"的位置换成类型筛选（全部类型和清单里有的类型）。二维资源页就是二维的目录。搜索只搜当前页，另一页也有匹配时列表下面提示"三维模型里还有 N 项匹配"，点了切过去；换页、换类型后看不见的项不再算选中。页和类型是界面状态，不持久化。
- 当前图层：只能单选。一行依次是手柄、复选框、符号、名称、紧跟名称的状态、行尾的框（年份、白膜的效果、"漫游"，宽度一样）、移除。
- 工具栏七个按钮：上移、下移、置顶、置底、透明度、图例、移除（2026-11-15 用户把定位换成移除；定位在双击、回车和右键菜单里）。模型没有透明度和图例；模型的移动只改列表的先后，遮挡按模型在空间里的位置。
- 当前图层里只有二维图层或只有三维模型时不显示组标题（2026-11-15 用户），这一组一直展开。三维里三维模型组在二维图层组上面，上下方向键也先走模型；二维里二维图层在上（方案乙）。
- 透明度、图例是两个独立的浮层，开在面板右边，箭头对着选中的行。图例浮层和右侧的"图例"页共用 `LayerLegend`；浮层编辑某个资源时，右侧图例里这个资源回到浏览，避免两个取色器对着同一个目标。
- 二维图层没有范围数据（后端给不出），"定位"只在没到最小显示级别时放大到那一级（第 5 条，不记 backlog）。

### 2. 状态：加入和显隐分开

- 资源图层的显示状态多一项 `added`。地图上画的是"已加入、显示着、到了最小级别"的资源（`isDrawn`）。`order` 仍然包括全部资源：已加入的在前、按当前图层的先后，其余按目录的先后排在后面。`withAdded` 把没加入过的整批放到最前。
- 偏好里没有 `added` 时按 `checked` 算，版本号不变。
- 三维模型的拥有者把"勾选的先后"拆成 `added`（新加入的在最前）和 `hidden`。隐藏用三维内容已有的 `show: false`，数据留着，再显示时不重新下载。加入、移出、显隐、移动是 `add`、`remove`、`setVisible`、`moveModel`。
- 三维里加入后等就绪飞过去，不看已经加入了几个；二维里只进列表，切到三维时也不飞。定位在模型还没就绪时等就绪再飞；二维里、隐藏着时不能定位。模型列表照旧不持久化。

### 3. 二三维共用一个面板

- 现状底图左侧一直是这个面板，只有漫游时换成漫游面板（`KeepAlive` 缓存面板，退出漫游原样回来）。漫游面板的收起不持久化，每次漫游从展开开始。
- 模型清单进页面就读：目录里要列出模型，二维里也能加入。清单读不到时在目录最后提示，可以重试。
- 二维里模型组变淡（符号、名称 50% 透明），组标题旁标一次"仅三维"；定位、漫游不可用，悬停提示"切换到三维后可用"；勾选、排序、移除、换效果照常。
- 上下方向键在两组之间连着走，只走展开着的组。

### 4. 三维里照常显示、点选资源图层

- app 注入的三维引擎不再收窄能力，`styleLayers`、`identify`、`splats` 都是 true。资源图层、图例、点/框选在三维里和二维一样，没有开关。
- 恢复 ADR 0048、0049 里三维的识别规则：登记的数据集在三维里一律查后端（倾斜视角下瓦片的级别是混着的）。
- 模型永远不是点/框选的结果。点到模型上时查模型脚下：命中点正下方的地面投影回屏幕，渲染要素、线和点的容差框都围着这一点；容差框和框选的四角、像素大小用只打地面的拾取。
- map-core 的 `PickOptions` 加 `ground`：只打地面，跳过模型和泼溅。二维、没有模型的引擎忽略它。
- 去掉三维里不识别的分支和"三维模式暂不支持点/框选"的提示。

### 5. 代码的位置

- `shared/map/layer-panel`：和业务无关的部件。面板外壳（两段和分隔条）、目录树（多选、键盘）、当前图层的一组（选中、键盘、拖动用 `useSortableList`）、工具栏、浮层、右键菜单、行的公共样式，以及目录的选择、节点和浮层位置这几个纯函数。
- 各 feature：目录节点和行的内容。`resource-map` 有 `ResourceLayerRow`、`LayerLegend`、`LegendSettings`（从 `ResourceLegend` 拆出）、`BatchYearSelect`；`scene-models` 有 `ModelLayerRow`。
- `pages/current-map/layer-panel/CurrentMapLayerPanel`：把两边拼起来，按选中项的种类把工具栏、菜单的操作交给对应的拥有者。选中、浮层、菜单这些界面状态在这里，不持久化。
- 旧的 `ResourceLayerPanel`、`CheckedLayerList`、`ResourceTreeList`、`SceneModelPanel`、`catalog-order` 删掉。

### 6. 这次不做的

- 标注（用户确认本次不做）。
- 三维模型的"细节加载中还有几块"：要改三维的契约，往后放（`docs/backlog.md`）。

## 后果

- 加入和显隐分开以后，隐藏的图层保留透明度、年份和顺序；目录的顺序稳定，不再因为调叠放顺序而变。ADR 0118 的"跨分类整组挪"随之没有了。
- 三维里同时画资源图层和模型、还要点选，帧率只能在显卡机器上测（`measure:3d`，用户在 RTX 3060 上跑）。
- 点到模型上时，高亮画在地面上，大部分被模型挡住；想看清可以在当前图层里先隐藏模型。斜着看时，"脚下"不是视线落到的地面。
- 界面细节记在 [current-map-reference.md](../design/current-map-reference.md)"已确认的界面细节"，组件用法见 [shared-map.md](../modules/shared-map.md)"资源图层面板"。
