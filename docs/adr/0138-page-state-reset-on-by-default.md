# 0138. 离开页面后重置：`.env` 提交的取值改为 true

- 状态：已接受
- 日期：2026-11-04
- 修改：ADR 0114 的默认取值（`.env` 写 `false`）；开关本身和两种取值的行为不变

## 背景

ADR 0114 加了开关 `VITE_PAGE_STATE_RESET`，`.env` 写 `false`，默认保留页面状态。提交 `e754bb0`（2026-10-29）把 `.env` 改成 `true`，说明是"为了一致的初始状态"，但 ADR 0114 仍写着默认 `false`，一直没有决策记录。

用户 2026-11-01 确认线上保留 `true`。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| `.env` 提交的取值 | 保留 `true`；改回 `false` | 保留 `true`：用户确认 |
| 内网是否单独写 | `.env.intranet` 继承；单独写一个值 | 继承：`.env.intranet` 现在就不写这个变量，用户没有提出要区分 |
| 页面缓存的代码 | 保留；随 `true` 一起删掉 | 保留：开关仍是部署时决定的，设成 `false` 构建时要照常工作，所以两种取值都继续测试 |

## 决定

- `.env` 提交 `VITE_PAGE_STATE_RESET=true`，公网、内网都用这个值
- 路由 meta 的 `keepAlive`、`AppLayout` 里的 `KeepAlive` 和 ADR 0063 的页面缓存保留，只在构建时设成 `false` 才生效
- 测试不依赖 `.env` 的取值：单元测试显式传入或用 `vi.stubEnv` 固定；生产冒烟用 `loadEnv` 读构建用的取值，验证对应的行为。开关打开期间，CI 的冒烟跳过关闭时的用例，需要时另做一次关闭开关的构建来跑

## 后果

- 现状底图、指标 AI 计算每次进入都重新创建地图（ADR 0114 估计约 1～2 秒、重新取瓦片），计算到一半离开会丢掉这次计算
- 现状底图每次进入都是矢量底图，底图的选择不读不写偏好；资源图层、符号、行政区等其余偏好照常恢复
- 文档里讲页面缓存的行为（如 ADR 0063、指标 AI 计算的"页面缓存期间推演暂停"）都是 `false` 时的行为，线上默认不会走到
