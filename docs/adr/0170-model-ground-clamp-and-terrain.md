# 0170. 三维模型贴地（清单的地面点）和天地图地形：两个 .env 开关

- 状态：已接受（2026-11-23 用户要求：新增配置开关，控制三维模型是否统一贴地；没有地形时贴合地图引擎的表面；三维里加天地图的地形服务，效果用户自己测；贴地要兼顾不同种类的模型，重点是非高斯泼溅的。同日用户确认下面的方案，"按建议实现"）
- 日期：2026-11-23
- 补充：ADR 0147 第 4 节（抬高的坐标边界：贴地的平移同样只在渲染适配器里）、ADR 0081 第 1 节和 ADR 0149 第 3 节（清单多一个可选字段 `ground`）、ADR 0031（天地图多一种用途：三维的地形）
- 修改：ADR 0161 第 8 节的"模型按真实高度摆、二维在 0 米，斜着看会错开"：写了 `ground` 的模型贴地以后不再错开

## 背景

- MapLibre 没有地形时表面是 0 米，模型按真实的椭球高摆：徐州的模型悬在底图上方三四十米，宿迁约 20 米，斜着看错开、拖动时滑动，三维放到 20 级后近看会钻到模型的地面以下（`docs/backlog.md` 原来的"显示用下沉量"一条，用户 2026-11-11 先记下、2026-11-16 同意单独排期）。
- 用户 2026-11-23 要两样：贴地的开关（主要目的），三维里的天地图地形（留给用户自己测）。
- 任务起草时把贴地定义成"包围盒的底面落到表面"。2026-11-23 在测试服务器 192.168.1.180 上读了四个瓦片集的根索引和最粗一级内容的顶点（15.111 本机连不上）：

| 模型 | 根包围体的底面（米） | 最粗一级顶点最多的高度 | 按包围盒底面贴地以后 |
|---|---|---|---|
| 彭城广场 `xz-gc`（倾斜） | 21.4 | 33（同一处泼溅的路线入口 33.79） | 地面仍高约 12 米 |
| 宿豫区01 `sq-syq01`（倾斜） | -11.6 | 20 | 地面约高 32 米，比不贴地（约 20 米）更高 |
| 星海广场站周边白模 `sz-white` | 0.0 | 0 | 不变，数据本来就在 0 米 |
| 星海广场站 `sz-station`（地下） | -343（根节点是半径 335 米的球） | — | 不能用 |

  倾斜摄影的包围盒留了余量，也包含坑和河道；地下站、墓葬泼溅的底面是站底、墓底。包围盒的底面不是地面。
- 天地图的三维地形（调研见 `docs/modules/map-core.md`"天地图地形"）：`mapservice/swdx?T=elv_c`，经纬度分块，6～12 级有数据（12 级约 65 米一个点），每块是 zlib 压缩的 150×150 个小端 int16，面向 Cesium；MapLibre 要的是墨卡托分块的 `raster-dem`。本机访问天地图被 WAF 拦（HTTP 418），没有请求过真实瓦片，格式来自官方 Cesium 插件的解码代码（三份开源实现一致）。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 地面在哪 | 包围盒的底面；运行时读最粗一级内容估计；清单写一个地面点 | 清单写地面点（用户按推荐）：包围盒差 10～30 米；运行时估计要先下载内容、结果跟着数据变，同一处的模型也难保证一致。地面点由工具 `3dt:ground` 离线估计、人看过再写，确定、不跳 |
| 没写地面点的模型 | 按包围盒的底面贴；不动 | 不动：按包围盒贴会让宿豫区01 比现在更高；没写的和现在一样，不会更糟 |
| 高斯泼溅 | 不参与；自己估；和同一处的倾斜摄影用同一个点 | 同一个点（用户按推荐）：倾斜一下沉，泼溅不跟着就悬在它上方、裁剪也错位；墓葬的包围盒底是墓底，不能自己估 |
| 室内、地下 | 贴地；不贴地 | 不贴地，清单里不能写：本来就在地面以下，漫游时照旧抬高（ADR 0147 第 4 节） |
| 平移放在哪 | 改会话里的高度（对外是画面上的高度）；只在渲染适配器里（对外仍是真实高度） | 只在适配器里：和抬高同一个原则（ADR 0147 第 4 节），路线、出生点、导航网格、拾取都不用改 |
| 有地形时 | 按大地水准面换算椭球高；取地面点处的地形高度 | 取地形高度：数据的高程基准不清楚（`docs/backlog.md` LCC2 那条），按差值平移不用知道基准 |
| 地形的数据 | 后端转换；浏览器里转换 | 浏览器里：同服务器底图（ADR 0165）的做法，map-core 的读取器加自定义协议 |
| 开关 | 界面上的开关；`.env` | `.env`（"配置"指 `.env`，用户 2026-11-17 的约定）：`VITE_SCENE_GROUND_CLAMP`、`VITE_SCENE_TERRAIN` |

## 决定

### 1. 贴地的参照和平移

- 清单的倾斜摄影、白膜、高斯泼溅可以写 `ground: { lng, lat, height }`：模型里一处地面的经纬度和椭球高，口径同 `placement`、路线。室内的不能写，`underground: true` 的也不能写（清单的校验）。
- 同一处配准过的模型（倾斜摄影和它范围里的泼溅）写同一个点。
- 会话的 `TilesetLayer`、`SplatLayer` 有可选的 `ground`，变了重新加载（同地址、摆放）。
- 视图把模型整体竖直平移 `表面高 − ground.height`：没有地形时表面是 0 米；有地形时是 `ground` 的经纬度处的地形高度（`MapTerrain.heightAt`，读取器自己取 12 级的瓦片，不依赖视野里加载了什么）。取到以后才把模型交给渲染器，取不到时按 0 米并报告错误。
- 渲染器的 `addTileset`、`addSplat` 多一个参数 `offset`，`offsetOf(id)` 读回。

### 2. 平移只在渲染适配器里

- 拾取对外是真实高度（减回平移和抬高量）。
- 投影：抬高（含隔离）期间加上那个模型的抬高量和平移，其余时候不加。地面上的点照常按地图投影。
- 漫游：`MapLibreRoam` 的相机换算用"抬高量 + 平移"（`shift`）；抬高量按画面上的最低处算；开始步行时从地图的相机换回真实高度也减掉平移。
- 建议的相机按球心离地面点的高度算（有地形时相机的中心也在地形上）。
- 泼溅裁倾斜摄影的盒子按泼溅自己的平移放，判断重叠也按两者画出来的位置。
- 状态栏的视点高度在漫游期间减掉 `shift`，是真实高度。

### 3. 天地图地形

- map-core 的 `TiandituTerrainReader`（`tiles/tianditu-terrain.ts`）下载、解压（浏览器自带的 `DecompressionStream`）、缓存 256 块；`createTiandituTerrain` 给出自定义协议 `tianditu-terrain://{z}/{x}/{y}` 和注入视图的 `MapTerrain`。
- 协议把墨卡托 z/x/y 重采样成 256×256：用天地图同一级（夹到 6～12 级）的瓦片，经度上边界正好对齐，纬度上最多跨两块；双线性插值，编码成 terrarium，直接给 MapLibre `ImageBitmap`（不预乘、不转色彩空间）。数据源 `minzoom` 6、`maxzoom` 12，更高级别 MapLibre 放大。
- 读取器的规则沿用官方插件：超出 -2000～10000 的值当 0；解不开、大小不对时报错、带上服务器给的文字；404 当没有数据（0 米）。
- 视图只在三维、样式已加载、不在漫游接管时打开地形（`setTerrain`，夸张 1），二维和漫游时关掉；数据源 `view-terrain` 留在地图上，整体重建的样式加载完成时再加。漫游的视点在墓里、站里，有地形时 MapLibre 会把相机推到地形上面；抬高、隔离期间二维本来就隐藏。
- app 的 `pageTerrain()`（`app/map-terrain.ts`）按配置建一个、注册协议，经 map-vue 的 `MAP_TERRAIN` 注入画布。测量工具导入的 `map-runtime.ts` 不读 `appConfig`，所以不放在那里。

### 4. 开关

| 变量 | 取值 | `.env` | `.env.intranet` |
|---|---|---|---|
| `VITE_SCENE_GROUND_CLAMP` | `true` / `false` | `true` | 继承 |
| `VITE_SCENE_TERRAIN` | `none` / `tianditu` | `none`（用户测试时在 `.env.local` 改） | `none` |

- 只在 `shared/config/app-config.ts` 读取和校验；`tianditu` 要求 `VITE_TIANDITU_ENABLED=true`，否则启动就报错，不悄悄当成没有地形（ADR 0031：内网不发公网请求）。
- 贴地的开关由现状底图交给 `useSceneModels` 的 `groundClamp`，关着时会话里不带 `ground`；开发页不传，不贴地。
- `vite.config.ts` 的 `test.env` 固定贴地为 true、地形为 none：测试不请求天地图。

### 5. 叠放

- MapLibre 有地形时 background、fill、line、raster 这类图层先画进每块地形瓦片的纹理，再贴到地形网格上；模型层在中间时分成两段，下面一段被模型挡住，上面一段（选中、区划遮罩、边界、标注）照旧画在模型上面。叠放规则（ADR 0161）不变。
- 渲染器画模型前后清深度，地形挡不住模型：山后面的模型照样看得见，地下站仍像透视。要遮挡得和 MapLibre 共用深度，这次不做（`docs/backlog.md`）。

## 后果

- 写了 `ground` 的模型在没有地形时地面落在 0 米：彭城广场（倾斜和泼溅）下沉 33.59 米，宿豫区01 下沉 20.55 米，星海广场站周边白模不变。其余模型的 `ground` 要在连得上 15.111 的机器上跑 `3dt:ground` 后补上（`docs/backlog.md`），补上之前和现在一样。
- 墓葬的泼溅要等周围的倾斜摄影（模型一～七）估出地面点后，按同一处写同一个点。
- 有地形时：模型的地面按地面点处的地形高度放，地形在别的级别插值不同，可能差几米；地面点离模型中心远、地势起伏大时也会差。
- 多了公网请求：天地图的地形瓦片（每块墨卡托瓦片 1～2 块），天地图按 key 限每日次数，整个部署共用一个 key。
- 性能：每块地形瓦片多一张纹理，模型层上下各画一遍地形网格；主线程的解压、插值每块在毫秒量级。只在显卡机器上测得出。
- 未验证：真实的天地图瓦片（负高程、没有数据时服务器返回什么）、地形和模型的实际观感、性能，由用户自己测。
