# 0098. 城市国土空间监测指标：拥有者分工、计算的轮询与成果图层

- 状态：已接受
- 日期：2026-10-28

## 背景

旧页面 `views/space-monitoring-indicators/` 是一个 2116 行的 `index.vue` 加 1087 行的指标树：左栏 348 宽，选年份、监测范围和指标；"指标计算"页签多选后开始计算，底部轮询进度；"指标展示"页签单选一个算完的指标，右侧显示计算结果、图例，地图上叠加这个指标的矢量瓦片（每个子图层一个 gdb 图层）。轮询、任务快照、地图上下文恢复都写在页面里，用递增序号判断过期；图例和图层管理器各自保存颜色和显隐。

2026-10-28 只读核对了真实接口（[migration.md](../migration.md)"城市国土空间监测指标：接口实测"）：指标树的字段因分类而异（`sfjy` 有布尔也有字符串，综合分析指标没有状态和结果，有一个没有下级的空分类），展示树的分类重复出现，进度和展示树在没有数据时是 `null`，成果的几何类型字段是 `type`，后端没有成果瓦片的数据。同一天用户在 `/dev/monitoring-indicators` 确认了布局和取舍（见 migration.md"与旧页面的差异"）。

## 候选方案

1. **页面结构**：沿用旧页面的左栏加地图；套用现状底图的画布、浮动面板和右下角控件
2. **状态的组织**：一个页面级的组合式函数管全部状态；按职责分成几个拥有者，页面组合
3. **计算进度**：照旧用 `setTimeout` 和递增序号；开始计算按写操作核对会话，查进度作为可替换操作（ADR 0039）
4. **图例**：复用现状底图的图例组件；并进成果面板的子图层列表
5. **交互预览**：`public/design.local/` 的 HTML 原型；真实页面换上固定数据的接口

## 决定

1. **画布型页面**（用户确认）：地图铺满，左侧 320 宽的"监测指标"面板（标题栏切换两个页签，可以收成竖条），计算页签的进度在地图底部中间，展示页签的成果在右上，右下是视图控件和底图卡片；指标面板和成果面板用 `useMapOverlay` 登记。窄屏（小于 1200）时指标面板和底图、成果、进度只显示最后操作的一边（`useSideExclusion`），开始计算、选中指标都算操作右边；这时进度停在底图卡上方、占满中间一列（2026-10-28 在 588、375 宽下发现进度被展开的指标面板挤成窄条后补上）。底图、行政区复用 `shared/map` 的拥有者，不记偏好；分组从下到上是底图、指标成果、注记、行政区，注记和边界不被不透明的区划范围面盖住。页面不进页面缓存，离开就停止查进度（旧页面也是）
2. **四类拥有者，页面组合**（`features/monitoring-indicators`）：
   - `useIndicatorConditions`：年份和监测范围，两个页签共用；范围用区划目录（ADR 0036），默认当年、南京市
   - `useIndicatorTree`：一棵指标树的页签、加载和选择。计算树多选、跨页签累计；展示树每个页签各选一个，换条件时清空。树的数据在查询缓存里、按条件标记，选择只按编码记，新树到达时去掉不在了、变成禁用的
   - `useIndicatorCalculation`：一次只有一个计算任务，见第 3 条
   - `useIndicatorResult`：选中指标的成果、子图层显隐和临时改色，推导成果分组，选中时定位到监测范围，见第 4 条

   接口通过 `IndicatorApi` 传入，页面默认用真实接口；组件不直接请求，只显示和调用
3. **计算**：先调用处理前验证（失败按"没有结果"处理），由界面确认（已有结果时问"是否重新计算"），确认框随组件卸载关闭；开始计算是服务端写操作，按 `useSessionGuard` 核对会话，已发出的不随卸载取消。之后的查进度是这次任务的可替换操作：每个任务一个 `LatestController` 信号，开始后等 3 秒查第一次、之后每 5 秒一次；后端还没有进度（`null`）时保留上一次的接着查；连续失败 3 次停下，提示一次，标题栏里"重新获取进度"；全部处理完（`ratio` 到 100）就停。重置、新任务、页面销毁都作废上一次的查询。任务的阶段（创建、开始、查询、停下、完成、失败）是数据，面板只显示
4. **成果图层**：按展示树的记录 ID 请求成果，结果标上 ID，和当前指标不一致时按加载中处理。每个子图层一个矢量数据源（`/api/analysis/mvt/{id}/{gdbName}/{z}/{x}/{y}.pbf`，绝对地址，最高 14 级），从下到上是区划范围、面、线、点；面另加同色边线。只有一个点图层时画旗子（不能改色），多个时用不同颜色的圆点。旗子在第一次用到时按像素画出（48 × 48、像素比 2），不再带 PNG 资源。子图层的显隐按指标记，换回来时还在；改色不持久化，换指标就清掉，取色按 ADR 0044 的规则（拖动只预览，确认才改）
5. **图例并进成果面板**（用户确认）：每个子图层一行，复选框控制显隐，后面的色块就是图例，点开取色，改过的可以恢复默认；不复用现状底图的图例组件（那是按资源的统一符号、分类样式设计的，这里只有单一颜色）
6. **按实测解析数据**：`sfjy` 按真假值解析（旧页面的 `Boolean("false")` 把综合分析指标全部禁用）；没有下级、没有统计范围（`bz` 为空）的节点是空分类，不显示；同一指标挂在几个分类下只留第一次出现的；进度结果去掉"分析结果:"前缀；区划范围是名称以"范围面"结尾的面
7. **交互预览用真实页面**：`/dev/monitoring-indicators` 渲染正式的页面组件，换上固定数据的 `IndicatorApi`（延迟、失败、空树可以切换）、独立的查询缓存和总是有效的会话核对；地图、底图和行政区是真的
8. **不迁移**：只弹"开发中"的"设置"和"点击查看详情"；走不到的图层同步和 `/api/analysis/layer`；进度摘要里和表格重复的"已选指标""数据总量"；没有被引用的 `mock-data.js`；`mockIndicatorLayers.js` 只用到区划中心，改用区划边界定位

## 后果

- 页面只做组合，轮询、选择、改色的规则都在拥有者和纯函数里，用假的 `IndicatorApi` 和假定时器测试，不需要地图引擎
- 后端没有成果瓦片的数据（返回"目录不存在"），地图上的指标图层没法用真实数据验收；瓦片失败按数据源错误处理（ADR 0041），不影响页面。瓦片请求不带 token，实测不带也一样返回，等后端有数据时再确认是否要鉴权
- 综合分析指标现在可以勾选和计算，旧页面里它们一直是禁用的；后端能不能算、开始计算的成功返回长什么样，都没有实测（只读核对不调用开始计算），待联调
- 成果和进度的接口在没有数据时返回 `null`，这些情况由 schema 显式处理，不在使用处兜底
