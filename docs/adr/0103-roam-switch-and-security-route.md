# 0103. 漫游切换不飞、进站路线先过安检、漫游时覆盖物不按级别重建、脱困按钮与 AI 头像底色

- 状态：已接受
- 日期：2026-10-28
- 修改：ADR 0080 第 1 节（覆盖物换了一级就重新推导）、ADR 0083 第 3 节（开始路线时飞到起点）与"规划结果"里的进站乘车、ADR 0086 第 3 节（步行进场飞 2 秒）、ADR 0102 第 1 节（脱困是文字按钮）与第 7 节（AI 头像 `--color-primary-border` 底）

## 背景

用户在 ADR 0102 验收后提出四点：

1. 漫游面板的"脱困"不用文字按钮，改默认或警告样式，加语义明确的图标
2. "进站乘车"要从起点先经过安检机，再过闸机进站
3. 切换步行 / 路线、换一条路线时，相机先升到模型外再落下来；切换过程中报错（控制台 `[map-vue]` 的 `RangeError: Array buffer allocation failed`，栈在 Cesium 的 `createGeometry` Worker 的 `packCreateGeometryResults`），地图失败卡片的技术细节显示 `[object Object]`
4. AI 对话的机器人头像底色改成主题色

排查：

- 升到模型外：路线开始、步行进场都用 `camera.flyTo`。Cesium 的飞行路径在起点、终点的椭球高都低于"弧顶高度"（两点距离的 0.2 倍）时按幂函数先升到弧顶再落下；漫游的相机在地下（-3.5、-8.46 米），弧顶总是正的，所以哪怕原地不动也要升到地面以上（浏览器测试实测从 -4.4 升到 0）
- 报错：漫游时相机在地下，`readCamera` 用画布中心的视线打椭球求缩放级，视线从椭球内部穿出，略向下看时打到地球另一侧，略向上看时打到几公里外，级别在 3～26 之间跳。覆盖物按整数级别求值、换一级就重建（ADR 0080），实测步行时上下看几下就重建 4 次（22 个贴地线的 Worker 任务，省界一次 180 KB 输入）。反复重建贴地线时 Worker 分配内存失败，渲染出错，视图进入引擎失败
- `[object Object]`：Worker 的异常传回主线程后是只有 `name`、`message`、`stack` 的普通对象，失败卡片只认 `Error` 的 `message`
- 安检机：在步行里逐处查看并对照导航网格。X 光机在站厅北侧一条安检通道的南边（局部坐标约 x 160.8～165、y 12.4～13.8，传送带沿车站走向），通道北边是玻璃隔栏；通道东头是北侧一组闸机，通道和车站走向垂直（向南进付费区）。原来的路线走西侧闸机，不经过安检

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 脱困的样式 | 默认按钮；警告按钮 | 默认按钮：它是恢复操作，不是危险操作，警告色会让人以为有风险；和"回到起始点"（浅色主色）分出主次 |
| 脱困的图标 | `Rank`（四向箭头）；`Position`；`FirstAidKit` | `Rank`：表示"挪到别处"，`Position` 像导航，急救包太字面；补进 page-layout 的操作按钮表 |
| 已经在模型里时怎么换位置 | 限制 `flyTo` 的弧顶（直线飞）；瞬时设相机；闪切（黑幕） | 近处（不到 2 米）瞬时设相机，远处闪切：直线飞会穿墙穿楼板；瞬时跳远会迷失方向。闪切沿用步行里瞬移的黑幕（160 毫秒变黑、260 毫秒亮回），抽成 `scene-blackout.ts` 给路线和步行共用 |
| 从路线换成步行 | 去清单的出生点；原地开始 | 原地开始：`chooseSpawn` 本来就在相机已在室内时选脚下的位置（ADR 0086），所以这一步不用黑幕，直接落下 |
| 覆盖物的级别 | 只在漫游时不重新推导；级别设上限；加滞回 | 漫游时不重新推导：漫游中算出的级别没有意义（相机在地下，或者在室内看不到地面），开始漫游时的级别保持到结束；上限和滞回挡不住 3～20 之间的跳动 |
| 进站路线 | 在原路线上加一段绕到安检机；重新规划前半段 | 重新规划前半段：出生点 → 安检通道西口 → 沿 X 光机北侧穿过通道 → 北侧闸机向南穿过 → 付费区 → 原来的西侧楼梯和站台段 |

## 决定

### 1. 漫游切换不飞（map-cesium）

- 新增 `scene-blackout.ts` 的 `Blackout`：盖在画布上的黑幕；`darken(then)` 全黑时调用 `then`，`lighten()` 亮回，`clear()` 立即撤掉；`cut(distance, place)`：不到 2 米直接 `place`，远了先黑下来再 `place`、再亮回
- `SceneRoute.start`：已经在模型里（从步行换过来、换了一条路线）时不飞，用 `cut` 挪到起点；先取消上一段飞行，飞行回调只认自己的路线（原来上一段飞行还没结束就换路线时，它的取消回调会把新路线标成已落地）
- `SceneWalk.start`：已经在模型里时不飞，用 `cut` 挪到出生点；取消上一段飞行后重新关掉相机控制（取消时 Cesium 会打开）。从室外开始的漫游照旧飞进去
- 步行里的瞬移、回到起始点、脱困、点不到的闪切改用同一个 `Blackout`，行为不变

### 2. 漫游时覆盖物不按级别重建

- `CesiumView` 写回相机时，漫游中（`#roaming()`）不因为级别变化重新推导覆盖物；样式变化照常重新推导。漫游结束、被别的定位接管后照旧按级别推导

### 3. 失败卡片的技术细节

- `describeMapStatus` 的技术细节：`Error` 取 `message`；带字符串 `message` 的普通对象也取 `message`；其他转成文字

### 4. 进站乘车

- 清单 `sz-station` 的 `enter` 前 8 个点换成 6 个：出生点 → (120.6663505, 31.3176131) 安检通道西口 → (120.6664135, 31.3176149) X 光机北侧 → (120.6665412, 31.3176393) 闸机北侧 → (120.6665501, 31.3175985) 闸机南侧 → (120.6665102, 31.3175861) 付费区，接原来的楼梯和站台段；地板都是 -5.1 米
- 在浏览器里用真实瓦片建的导航网格规划：各段都能沿直线走（`walkLine`），穿闸机的一段沿车站的垂直方向（方位约 169°）选露出地板最多的通道；长度 125.2 米（原来 120.6）

### 5. 界面

- 漫游面板"脱困"：`<ElButton size="small" icon={Rank}>`（默认样式），Tooltip 不变；page-layout 的操作按钮表补"回到起始点 `RefreshLeft`""脱困 `Rank`"
- AI 对话的助手头像：欢迎语的 56 圆底、消息的 32 圆底改为 `--color-primary`

## 后果

- 换路线时黑幕约 0.4 秒，路线换成步行在原地开始、没有黑幕；从室外开始漫游、退出漫游飞回照旧
- 漫游期间省界、区划遮罩保持开始漫游时那一级的简化程度，地下空间里看不出差别
- 测试：`CesiumView` 补"漫游时覆盖物不随级别重新推导"，`describeMapStatus` 补普通对象的异常；浏览器测试补"换一条路线闪切、相机不升高"和"路线换成步行在原地开始、步行换成路线闪切"。改坏验证：去掉漫游判断、只认 `Error`、开始时照旧 `flyTo`，相应测试都以断言失败（照旧 `flyTo` 时相机从 -4.4 升到 0）
- 仍会飞到室外再飞回的情况：第一次漫游时站内空间还没分析完（"正在分析站内空间"），先切到路线又切回步行，步行要等导航网格建好才交给会话，期间撤掉路线会飞回开始前的位置。只在进入后约 3 秒内来回切换才会遇到，记为待办
- 本机内置浏览器的窗格隐藏时 WebGL 的绘制缓冲变成 0 宽，Cesium 渲染报 `Expected width to be greater than 0`，属于窗格环境，不在本次处理
