# 0173. 图层的要素过滤：按字段勾选取值，地图、标注、图例和点选用同一个条件

- 状态：已接受（2026-11-24 用户要求在"图层"里加"过滤"，参考 QGIS 的图层过滤，不要复杂的条件和操作符；看过第一版"过滤列表的行"的方案后说要的是按属性过滤要素："例如学校面，我可以只展示小学 大学，同样的，图例中如果是分类展示，也需要过滤其他属性的图层"，并同意"放不下的话可以把按钮❌移除"；第二版原型 `local/design/layer-filter/` 确认"按推荐做"）
- 日期：2026-11-24
- 修改：ADR 0157（"图层"工具栏最右的"移除"换成"过滤"；行尾的叉、Delete、右键菜单的"移除"保留）
- 补充：ADR 0041（资源的显示状态多一项 `filter`）、ADR 0042（偏好 `resource-layers` 每个资源多一项可选的 `filter`，版本不变）、ADR 0043（图例按条件只列勾着的类别）、ADR 0048（过滤着的资源照旧按它识别，后端的结果在前端按同一个条件筛，一页都不符合时接着查，最多 5 页）、ADR 0050（过滤着时框选按后端第一页的总数拦）、ADR 0123（分类字典同时是过滤的取值）、ADR 0169（条件按套）

## 背景

- 资源是矢量瓦片。前端按 `code` 登记按属性配色的规则（ADR 0123），51 个资源有分类字段和字典，图例和地图都从它推导（ADR 0043、0124）；别的属性前端只知道名字（标注字段，ADR 0160），不知道取值。
- 学校面层的分类字段 `cc` 只有"中小学""高等院校"这一级；"小学""普通高等学校本科院校"在 `type` 里（25 个取值，`probe:resource-classes` 2026-11-02 的结果）。只按分类字段过滤做不到用户的例子。
- 点选在二维 14 级以下和三维里对登记的数据集查后端（ADR 0048），后端的范围查询不能按属性筛，结果分页、带总数。
- "图层"标题行在 320、294、264 宽的面板里除了必要的间距只剩 13.4、7.4、5.4 像素（2026-11-24 在 `/dev/map-ui` 实测），放不下第 9 个按钮。

## 候选方案

| 问题 | 候选 | 选择与理由 |
|---|---|---|
| 过滤什么 | 列表的行（类型、分类、状态）；图层里的要素（按属性） | 要素：用户看过第一版"过滤列表的行"后明确（原型留在 `local/design/layer-filter/v1-list/`） |
| 取值从哪来 | 分类字典，加上探查、人确认后登记的字段；运行时从瓦片抽样；后端接口 | 第一种：纯前端；抽样只有已加载的瓦片、随视野变，ADR 0043 不在前端统计瓦片；后端没有取值接口 |
| 条件 | 选字段、勾取值（一个字段里满足一项，几个字段同时满足）；表达式和操作符 | 前者（用户：不要复杂的条件和操作符） |
| 勾选的意思 | 勾着的显示、默认全勾（同 Excel、WPS 的筛选）；勾着的才显示、都不勾等于不过滤 | 前者：复选框和地图上画的一致；悬停一项有"仅此项"，一下只看一项 |
| 入口 | 工具栏第 9 个按钮；标题下面加一行；工具栏的"移除"换成"过滤" | 换掉"移除"（用户同意）：标题行宽度不变，二维不加高；作用于选中的一行，同透明度、图例、标注 |
| 图例 | 只列勾着的类别；全部列出、没勾的变灰；不变 | 只列勾着的（用户："图例中如果是分类展示，也需要过滤"）；类别体现不了的条件写在名称下面 |
| 点选 | 照旧查后端，后端的结果在前端按同一个条件筛；过滤着的资源只用渲染要素 | 前者：14 级以下地类图斑的瓦片不带 guid（ADR 0050），只用渲染要素就完全点不到、框不到（2026-11-24 审查发现）；后端的总数是筛之前的，列表的数量写明筛到哪里 |
| 记住 | 按账号记住，资源显示状态的一项；只在页面里 | 记住（用户按推荐）：和透明度、标注一样是资源怎样显示；行上的漏斗提醒过滤着 |
| 字段登记的格式 | TS 模块，同分类字典、标注字段；JSON，部署时可以换 | TS：取值是人确认过的数据字典，和分类字典同一套流程；不随后端环境变（不同于最小显示级别） |

## 决定

### 1. 字段和取值

- `features/resource-map/filter-fields.ts` 的 `filterFieldsOf(code)`：有分类的资源第一个字段是分类字段（ID `CLASS_FIELD`，叫"分类"，地类叫"地类"），取值、名称就是分类样式的取值（`classItems`），最后是兜底的"其他"（地类是"未匹配的地类"）；地类写编码、按一级类分组，历史地类一组。
- 别的字段按 `code` 登记在同一个文件（`REGISTERED_FIELDS`，一个资源一行：属性名、叫法、取值），取值来自探查，字段的叫法和代码的名称由人确认；最后加"未列出的取值"。第一批是学校面层、学校点层的"类型"（`type`，用户 2026-11-24 确认），别的字段确认叫法后再加（`docs/backlog.md`）。取值很多的字段（名称、编号）不做成复选。
- 没有分类、也没有登记字段的资源不能过滤；三维模型没有属性过滤。

### 2. 条件和状态

- 条件是 `FeatureFilter`：字段 → 勾着的取值的键；没有的字段不过滤，全勾的字段不留，空数组是一项都没勾（这一层不画）。纯函数在 `feature-filter.ts`：整理（`normalizedFilter`：去掉不认识的字段和取值，存下的取值一个都不认识时不再过滤这个字段，免得整层消失）、换一个字段的取值、比较、条件的文字。
- 条件是资源显示状态的 `filter`（ADR 0041），拥有者的 `setFilter(code, filter)` 整理后写入，和原来一样时不替换状态；按套（ADR 0169），切换维度时各用各的；换年份、换样式方式时保留。目录（重新）到达时按现在能过滤的字段整理。

### 3. 地图、标注、点选

- 表达式（`filterExpression`）：分类字段用分类样式的匹配结构（`classExpression`，和配色同一个，地类先按编码再按名称查历史地类），登记的字段按属性的取值（`match`，列表以外的算"未列出的取值"）；几个字段 `all`。和几何过滤一起放进资源的每个图层和标注图层（`resource-labels`、`selection-labels` 都读标注目标的过滤），过滤掉的要素不画、不写标注。
- 点选、框选：照旧按 ADR 0048 识别（二维 14 级以上用渲染要素，画出来的已经按条件过滤；14 级以下和三维查后端）。后端的结果在前端按同一个表达式筛（`serverCandidates` 用 `featurePasses`，后端记录的字段和瓦片一样，2026-10-14 实测）；一页里一个都不符合、后面还有页时接着查下一页，一次最多连查 5 页（`FILTER_SCAN_PAGES`，150 个），都不符合时这个资源当作没有结果。后端的总数是筛之前的：候选全部筛完时写"共 N 个"，没筛完时写"已筛出 N 个，M 个未筛"，"加载更多"接着筛。框选时渲染要素的估数只数符合条件的，拦不住后端按范围的统计（ADR 0050）：过滤着的资源第一页的总数超过 5000 时提示缩小范围（写后端的总数），不再往下查（2026-11-24 集成审查）；单击的范围小，不拦。
- 条件变了时进行中的识别、列出的候选作废（识别目标带着识别时的条件），详情里的要素按 style-spec 求值，被过滤掉时关闭（同隐藏图层），还在时保留，但不能再返回旧的列表。

### 4. 图例

- `legendEntry` 按条件只留勾着的类别：右侧"图例"页、图例浮层、行首的摘要（ADR 0159）都只用它们，"盖住模型"的不透明度也只看它们（ADR 0161）。
- 样式设置（整层的配置、单项编辑）的类别列表不按条件，仍是全部：正在编辑的一类被过滤掉时编辑器仍对着它，过滤掉的类别也能从下拉里选来改（2026-11-24 审查发现：用过滤后的列表时编辑器会悄悄换到别的类别）。
- 类别体现不了的条件（别的字段；统一样式时、一项都没勾时的分类条件）写在名称下面一行"只显示 类型：小学、普通高等学校本科院校"（多于 4 项写前三个和项数）；过滤着的资源名称后面一个漏斗。打印的图例写出全部条件，分类字段的也写（类别只列画面里出现的，体现不了勾了哪些，ADR 0174）。

### 5. 界面

- "图层"工具栏：上移、下移、置顶、置底 | 透明度、图例、标注、过滤，少一条竖线；"过滤"打开第四种浮层（ADR 0157、0160 的浮层，宽 300），没有可过滤字段、三维模型时灰着写原因。右键菜单在"标注…"后面加"过滤…"。过滤着的行名称后面一个主色的漏斗（同"盖住模型"的位置），悬停写条件，点了打开过滤。换到不能过滤的行时浮层关闭。
- 浮层：选字段（PanelTabs 的样子，过滤着的字段后面写勾了几项；只有一个字段时只写名称）和一行说明图例怎么跟；取值多于 10 个时可以搜索；"全选"三态（搜索时只管搜到的）；取值是复选框，分类字段前面是图例的符号（统一样式时没有），地类按一级类分组、组也能勾；悬停一项"仅此项"。上面的字段、搜索、全选和下面的条件、"清空过滤"贴住浮层内容区的上下边，取值在中间滚动。细节见设计文档。

### 6. 偏好

- `resource-layers` 每个资源多一项可选的 `filter`（字段 → 字符串数组），没有时不过滤，版本不变；字段和取值不在 schema 里校验，目录到达后按能过滤的字段整理。

## 后果

- 一套条件同时管地图、标注、点选和图例，不会一处过滤了、一处还在。
- 用户的例子要靠登记的字段；没有分类、没有登记的资源不能过滤，加字段要探查、人确认叫法和代码的名称。
- 过滤着的资源在 14 级以下和三维里照旧查后端，但后端不能按属性筛：符合条件的很少时要多查几页，连查 5 页都没有时当作没有（缩小范围再点、再框）；框选的范围大时要等第一页的总数回来才提示缩小范围，后端已经统计过一次；没筛完时列表的数量不是总数。后端的范围查询有 `conditions` 参数（`docs/archive/migration.md`"后端的范围查询"），以后能在后端筛时总数才准，要先在真实后端验证（`docs/backlog.md`）。
- 工具栏没有"移除"了，移除在行尾的叉、Delete 和右键菜单里。
