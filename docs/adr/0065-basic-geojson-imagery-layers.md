# 0065. 基础 GeoJSON 与栅格使用统一影像层序

- 状态：已接受（用户确认统一影像层方案）
- 日期：2026-10-19
- 依据：[ADR 0064](0064-three-dimensional-integration-scope.md)、[3D.3a 支持清单](../stages/stage-3d-3a-basic-style.md)

## 背景

会话按“底图 → 资源 → 高亮 → 遮罩 → 注记 → 边界”等分组排序。Cesium 原生 GeoJSON 实体或地面图元与影像属于不同渲染通道，不能仅靠调整实体顺序实现影像、GeoJSON、影像的穿插。旧项目把 GeoJSON 放在全部影像之上，不能作为当前会话层序的实现。

## 决定

- 基础 background、raster、GeoJSON fill/line/circle 全部通过 Cesium 影像层叠放，顺序来自同一会话快照；不为三维另存业务层序
- GeoJSON 先在按需创建的 Canvas 瓦片中绘制透明点线面，使用 Web Mercator 分块；标准库负责属性与过滤求值，Cesium 公共投影 API 负责坐标转换
- 属性、过滤和显隐使用共享相机的实际缩放级。绘制的像素尺寸按相机级别与瓦片级别换算，不能把瓦片级别当作样式级别
- 初期使用内联小数据同步绘制；MVT、Worker 调度、缓存预算与规模性能在 3D.3b 处理，不引入模块级数据缓存或第二份业务状态
- 暂不支持的属性或几何明确诊断并跳过；不改写跨经线或覆盖世界的多边形来“修复”画面，区域遮罩按 3D.3c 单独实现
- 首个业务影像不能因 Cesium 底层影像的边缘延展规则扩散到数据范围之外；渲染器须隔离这一 SDK 行为并用真实画面验证

## 取舍与验收

原生图元的备选方案实现直接，但无法满足本步完整层序要求。统一影像可共用排序与透明合成，代价是像素图形随球面透视变化、栅格清晰度和瓦片接缝需要验证，不能承诺与二维逐像素相同。

本步验证局部点线面、Multi 几何、孔洞、分类配色、显隐、透明度、跨瓦片边界、相机级别变化及资源释放。Canvas 不能准确表达的抗锯齿开关或特殊连接阈值不计为支持；详细清单随实现和测试记录同步。业务页切换仍等 3D.3、3D.4 完整验收后开放。
